# 历史成功摘要不等于本次调用成功

2026-10-31，[六个 Godot 运行器的独立拒绝实验](../audits/runner-rejection/README.md)实际确认：Python -O 调用均退出 1，未进入引擎调用，却保留预置的历史 PASS 摘要。只复制 Python runner，未运行 Godot，也没有重写任何既有运行源或引擎日志。

这些运行器在优化模式拒绝之后，进入正常路径才删除旧 `results/summary.json`。因此旧文件存在、内容是 PASS、甚至文件时间较新，都不能单独作为某一次调用成功的依据。拒绝本身有效；问题是消费者误认历史产物，而不是程序返回了虚假成功。

消费者必须保存本次调用的命令、源身份、起止时间、退出码与输出引用；非零退出不能被旧摘要覆盖。当前历史摘要没有唯一 invocation ID。需要新执行证据时，在新的隔离副本中运行并保存外部调用回执，将新摘要与该次调用绑定；不要直接覆盖已归档证据。文件一致性校验只说明选定历史文件相互一致，不能证明最近一次尝试成功。

本审计没有验证所有失败分支、并发调用、权限错误、崩溃持久性或上游程序身份。`godot-fixed-step/run.py` 的旧注释关于失败不留旧摘要，只适用于已到达清理点之后；保持原始源哈希，不静默修改历史实验代码。未来可以设计唯一调用 ID 与每次独立输出目录，此处不声称已经实现。

本说明不宣称六个 Godot runner 已修改；原始源与既有执行记录保持不变。

ICU 夹具的新版 runner 已单独修复优化拒绝前的摘要清理，并测试超时部分输出保留；[有限证据](../experiments/icu-message-boundary/runner-negative/README.md)不代表六个 Godot runner 也已修改。
