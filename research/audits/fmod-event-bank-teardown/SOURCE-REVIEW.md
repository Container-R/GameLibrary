## 接受的推论与项目决定

按顺序请求停止、释放、bank 卸载，不建立尾音已完成的合同。这是多个 API 寿命语义的组合推论，不是实际听到截断或观察到错误。产品若要求继续事件尾部，应把所需 bank 的持有责任延长到经项目定义的结束处理；立即回收则明确接受可能中断。保留 bank 是必要资源条件，不是可听完整性的充分条件。

应保留以下具体限制：

1. `release` 不是 stop；也不是一调用即必然无效。文档允许销毁前继续交互，但 stopped 后销毁会使后续操作失败。不要把缓存的句柄或早先有效性查询当作以后可用的保证。
2. 回调到来时的 SDK 状态、搬到游戏线程时的句柄寿命、bank 管理器接纳卸载是不同阶段。可搬运项目身份/结果记录，不承诺延迟再查询原句柄仍有效；身份与其他使用者收束不能由一次非原子的状态读取代替。
3. DESTROYED 本身不说明为何销毁；即使 STOPPED 也不是扬声器声学尾部结束回执。不得以“卸载引发的销毁通知”证明自然淡出已经履约，也不推断所有销毁路径的具体通知顺序。
4. 继续服务 Studio update，但不设计阻塞忙等；等待策略、失败/超时政策、线程搬运与共享使用者管理仍是原创未执行设计。不能把所有权延长写成厂商现成引用管理器。
5. 普通事件范围内，AHDSR/DSP 尾部语义不扩展成所有总线、混响、流式 I/O 或跨 bank 图的完整保护证明。保留既有 START_FAILED 不等待 STOPPED 的独立路径。
