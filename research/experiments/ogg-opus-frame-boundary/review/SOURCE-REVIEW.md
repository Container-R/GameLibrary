## Source conclusions

[RFC7845](https://www.rfc-editor.org/rfc/rfc7845.html), April2016, §§3–5.2: granules use48kHz samples per channel; pre-skip is header-derived. The first non-EOS completed-audio-page granule may exceed its completed durations, but cannot be smaller. Equality deliberately fixes the proposed initial offset to zero. EOS can trim samples; its discarded amount SHOULD not exceed the last packet's duration. Thus this gate's enforced bound is a supported narrower subset, not a universal MUST. For this verified zero-offset case, final granule minus pre-skip is the presented count; general cropped/joined streams need different initial-position handling. Identification data must occupy the first page alone. Comments begin on page2 and finish their completion page; audio follows on a later page. Header-completion granules are zero. Comment metadata may have padding/binary data after the bounded string list.

[RFC3533](https://www.rfc-editor.org/rfc/rfc3533.html), May2003, Informational, §§5–6: page size follows27-byte base plus segment count/table/body sum. Lacing255 continues a packet; smaller values finish it, including a zero terminator for exact255 multiples. Fields are little-endian; granule -1 denotes no packet completion. Page CRC covers the whole page with its stored checksum zeroed. These support the proposed exact-offset reader, but not scanning payload magic for new pages or treating an incomplete packet as completed.

Continued-page flag agrees with pending packet segmentation; support in code is not observed continuation coverage when generated output contains none.

Its payload length is packet length minus1 and is bounded above by1275; zero-length frames are allowed by the format. ## Conditions to make explicit before frozen protocol

1. **Header placement:** require all page0 payload to be exactly the supported completed OpusHead packet, with no second packet or pending tail. OpusTags starts on page1 and finishes its completion page, with no audio data on that same page. Merely requiring it to precede audio in packet order is insufficient. Keep header pages separate from audio granule checks.
2. **Subset classifications:** nonempty payload, no chained streams, exact header version/length, strict initial-zero anchor, strictly increasing EOS position and at-most-one-final-packet trimming are chosen acceptance restrictions where narrower than the format. Unsupported valid variants must not be reported as malformed Opus.
3. **Comment bounds:** bound every length and the declared comment count before iteration/allocation. Do not reject permitted post-list padding merely because the string list ends before the packet does; either record its byte count and ignore it, or expressly freeze a narrower padding policy. No Vorbis framing-bit requirement should be imported into OpusTags.
4. **Granule domain:** parse the64-bit field deliberately; only the no-completion sentinel may be negative. Reject other negative values, unfinished EOS packets, and granules beyond the cumulative accepted durations. Preserve page completion indices so EOS trimming uses the last completed-packet page, not an arbitrary preceding no-completion page.
5. **Finite oracle:** final-granule/pre-skip/count equality and actual full decoded PCM frame count are complementary checks, not proof of waveform equality or seamless playback. If actual packet layout is outside the frozen subset, retain it and stop; do not repair media or broaden the reader after observing results.

With these explicit restrictions, the gate supports a meaningful narrowly generated-stream protocol. No general-purpose Ogg/Opus conformance checker or entropy decoder is justified.
