# 完整文件替换与版本正确性：两个受控 Linux 轨迹

原创窄实验，2026-10-31 实际运行。不是 Steam 集成、崩溃测试或可直接部署的存档实现。

## 结果

实际环境 Python3.12.14、Linux6.18.57 x86_64、glibc2.41；临时目录实际文件系统为 **tmpfs**（`stat -f -c %T`）。调用 Python `os.replace`；未进行 syscall tracing，不声明具体底层 syscall 名称或持久磁盘行为。进程启动方式显式 `spawn`。

| 轨迹 | B 发布后重新读取 | 旧完成是否接受 | 最终重新读取 | 断言 |
|---|---|---|---|---|
| 替换前仅检查过旧基线 O | 完整 B | 否 | 完整 A | 反例成立：B 被覆盖 |
| 放行后、替换 API 前再检查失效标志 | 完整 B | 否 | 完整 B | 此安排时序下旧替换被跳过 |

两份载荷都是10345字节；每次读取解析 JSON、验证 payload 摘要，再比较全部字节与预期编码。原始结果包含完整文件 SHA256。两个临时目录均自动清理。stderr 为空，进程退出正常；没有 sleep、杀进程、注入崩溃或 fsync。

## 可证伪命题与屏障

待反驳命题：“预先检查基线，再替换完整临时文件，最后拒绝过期完成，就能避免覆盖新版本。”

协调进程创建并关闭 O/A/B 文件；旧写子进程读到 O 后设置 `checked`，在 `release` 上阻塞。协调进程等待 `checked`，将 B 替换到目标并重新读取验证；设置 `invalidated`（本实验一个布尔失效事件，代表唯一一次 epoch 改变），再设置 `release`。旧子进程按所选轨迹替换 A 或跳过；协调进程收结果、join，然后读取最终文件。事件等待与 join 的超时仅用于检测协调失败，不用于决定交错顺序；文件系统调用本身没有可取消或统一完成时限，不能据此承诺整个实验总能在固定时间退出。总计执行两条轨迹，不做随机并发采样。

反例证明：文件内容可以完整，版本却错误；拒绝完成通知没有撤销已发生的路径替换。对照中的重检查**不是通用修复**：生产代码若在重检查和替换之间允许另一写者进入，竞争仍在。共享权限下的串行提交协议、锁或版本存储设计需要另行定义；非合作写者尤其不受该检查约束。

## 证据边界

- 旧写延迟发生在 `os.replace` **调用之前**，不是已经运行中的内核 I/O；两次替换调用按屏障顺序发生，并不重叠。
- 本实验没有验证 Steam 通知、真实挂起恢复、异步取消、CAS、跨设备、跨文件系统、多文件事务或云上传。
- tmpfs 不是持久磁盘。没有断电、fsync 或目录持久化验证；不能证明崩溃安全。
- 没有持续并发读者，只有屏障后的完整读取；不是对所有平台原子可见性的实测证明。
- 实际调用关闭临时文件后再替换，不会写入任何用户存档。运行需普通 Linux/Python 标准库与 GNU `stat`。
- 两条轨迹是反例及安排好的对照，不应作为两项“平台安全通过”计入原模型保护测试。

## 重现

```sh
python3 experiment.py > results.json 2> stderr.txt
```

`results.json` 是本次原始输出；包含代码 SHA256、时间、实际平台、文件系统和读取摘要。`SHA256SUMS` 固定本次代码、说明和输出。代码在导入阶段显式拒绝 `python -O`（结果判定仍依赖断言；协调等待已移到显式超时检查）；`optimized-rejection.txt` 保存实际拒绝输出，该运行未进入两条轨迹。
