# 客户端预测确认契约：离散教学模型

## 目的

用原创的一维整数运动模型检查连续确认前缀、客户端后缀重放、乱序/重复处理、快照新旧判定与有界历史。模型不导入第三方代码，不需要网络或游戏引擎。

## 运行

需要 Python 3.10+，仅使用标准库。进入本目录执行：

```sh
python3 test_prediction.py
```

`test-output.txt` 保存 2026-10-31 的实际运行结果：16 项 unittest 测试通过（部分用 subTest 覆盖多个畸形字段）。这些数量不是网络覆盖率或安全保证。

## 契约

- `Command.epoch`、`Command.seq` 必须为精确的正 `int` 类型；Python 的 `bool` 和 `float` 不能冒充序号。
- 服务器限制接收窗口为 `ack+1` 至 `ack+32`；每步最多消费一条。相同 seq 首次入队内容保留；无效 axis 最终消费为 no-op。
- `Snapshot.epoch` 必须正整数，tick/ack 必须非负整数，x 必须整数；畸形快照在任何状态变更前抛错。测试构造器只接收本地可信配置，网络解码另行实现。
- ack 表示连续最终处理前缀。缺口存在时角色不消费后续命令，世界 tick 仍推进；本模型没有生产级缺失输入超时规则。
- 快照 tick 较旧或 epoch 不符时忽略；较新 tick 即使 ack 未变也接受权威纠正。
- 表现事件只在首次本地命令执行时登记；重放不产生副作用。撤销预测效果不在模型内。

## 不涵盖

不含 socket、认证、角色所有权校验、字节解码、序号回绕、敌对流量防护、延迟/丢包概率模型、碰撞、平台移动、时钟映射、速度积分、物理确定性或引擎回调。服务器对象构造参数是可信配置，不是消息输入。Python 无界整数亦不能代表真实报文位宽。

生产方案必须补齐上述边界及缺失命令最终处理策略；不能把本模型的测试通过视为防作弊审计或可直接部署的网络层。

表现效果用追加日志记录每次实际发射，而非用集合去重后再计数，避免重复发射被集合掩盖。该日志仅用于有限教学测试审计，随输入增长；不是有界运行时缓存。生产去重存储需定义安全退休水位、迟到事件窗口与epoch清理，pending有界不等于全部内存有界。
