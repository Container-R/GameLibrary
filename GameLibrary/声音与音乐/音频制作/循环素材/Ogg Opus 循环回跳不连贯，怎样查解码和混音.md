# Ogg Opus 循环回跳不连贯，怎样查解码和混音

同一段音乐交给两个打包设置，一个用 10 ms 的 Opus 包，另一个用 20 ms。工具列出的整包时长不同，但这不必改变实际循环周期。反过来，即使完整解码的长度正确，听起来仍可能在返回循环起点时停一下。要定位这种问题，分三个位置测：容器解码产出的 PCM、回跳后实际读到的内容、混音器真正交出的帧。

本文使用 48 kHz 的单条 Ogg Opus 流。一个 PCM 帧包含同一时刻的所有声道样本，双声道不会把帧数乘二。先按[PCM 循环区间](如何标记和检查PCM音乐循环区间.md)保存一份有明确坐标的标记，再核对转码后的文件。

## 不要拿整包时长填循环长度

一个 Opus 包可以解出一段固定数量的 PCM，但容器不一定把这些帧都交给播放器。流头的 `pre-skip` 要求从开始解出的内容中丢弃指定帧数；尾页的计数则告诉播放器最后一页应保留多少内容，不必播到最后一个编码包的物理边界。[1]

我用 FFmpeg 7.1.5 调用 libopus 编码同一段 94,001 帧的探针。按整包解出的长度计数，10 ms 设置得到 94,560 帧，20 ms 设置得到 95,040 帧；两份的流头丢弃均为 312 帧，流尾分别丢弃 247 和 727 帧。让 FFmpeg 完整解码并数输出 PCM，两份都正好有 94,001 帧。如果误用整包长度作为整个素材的循环长度，20 ms 版一轮就多算 1,039 帧，约 21.65 ms。这里测的是解码长度，不是两种包设置的音质是否相同。

Ogg 页有一个 48 kHz 时间轴上的计数，叫 `granule position`。对 Ogg Opus，用该计数减去 `pre-skip` 可换算到 PCM 时间轴上的位置，这个位置标的是已经播放到哪一个边界，不是从零编号的样本下标；它也未必以零为起点。[1] 对首个完成音频包的页不是尾页的普通多页文件，可用该页的计数减去该页完成的音频包解码帧数来确定包时钟的初始计数。丢弃流头 P 帧之后，首个可播放帧之前的包时钟边界是「初始计数 + P」；换到 PCM 时钟时减 P，首个可播放边界的数值便等于初始计数，不要再减一遍。若首个完成包的音频页同时是尾页，按规范另行处理，不套用这个简式。 例如只给一份测试文件的音频页计数加 48,000，不改变实际 Opus 音频包；两份文件的流尾计数成为 94,313 和 142,313，换算后的最终 PCM 边界分别是 94,001 和 142,001。第二份的起始边界为 48,000，所以相减后长度仍是 94,001。实际用 FFmpeg 将两份完整解码为浮点 PCM，逐字节相同。检查长度时，要么数实际交付的帧，要么在同一时钟里求起止差；不要把界面显示的绝对结束时刻当作片段长度。

## 回跳时，游标和读到的帧都要检查

假设循环主体为输出 PCM 的 `[62513, 63214)`。对于以第一帧为零的接口，回跳目标就是 62,513，不取整到上一个包，也不在调用前手工加一次 `pre-skip`。若接口接收绝对容器时间或不同的采样率，先查清它的单位与零点。中途定位时，RFC 7845 建议从目标之前至少 3,840 个 48 kHz 帧开始解码，丢掉预解码输出；否则解码器可能缺少历史。若这段预解码从流头之前开始，则从流头按正常规则处理 `pre-skip`，再继续到目标。这个 seek pre-roll 不等于每次回跳再从播放结果里多扣一截。[1]

测试素材两声道都放不对称、非周期的定位特征。先用独立工具完整解码对照，然后用目标路径测试新开的流和真实的向后回跳：记录落点、实际取到的帧数、取完后的游标，并用目标附近的几段对照相同帧数的波形。故意把目标挪一帧做负对照，确认这套检查能识别一帧差异。不要仅凭波形非零差就判断位置错了；不同定位路径可能有不同的解码历史。[2]

测试中的 libsndfile 1.2.2 在两份文件上调用同一相对位置的 seek，报告与实际回读结果一致于零原点文件的对应片段。例如 62,513 回读 701 帧，两个文件逐值相同。但如果直接把非零原点文件在同一个库里**刚打开就开始顺读**的结果当作标准，情况倒过来：回跳取得的 701 帧，在这份顺读结果里实际匹配到 62,825。再和零原点顺读及两份 FFmpeg 完整输出交叉比对，可把偏移定位到该版本在这个构造文件上的初始顺读，而不是给 seek 参数减 312。另开一个流，显式 seek(0) 后读首 128 帧，又能与零原点文件的对应片段逐值对齐。固定版本源码也解释了为什么两条路径可能分开：顺读补包时拿绝对包位置和相对的 `pre-skip` 比较，而 seek 换算目标时把流起点与 `pre-skip` 都计入。这个例子不代表其他库或游戏引擎有同样行为。[3]它提醒我们：总帧数、接口返回的游标、实际内容对应的位置，是三个不同的检查量。

## 循环边界落在混音块中间时，要在这一块接上

上面的区间一轮为 701 帧。若每次混音器要求 512 帧，第一块交出 512 帧；第二块先交出本轮剩余的 189 帧，然后接上下一轮开头的 323 帧。此时应该看到最后一个PCM 帧 ID 63,213 后立刻接 62,513。没有必要等第三次回调才返回起点。等待回调才补的位置，可能继续输出区间外内容，也可能空出 323 帧；无论哪种，正确的解码定位都救不回来。

可以先用缓存 PCM 或带编号的测试帧验证输出调度，把 I/O 和重新解码从这个测试中排除。每次只取「本次还要的帧数」和「离循环末尾的帧数」中的较小值，触及末尾就从开头继续填；若刚好填完本块，下块从开头起；若块比整个循环长，同一块可能多次换回。确保区间非空。在实际运行的帧编号模型里，正确实现第一次回跳发生在第二块内偏移 189、累计输出 701 帧处；把回跳拖到下一块的对照第一次在第三块开始回跳，累计到了 1,024 帧，之前有 323 帧空洞。这只是编号输出的验证，不是运行时混音器的时延测量。线上流式播放需要在实时回调之外备好回跳所需数据；短循环可缓存 PCM 换取确定的填充，长素材则要权衡缓存大小和预备解码的时间，不能先阻塞回调读取再拿正确帧数当验收。

排查时先看完整 PCM 的长度和起点，再看跳转返回的**内容**。最后，在该声部混入总线、进入效果或重采样之前捕获输出，测重复标记之间隔了几帧。可用预分配的记录缓冲，在回调外读出每块的请求帧数、实际填入的帧数与补零数；每次换回时，另记当下从循环起点连续可读的帧数。边界后的数据已经可用却没填，与回调到来时确实无数据可填，是两种不同故障。若这些都对，接缝仍然可闻，再回到[接缝波形与听感](环境音找到零交叉，为什么循环点还能听出接缝.md)检查素材的连续性。
