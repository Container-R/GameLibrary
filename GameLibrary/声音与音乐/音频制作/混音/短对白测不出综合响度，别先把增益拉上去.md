# 短对白测不出综合响度，别先把增益拉上去

一句短促的「走！」和一句完整的任务说明，一起进了配音交付检查。任务说明测出正常的综合响度，「走！」却被工具报成 −70 LUFS。若按目标值直接补增益，可能把已经很响的素材推到削顶。也别反过来规定每句都要和任务说明一样响：悄声和喊话本来就可能有意不同。该先分清的是：读数是否有效，素材的轻重是否符合场景，以及调整后是否还有余量。

## 先知道仪表是在测什么

BS.1770 的综合响度（Integrated，I）不是文件的峰值或不加权 RMS。它先对各声道做 K 加权，再以 400 ms 的完整滑动块统计能量，块之间重叠 75%，即约每 100 ms 更新一块。末尾不完整的块不纳入。先用 −70 LKFS 的绝对门筛掉过低的块，再用绝对门留下的块算相对门，门限比其响度低 10 dB；最终在同时超过两道门的块上做能量汇总，而不是把保留的 dB 数值取平均。[1] 在同一算法的响度刻度上，LKFS 与这里工具显示的 LUFS 数值可直接对照。

这带来两个容易混淆的结果：

- 一段不到 400 ms 的文件没有完整块。即使录音并不轻，也不能拿仪表为了显示结果而给出的数字算增益。FFmpeg 7.1.5 的 `ebur128` 在本例会显示 −70.0 LUFS；这是本例无合格块时的输出，不是把真正的短句测成了 −70，也不是所有仪表的无结果标记。[2]
- 门控的是块，不是单个采样。用零补齐 400 ms，块里原有的声音会和补入的静音一起平均。比如忽略滤波边缘与门控，200 ms 的恒定能量加 200 ms 零，块均方能量减半，读数低约 3 dB。补零能做诊断，但不能当作原来短文件的「正确 LUFS」。同样，长尾并不一定把综合响度拉低：纯静音块会被门挡掉，含收音和静音的边缘块仍可能过门，是否改变结果取决于实际内容和块对齐。

## 用同一段声检查是剪辑边界，还是录音真的偏轻

下面用同振幅的合成音替代对白，只比较测量，不推断听感。峰值不变而综合响度变动时，应先核对两次读的是不是同一文件边界、声道配置和仪表设置。

本例用 48 kHz 单声道、1 kHz、峰值振幅 0.1 的正弦波，FFmpeg 7.1.5 输出如下。表中各处理的真峰值都为 −20.0 dBTP。

| 时长与处理 | 工具汇总 I（LUFS） | 验收上怎样解释 |
| --- | ---: | --- |
| 200 ms 或 350 ms 原文件 | −70.0 | 无完整块；不要算增益。 |
| 200 ms 音 + 200 ms 零 | −26.0 | 一个块，一半是零；不是原文件的读数。 |
| 350 ms 音 + 50 ms 零 | −23.6 | 同样补到 400 ms，但有效声占比不同。 |
| 连续 400 ms 或 1 s 音 | −23.0 | 完整块内维持同振幅。 |
| 1 s 音 + 1 s 零，或先放 1 s 零 | −23.7 | 跨起声或收声的块仍可能算入，不能把门控当成删去静音。 |

对照另做了真正的电平变化：持续 1 s 的声振幅从 0.1 改到 0.025，综合响度从 −23.0 变为 −35.0，真峰值从 −20.0 变为 −32.0；给后者加 12 dB，复测约 −23.1 LUFS、−20.0 dBTP。这里是展示「只改边界」与「真的改增益」的差别，不把 0.1 LU 的显示差设为通用误差，也不把正弦当成角色表演。

## 把剪辑异常与有意的表演差异分开

1. **先确定读数能否用于判断。** 对实际会进引擎的文件记录版本、时长、声道、开尾留白、综合响度和真峰值。如果片段短于一个完整块，或虽够长但仍没有过门的块，就把综合响度标成「不适用」，别填入目标减实测的增益公式。回读波形确认没裁掉辅音、呼吸或尾音；把峰值用于检查异常峰，别用峰值替代响度或角色判断。若另外用短窗有效声能量做内部对照，要注明窗长、截取规则、单位及参考片段，不把它标成 LUFS。
2. **和同一用途的录音比。** 连续导航说明、悄声交流、喊话和极短的动作回应可分开验收。先以项目已通过的同角色或同用途片段作参考，以相同文件范围和仪表比较；再在代表场景试听。比如一声低语如果只在同一角色的低语组中突兀，先检查录制距离、导出增益和剪辑；如果单独听合理、只在配乐进来后听不清，查混音里的遮蔽或总线增益，而不是给整组低语统一加响。按场景回放语言版本时，用实际出现顺序和间隔；不要随意拼接静音后把读数当原单句结果。
3. **只改需要改的增益，并复测输出。** 目标值减去有效综合响度可以作为静态增益的起点，不是最后一笔账：跨过绝对门的块集合可能变，素材还会进总线处理。先用真峰值加预计增益估算余量，再按项目的素材/总线余量验收实际导出、必要的重采样和运行时混合。例如 −28 LUFS 要调到 −24，需要先看 +4 dB 是否可用；若素材真峰值已为 −3 dBTP，这笔增益会把预测峰值推到 +1 dBTP，应退回检查，而不是给所有句子一刀切加限制器。[1][3]

判断依据最好能让下一位接收人重做：保留这条声为什么需要修、修多少、是素材问题还是场景问题。单文件响度通过只能说明资产检查的那个环节；要保住玩家听到的第一词，仍要在有主音乐和音效的场景检查，不是给整库再设一个统一数字。
