# 角色瞬移后，空间音效为什么突然变调

角色传送后，身边持续响的机器声突然拔高一下，接着恢复。立刻关掉多普勒能压住问题，却也会拿掉赛车驶过等真正需要的音高变化。先检查更窄的一层：位置需要跳到目的地，但不能把这段跳过的距离，当成声源或监听器在一帧内实际走过的路。

## 位置可以不连续，速度输入不能靠盲目做差

多普勒取决于沿声源和监听器连线的速度分量，不是速度大小。以监听器静止、声源沿直线靠近为例，声速为 c，声源沿连线朝监听器的速度为 v，简单亚音速模型给 `f = f0 × c/(c−v)`；远离时 v 为负，音高降低。若只是横向运动，瞬时沿连线投影可近零。监听器本身也会参与；不能只记录声源数据。OpenAL 规范的模型使用声源和监听器各自沿连线的投影，另有全局多普勒比例、声速与速度极限处理；不同中间件不一定用同样的实现。[1]

假设游戏按米计，一个本来静止的声源在 1/60 秒的更新间隔内跳近 2 米。若把差分当速度，就会提交 120 m/s 的接近速度。以 c=343 m/s、440 Hz 为参照，简单模型预测约 677 Hz；真正以 5 m/s 接近，只约 447 Hz。后端若把这份属性保留几个混音块，听到的未必恰是一帧突刺；持续多久取决于参数何时提交、消费和平滑，不该从 60 Hz 直接推成 16.7 ms。

FMOD Core 2.04 的监听器属性文档明确要求速度用世界单位每秒，不是每帧的位移，并把距离尺度作为专门设置。[2] Unity 6 对 `AudioSource.velocityUpdateMode` 的说明也提醒，若多普勒表现不正确，检查声源更新方式是否与实际移动发生的更新循环一致。[3] 两者都不能替代对游戏采样顺序的核对。场景用厘米、后端按米解释，或位置仅在固定步变化却拿渲染帧间隔做分母，都能制造不需要传送也存在的错误。

## 给传送和镜头切换标记一个新的连续段

在玩法层或音频桥接里区分「位置变了」和「运动样本连续」。传送、重生、监听器换绑、镜头硬切、世界原点重置，都可能让两次世界位置不是同一条路径。让这些事件与位置一同进入音频属性更新，并把它们与普通高速运动分开。只靠「位移超过 N 就清零」容易吃掉正常的快速飞行，也可能漏掉短距离传送。

一次更新可按下面的顺序做：

1. 采集同一个运动时间基准上的位置、时间戳、对象身份和连续段编号。声源、监听器都需要。若拿得到同一坐标系和单位下的可信物理或玩法速度，不必从画面位置反推。
2. 发现新连续段、首次有效样本或时间戳无效时，不形成跨边界差分。把**新位置照常**交给空间化；速度提交明确的后续运动速度，若到达后静止或未知，本次先用零。源和监听器分别决定，不能因为一个切换就把另一个的合法运动也抹掉。
3. 只有位置与时间戳有效，才能将新样本设为后续差分起点；若时间无效，等首个有效样本重新建基线。下一次取同一连续段、时间确实前进的后续样本；如果本帧前面暂存过旧速度，不要让它稍晚又被提交。若平滑器或音频属性缓存也保留旧运动，按实际实现复位或在同一批更新中切换，检查音频线程最终消费到的那一份。
4. 原点重置如果只改变坐标表示，优先把同一变换应用到新旧位置和所有对象，再比较一致坐标系中的运动，或显式重置基线；不能一边用新原点，一边用旧原点。最好将源与监听器新变换一起提交，避免一帧把它们放到两个坐标系。

例如监听器从角色视角切到观战位，听感上可以立刻换方位和距离，镜头没有必要从旧位飞到新位。若想让切换更柔和，可以另做混音或位置过渡；这不是把原本没有的穿越速度喂给多普勒。真正连续运动的声源可保有它物理上的速度。传送点位于声源另一侧时，径向投影也会因新相对方位改变，这是正确几何，不必强行保留之前的音高。

## 复现时把音高与音量、声像分开

先用单声道持续音做基线，不改变素材、基础 pitch、随机调制或路由，必要时对照关闭多普勒的版本。录制监听器不动、声源匀速接近与远离两组；随后分别只传送声源和只切换监听器，最后检查原点重置后下一次普通运动。日志保留原始位置、有效时间差、提交速度、沿连线投影、是否跨连续段和音频更新编号。

如果频率始终不变，只是突然更响或更偏向一边，应先查到达新位置的距离衰减、HRTF 或混音过渡；别把所有听感变化都叫多普勒。如果音高跳变但速度日志正常，检查真正交给后端的属性、基础音高变化与效果链。先用持续音确认机制，再回到原素材确认变调长度和主观可闻性。

## 用同一段音频验证速度属性

我用 OpenAL Soft 1.24.2 的 loopback 实际渲染了 440 Hz 持续音。保持声源与监听器位置不变，去掉距离衰减，分别提交四个恒定声源速度，测稳定区的基频：

| 朝向监听器的输入速度 | 测得频率 |
| --- | ---: |
| +5 m/s | 446.506 Hz |
| −5 m/s | 433.676 Hz |
| +120 m/s（用来模拟错误差分的值） | 676.771 Hz |
| 0 m/s（到达静止时的提交值） | 440.000 Hz |

[四段实录对照](../../../../管理档案/实验/空间音频的瞬移与多普勒/comparison.opus)依上表排列，有短静音分隔；数字取自未压缩的输出。本试件只隔离「给混音器错误速度会怎样」，并未在游戏里移动物体或模拟一次短暂更新，不能证明任一引擎的变调时长、平滑或空间化表现。
