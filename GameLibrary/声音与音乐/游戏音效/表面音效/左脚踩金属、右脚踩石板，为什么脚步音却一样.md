# 左脚踩金属、右脚踩石板，为什么脚步音却一样

角色站在金属板和石地的接缝上，左右脚已经踩在不同表面，却都播石地声。先别换音效文件。可能是脚步检测一直在读角色中心下方；也可能两脚确实命中了该踩的位置，却只拿到平台统一的标签；还有一种情况是标签已不同，音频映射仍把它们送到同一个声音。用一条日志把这三处拆开，才知道该改玩法查询、碰撞资产还是音频表。

## 先找这只脚真正踩到的支持物

脚步通知回答“哪只脚现在落地”。材质查询回答“它踩到哪”。不要用角色中心替代脚：中心可能一直在石地上，而左脚已跨上金属板。按落地的那只脚取接触位置；若项目已能提供这只脚的接触点与支持体，优先用它；角色胶囊的整体支撑信息不能替代左右脚的各自记录。若从动画通知采样，就在物理可查询的时机，从该脚附近沿重力方向做短查询，检查是否符合游戏认可的地面或台阶。设置碰撞层，排除角色自身和无支撑作用的触发器；区分“有个东西在射线下方”和“脚已经触地”。跳跃中的脚能向下射到地面，不表示此刻该播脚步。

再用一块铺在地形上的木板做对照。从落脚处应先识别实际支持脚的木板；只有确认支持物是地形，才去读取地形层。Unity 6000.0 的 `TerrainData.GetAlphamaps` 给出每个纹理层的混合权重，不直接给出“该播什么声音”。若关卡用它作为材质数据，先以命中的地形把坐标映射到所属 alphamap，再由项目定义主层或混合方式。地形下面是什么，不能盖过脚踩木板的事实。混合区明确选择规则，避免采样点稍微抖动就让相邻脚步反复换标签。[1]

## 命中同一物体，不代表两处材质相同

大型平台可以是一个碰撞体，绘制时却有两种材质。若查询或资产只提供物体级标签，两脚即使坐标都对，也只能得到一份标签。此时不能靠缩短射线解决。先查碰撞实际提供的粒度，再选制作方案：

| 可用数据 | 做法 | 要验收的地方 |
| --- | --- | --- |
| 可稳定区分各支持形状 | 把地板按声音区域分形状，在形状或查表数据上给分类 | 检查接缝、缝隙和形状维护成本；不能让重叠引发两次脚步 |
| 支持面能返回可用的碰撞三角面或物理材质 | 用命中结果查每面或每区对应的音频标签 | 表是为碰撞资产建的，不默认与渲染网格三角顺序相同；碰撞重建、简化或换后端后重测 |
| 只有一个粗略碰撞体，但仍能在物体内区分 | 用与命中点同一物理步的物体变换转到作者定义的局部坐标，再查表面区 | 地图跟资产走，验证平移、旋转及实例变换；纹理仅当它表达设计需要的表面时才可作为数据 |

几何对照用一个碰撞体的四个三角面，材质分界在局部 X=0。左脚局部 X=−0.2，右脚 +0.2；物体统一标签都是“通用”，逐面和局部区则得到“金属／石”。把平台平移 +3，落脚点在世界 X=2.8 和 3.2。用原来的世界 X=0 分界就会得到“石／石”，而把命中点转回平台局部后仍是“金属／石”。这是对坐标和标签查找的合成演示，不是引擎碰撞或音频实测。

Godot 4.6 的射线命中结果里，`shape` 和 `face_index` 是不同字段：能拿到形状，不代表能拿到面。面索引只适用于凹多边形形状；Jolt 默认仍给 −1，文档有单独开关，也说明了增加凹形状内存的代价。没有面时应走设计好的退路，例如形状标签、局部区域或有记录的通用标签，而不是把 −1 当表下标。Unreal 的 `bReturnPhysicalMaterial` 和 `bReturnFaceIndex` 也是不同查询选项；实际用的是简单还是复杂碰撞，要看资产配置，不只看调用上的选项。碰撞体选择与返回标签都须在目标版本用自己的资产核实。[2][3][4]

在实际 Godot 4.7.2（Jolt）的离屏测试中，我们让两条射线命中同一个四三角形地板，两个命中的形状编号都为 0。默认面号为 −1、−1；开启面号后，这份碰撞数据得到 0、3。把地板沿 X 轴平移 3 个单位后，两个局部 X 仍分别为 −0.2 和 0.2，面号也没变。加入测试用的触发区与木板后，不查询 Area 时左边命中地板、右边命中木板；打开 Area 查询，左边改命中更近的触发区。这个测试只观测射线和查表输入。它既不验证真实脚的支撑力或播放，也不承诺碰撞数据重建后仍是这些面号。

## 看最终送给音频的标签有没有变

在脚步进入音频中间件或播放组件前，记下脚、触地位置、支持碰撞体、形状/面字段、最终表面标签，以及选中的事件或切换值。若预期踩木板却命中下面地形，先修支持物查询；若已经命中木板但还查地形权重，改的是后续标签数据的选择。若同一平台两脚位置正确但都读到通用，先修碰撞资产或局部地图。若一边已是金属、另一边已是石，最后却走到同一个音频分支，查映射和回退。多个表面也可以共用一个音频事件来接收不同的切换值，所以只看到事件名相同还不能判错。Epic 的 Shooter Game 样例文章展示了把移动命中的表面结果交给音频选择的流程；这里只借用这种分工，不把样例当成逐脚或所有版本的行为证明。[5]

验收至少摆三处：接缝、木板覆盖地形、已知无表面标签的地面。在接缝停步或慢放，让两个触地都指向预期标签，接着平移平台再测。木板用临时的可辨两种测试音或事件名验证，确保没有同时触发下方地形；无标签允许回退，但回退的原因应可查。若标签已分开、听感仍接近，用音频单步和映射检查分辨“选择了同一样本”还是“选择不同样本但制作上难区分”，不要回头改射线。每次触地只提交一次选声，避免持续采样把脚留在地上当成多次脚步。
