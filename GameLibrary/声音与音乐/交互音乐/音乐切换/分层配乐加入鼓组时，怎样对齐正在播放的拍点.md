# 分层配乐加入鼓组时，怎样对齐正在播放的拍点

探索时只播和声，进入战斗才加入鼓组。两份素材都标着 120 BPM，第一下鼓却落在和声两个拍点之间；后来每拍的间隔一样，错开的半拍也一直没消失。对同一首曲子的平行分轨，这不是两条轨的速度不同，而可能是鼓组采用了自己的起点。敌人出现的时刻可以决定何时让鼓声变响，不应默认把那一刻当作鼓组乐句从头开始的时刻。

## 同速只是拍间距一样，还要对齐位置

给这首配乐设一个公共播放位置：从曲目的约定起点起，输出时钟已经过了多少采样帧。假设两份 PCM 素材都从同一音乐拍点导出，播放与素材都是 48 kHz、速度不变，120 BPM 的一拍就是 24,000 帧。和声的拍点落在 `0、24000、48000、72000…`。用「采样帧」是为了避免把立体声的左右两个数值当成时间上先后两步。

假设进入战斗的控制在第 36,000 帧生效。此时公共位置已经在第二拍后半段。若把鼓组从自己的第 0 帧启动，它在输出的 `36000、60000、84000…` 下鼓，和声依然在原来的拍点上。两条序列的拍间隔都是 24,000 帧，但偏移恒为半拍。若鼓组已和和声一起走、只是原先不输出，开增益后第一下鼓仍在 `48000`。这是假设鼓层在本例每拍整点有一下，没有提前的弱起或持续的余响。真实曲子何时听到第一声还取决于这段素材。

把两条测试脉冲分别送到同一份立体声输出的左、右声道，用 OpenAL Soft 1.24.2 离线回读。底轨的拍点从 0 开始，每 24,000 帧一次；四组都在第 36,000 帧开放鼓层输出，读到的右声道脉冲起点如下：

| 鼓组怎么进入 | 输出的前三次脉冲（采样帧） |
| --- | --- |
| 此刻从素材第 0 帧开始 | 36000、60000、84000 |
| 一起启动，原先增益为零，此刻打开 | 48000、72000、96000 |
| 此刻才启动，但游标先设为第 36000 帧 | 48000、72000、96000 |
| 一起启动，此刻打开，但素材内部拍点统一滞后 2400 帧 | 50400、74400、98400 |

这是预生成 PCM 与受控混音块的对照。输出证明常驻开增益、对齐后再启动，在此条件下都可对上公共拍点；也表明共同启动不会自行补偿素材的 2400 帧起点差。它没有流送、编码、虚拟化或设备延迟，也没试听真实鼓声。

这个错误不靠把参数提交限制在小节线上就能普遍解决。小节量化说明**何时允许加入**；在量化点从鼓组的第零帧启动，又是**从乐句的哪一位置加入**。例如一段鼓有四小节变化，而和声已在第三小节开头，即使撞上四拍的强拍，重新从鼓组第一小节播放也可能接错段。需要确认的是它们处于同一段音乐的同一位置，而不只是 BPM 相同。

## 制作和接入要共享哪一个原点

交付分轨时保留相同的工程起点，包含起点到各轨第一个音之间该有的静音；不要让批量裁掉文件首部时，把鼓的弱起或休止当成无用空白。还要一起交付实用的长度、循环起止点和相对偏移。只比较文件长度查不到前置静音被剪掉又在末尾补回的错误。把一条直白的拍点参考轨或导出标记和每条分轨一起检查；如果素材经过编码、解码或重采样，量的是**实际导入后**的节拍位置和循环周期，不能只看工程时间标尺。[1]

接入有两个常见选择：

- **一起启动，只控制可听程度。** 让各层由同一个音乐会话推进，先听底轨，战斗请求只改鼓层的增益，按音乐需要做短淡入或等下一允许拍点。前提是被静音的层仍按同一时钟推进，不能把静音当作暂停。如果中间件将不可听的声音虚拟化，确认恢复政策是继续时间线还是从头回放。例如 FMOD Core 的虚拟声部恢复通常接在已推进的位置，但它也有显式从头重播的模式。[3] 常驻或持续解码也可能占用预算，不能只按音量为零推断它没有成本。
- **需要时才启动，但接入此刻应在的位置。** 先定未来能可靠提交的混音时钟位置，再算该位置对应的轨内游标，并在资源和游标都就绪时调度开始。以同采样率、速度固定、已在循环主体为例：循环范围是 `[begin,end)`，从主体开始经过 `n` 帧，对应素材位置是 `begin + n mod (end−begin)`；若仍在引入段则按引入的映射，不能把整首歌盲目取模。素材速率与输出时钟不同，先换算各自单位。若解码预热或定位精度不足，不要在旧点补播；按项目规则等下一个可用点，或者选择一起启动。

以 FMOD 2.04 Core 为例，`ChannelControl::getDSPClock` 能取得父时钟，`ChannelControl::setDelay` 用父 `ChannelGroup` 的 DSP 时钟安排样本级的开始或停止。[2] 这解决的是「混音时间到哪里开始」，不能代劳「该从文件哪一位置开始」。若要先设位置再调度，选定有效的源位置设置方式，并核对目标声源类型的精度与准备时机。例如用 `Channel::setPosition` 定位流式素材，非阻塞重定位可能尚未完成，不能把请求提交当成就绪；变码率素材没有适用的定位表时，定位也可能不够准。[4] 本文未执行 FMOD；不能用该文档或离线夹具推断扬声器何时响。

## 用一次混音输出确认修的是哪一层

先用测试用的短脉冲或明确拍点做基准，把底轨与鼓层分开读回，或把它们录在同一时钟的不同通道。记录玩法请求、音频采用该控制时的混音帧、实际输出拍点三件事。看到错开时，先找规律：

- **第一次就偏，之后不再增长。** 优先查素材导出原点、运行时启动帧和素材游标。分别保留「从零启」和「继续公共游标」的负、正对照。
- **每轮多错一点。** 对照素材可用帧数、实际播放速率和循环区间，尤其在两轮以后量周期。只修启动不能修周期差。[1]
- **只有隐藏再回来才突然错开。** 记录这条声部是静音、暂停、停止还是虚拟化，把恢复位置与音乐时钟比较。有人重新启动过它，或者后端保留的是旧位置，都需要分别核查。[5]

至少覆盖半拍打开、循环边界打开、以及退出战斗后再进入一次。自动检查可验证拍点、循环和对齐；音乐上这一段是否适合作为鼓组入口、淡入是否遮掉主要鼓点，还需要用实际素材试听，而不是只看两条脉冲是否在同一帧。
