# 传送带上的物品都在移动，为什么不必逐件更新位置

一条长传送带上有很多物品。每次更新，程序读取每件物品的位置，加上同样的位移，再写回去。画面和规则都没有错，但物品越多，要修改的位置也越多。

在没有阻挡或取放时，这些写入里有一种重复：所有物品一起前进，它们之间的距离并没有变化。能否把这个不变的关系保存下来，只更新真正变化的部分？

本文面向运行时与玩法程序员。Factorio 的一篇历史开发日志提供了这个思路；下面用一条明确规定规则的玩具传送线手算，解释它何时能省下逐件写入、又会把哪些工作转移到别处。没有运行游戏、复现私有实现或测量性能。

## 改变的不是物品有没有位置，而是怎样表示位置

Harkonnen 在2017年的 Factorio FFF176 中介绍，为0.15准备的优化把相邻传送带组织成较长的运输线，并用物品间距离及两端空隙表示位置。自由流动时，内部相对距离不变，主要修改两端；但按数组序号取得绝对位置，需要累加距离。[1]

物品没有因此失去位置或身份。改变的是存储表达：不再让每个物品的位置都独立承受同一次平移。这里也不是将某些物品移到别的线程，而是减少这一步必须修改的数据。

先看一个完整的小例子。线段从0到10，物品都长1，前进方向朝右。三件物品的左边缘分别在1、4、7；最前面的物品占据[7,8]，距离右端还有2。假设每步按从最前到最后的顺序处理，每件尽量前进、最多1，不能重叠，也不能越过右端。暂时不发生取放、传出或新物品进入。

按从左到右的顺序，记录四个**空隙**：

- 起点到第一件物品：1。
- 第一件右边缘到第二件左边缘：2。
- 第二件右边缘到第三件左边缘：2。
- 第三件右边缘到线段终点：2。

于是，可以把这份位置状态写成 `(1, 2, 2, 2)`，同时另存三件物品的身份与顺序。空隙合计7，加上三件物品占用的3，正好是线段长度10。本例的空隙是物品之间的空白长度，不是中心距，也不是原游戏的数据字段。

## 整队前进时，中间的空隙不用改

第一步没有阻挡，左边缘变成2、5、8，空隙变为 `(2, 2, 2, 1)`。起点一侧多了1，出口一侧少了1，两个内部空隙仍然都是2。

再前进一步，左边缘是3、6、9，空隙为 `(3, 2, 2, 0)`。最前面的物品现在刚好抵达右端。

在这两步中，只改第一个和最后一个空隙，就能表示全部物品平移后的状态。对于任意多件同速且未受阻的物品，只要顺序、尺寸和内部间隔都保持不变，同样的表示关系仍成立。这是本例的代数性质，不是“整个游戏每步只做两次写入”的结论。

要恢复第二件物品的左边缘，先走过起点空隙，再走过第一件物品的长度和其后的空隙。例如第二步后：

`第二件左边缘 = 3 + 1 + 2 = 6`

第三件则再加第二件的长度1及下一个空隙2，得到9。物品的位置仍能求出，只是不再各自存成一个随整体运动变化的数。

## 前面堵住以后，不能继续只改两端

第三步，最前面的物品已不能右移，后面两件仍有空间前进。规则要求它们尽量移动，但最多1，因此左边缘变成4、7、9，空隙为 `(4, 2, 1, 0)`。如果仍把最后的0减成−1，就会把最前面的物品推出边界；若只因前端堵住就让整队停下，又会漏掉后面的合法移动。

继续按同一规则手算：

| 时刻 | 三件物品左边缘 | 从左到右的四个空隙 |
|---|---|---|
| 前端刚抵达边界 | 3、6、9 | 3、2、2、0 |
| 再走一步 | 4、7、9 | 4、2、1、0 |
| 再走一步 | 5、8、9 | 5、2、0、0 |
| 再走一步 | 6、8、9 | 6、1、0、0 |
| 全部贴紧 | 7、8、9 | 7、0、0、0 |

堵塞从右边逐渐传到后面。已经贴紧的一对物品，在本例没有取放、传出或倒退的条件下，不会自行重新拉开；下一处要压缩的空隙逐步向左移动。

原作者利用过类似的单调关系，缓存最后一个正空隙的位置，避免每次都从头寻找，并据此讨论分摊后的更新成本；这一持续压紧的前提限于远离机械臂干预的情况。[1] 这里没有复原其数组方向、跨运输线转移或全部复杂度分析。表格只帮助理解为何“记住上次找到哪里”有时成立，以及这个依据来自什么规则。

## 取走一件物品，旧结论就可能失效

现在改变前提：从全部贴紧的7、8、9中，取走中间那件。剩下两件仍在7与9，中间重新出现长度1的空隙；新的空隙是 `(7, 1, 0)`。

这时，原来“内部已经没有正空隙”的记录便不再适用。如果下一步仍按旧记录认为整条线都不能动，左边那件就会错误地停在7，而不是前进到8。

这是本文模型中的反例，不是 Factorio 的实际缺陷。它说明，缓存一个搜索位置必须连同维持它的条件一起设计。取走、插入、拆线、合线或改变速度规则时，不能只修改物品列表而忘记重新建立相关表示。至于每一种事件应该局部修补还是重建，需要具体实现另行决定。

## 少写位置，不代表所有查询都变便宜

逐件保存位置时，按索引读一个位置很直接。改成空隙后，如果没有额外索引，找后面某一件的位置要累加前面的长度与空隙。若渲染一次按顺序访问全部物品，可以边累加边前进；若大量系统反复随机查询不同物品，又每次从头累计，省下的更新工作可能换成了更贵的查询。

原日志说明，其机械臂需要连续跟踪物品，因此能利用前后更新关系维护所跟踪的位置，并对取放附近的运输线长度作限制。[1] 这不是任意随机查询都自动具有相同代价的保证。

对自己的实现，比较时至少要看整体移动、堵塞推进、取放、跨段转移以及实际位置查询，而不只数“移动循环少了多少次”。同时确认物品身份、顺序、碰撞与交接规则仍然相同。两端空隙更新得很快，却让取物目标或渲染位置发生偏差，不能算等价优化。

这类方法值得借鉴的，是先找出**哪些关系在一段更新期间不变**，再围绕这些关系选择数据表达。少修改数据可能比更快地重复相同修改更有价值，但它依赖明确的规则和使用方式，不是一种适用于所有移动物体的通用压缩。
