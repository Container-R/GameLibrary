# 多文件本地存档的代际发布与恢复

角色文件已保存“获得钥匙”，城镇区块还记录“宝箱未领取”。两个 JSON 都能解析，读档后玩家却能再次领奖。原因不一定是文件写坏：保存程序逐个替换正式文件，在两次替换之间退出，就会留下业务上从未存在过的世界。

本文面向能实现文件读写与对象序列化的运行时程序员，给出完整复制存档的基线：把同一快照写成不可变的一代，用清单绑定全部必需文件，用一个根记录决定已发布的代，恢复时整体接受、整体回退或拒绝。限定单机、单槽、同一文件系统、所有合作写者经过同一串行入口；云同步、跨进程竞争和恶意文件改写不在保证范围。

进程中止后的选择正确性与机器掉电后的持久性是两件事。下面的真实夹具观察前者；持久化步骤说明平台实现的责任，没有经由这些实验获得断电保证。

## 1. 先定义共同快照，再定义文件集合

用一个教学状态说明约束。A 的修订号为1：角色没有钥匙，town 宝箱未领取，区块集合为 town、old。B 的修订号为2：角色有钥匙，town 宝箱已领取，集合变为 town、new。角色持钥匙必须与宝箱领取状态一致，B 不得漏掉 new 或重新加载 old。

实际项目应从数据模型提取约束，例如装备拥有者与背包记录一致、任务引用的实体存在、角色位置指向本代声明的场景。摘要只验证选定的字节，业务检查也只覆盖明确列出的不变量。

后台线程不能依次读取仍在变化的游戏对象，最后统一写上同一代号就算一致。可在短暂写入屏障内复制世界快照，再异步编码；或者使用已有版本化快照机制。代 ID 标识一次固定保存操作，schema 解释格式，修订号描述业务进度，三者不能互相替代。每个操作 ID 不复用，并与快照、槽身份及预期父代绑定。

每代目录包含 metadata.json、character.json、chunks/ 下的必需区块和 manifest.json。manifest 记录槽、代、父代、schema、修订号，以及对象相对路径、角色、长度和摘要。metadata 声明业务期望的完整区块集合。清单描述保存的字节，元数据描述必须存在的对象；两者对照才能发现“清单自身漏块而其余摘要都正确”。

验证一代分四层：

1. 定位合法：拒绝越界相对路径、重复路径和协议外别名，限定角色与命名，拒绝符号链接。跨平台需明确大小写和规范化规则。
2. 字节完整：全部必需对象存在，长度与摘要匹配；manifest 字节摘要由根引用绑定。
3. 解释一致：使用支持的解码器，核对所有对象的槽、代、修订、schema、角色和对象 ID。未知格式不能按旧版本猜着读。
4. 闭包及业务合法：对象集合恰好满足元数据声明，引用都有目标，跨文件业务约束成立。

B 缺少区块时不从 A 补文件。未被清单声明的临时文件不参与恢复，也不能靠目录扫描成为“最新数据”。摘要不提供鉴权；面对不可信输入还需解析大小/深度上限及无竞争路径打开方式。教学夹具不是安全解析器。

## 2. 候选准备完成后，还需要一个发布决定

布局中 CURRENT 与 generations 同处一个槽目录。每个 generations/G 目录在发布后不可原地修改。CURRENT 的正文包含 record version、slot、active 和 previous；active、previous 引用由代 ID 与 manifest 摘要组成，previous 允许显式 null。记录外层对规范编码后的正文计算校验和，用于检测意外损坏。

发布 B 时，previous 从原 CURRENT 的 active 引用复制，而不是扫描目录猜出“上一代”。这条记录只保留一个前代，父代字段也不是可以任意追溯的可信提交历史。

Linux rename 对存在目标名称的替换提供名称查找层面的原子性，已打开描述符不受改名影响。[1] 因而可以把集合发布缩成一次小根文件切换，但多次 rename 不是集合事务，也不应把替换非空代目录当成同一配方。

已有活动 A 时，在同一串行所有权下保存 B：

1. 读取并验证 CURRENT，核对 active 仍为请求预期的 A。缺根或读错不是创建新游戏的依据。
2. 排他创建不复用的 B 目录，写固定快照的全部对象，处理短写及写入、同步、关闭错误。
3. 写并同步 manifest，重新打开候选，用实际解码器完成整代验证。
4. 按目标平台契约同步新增目录，从 chunks、B 向 generations 及必要父目录推进。
5. 构造 active=B、previous=A 的根，写专用临时文件，检查字节并同步。
6. 用平台适配层的单文件替换原语发布 CURRENT。
7. 同步 CURRENT 所在目录，达到平台规定的最终确认点后，才报告相应级别的保存完成。

文件 fsync 不替代包含它的目录项同步；同步本身可能报 EIO、ENOSPC。[2] Windows ReplaceFileW 的一些失败码对应不同残局，WRITE_THROUGH 标志也不受支持。[3] 适配层必须区分确定未发布、当前可见发布和结果未知，不能让上层把统一的 false 理解成“旧根未动，可以删除候选”。

在进程中止模型下，替换前 CURRENT 仍选没有被修改的 A；替换后它选已经完整准备的 B。读者只读一次根并固定代，不在每次打开区块时重新跟随 CURRENT。这个因果依赖不可变代、串行写者与替换原语，不说明掉电后设备保留了哪些写入。

LevelDB 的 MANIFEST 描述文件集合、CURRENT 指定清单，提供组织结构上的对照。[5] SQLite 多数据库 rollback-journal 事务使用共同提交判据，也说明准备与提交必须可区分。[4] 这里没有复制它们的实现或继承其崩溃保证。

## 3. 第一份可信根怎样建立

初始化资格来自明确的新槽请求和本次排他创建此前不存在目录的成功结果。槽管理入口分配唯一槽 ID，将它绑定到受控父目录下的新路径；目录已存在就失败，不能使用“存在也算成功”。即使旧目录为空或没有 CURRENT，也不自动初始化。本次成功创建的资格不在重启时凭残留外观重新推断。加载器还需从槽入口取得预期槽 ID，与文件身份核对。

首代记为 G0：manifest 必须明确含 parent=null；根必须含 active=G0 的完整引用和 previous=null。null 表示本谱系没有已发布父代/前代，不是字段缺失、空字符串或无需验证。后续 G1 的 parent 指 G0，previous 保存 G0 的完整引用。

首次发布顺序如下：

1. 持有本次新槽创建资格，冻结初始内容。它可以是新游戏，也可以是用户明确选择的完整旧进度；重新编码新槽身份和全新代 ID，业务进度不必清零。来源槽/修订只能作为说明，不能冒充新谱系父代。
2. 创建 generations/G0，按完整集合写数据和 manifest，同步并重读验证路径、字节、身份、闭包和业务约束。
3. 同步新增目录，自内向外覆盖新槽目录在存档父目录中的目录项。随后写并同步临时根，在独占的新槽内改名发布 CURRENT。若正式 CURRENT 意外出现，停止保留现场，不把初始化变成覆盖旧根。
4. 同步根所在目录，完成平台最终确认后才开放普通保存入口，以 G0 为后续预期父代。产品可显示“创建中”，但首根发布并验证前不能把它当已有存档加载。确认失败时保持待处置，不因当前能读到 G0 就宣布持久完成。

首次发布前中止意味着没有已发布存档可加载。重启见已有目录缺可靠 CURRENT，应保留现场并拒绝自动加载、自动提升候选及原路径重初始化。核对后若明确继续，应新建独立槽 ID、路径和请求。这避免猜测它是未完成新槽还是丢根旧槽。

首次根已发布而确认失败或响应丢失，可以检查当前 G0 是否可恢复，但不能补称旧确认完成，普通写入继续冻结待处置。若首代必需对象损坏且 previous=null，active 整代失败就直接拒绝，保留原内存与磁盘，不扫描其他目录找“前代”。

这两条首代路径是协议推演：在根改名前中止，重启无根而拒绝；根发布后必需区块缺失，因无前代而拒绝。当前夹具每例正常建立 A，但没有注入首代故障，也没有实现槽注册、全部首代负向格式校验或产品读写门控。

## 4. 磁盘接受之后，还要完整接受内存世界

加载先暂停写入，固定一次 CURRENT 和必要读者租约。根不可靠则拒绝。根可靠时，完整验证 active；失败时仅完整尝试非 null 的 previous。两个候选都失败，或者 active 失败且没有前代，则拒绝。不得逐文件挑选“仍可读”的部分。

解码、引用解析、必要迁移、派生状态重建和业务检查都在未接入主循环的私有对象图进行。候选不能提前发奖励或事件。所有可能失败的构造完成后，在主线程安全点一次替换世界句柄。多线程引擎还须让相关系统一致切换世界版本，延后销毁旧对象；Python 字典赋值不代替实体和资源生命周期设计。

如果回退到前代，向玩家说明实际恢复的进度。原槽不自动重写 CURRENT，保持只读，防止自动保存掩盖损坏。仅换操作 ID 不能解锁：预期父代填坏 B 会验证失败，填 A 又与根 B 冲突。首版不提供原槽原地修复。用户明确选择已完整加载的 A 后，可在独立新槽用其内容重新编码，通过第3节建立新谱系，再继续保存。不能复用旧身份，也不能说此前 B 已成功恢复。

根自身损坏时，即使 A、B 都完整，也不扫描最大代号自动选档。完整候选不证明它曾发布。需要更强自动恢复能力时，要另行设计可信备份根、双槽记录或提交历史，并分析它们自己的发布规则。

恢复读路径不改磁盘，不删除损坏数据。解析和私有构造中再次中止，下一次恢复仍面对同一现场。若无法完成私有构造，原运行世界保持不变。

## 5. 重试和回收不能抹掉失败的含义

发布前的候选写入、验证或同步失败，不改变旧活动根，报告未保存并保留/隔离候选。替换结果不明或替换后的最终同步失败，则保留两代、不盲目写回旧根、不删除本代，冻结写入并诊断。新根当前可读不等于掉电持久；真正 EIO 后再试一次 fsync 也不是通用修复。

同操作重试看到根已经指向自己且验证通过，只能确认当前可见、可恢复。夹具返回 observed_active、durability=not_established、requires_resolution=true，退出3，不是保存成功。缺少独立确认记录时，即使旧操作可能完整成功，也保守等待处置。

如果 B 预期父代 A，而根已经到 C，拒绝 B，不能倒退进度。父代检查和发布必须在同一串行所有权下，它不是跨进程 CAS。无限历史查询也不由单前代根提供。

若根仍为预期父代，但同名 B 候选目录已存在，返回 candidate_exists、publication=not_attempted、requires_resolution=true，退出3，保留现场，不自动覆盖续写。核对确定未发布、故障已解决且仍要保存时，才能发起新 ID、重新确认快照和父代的新请求。未知发布结果不能靠换 ID 绕过。一个操作 ID 也不能承载不同快照；示例 A/B/C 固定了这种对应，生产接口应实际绑定内容身份。

正常路径返回 published_visible、final_directory_sync=returned_success、durability=platform_contract_required，表示本次调用结果，不宣称已实验验证断电。

完整复制至少要预算当前、前代和候选的空间，估算不能替代处理实际 ENOSPC。新代确认前不删唯一旧代；旧读者仍固定某代时不能回收它的后续文件。维护阶段保留 active、previous、读者固定代和未判定操作。清理失败不撤销发布。实验的清理中止只删除独立垃圾目录中的一项，不验证通用代回收算法。

全量复制换来清楚的恢复边界，代价是 I/O 和空间。若权威状态能全部进入一个成熟数据库事务或容器，应比较该方案；外置区块不会自动参加数据库提交。共享不可变块可省 I/O，但清单仍须完整，回收按所有保留根的可达闭包。原地更新加 undo/redo 日志需实现排序、提交判据和可重复恢复，不是加一个 .bak 就足够。[4]

## 6. 本次可访问的实验说明

本稿对应恢复后实际重新运行的证据。夹具代码与执行计划已按历史摘要逐字核验；旧运行原始记录仍缺失，没有被新结果冒充。运行环境记录不公开；本稿不披露运行时间、主机、操作系统、解释器、库、编译器或文件系统的实际环境信息，也不沿用旧机器的环境结论。下文只报告这份有限夹具记录中的行为，不推断其他运行环境。

父进程等待保存子进程报告指定屏障，发 SIGKILL 并等待退出，然后启动新的恢复进程。12个屏障各3次，分别为半写区块、数据完成、清单完成、候选验证、目录同步、临时根半写、临时根完成、替换前、替换后、根目录同步后、通知后、清理中。每次从独立完整 A 开始。

本次 suite 共51项，记录中全部符合判据：发布前8个屏障的24例选择A，发布后4个屏障的12例选择B；另有1例逐文件基线实际产生可解析但业务不一致的状态，9例完整未发布候选/损坏输入，1例重试组合，2例恢复中止和2例软件错误注入。

完整未发布B未被提升。缺块、完整跨代块、对象槽错误、对象schema与清单不一致、摘要重算后的业务错误、对象集合不闭合，都拒绝活动B并整体回退A。根截断或两个可信候选均坏时拒绝，原内存哨兵不变。未知schema案例是对象版本999而清单仍为1，不是整代未知版本迁移测试。完整跨代块首先被字节摘要拒绝，不能单独用它证明身份检查覆盖。

补充4项检查记录为通过：EIO后同B重试返回非成功 observed_active/not_established；ENOSPC后同B重试返回 candidate_exists；两类重试磁盘不变；-O和PYTHONOPTIMIZE=1启动退出4、未创建测试输出目录。关键校验使用assert，因此夹具拒绝优化模式；生产实现应改用不可关闭的显式验证错误。

这些通过值来自本次结果文件检查，不是对真实游戏的认证。日志包含命令、退出码、恢复选择与错误、内存前后、CURRENT字节和文件摘要；它是包装层事件，不是完整系统调用追踪。三次确定性重复不构成可靠度统计。SIGKILL后内核和缓存仍运行；半写是主动屏障；ENOSPC/EIO是软件抛错而非真实设备故障。未测系统调用内部撕裂、随机竞争、真实短写/close错误集合、恶意解析、共享块回收或真实引擎生命周期。

要交付目标平台的掉电保证，还需核对文件系统/设备契约及平台适配，使用受控虚拟机或块设备故障观察丢写和重启结果。不能用新进程读到B或fsync返回成功代替这一工作。
