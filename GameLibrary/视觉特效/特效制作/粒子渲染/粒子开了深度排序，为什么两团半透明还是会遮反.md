# 粒子开了深度排序，为什么两团半透明还是会遮反

两团半透明烟有时前后翻转。特效师给两边的粒子都开了深度排序，左边看起来正确，右边还是盖错；改一个排序优先级，又变成右边正确、左边错误。先别继续调数字。要问的不是“有没有排序”，而是**需要互换前后的两片，是否真的参加了同一次排序**。如果相交的恰是同一对面片，连共享整片排序也修不了。

## 先判断是哪一层在排

在普通半透明的 source-over 混合中，后画的颜色有更多机会留在最上面。用不发光、不受光照的 50% 红片 A 和 50% 蓝片 B 叠在黑底上：先画 A 再画 B，线性 RGB 是 (0.25, 0, 0.50)；反过来是 (0.50, 0, 0.25)。蓝片并没有完全遮住红片，它只让之前写入的红色再乘 0.5。先用这种能看出顺序的材料排查；单测纯加色往往看不出普通 alpha 烟雾的遮挡错误。[1]

**粒子排序**在一个渲染器处理的粒子列表内选顺序；**绘制排序**则可能把整份列表当成一项再排。如果实际提交的是「A 的全部粒子，然后是 B 的全部粒子」，各自改成从远到近，也不能把 B 的一粒插到 A 的两粒中间。再往外是**渲染通道**：如果两个对象落在不同通道，例如一个在景深前绘制、另一个在景深后绘制，先检查通道组织，不要把一个局部优先级当成可以跨通道交换绘制的全局顺序。

- **Unreal Engine 5.5：** Niagara Sprite Renderer 的 `Sort Mode` 描述的是粒子排序；`Sort Order Hint` 给同一 Niagara 系统里同类型材质的渲染器排序，文档说明低值先画。组件的 `Translucency Sort Priority` 是透明 primitive 的排序级别，不是让几个组件共享粒子列表。先在捕获里确认实际材质通道和绘制，再判断该改哪个层级。[2][3]
- **Unity 2022.3：** 内置 Particle System 的 Renderer 模块将系统内的 `Sort Mode` 与影响整个系统排序的 `Sorting Fudge` 分开。文档也把按距离和按视图深度分开，转动相机或换成分屏视角后要重新核查；这里不把内置粒子系统的行为套给 VFX Graph 或所有渲染管线。[4]

## 同一对颜色，做两种不同的几何

用正交视图，深度数越大越远。第一种几何有四个平行于画面的短片，各占左右半幅，A 和 B 每边各一片。

| 采样区 | A（红）深度 | B（蓝）深度 | 正确的从远到近顺序 | 线性 RGB |
| --- | ---: | ---: | --- | --- |
| 左 | 4 | 2 | A 左 → B 左 | (0.25, 0, 0.50) |
| 右 | 1 | 3 | B 右 → A 右 | (0.50, 0, 0.25) |

以组为单位，只能是 A 先或 B 先，怎么选都错一侧。四片能参加同一个兼容排序时，可以实际按深度提交 **A 左、B 右、B 左、A 右**。来自另一侧的面片不贡献这个像素，于是两个采样区都得到正确顺序。

第二种几何只剩下两张铺满画面的倾斜卡片。A 从左端深度 4 变到右端 1，B 从 2 变到 3，中间相交。正确的两边颜色仍同上，但现在是**同一对面片**在两边要求相反顺序。就算把大卡合到一个渲染器，给每张卡分配一个中心深度再排，它们还是只有 A 先或 B 先两种整片顺序。要保住两边的透过关系，需要改变几何粒度（例如适合时在交界拆片）或改变合成方法；若美术允许，也可以重排效果，避免这一交叠。

这两组各自在 Mesa llvmpipe 的离屏 OpenGL 4.5 绘制与读回。目标为线性 RGBA16F，关闭透明深度写入，保留深度测试。四片按交错顺序**逐片提交**时，左、右读值分别为 (0.25, 0, 0.50) 和 (0.50, 0, 0.25)。两大卡换整卡顺序，只会在“左右都偏蓝”和“左右都偏红”之间切换。另一次保持 A 先打开透明深度写入，右侧变成 (0.50, 0, 0)：近处 A 写深度后，原本仍应透出的蓝片被后续深度测试拒绝。它看起来不再反盖，却是**少画了一层**。[5]

## 到项目里按这个顺序查

1. **先固定一帧和一个观察视角。** 临时给两组设不同纯色、同透明度，用单独显示 A、单独显示 B、一起显示确认两层都覆盖问题像素。保留需要的场景不透明深度，把色调映射、雾和其他透明物从诊断里隔开；直接查看线性中间目标，别拿带后处理的屏幕色反推混合系数。
2. **查实际画了什么，再查顺序。** 在目标渲染器的帧捕获里，记录这两个来源的通道、混合、深度读写和提交次序；需要时逐次看同一像素的中间色。如果某一层没提交、没覆盖或没通过深度，就先查相应原因。两组都覆盖且实际分组提交，再用两个顺序各跑一遍，看看是否恰好只交换正确的区域。
3. **按反例选修法。** 能给每粒一个顺序、但当前排序列表隔开时，考虑共用渲染器或允许跨组交错的路径，先核对材质、混合和通道能否兼容；合并后再量排序成本和可见性粒度。确实是始终不交叉的设计层，例如固定在烟后面的霓虹标记，可以用组优先级。若同一面片对的深度关系在覆盖区域内翻转，别再调中心深度；优先缩小或拆分几何、调整布局，或评估逐片元合成与可接受的近似。加权 OIT（无需逐层排序的合成近似）不等于精确逐层合成，见[加权透明混合的边界](../../../图形渲染/画面呈现/透明合成/加权透明混合不用排序，为什么仍不等于逐层合成.md)。

最后回到真实相机路径、实际材质和目标平台再测一次。此试件只验证给定绘制顺序与深度状态的后果，不是 Niagara 或 Unity 的自动排序实测、硬件 GPU 性能测量，也没有证明任意相交粒子都能用一次全局排序解决。
