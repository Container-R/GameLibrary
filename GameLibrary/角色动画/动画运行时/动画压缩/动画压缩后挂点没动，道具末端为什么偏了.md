# 动画压缩后挂点没动，道具末端为什么偏了

动画师让角色手里的长杆末端在某一帧刚好触到墙上的标记。原动画对得上，压缩后杆端有了缝隙，但检查手部挂点，原点几乎没动。只比较原点，甚至只看骨骼的位置曲线，都可能漏掉原因：挂点的朝向变了一点，离它较远的点会把这点差异放大。本文面向做骨骼动画接入和压缩验收的开发者，说明该测哪些点，以及怎样区分压缩与其他运行时步骤。

## 原点对上了，朝向还能不一样

先假设挂点原点不动，原始与解码后的姿势只差一个角度 `θ`。用一条从旋转轴垂直引到被测点的线，记其长度为 `r`。旋转前后，点落在同一个圆上；两位置之间的直线距离是弦长 `2r × sin(θ/2)`。**这里用的是到旋转轴的垂直距离，不是到挂点原点的直线距离。** 一个点即使离原点很远，只要仍在轴上，就不会因这次旋转而平移。

把这点用于一个纯几何对照：固定原点和缩放，两种姿态只绕 Z 轴相差 0.1°。同一组点分别用三维坐标旋转和弦长公式计算，结果一致：

| 被测点 | 到旋转轴的距离 | 位置偏差 |
| --- | ---: | ---: |
| 手部挂点原点 | 0 cm | 0 cm |
| 离轴 3 cm 的短探针 | 3 cm | 0.005236 cm |
| 离轴 80 cm 的杆端 | 80 cm | 0.139626 cm |
| 距原点 80 cm、但在轴上的点 | 0 cm | 0 cm |

若将 0.01 cm 暂当这个例子的位移界线，短探针通过，离轴的杆端却不通过。这不是 ACL 实际压出了 0.1° 的报告；这里故意把误差固定，以展示换观察点就能改变判断。轴上的点不动，也不能证明整个道具的轮廓不变。

## 压缩器的虚拟探针不是游戏里的道具

骨骼动画的局部 TRS（平移、旋转、缩放）要沿父链合成，才能得到角色物体空间中的骨骼姿势。上臂转了一点，即使手骨的局部曲线分毫未改，手和挂件也可能已经偏离。ACL 作者用物体空间的位置误差说明这个问题，并用距骨骼一段距离的虚拟顶点，近似检查逐点蒙皮的结果。[1]

以 ACL v2.1.0 的公开源码为例，`shell_distance` 决定虚拟探针的距离，轨道的 `precision` 则是压缩比特分配所追求的误差精度。二者不是同一个旋钮。在所核对的 QVV 误差度量中，带缩放分支会沿三个坐标轴取点，分别以原始姿势与有损姿势变换这些点，比较位置差；该版本无缩放路径用两个点。[2] 这些点不是把每个真实网格顶点和挂件都送进压缩器。对同一纯旋转误差，放大相关虚拟距离一般会使离轴探针对转角更敏感，但这不等于指定了道具杆端，也不能凭公式预测重新压缩的角度误差或文件大小。

Unreal 5.9 的 ACL 插件文档列出普通骨骼与需更精细骨骼的虚拟顶点距离，还可以设置骨骼网格作为形变估计目标。按文档的默认分类，挂有 Socket 的骨骼使用高精度类别的 Safe Virtual Vertex Distance；改普通类别的距离不一定影响它。[3] 角色使用的 Skeletal Mesh 和独立挂上的长杆并不天然是同一份压缩输入。除非已经核实工具将杆上的点纳入度量，否则应把它们单独验收。Socket 的 Force Always Animated 可以让父链在模型细节层级（LOD）变化时仍被求值；它解决的是骨骼是否还参与求值，不会消除压缩引入的姿势差。[4]

## 给一次压缩改动安排两遍验收

**第一遍隔离编解码。** 选择包含关键接触姿势的片段，固定骨架、采样时间、插件版本、缩放和同一挂接变换。以未压缩姿势为参考，对比同一时刻的解码姿势。用与目标运行时一致的变换合成方式，从两者各自的父链求出挂点，再把道具局部空间的标记点变换到同一个角色物体空间。记录挂点原点和至少一个真正用于对齐的道具点；若杆在多个方向接触，用多个点。分别记下误差最大值、出现时间和对应姿势，而不是让平均值吃掉一次可见错位。除源采样点，还应在接触窗口内检查运行时可能求值的中间时刻；解码取样和参考插值需确定可比。

如果第一次比较发现原点接近、杆端明显偏，先确认挂接变换和取样时间，然后查看朝向差及相关父骨。保留基线的压缩字节数，在同一数据和条件下只调整相关骨或类别的探针距离，或用能代表该接触的优化目标重新压缩。工具若只能调整整类骨，结果就按类别报告。记录修改后的压缩字节与道具点偏差，判断是否值得为这个接触窗口保留更多精度；若差异不在编解码对照中出现，不要先调压缩参数。

**第二遍放回运行时。** 用目标动画实例和道具验证相同的接触，按实际流程打开重定向、混合、IK（逆向运动学）和 LOD。若离线的解码比较已对得上，最终输出却偏了，逐层比较姿态或保存关键阶段的点位；例如检查 LOD 切换是否还求值相关骨骼、IK 是否改变了挂点的父链姿势。反过来，运行时 IK 修正了杆端，也不表示压缩误差已经不存在。这里验收的是几何对齐；画面能不能察觉、玩法取的碰撞或交互点是否跟这个视觉点一致，要另行判断。
