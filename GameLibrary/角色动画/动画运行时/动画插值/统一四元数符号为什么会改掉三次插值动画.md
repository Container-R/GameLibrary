# 统一四元数符号为什么会改掉三次插值动画

一个导出工具想把旋转数据整理得更一致：遇到某些关键帧，就把记录旋转的四个数一起取负。逐个比较关键姿势，整理前后的朝向完全一样，于是工具把这一步当成“不改变动画”的清理。

但关键姿势相同，不代表它们之间的转动也相同。下面用一个明确虚构的工具改写例子说明原因：不改关键时间，不改起止朝向，只改变一个旋转关键值的符号，三次插值的中间朝向就能不同。这是理想实数下的手算，不是实际导出器或播放器的故障记录。

本文面向动画工具与动画程序开发者，限定三维资产交换格式 glTF 2.0 的旋转 `CUBICSPLINE`。这里的“统一符号”指**逐个关键值选择符号代表**，不是把整条曲线的所有数据同时取负。

## 四个数可以不同，朝向却相同

四元数用四个分量表示旋转。glTF 按 `(x,y,z,w)` 存储，其中 `w` 是标量分量；表示旋转的四元数必须是单位长度，也就是四个分量的平方和为1。[1] 它不是三个欧拉角再加一个额外角度，不能把四个数分别当作四次旋转。

对于单位四元数 `q`，把四个分量全部取负得到 `−q`，表示的仍是同一旋转。这种“一种旋转对应两个相反的单位四元数”的关系，常称为双重覆盖。可以从旋转矩阵理解它：矩阵中的相关项是分量的平方或两两乘积，全部取负不会改变这些项。

例如，绕 Z 轴旋转角度 θ，可以用下面的四元数表示：

```text
q = (0, 0, sin(θ/2), cos(θ/2))
```

绕 Z 轴转120°，可写成 `(0,0,√3/2,1/2)`，也可写成 `(0,0,−√3/2,−1/2)`。只看这个时刻的朝向，两者没有区别。

问题在于，动画不仅保存“到了这里朝向是什么”，还要决定“怎样从前一个朝向走到这里”。插值会使用那些具体数值；终点旋转等价，不等于参与插值的四个坐标可以随意替换。

## 先分清使用的是哪种插值

glTF 对旋转的 `LINEAR` 模式规定的是球面线性插值，而不是直接对四个分量作普通线性混合。规范给出的符号处理让这类插值沿两四元数定义的大圆短路径进行。[2]

旋转 `CUBICSPLINE` 则不同。每个关键时间对应入切线、关键值、出切线；段内使用逐分量的 Hermite 三次插值，随后必须将结果归一化，再用于节点旋转。[2] 切线描述值随时间的变化，公式会乘以这一段的时长。因而，关键时间、关键值与切线共同定义了曲线。

不能看到 `LINEAR` 有短路径处理，就把相同的逐键符号调整直接用来重写三次样条。下面故意把所有切线设为零，让差异只来自关键值的符号；这样也不需要先掌握完整切线编辑方法。

## 两个端点不变，中点却转向另一边

设关键时间为0和1，采用以下两个单位四元数，顺序均为 XYZW：

```text
q₀ = (0, 0, 0, 1)          起点不旋转
q₁ = (0, 0, √3/2, 1/2)     终点绕 Z 旋转120°
```

所有入、出切线都为零。整理后的数据保留 `q₀`，只把终点改成 `−q₁`。两份数据在起点、终点表示的旋转相同。即便工具还把终点切线一起取负，本例也不会改变，因为零向量取负仍是零。

用 `u` 表示这一段已经经过的比例，范围为0到1。零切线情况下，三次插值只剩两个关键值的权重：

```text
a = (1−u)²(1+2u)
b = u²(3−2u)
```

原曲线归一化前是 `a q₀ + b q₁`，整理后则是 `a q₀ − b q₁`。注意，这不是把整个结果取负：起点那一项没有改。

在中点 `u=1/2`，两个权重都是 `1/2`。代入并归一化，得到：

| 数据 | 归一化前的中点 | 单位长度的中点 |
|---|---|---|
| 原始关键值 | `(0,0,√3/4,3/4)` | `(0,0,1/2,√3/2)` |
| 终点取负后 | `(0,0,−√3/4,1/4)` | `(0,0,−√3/2,1/2)` |

第一行的原始长度为 `√3/2`，第二行为 `1/2`；分别除以自己的长度，便得到右列。由前面的绕 Z 表达式，右列分别表示 **+60°** 与 **−120°**，不是同一旋转的两个符号代表。

也可以不只看角度：假设节点没有额外的缩放、平移或父级变换，让它旋转指向 X 正方向的单位箭头。两种中点会分别把箭头转到：

```text
原曲线：      ( 1/2,  √3/2, 0)
终点取负后：  (−1/2, −√3/2, 0)
```

两支箭头在此时朝向相反。这个方向比较来自规范旋转矩阵的代入，不是渲染截图。它已经足以否定“起止姿势相同，所以整理没有改变动作”的判断；却没有告诉我们哪条转动更符合动画师的意图。

## 这不是归一化零向量造成的假问题

有人可能怀疑：是不是某条曲线中途变成了全零四元数，才导致这个反例？可以直接检查整个区间，而不只检查中点。

在 `0≤u≤1` 内，`a`、`b` 都非负，且 `a+b=1`，所以 `ab≤1/4`。两个端点单位四元数的点积为 `1/2`。据此，两条未归一化曲线的长度平方分别是：

```text
原曲线：      a²+b²+ab = 1−ab  ≥ 3/4
终点取负后：  a²+b²−ab = 1−3ab ≥ 1/4
```

它们在整个闭区间内都不为零，因此都能归一化。差异确实来自曲线改变，而不是拿一个无效中间值充当旋转。

规范要求旋转三次插值后归一化，并提醒导出时避免插值产生全零四元数。[2] 上述下界只证明这个例子满足非零条件，不是任意切线或任意浮点资产的完整检查算法；也不能据此给出统一的数值误差容限。

## 整条曲线一起取负，为什么又可以

如果把整条曲线的所有关键值及相关入、出切线同时取负，Hermite 公式的每一项都会取负，结果便整体变成原来的负数。

在原曲线非零的地方，归一化后仍是 `q` 与 `−q` 的关系，所以表示同一旋转。这给出了一个充分的保持条件，但不是所有安全变换的完整分类。

区别正在这里：**全局取负改变的是整条曲线的符号代表；逐键取负可能改变曲线本身。** 即使局部修改同时处理了那个关键值的切线，也不能把它自动当成全局变换。本例的零切线已经说明这种推论不成立。

## 工具接收时，应保住什么

回到开篇的导出工具，首先要确认整理目标。如果只是要求关键时刻的朝向一致，端点比较回答了这个较窄的问题；如果要求保持原动作，就必须把段内旋转也纳入判断。不能用较窄的检查替较宽的承诺签字。

接着核对实际修改范围：插值模式有没有改变，关键时间是否相同，哪些关键值及切线被改写。只有知道变换做了什么，才能讨论它为何保持曲线，或需要怎样的误差验收。这个反例没有提供“采几个点就足够”的通用数量，也不是自动修复方案。

若发现段内差异，应让动画侧确认原本希望保留的转动，再由工具侧判断是否撤回改写、调整变换或明确接受动作变化。不要因为端点看起来正确就忽略差异，也不要反过来认定所有符号调整都有问题。

这里讨论的是资产中一段旋转曲线的表示，不是动作之间的混合、骨骼约束或脚部接触。若问题发生在被打断的过渡中，可另读[《用惯性化平滑被中断的动画过渡》](../动作过渡/用惯性化平滑被中断的动画过渡.md)；那里的标量残差计算不能直接充当本题的四元数算法或验证结果。
