# 两骨IK的位置构造与弯曲方向控制

让手够到握点、让脚接近地面目标时，常会遇到三种看似相同的失败：末端始终差一点，膝肘突然转到另一侧，或者求解器报告成功，动画图末尾的位置却仍然偏离。它们分别可能来自骨长限制、弯曲方向缺失，以及姿态读取和写回顺序。只调高 IK 权重，无法区分这些原因。

本文面向会用三维向量、点积和基本父子变换的动画程序与技术动画人员。先给出一个可实现的两骨位置方法，再用 ozz-animation 的固定版本说明怎样接入真实骨架接口。位置方法采用**无状态、固定骨长、缺少方向便明确返回**的契约；调用者可以选择拒绝不可达目标，或者改用最近可达目标。它不保存上一帧，不承诺任意输入连续，也不求末端朝向、碰撞、关节限位或全身平衡。

## 先确定求的是哪三个位置

记根关节位置为 `O`，中间关节为 `K`，末端为 `E`。两段长度分别是 `a=|K−O|>0`、`b=|E−K|>0`，要求的末端目标是 `T`。求解过程中根位置和两段长度不变。手臂可把它们理解为肩、肘、腕；腿可理解为髋、膝、踝。

所有点必须位于同一个欧氏坐标空间，长度使用同一单位。实际接入时，可以从同一阶段的三关节位置计算骨长，或使用已经核对过的绑定长度。不能把世界空间目标与骨骼局部位置直接相减，也不能把厘米的骨长与米的目标混用。

三点位置只确定两段指向，不能唯一确定骨骼绕自身轴的扭转，更不会自动给出脚掌或手掌朝向。位置与朝向是不同的 IK 任务；关节限位和碰撞也属于额外约束。[1] 本文的位置几何允许自由选择弯曲平面，实际骨架是否能通过规定的关节轴实现它，要在接入时另查。

弯曲控制有两种常见输入，必须先统一含义：

- **提示点 `H`**：先计算方向 `p=H−O`。
- **提示方向 `p`**：已经是向量，直接使用，不再减去 `O`。

下文算法只接收方向 `p`。提示点并不是中间关节必须到达的位置；它只是告诉我们，中间关节应该朝根到目标轴的哪一侧弯。

## 骨长先决定可达距离，再留下一个圆上的选择

令 `d=|T−O|`。由三角形不等式，存在位置解的必要条件是：

```text
|a−b| ≤ d ≤ a+b
```

完全伸直给出外边界 `a+b`；两段反向折回给出内边界 `|a−b|`。所以不等长骨链的根附近也有不可达区域。平面两转动关节模型的推导同样得到这两个边界。[1] 对本文允许自由转动的三维位置问题，它们也是充分条件；下面直接构造解。

先考虑 `d>0` 且目标可达。定义单位轴 `u=(T−O)/d`。把中间位置分成沿轴和侧向两部分：

```text
K = O + x u + h v
|v|=1，v·u=0，h≥0
```

`x` 是沿目标轴的**有符号**距离，`h` 是离轴距离，`v` 是尚待选择的弯曲方向。两段长度约束给出：

```text
x² + h²       = a²
(x−d)² + h²   = b²
```

相减消去 `h²`，得到：

```text
x = (a²−b²+d²)/(2d)
h² = a²−x²
K = O + x u + h v，E=T
```

再代回第二式，可以核对 `|E−K|=b`，而不必只相信公式的形式。当 `h>0` 时，中间关节的全部位置解组成一个圆：圆心为 `O+xu`，半径为 `h`，圆面垂直于 `u`。它在三维中并非天然只有“肘上、肘下”两个解；只有先固定一个平面，才会缩成两个方向。

这个分解也解释了为什么“膝盖总在根与目标之间”是错误假设。取精确数学数值 `a=0.4 m`、`b=0.6 m`、`d=0.2 m`，则 `x=−0.4 m`、`h=0`：第一段朝目标的反方向伸出，第二段再折回来。交换两段长度，`x` 则为 `+0.6 m`。这里必须保留符号，不能对 `x` 取绝对值。

### 用提示方向选出圆上的一点

把 `p` 沿 `u` 的分量减掉：

```text
q = p − (p·u)u
v = q/|q|                 仅在 q≠0 时定义
```

`q` 位于垂直于 `u` 的平面内，恰好提供圆上的方向。把提示点沿目标轴移动，不会改变这个侧向投影；提示点离根更远，也不一定使膝盖更弯。弯曲幅度 `h` 已经由骨长和目标距离确定。

例如 `O=(0,0,0)`、`T=(0.5,0,0) m`，骨长 `a=0.6 m`、`b=0.4 m`，提示点 `H=(0,1,0) m`。此时 `u=(1,0,0)`、`v=(0,1,0)`，算得：

```text
x = 0.45 m
h = sqrt(0.6²−0.45²) ≈ 0.396863 m
K ≈ (0.45, 0.396863, 0) m
E = (0.5, 0, 0) m
```

检查 `sqrt(0.45²+0.396863²)≈0.6`，第二段则为 `sqrt(0.05²+0.396863²)≈0.4`。交换骨长后，`x` 变为 `0.05 m`，`h` 不变。这是方法的手算例，不是角色观感或引擎运行结果。

若 `p=0` 或与 `u` 共线，`q` 就没有方向。此时圆上仍有很多满足骨长的位置，只是提示没有告诉我们选哪一个。本文返回 `NEED_BEND_DIRECTION`，不偷偷选择世界 X 轴，也不沿用某个未声明的上一帧值。

## 不可达目标与零距离必须走不同分支

### 拒绝原目标，或明确生成有效目标

默认的 `reject` 模式在距离越界时返回 `UNREACHABLE`，不输出位置。另一模式 `nearest` 允许改变末端目标。对 `d>0`，令：

```text
d_eff = clamp(d, |a−b|, a+b)
T_eff = O + d_eff u
```

随后用 `d_eff` 代替 `d` 构造中间位置，令 `E=T_eff`。这确实是在本文几何条件下离原目标最近的末端位置：任一可达点 `X` 都有 `|X−T|≥||X−O|−d|`；沿 `u` 选最近的可达半径，便达到这个下界。

代价必须保留在输出中：原目标误差为 `|d_eff−d|`。例如 `a=0.6 m`、`b=0.4 m`、`d=0.1 m`，最近距离仍为 `0.2 m`，末端差 `0.1 m`。把有效目标求准，不等于把原目标求准；对反三角函数输入做 clamp 也不能取消这项差距。

非零距离的两个精确边界可直接求位置，不需要提示：

| 条件 | 中间位置 | 形状 |
|---|---|---|
| `d_eff=a+b` | `K=O+a u` | 完全伸直 |
| `d_eff=abs(a−b)>0` 且 `a>b` | `K=O+a u` | 折回，末端在第一段上 |
| `d_eff=abs(a−b)>0` 且 `a<b` | `K=O−a u` | 第一段背向目标 |

这里 `h=0`，所以位置不依赖 `v`。不过，骨骼扭转仍未确定；下一帧重新弯曲时也仍然需要方向。

### 目标恰好等于根位置

`d=0` 时没有目标轴 `u`，不能在通式里除以 `d`。本文为这个分支单独接收可选方向 `w`，称为“零距离方向”，与正常分支的提示 `p` 分开提供：

| 骨长与模式 | 返回或构造 |
|---|---|
| `a=b`，未给非零 `w` | `NEED_FOLD_DIRECTION`：目标可达，但无法选择中间位置 |
| `a=b`，有 `w` | 归一化 `w`，令 `K=O+a w`、`E=O` |
| `a≠b`，`reject` | `UNREACHABLE`，即使给了方向也不能命中原目标 |
| `a≠b`，`nearest`，未给非零 `w` | `NEED_TARGET_DIRECTION`：最近可达末端在一整个球面上，需要先选方向 |
| `a≠b`，`nearest`，有 `w` | 令 `E=O+abs(a−b)w`；`a>b` 时 `K=O+a w`，否则 `K=O−a w` |

等长时 `w` 指中间关节方向；不等长的最近目标分支中，`w` 指有效末端方向。这两种用法不能混为 pole 投影。比如 `a=0.4 m`、`b=0.6 m`，选择有效末端朝 `+X`，中间关节必须在 `−X` 的 `0.4 m` 处。

这些返回值并不是“求解器迭代不够”。它们区分了无解与有解但缺少选解信息。调用者收到没有位置的状态后，可以保留基础动画、要求上游提供方向或改变目标；不能把旧输出误认为这次已经求出的结果。

## 一条可执行的无状态流程

下面给出完整位置流程。正常提示为 `p`，零距离方向为 `w`，两者可以缺省。`unit(v)` 对非零向量先除以其最大绝对分量，再除以缩放后的长度，避免直接平方巨大或极小数；零向量或缺省返回“无方向”。所有输入向量都先检查三个分量有限。伪代码中的 `length` 与 `robust_length` 都表示防止中间平方溢出的长度计算，例如 `hypot(x,y,z)`；也可先取 `m=max(|x|,|y|,|z|)`，`m=0` 时返回 0，否则返回 `m*sqrt((x/m)²+(y/m)²+(z/m)²)`，并在调用处检查最终结果是否有限。

计算先平移到根，再以 `S=max(a,b)` 归一化。记 `A=a/S`、`B=b/S`、`t=(T−O)/S`、`D=|t|`。这能避免直接计算大骨长的平方，但无法恢复输入在相减之前已经丢失的精度。为了让数值约定可检查，本文参考实现选用 64 位浮点数 binary64，并采用以下**实现政策**，它们不是几何定理，也不是 ozz 的参数：

- 归一化较短骨长低于 `10⁻⁸` 时返回 `NUMERIC_RANGE`，不尝试支持任意悬殊的骨长比例。
- 对单位化后的提示，侧向投影长度须大于 `10⁻⁶`，即提示与轴夹角的正弦须超过这个阈值。阈值内返回缺少可靠弯曲方向。
- 每段长度的相对残差，以及有效目标的尺度化残差，须分别不超过 `10⁻⁹`。这是本参考实现的验收门槛，不是对所有 binary64 输入的误差上界。

实际项目应按输入噪声、角色尺度和最终精度重新选择这些政策。若换用 binary32，不能只原样复制阈值。

```text
solve(O, T, a, b, p=缺省, w=缺省, mode=reject):
    本次结果.positions = 无
    若任一已提供输入非有限、向量维数错误、a≤0、b≤0、mode未知:
        返回 INVALID_INPUT

    S = max(a,b); A=a/S; B=b/S
    若 min(A,B)<1e-8: 返回 NUMERIC_RANGE
    delta = T-O; t=delta/S
    若相减/缩放非有限，或非零 delta 分量缩放成零:
        返回 NUMERIC_RANGE
    D = robust_length(t)
    若 D 非有限: 返回 NUMERIC_RANGE
    lo=abs(A-B); hi=A+B
    relation = D<lo ? too_close : (D>hi ? too_far : inside)
    near_boundary = min(abs(D-lo), abs(D-hi))≤1e-9
    若 relation≠inside 且 mode=reject: 返回 UNREACHABLE
    De = (mode=nearest) ? clamp(D,lo,hi) : D
    target_changed = (De≠D)
    direction_used = 无

    若 D=0:
        z = unit(w)
        若 z 无方向:
            返回 (A=B ? NEED_FOLD_DIRECTION : NEED_TARGET_DIRECTION)
        direction_used=z
        若 A=B:
            k=A*z; e=(0,0,0); shape=folded_at_root
        否则:
            e=lo*z; k=(A>B ? A : -A)*z; shape=inner_boundary
    否则:
        u=t/D
        e = target_changed ? De*u : t
        若 De=hi:
            k=A*u; shape=outer_boundary
        否则若 De=lo:
            k=(A>B ? A : -A)*u; shape=inner_boundary
        否则:
            x=0.5*(De + ((A-B)/De)*(A+B))
            h=0.5*sqrt(hi-De)*sqrt(hi+De)
                  *sqrt((De-lo)/De)*sqrt((De+lo)/De)
            若 x 或 h 非有限，或 h≤0: 返回 NUMERIC_FAILURE
            ph=unit(p)
            若 ph 无方向: 返回 NEED_BEND_DIRECTION
            q=ph-dot(ph,u)*u; s=robust_length(q)
            若 s≤1e-6: 返回 NEED_BEND_DIRECTION
            v=q/s; direction_used=v
            k=x*u+h*v; shape=bent

    K=O+S*k
    E = target_changed ? O+S*e : T
    若 K 或 E 非有限: 返回 NUMERIC_RANGE
    kr=(K-O)/S; er=(E-O)/S
    ra=abs(length(kr)-A)/A
    rb=abs(length(er-kr)-B)/B
    rt=length(er-e)
    若任一残差非有限或大于1e-9: 返回 NUMERIC_FAILURE
    返回 SOLVED，以及:
        O,K,E, relation, near_boundary, target_changed, shape,
        direction_used, ra,rb,rt,
        original_error_scaled=length(er-t),
        policy_error_scaled=abs(De-D)
```

在代码中，每个失败分支都返回同一个结构中的状态和已有诊断值，`positions` 始终为空；只有 `SOLVED` 才携带三点。因而 `SOLVED + target_changed=true` 是“有效目标已构造”，不是“原目标已到达”。无效输入或数值范围失败发生在距离判断之前时，`relation` 也应保持未知。

### 为什么这样计算半径和残差

伪代码中的 `x` 与前面的式子相同，但用 `(A−B)(A+B)` 代替两个平方相减。半径使用下面的等价关系：

```text
h² = ((A+B)²−De²)(De²−(A−B)²)/(4De²)
```

把它分成四个非负因子再开方，避免先求 `A²−x²` 时丢掉很小的半径。进入该分支前已检查 `lo<De<hi`，各分母也非零；等长且目标极近时，`lo=0`，后两个比值为 1，不需要先算一个可能下溢的 `De²`。这是减少特定数值损失的重写，不是浮点全域稳定性证明。出现非法中间值时返回失败，而不是无条件用 `max(0,h²)` 抹掉原因。

残差在**组装最终坐标之后**重新计算。`ra`、`rb` 分别相对于各自骨长；`rt` 相对于尺度 `S`。只在归一化临时变量里验证，会漏掉把 `K` 加回巨大根坐标时的舍入。例如长度 `0.5` 的骨链放在 `10¹⁶` 附近，某些小位移已无法由 binary64 坐标表示，最终长度检查就应失败。使用角色附近的求解原点或更合适的数据表示，比扩大容差更有意义。

这个实现不把“足够接近边界”偷偷改成边界。`near_boundary` 只供诊断，距离比较依当前浮点数进行；只有显式的 `nearest` 模式才能夹取距离。数学中 `0.6−0.4=0.2`，binary64 的这些十进制输入却未必恰好满足同一等式。参考计算中，`a=.4,b=.6,d=.2` 得到约 `1.26×10⁻⁸` 的侧向高度，两段相对长度残差仍约为 `10⁻¹⁶`。精确边界的规则没有改变，变的是输入和运算的有限表示。

因此，项目若要求“距离边界一定范围内一律伸直或折回”，应把它定义为另一项有效目标政策，记录修改量，并检查原目标误差。不要一边改变目标，一边继续声称严格求解了原输入。这里没有实现这种吸附政策。

## 提示跨轴和接近伸直，是两种不同的敏感性

### 精确服从提示，不能保证任意跨轴运动连续

固定 `u=(1,0,0)`、固定 `h>0`，让提示方向从 `(1,+ε,0)` 经过 `(1,0,0)` 到 `(1,−ε,0)`。投影归一化后，前后分别是 `+Y` 与 `−Y`；两个中间位置相距 `2h`。即使 `ε` 很小，位置差也不会随它一起趋于零。

前面的 `0.6/0.4/0.5 m` 例子中，提示从 `(1,0.01,0)` 换到 `(1,−0.01,0)`，中间关节从 `y≈+0.396863 m` 变为 `y≈−0.396863 m`。轴上的那一帧缺少方向；本文会返回状态。设置角度阈值可以更早拒绝不可靠提示，却不会把拒绝区两边的解自动连接起来。ozz 的接口也明确把 target 方向与 pole 对齐或穿越导致的朝向翻转交由调用者避免。[2]

有状态控制器可以在提示退化时暂用上一有效方向，但这意味着暂时不精确服从当前提示。保存的方向还要投影到新的目标轴垂面，这个投影也可能退化。历史究竟保存在世界空间还是角色空间、首次启用和瞬移时怎样初始化，都需要设计。

从历史方向恢复到新提示时，滞回能减少阈值附近反复切换，却不能保证切回瞬间连续。若要保持两段长度，可以绕目标轴在解圆上逐渐改变方向；直接线性混合两个 `K` 通常会离开圆，改变骨长。相反方向之间往哪边转也需要约定。这些是额外控制器的取舍，不是上面的无状态函数暗中具备的能力。

### 同一侧弯曲，也会在近伸直处变化很快

即使提示方向始终稳定，固定骨长仍会带来距离敏感性。令两段都长 `L`，`θ` 为中间关节的内角，完全伸直是 `θ=π`。余弦定理给出：

```text
d = 2L sin(θ/2)
θ = 2 asin(d/(2L))
d′(θ) = L cos(θ/2)       θ以弧度计
```

当 `θ` 接近 `π`，距离对角度的变化率趋近零；反过来，为增加同样的距离，就需要更大的角度变化。取 `L=0.5 m`：

| 目标距离变化 | 内角变化 | 增量 |
|---|---|---|
| `0.70→0.71 m` | `88.854°→90.470°` | 约 `1.616°` |
| `0.98→0.99 m` | `157.043°→163.781°` | 约 `6.737°` |

这是固定弯曲平面的原创几何算例，不是提示翻侧，也不是某个 API 的局部旋转角。目标连续，不代表关节每帧变化都小。

处理时必须决定允许放弃什么。限制有效目标的伸展距离，可以保持骨长，但末端会落后；改变根位置或动作，会影响身体与接触；允许骨长变化，则需要检查蒙皮、碰撞与资产约定。Kovar 等人在 2002 年的足滑清理方法中，选择近伸直时限制膝角修正，再调整腿长来满足踝目标；该工作使用接触标记与邻近帧，在线使用须接受相应延迟。[5] 这是另一套约束取舍，不是本文固定长方法的一部分，也不能仅凭“soften”这个名字与某个引擎参数等同。

## 从位置方法接到 ozz 的局部旋转修正

上面的 `K、E` 可用于生成位置、调试目标和检查几何条件。实际骨架通常存储的是相对父骨的局部旋转和位移，不能把 `K` 直接写进某个关节的局部平移。下面以 ozz-animation 提交 `744eb9d99f606eda849acb0b1204f7a3dc20bca1` 为具体接入例：它自己计算旋转修正，不调用本文的位置函数，也不承诺与本文的浮点分支相同。[2][3]

### 1. 在同一姿态阶段准备所有输入

先求基础动画或当前输入姿态，再由这些局部变换做正向运动学（FK），得到 model-space 的三关节矩阵。这里 model space 是角色模型坐标系，不是每根骨骼自己的 local space。`start_joint`、`mid_joint`、`end_joint` 必须来自同一轮姿态，不能把上帧的髋、IK 前的膝和 IK 后的踝拼在一起。

ozz 要求三个关节位于同一祖先链，允许中间夹有其他关节；夹在其中的关节不直接获得这两个修正。[2] 初次集成宜先用直接相连的两段验证，之后再检查实际辅助骨链和关节轴。样例中从 rest pose 重置局部变换只是一个测试开关，不代表运行时应在每帧丢弃基础动画。[3]

### 2. 目标按点变换，pole 按方向变换

若角色模型到世界的变换为 `M`，且输入是世界目标点 `T_world` 与世界提示方向 `p_world`：

```text
T_model = TransformPoint(inverse(M), T_world)
p_model = TransformVector(inverse(M), p_world)
```

点的变换包含平移，方向不包含平移。ozz 样例正是分别使用这两个操作。[3] 若工具保存的是世界提示点 `H_world`，应先取 `p_world=H_world−O_world` 再变换方向；等价地，分别把 `H_world` 与 `O_world` 转成模型点后相减。直接把 `H_world` 当方向传给 `TransformVector`，会漏掉“从哪里指向哪里”。

对刚体变换，长度与角度保持不变；一致的正均匀缩放还要求同步换算长度。非均匀缩放则会改变方向之间的角度与欧氏距离，不能把变换后的模型当作同一个固定长度三角形。本文参考位置法应在度量明确的空间中使用；有非均匀父缩放、剪切或奇异矩阵时，应先修正数据表示或使用经过专门核验的尺度处理方案。下面的转轴检查还要求 mid local 到 start/model space 的相关变换路径保持角度，即由旋转、平移和正均匀缩放组成；只检查角色根 `M` 没有非均匀缩放，还不足以确认骨链内部符合条件。

### 3. 检查当前骨链的 mid 局部轴，而不只检查归一化

头文件规定，`mid_axis` 是**中间关节局部空间**中的归一化转轴，正向绕它旋转应打开两骨夹角。它与 model-space 的 `pole_vector` 不是同一个量。[2] 样例设为局部 Z，是针对样例骨架的选择，不应照抄到所有角色。

仅检查轴长和“小幅正转是否打开角度”，还不够。`ComputeMidJoint` 把余弦关系求出的内角差直接用作绕 `mid_axis` 的旋转量；`ComputeStartJoint` 又把变换后的 `mid_axis` 当作骨链平面的法向。[2] 在前述保持角度的变换路径下，要使这种平面三角形解释成立，一个充分的轴条件是：**当前两段有效骨向量都垂直于该轴，且轴的正方向符合绑定指定的弯曲侧。** 这是由实现和几何推得的接入条件，不是头文件额外列出、或 `Validate()` 已经执行的检查。

令 `M_mid` 为本次输入的中间关节 model-space 矩阵。把同一阶段的根、末端位置都转到这个 mid local space。中间关节在自己的空间中位于零点，因此可像实现一样取得两段向量：

```text
O_mid = TransformPoint(inverse(M_mid), O)
E_mid = TransformPoint(inverse(M_mid), E)
r = -O_mid               // 根到中间关节
s =  E_mid               // 中间到末端关节
n = mid_axis
```

`r、s` 都必须非零。除 `|n|=1` 外，还要检查 `n·normalize(r)=0` 与 `n·normalize(s)=0`。工程实现可要求这两个点积的绝对值不超过选定的无量纲容差，再用 FK 误差验收；容差不是数学上的完全正交。检查对象是**当前有效姿态**，不能只证明绑定姿态垂直，就假定动画叠加、辅助骨或中间骨变化后仍然成立。

两段不共线且轴垂直时，绕 `n` 转动第二段，才会在同一个平面内按相同角度改变有符号内角。绑定交付仍需指定轴的正负；可在已知正常弯曲侧施加一个很小的正向局部旋转，再由 FK 检查内角增大。该侧也应满足 `(r×n)·s>0`，实现用这个量的符号判断初始弯曲侧。[2] 若它为负，应区分轴反号与当前姿态确实反弯，而不是每帧按叉积自动翻转绑定轴。

两段共线时，`r×s=0`，当前位置无法给出唯一平面法向或判定预期弯曲侧。此时仍应使用绑定时依据已知弯曲平面给出的 mid 局部轴，检查它垂直于当前共同骨方向；不要把零叉积归一化，也不要临时挑任意世界轴。若绑定轴在当前姿态中不再符合这项条件，应修正轴、输入姿态或选择适合实际关节模型的求解器。

一个反例说明为何“小幅正转会打开”不足以保证命中。设关节旋转均为单位旋转，`O=(0,0,0)`、`K=(1,0,0)`、`E=(1,1,0)`，令 `n=(0,1,−1)/sqrt(2)`，目标为 `(2,0,0)`，`weight=soften=1`。这个轴已归一化，正转 `0.01 rad` 也确实增大内角，但它不垂直于第二段。将源码角度关系给出的 `+π/2` 修正代入旋转公式，第二段变为 `(1/sqrt(2),1/2,−1/2)`，根到末端距离只有 `sqrt(2+sqrt(2))≈1.847759`。后续根关节的刚体旋转只能改变朝向，无法消除至少约 `0.152241` 的目标误差。改用垂直两段且同样正向打开的 `n=(0,0,−1)`，同一修正才把第二段转到 `+X`，得到距离 2。这里是根据源码关系作出的几何反例与原创数值核对，不是原生 ozz 执行结果。

轴检查通过后，仍需按下一步实际组合旋转并做 FK。它补齐的是求解器使用平面角度关系的条件，不替代浮点误差、权重、pole 和后续姿态修改的验收。

### 4. 把修正组合回原局部旋转，再更新 FK

`IKTwoBoneJob::Run()` 输出 `start_joint_correction` 与 `mid_joint_correction`。样例调用 `MultiplySoATransformQuaternion`，而该函数的实际乘法是原局部四元数在左、修正在右：[3][4]

```text
q_start_new = q_start_old * correction_start
q_mid_new   = q_mid_old   * correction_mid
```

不能把 correction 当作绝对局部旋转覆盖基础动画。使用其他数学库时，还需确认主动/被动旋转、乘法作用顺序和坐标约定，而非只保留这行代码的字符顺序。

写回两处局部旋转后，从受影响的 start 关节开始重算模型矩阵；start 以前的祖先矩阵必须已经有效。样例正是再运行 `LocalToModelJob`。[3] 读取旧模型矩阵检查末端，会误以为旋转修正没有生效。末端朝向若还要约束，应由明确的后续步骤负责，并重新检查它及其他后续操作是否改变了位置。

### 5. 把接口执行、reported reached 和最终误差分开

该版本 `Validate()` 检查必要指针及 `mid_axis` 是否归一化，不检查上述轴与当前两段向量的正交关系；`Run()` 返回 true 不是骨架内容、尺度或最终姿态已经全部验收的证明。[2]

`weight` 作用在旋转修正上：实现对单位四元数与修正做归一化线性插值。权重一半不意味着末端正好走过到目标直线的一半。`soften` 允许末端在接近伸展时落后于目标；它不是保存历史的时间滤波器。[2]

实现中的 `reached` 在写回旋转和重新 FK **之前**设置。由该版本源码可读出，它依据 start-space 中的原目标距离、骨长差、soften 阈值和 `weight≥1` 判断；内侧边界采用严格大于，因而纯几何可达的内边界或等长零距离也不等于这个标志为 true。[2] 用它作诊断可以，用它替代最后的空间误差则不行。上游测试另有重新组合修正后模型矩阵、比较末端距离的检查；其测试容差属于那组用例，不能照搬成所有角色的标准。[6]

本文依据固定源码解释接入，没有运行 ozz 或真实角色。另须注意，上游对 pole 恰共线的测试没有规定具体的 start 修正四元数。[6] “存在这一测试”不能推出共线两侧连续，也不能当作本文 `NEED_BEND_DIRECTION` 分支的实现证据。

## 用哪些量判断问题已经解决

先在没有权重混合、softening 和后续约束的最小骨链中核对位置，再逐项恢复实际流程。建议把以下量放在同一帧、同一空间中观察：

1. `a、b、d` 与可达区间，是否改过有效目标，是否接近边界。接入旋转求解器时，另查当前两段向量与 mid 局部轴的点积及其正方向。
2. 方向输入、侧向投影大小、实际采用的方向与返回状态。对边界形状，不要伪造一个未用到的弯曲方向。
3. 两段最终长度残差、`|E−T_eff|` 与 `|E−T|`。前者诊断求解与写回，后者还包括主动让步的目标偏差。
4. IK 刚写回并完成 FK 时的末端误差，以及整条动画图结束后的误差。前者正常、后者异常时，沿后续父骨修正或约束继续查；两者都异常时，先查空间、轴、输入姿态和写回方式。

本文原创参考实现对正常构造、两种不等长次序、内外边界、零距离、提示共线两侧、尺度变化及共同刚体变换进行了有限数值检查。前述正常算例输出与手算一致；零距离缺方向返回明确状态；位于巨大原点而无法保留骨长的结果被残差检查拒绝。这些检查支持所写位置流程，不代替骨骼转轴、蒙皮、动作切换和观感验收。 完整伪代码已在正文，另附可选的[参考实现与复现材料](../../../../管理档案/研究/TASK-2026-0291/复现/README.md)，用于检查这些有限输入，不扩展方法的保证范围。

真正接入后还应比较提示跨轴、接近伸直、启停 IK、角色旋转与瞬移等轨迹。若项目要求连续运动，就必须在固定骨长、严格目标、提示服从和时间变化之间作出额外选择。位置构造的价值，是先把可以满足的约束、缺少的信息和主动放弃的条件分开，让这项选择有明确依据。
