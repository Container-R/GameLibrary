# 用惯性化平滑被中断的动画过渡

角色正从跑步过渡到停止，玩家又要求转身。此刻屏幕上的姿态，已经不是原跑步片段单独播放的结果。如果新一轮过渡仍从那个原片段开始计算，上一轮尚未消失的修正就会突然被丢掉，画面可能出现跳变。

惯性化的一种做法，是立即改用新目标，再把切换瞬间的差额加回来，让差额逐渐消失。关键不只是“怎样衰减”，还有“差额到底从哪里取得”。本文面向动画程序和需要理解接续机制的技术动画人员，先把问题缩到一个位置坐标，讲清数值和速度如何连续；它不是完整骨架、旋转或足部接触方案。

## 切换时，保留的是当前输出，而不只是旧片段

假设同一时刻，旧片段的位置为 `2`，上一轮过渡还加着 `1` 的修正，所以实际输出位置是 `3`。旧片段速度为 `1`，修正的变化速度也是 `1`，实际输出速度便是 `2`。

现在改用新目标：位置为 `1`，速度为 `-1`。要让切换瞬间看不出数值跳变，应设置：

```text
位置差额 = 当前输出位置 − 新目标位置 = 3 − 1 = 2
速度差额 = 当前输出速度 − 新目标速度 = 2 − (−1) = 3
```

新侧位置是 `1 + 2 = 3`，速度是 `-1 + 3 = 2`，正好接住原输出。

若误用旧片段的原始位置和速度，算出的差额会是 `1` 和 `2`，新输出便变成位置 `2`、速度 `1`。丢掉的恰好是上一轮修正，而不是新目标有什么问题。这个手算例不涉及真实骨骼或引擎。

Daniel Holden 的惯性化说明也把已有位置、速度偏移带入下一次切换，再用弹簧衰减偏移。他同时区分了这种弹簧形式与原先在指定时间内完成的多项式形式：弹簧不提供固定完成时间，并可能越过目标。[1] 本文只展开这个一维弹簧版本，不把它称为所有惯性化算法的共同实现。

## 把“新目标”和“正在消失的差额”分别表示

下面用几个符号写出同一个过程：

- `t` 是整体时间，切换发生在 `t₀`；`s = t − t₀` 是这轮过渡已经经过的时间。
- `p(t)` 是新目标位置，`p′(t)` 是它随时间变化的速度。
- `r(s)` 是位置差额，`u(s) = r′(s)` 是差额的变化速度。
- 最终输出位置 `z(t) = p(t) + r(s)`，输出速度为 `p′(t) + u(s)`。

所有位置都必须处于同一坐标表示，速度也要采用相同时间单位。若位置单位是米、时间是秒，那么速度单位就是米每秒；不能把每帧位移当成每秒速度填入公式。

记切换前实际输出为 `z⁻`、实际速度为 `w⁻`，初始化就是：

```text
r₀ = z⁻ − p(t₀)
u₀ = w⁻ − p′(t₀)
```

目标与输出应取自同一切换时刻。不能拿上一帧的位置、当前帧的速度和下一帧的新目标混在一起，再期待它们自动接上。

初始化之后，后续计算只需要新目标和两个差额状态，不必为了这次衰减继续播放旧片段。不过，怎样从真实动画数据取得可信速度，是接入时另一个必须处理的问题，本篇假定目标值和导数已经给定。

## 让差额按临界阻尼衰减

选择一个正数 `λ`，在本轮过渡内保持不变，单位是每秒。它控制衰减快慢，但不是“到这个秒数必然结束”的时限。让位置差额满足下面的微分方程：

```text
r″ + 2λr′ + λ²r = 0
```

其中 `r′` 是变化速度，`r″` 是变化速度的变化率。这是一个朝零恢复的临界阻尼形式。给定初值 `r₀`、`u₀`，可直接计算任意非负时间 `s` 的结果：

```text
b = u₀ + λr₀
r(s) = (r₀ + b s) exp(−λs)
u(s) = (u₀ − λb s) exp(−λs)
```

`exp(−λs)` 就是指数衰减因子。检查这个公式不必先相信名称：令 `s=0`，得到 `r₀` 和 `u₀`；对位置式求导，正好得到速度式；再求导代回微分方程，各项可以抵消。因此它连接的是给定的两个初值，而不是猜一个混合权重。

在实数运算中，随着时间趋向无穷，位置与速度差额都趋向零。浮点程序还需要处理范围、非有限值和舍入，不能把代数解直接当成所有输入都稳定的证明。这里用标准指数表达式说明数学关系，不复制来源演示中的快速近似，也不声称性能相同。

## 在一帧中间又切换，先走到那个时刻

设这次更新覆盖 `1.0` 秒到 `1.2` 秒，而新的转场发生在 `1.125` 秒。不要等到 `1.2` 秒才假装切换刚发生，也不要把整个 `0.2` 秒都按新目标推进。

正确的处理顺序是：

1. 沿原来的段推进到 `1.125` 秒，求出当时实际输出位置和速度。
2. 在同一时刻取得新目标及其导数，按前面的两式重新计算差额。
3. 从新侧继续推进剩下的 `0.075` 秒，在区间终点把目标与差额相加。

普通更新也一样：终点差额应与终点目标配对，不能与区间起点目标相加。若要比较不同更新步长，必须使用相同的切换时刻、事件顺序和目标定义；不同输入采样本来就在问不同问题。旧研究中分割更新区间的数值一致性，不是跨机器位级确定性或任意输入下帧率无关的保证。

## 连续，并不等于每种意义上的平滑

这里首先保证的是切换点的**位置连续和速度连续**。如果每段目标自身具有连续的一阶导数，并在切换点有有限的相应单侧值与导数，使用这些对应值初始化，输出可以保持一阶连续，通常记作 **C¹**。

它不自动保证加速度连续，即 **C²**。在新侧，若目标二阶导数存在，加速度为：

```text
新侧加速度 = p″ − 2λu − λ²r
```

它通常不等于旧侧加速度。因此，即使位置和速度都接上，变化仍可能在更高阶上不平滑；还要根据动作目的判断是否可接受。

“临界阻尼”也不代表任意初值都只会单调接近目标。初始速度可能先把差额推大。另一个简单例子是 `r₀=1`、`u₀=-4`、`λ=2`：此时 `r(s)=(1−2s)exp(−2s)`，在半秒时位置差额为零，速度差额却仍为 `−2/e`，约 `−0.736`。它正在经过零点，并没有停止。只看位置第一次归零，就结束整个修正，会丢掉剩下的速度。

所以，“半衰期”“混合时长”和“允许结束的误差”应说清含义。不能把来源里便于调节的半衰期参数，解释成任意初始速度下位置差额都恰好减半；也不能把浮点下溢成零，当成实数解在有限时间内完全收敛。

## 一个生产对照：保留动画，只平滑转头修正

另一类问题发生在动画一直播放、角色还要转头注视目标时。川地克明在 CEDEC 2024 的 FFXVI Look-at IK 讲义中，提醒不要把动画每帧给出的关节角度整个当作 PD 控制的追踪目标：这样连原有动画也会落后。单纯提高追踪速度，又会削弱原本想得到的平滑效果。讲义建议的分法是保留基础动画，追踪 IK 带来的角度偏移，再把结果叠加回去。[3] 这里的 Look-at IK 指依据注视目标调整姿态，PD 控制则依据偏差与速度调整追踪过程。

这和本文都在区分“原本要播放的内容”与“额外修正”，但两者不是同一个算法：本文在切换时初始化差额，再让它朝零衰减；注视修正则可以持续追踪一个变化中的非零目标。不能因为都写成“基础值加修正”，就把惯性化的衰减函数当作完整的注视控制器。

实际接入前，可以先问：希望变慢的是人物原有动作，还是新加的注视变化？若只想平滑后者，应把两份数据分开检查，而不是先给最终姿态加滤波，再用更大的参数补救。这个对照也不提供三维旋转的直接相加规则；骨骼空间、旋转组合顺序和约束仍需另行处理。本文未运行 FFXVI 或这套 IK，没有据讲义的演示判断实际观感。

## 接入 Unreal Engine 时，姿态还在过渡，不代表旧通知仍会到达

前面的差额可以保留旧动作的运动趋势，却没有承诺继续执行旧片段。在 Unreal Engine 5.6 的惯性混合说明中，源姿态在惯性混合开始后停止求值；源动画序列的后续 Animation Notifies 也不再触发。[4] 这里的通知，是放在动画时间轴上、供系统响应的事件。这个接入条件来自引擎文档，不是从本文的弹簧公式推导出来的。

例如，假设一个挥剑片段用前面的通知开启持续特效，原定在后面的通知关闭；如果惯性混合在两者之间开始，就不能仅因画面仍平滑保留挥剑趋势，期待旧片段的关闭通知照常到达。这是一个未运行的接入反例。迁移过渡方式时，应检查持续效果由谁持有、动作被中断时谁负责收尾，而不是把旧片段末尾的通知作为唯一退出路径。另设收尾责任是应用层设计建议，不是该节点自动提供的保证。

这条说明不判定已经触发的通知会被撤销，也没有核验 Notify State 的结束回调、蒙太奇或其它引擎的行为；不要据此把所有“结束事件”都当作同一种机制。本文没有运行 Unreal Engine，旧标量实验也不能验证这些引擎回调。

## UE 5.6：动画曲线要不要跟着平滑，应另作决定

动画通知是事件，动画曲线则是随动画变化的浮点值，可以用来控制 IK 节点的混合权重等属性。[5] 源片段停止发出后续通知，并不表示动画曲线也直接消失。UE 5.6 文档说明，Inertialization 节点会跟踪姿态运动与动画曲线的变化；需要跳过曲线惯性混合时，可以在节点的 **Filtered Curves** 列表中按名称排除。[4]

假设我们的项目有一条 `FootIKWeight` 曲线，旧动作给它 `1`，新动作给它 `0`，用来让一个脚部 IK 修正参与或退出。这是另行构造的接入例子，没有在引擎中运行。若新动作开始时必须立即退出该修正，就不能只看姿态已经切换，便认定读取它的节点必然已经收到 `0`。若设计上希望权重逐渐退出，保留曲线混合又可能正是需要的行为。应先确定这个数值在项目里的意思，再决定是否排除。

对这样一条曲线，可按下面顺序检查：

1. 找到实际读取它的节点，确认要求是权重连续变化，还是随动作切换立即改变。不要因为曲线名字带有 IK，就默认它一定控制整个 IK 系统。
2. 若需要绕过惯性混合，选中 **Inertialization** 节点，在 **Filtered Curves** 用加号添加一项，填入准确曲线名。文档规定被列出的曲线会立即改变，不经过该节点的惯性混合。[4]
3. 在项目中比较排除前后实际使用的曲线值与动作表现，检查立即改变是否引入了本来不希望出现的姿态跳变。这里给的是待执行检查，不是已经观察到的效果；其它混合节点、取值位置和更新顺序仍可能影响最后被使用的值。

这个列表不删除曲线、不恢复源片段，也不补发关闭通知。它与 **Anim Curves** 面板中仅控制列表显示的 **Curve Filtering** 不是一回事。[5] 还要区分表示动画属性的曲线与过渡权重曲线：文档说 Inertialization 忽略 transition blend curves，不能据此理解成它完全不处理 Animation Curves。[4] 本节只讨论 UE 5.6 文档所述配置，不推断精确衰减数值、Notify State 生命周期或其他节点的专属行为。

## 放回角色动画以后，还缺哪些检查

差额为零时，输出直接等于新目标；本方法不是每帧把整个目标再送入一个追踪滤波器。但转场期间仍有差额，反复切换也会不断重新建立差额，不能据此宣传为普遍“零延迟”。

更重要的是，位置连续可以连续地离开地面。它不保证脚贴地、关节可达、身体不穿墙或姿态好看。实际接入还要处理骨骼空间、旋转、速度估计、根运动与控制器职责；四元数尤其不能不加说明就套用一个标量坐标的减法。足部问题可从[《排查原地转身时的脚滑》](../../角色移动/脚部接触/排查原地转身时的脚滑.md)继续。

若正在把这些状态接到旋转接口，还要区分“旋转向量的变化率”和“物体角速度”：两者都有三个分量，却不一定代表同一种速度。[2] 可选读[旋转向量的变化率为什么不等于角速度](../../../../管理档案/支持资料/旋转向量与角速度/README.md)，其中用一个非同轴的纸面例子说明区别，不提供完整旋转惯性化实现。

本库旧标量模型曾用闭式计算、独立编写的数值积分和多次中断反例互相核对。它观察到了忽略速度差额、忽略上一轮残差的跳变，也保留了加速度不连续和经过零点未停止的反例。本次只重新说明代数与已发表范围，没有运行模型或检查动画效果。

需要复查有限实现时，可读旧文的[数值证据状态](https://github.com/Container-R/GameLibrary/blob/1a7bf18b24ba56395892c4c0cdb3b2acecc16985/solutions/animation/scalar-inertialization-continuity.md#数值证据状态)及后续适用限制。那里说明采样、误差尺度、输入范围与拒绝规则；两份积分器同属经典四阶 Runge–Kutta 方法，不是两个独立数值方法家族。历史有限检查不提供所有浮点输入的误差上界，也不能替实际引擎和角色验收。

这套一维推导最值得保留的习惯，是每次中断都先问：**屏幕对应的输出此刻是多少、变化得多快？** 从这两个真实接续状态出发，才不会为了赶上新动作，反而把上一轮仍然存在的修正突然扔掉。
