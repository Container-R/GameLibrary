# 越障动画的根运动扭曲：落点对了，手为什么还没贴住

同一段撑手翻越动画，拿去翻一堵略宽的矮墙。角色最后站到了正确的位置，回放却看见手先撑在空气里，随后在墙沿滑了一截。把落点再调准一点不一定有用：**翻过墙落在哪里，和手在哪一刻、在哪块表面撑住，是不同的约束。**

这里讨论已经选定动作片段之后的接触排查。读者应能读取角色位移、骨骼姿态和碰撞结果。正文给出判别办法，并用 Unreal 的 Motion Warping 说明可配置的边界；两个算例不是 Unreal 插件或角色控制器的复现。

## 先分清是哪个位置对了

动画的**根运动**是从根骨轨迹提取的移动量；项目可以用它驱动角色整体移动。**根运动扭曲**在指定时间段修改这段移动，使动作对齐关卡里的目标。UE 文档中的 Skew Warp 以扭曲窗口末端的目标位置与旋转为对齐目标，是否扭曲平移、Z 方向和旋转可以分别配置。文档的攀越例子也提醒，把窗口放在适合调整的阶段，考虑手搭上障碍的时刻。[1] 这些设置说明它能改什么，不能替项目说明哪一帧是支撑相位，或手要在同一块表面停多久。

排查时至少要看三个不同的结果：

- **动画请求的角色位移。** 根轨迹经过扭曲后希望角色怎么走。
- **角色实际位移。** 关卡碰撞、移动模式等处理后，角色实际移动了多少。UE 的 Root Motion 文档区分了骨骼网格与角色胶囊；移动组件的扫掠碰撞只考虑它实际移动的组件，不等于逐根骨骼检查环境接触。[2][3] 例如，UE 文档里的 Walking 和 Falling 会忽略根运动的 Z 分量；如果只少了竖直位移，先核对当前移动模式与扭曲的 Z 设置，不要直接认定撞了墙。[1][2]
- **最后求值的手的位置。** 混合、姿态修正和逆向运动学（IK）之后，手掌的接触点最终在哪。记录手掌实际贴墙的位置，必要时从手骨加一个局部偏移，不要把手腕原点默认当成掌心。

如果只按动画请求的位置计算手的位置，会把胶囊受阻造成的偏差漏掉。反过来，胶囊正确到达也不能说明手贴住了。正式排查应同时记录这三层，用同一帧、同一坐标系比较。

## 窗口末端命中，并不会替较早的接触帧填上条件

先用一个可复算的一维例子拆开约束。只看角色前进方向，不计旋转、骨骼混合、碰撞或手臂伸缩：

- 在动作中点，原始角色位置为 0.40 m，手在角色前方 0.50 m，所以手在 0.90 m；墙上预定支撑点在 1.10 m。
- 动作末端，原始根位置是 1.00 m，实际想把角色送到 1.30 m。
- 假设只把末端所需的 0.30 m 修正按时间线性摊开。中点只加 0.15 m，手在 1.05 m，离支撑点还差 5 cm；末端误差却已经归零。

| 对照方案 | 接触帧手位置误差 | 末端根位置误差 |
| --- | ---: | ---: |
| 不修正 | −20 cm | −30 cm |
| 只把末端修正线性摊开 | −5 cm | 0 cm |
| 在两时刻分别满足位置条件 | 0 cm | 0 cm |

试件只比较这两个时刻。最后一行是在接触点应用 +0.20 m、末端应用 +0.30 m，不代表已经找到了连续、自然、无碰撞的路径。实际的 Skew Warp 不等于这条线性曲线；例子只说明，一个正确的末端值不足以推出中途接触也正确。

对于能分阶段的翻越，先标出首次接触、承重期、释放、落地。可以让进入支撑的调整对齐第一段的接触目标，再让脱离之后的另一段调整处理落点。若两个要求落在同一帧而资产的相对姿态不容许同时满足，不能靠再加一个末端目标解决；应该换片段、缩小可接受的障碍尺寸范围，或让手臂在合理关节范围内用 IK 补剩余差值。[4] UE 的 Motion Warping 还允许用静态变换或骨骼提供动画侧对齐点。[1] 这可以表达“用这个点对齐”，但即便某一帧用手附近的点对齐，持握期间的姿态与碰撞仍需要验收。

## 只接触一帧，和撑住一段时间不是一回事

若手应该在墙沿撑住，就不能只在第一帧取一次世界坐标。静态墙上这可能看不出错，移动或旋转的障碍上，手会留在原来的世界位置。对移动表面，先记录手的**障碍物局部锚点**，即“这块障碍上的哪个点”，支撑时再用当前障碍变换把它换到世界坐标：

```text
目标掌点(世界) = 障碍物变换(该帧) × 局部锚点
接触误差(世界) = 实际掌点(该帧) − 目标掌点(该帧)
```

“变换”包括转动和位移，不是每帧只给旧手点加一个平台位移。这里假定接触面是刚体；如果表面随蒙皮或形变移动，应跟踪负责接触的骨骼或实际表面，而不是把点永久固定在整件物体的组件上。第二个二维试件固定局部锚点 (30,10) cm：障碍先从 (100,200) 平移到 (112,200)，再到 (112,212) 并逆时针转 90°。只更新平移在前一帧完全正确，在后一帧会错 (+40,−20) cm；冻结最初世界点甚至在仅平移的一帧就错 (−12,0) cm。试件中的正确转换只是找到了锚点，并没有求出手臂能否到达。

若实现让扭曲目标来自一个组件，Epic 的 FMotionWarpingTarget API 把 bFollowComponent 定义为在扭曲期间是否按组件及可选骨骼更新目标。[5] 不能据此假设窗口结束后的掌点也会自动跟随。应分别检查根运动的目标是否更新、掌点约束由谁更新、何时释放。若画面有一帧偏差，记录障碍变换与角色姿态各自的采样时刻和求值阶段。同一个帧号也可能混着移动前的胶囊、移动后的障碍和尚未求完 IK 的手骨。物件失效、超出可达范围或接触被撞散时，按项目的失效阈值进入事先设计的退出或备用片段；不要继续让 IK 拉长手臂，也不要把退出等同于当帧将权重突然清零。

## 从误差出现的位置选择修法

在可重复的关卡里先分别录四次：原尺寸静态墙、改尺寸静态墙、平移并转动的障碍、根轨迹能对准但角色扫掠会受阻的障碍。每次保留同一动作片段、初始站位和播放倍率。沿时间线记录片段时间、扭曲的有效窗口、根的请求位移与实际位移、碰撞命中、同帧掌点和锚点，以及落点。对持续支撑，额外比较掌点在障碍局部空间中的偏移，不让平台本身的运动混进滑动指标。

| 看到的证据 | 先查或改什么 |
| --- | --- |
| 根请求和实际轨迹一致，落点准确，但首次接触帧手偏了 | 检查窗口和接触标记是否对齐，动画侧对齐点是不是掌点；够得着的少量剩余差值交给 IK，而不是整体再加位移 |
| 首触准确，支撑时才滑；移动或转动的障碍更明显 | 检查锚点是否冻结在世界空间、是否漏了旋转、是否同帧求值，IK 权重是否过早撤掉 |
| 请求位移到得了，实际胶囊先撞停 | 先处理路径与障碍几何、碰撞形状或动作可用条件，别把视觉手拉过去掩盖角色过不去 |
| 手和落点都对，但动作突兀或很像拉伸 | 看接触前后的速度、转向和关节伸展；缩小资产适配范围，必要时回到片段选择或更换动作 |

验收不要只截一张落地画面。对首触、整个支撑期和落地分别定容差；旋转误差、穿墙、末端速度和回到玩家控制的衔接应按实际玩法另测。没有合适的片段时，[FFXV 的越障后续片段案例](../../动画运行时/动作选择/FFXV如何组织越障动画的后续片段.md)解决的是上游选择；已选到片段但接触滑动，可另参照[转身脚滑的排查](../脚部接触/排查原地转身时的脚滑.md)。这三类方法能串用，但不能用某一层通过代替其他层。
