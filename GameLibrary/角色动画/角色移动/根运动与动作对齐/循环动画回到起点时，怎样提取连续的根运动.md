# 循环动画回到起点时，怎样提取连续的根运动

一个两秒的走路动画，姿势每两秒回到片头，角色却不能每两秒退回原地。如果动画程序把当前和上帧的根骨采样位置直接相减，角色可能一直向前，到循环边界突然倒跳；换成原地跑动画后故障消失，也未必说明循环已修好。

这个故障发生在**播放时间**和**位移时间**之间：用循环内的相位采姿势没有问题，但提取要移动角色的增量，需要知道播放头沿哪段路径走到了这里。本文讨论同一个刚体根轨、有方向的播放推进，不讨论多个片段的混合、角色碰撞解算、网络同步或走路动作本身是否好看。

## 先把循环回绕和角色位移分开

设一个合成片段的根轨在 2 秒内从 x=10 匀速走到 x=14；两个周期相接时，骨架姿势可以相同，但角色每圈向前 4。1.75 秒处根轨是 13.5，推进 0.5 秒后相位回到 0.25 秒，根轨采样值 10.5。直接相减会得到 −3。真正发生的运动有两段：

- 尾段：从 13.5 到 14，前进 0.5。
- 首段：从 10 到 10.5，再前进 0.5。

角色应前进 1。这里必须同时采原片末端 14 和原片开头 10；若“取末端”的采样函数会先对 2 秒取模，它给的是 10，拿它算尾段仍会错。工具应保存导入后的端点样本或一圈位移，并区分原轨的末端采样和播放循环的相位 0。比如精确走到 2.0 秒，显示相位 0，并不表示从上一帧到这一步应该输出零位移。

传给抽取层的时间最好是有方向的连续时间，或至少是「循环编号＋相位」。相位从 0.25 到 0.75 可能是走了 0.5 秒，也可能是走了整两圈再加 0.5 秒；只有这两个相位，没法恢复丢失的两圈。长时运行也不要用一个不断增长的单精度秒数保存细小的相位变化；可以用整数播放刻度，或把圈号与有限范围的局部相位分开。已有引擎能给出满足项目条件的根增量时，优先用该增量，不要再把两个根轨采样作差，也不要额外补一圈。Epic 的 Montage 接口把轨道区间和可能跨过的子片段分开，抽取连续小段并按顺序组合；Montage 轨道、片段循环和跨段跳转有各自的边界。[1]

## 转弯动作不只是一维加法

直走的两个小位移能直接相加，转弯时后段的平移方向已经转过。约定根姿势 P(t) 把根局部坐标映射到这条动画轨的坐标，使用列向量，A·B 先执行 B。定义：

- T 为片段时长；P(0) 和 P(T) 为原片起点和末端的刚体变换。
- Q(p) = P(0)⁻¹·P(p)，把片内相位 p 表达到片头的坐标基准。
- C = P(0)⁻¹·P(T)，表示完整一圈的平移和转向，通常不是单位变换。
- 在持续播放的时间 t 写成 nT+p（0 ≤ p < T）。展开的根轨为 U(t) = P(0)·Cⁿ·Q(p)，从 a 到 b 的根局部增量为 D(a,b) = U(a)⁻¹·U(b)。

这么做使前一圈的末端 P(0)·Cⁿ·Q(T) 等于后一圈的开端 P(0)·Cⁿ⁺¹，不会在换圈时重置正常的前进。对连续播放可直接计算更短的相对式 D(a,b) = Q(pₐ)⁻¹·C^(nᵦ−nₐ)·Q(pᵦ)；不用为短小增量建立离初始位置很远的绝对坐标再相减。这里的指数是圈号差；负指数用逆变换。倒放若仍是同一根轨上的连续推进，反向区间的 D 等于正向 D 的逆；负时间的圈号应向下取整，而不是总向零截断。往返播放的拐点、剪辑拼接和非刚体缩放要另外定义，不能直接当普通同向重复。

也可以依时间顺序逐段抽取：先做本圈尾段，再做整圈，最后做下一圈首段。把每段增量右乘到此前姿势上，即 U(b) = U(a)·D(a,b)，相邻区间用 D(a,b)·D(b,c)。各引擎 API 的矩阵书写和增量空间可能不同；接入时先确认返回的是根局部、模型组件还是世界空间，再决定是转基、相加还是相乘，不把本文运算符原样搬到不同约定的接口。

一个精确的二维试件让片头已有旋转 90°、位置 (3,−2)，每圈相对于片头再转 90°、走 (2,1)。每圈的 (2,1) 都在上一圈结束后的朝向里；第二圈位移转过 90°后是 (−1,2)。两圈相对原片头合起来走 (1,3)、转 180°，不是直接加成 (4,2)。这个例子也让两个时点具有相同片内相位：只比较包裹后端点会得到单位变换，但实际跨一圈的局部增量含 90° 转向和 (1,2) 平移。这个平移是从**中途的根姿势**出发的，不能把从片头出发的一圈位移 (2,1) 代进去。四圈的净变换可以是单位变换，角色中途却走过一圈；若需要沿途碰撞检查或触发事件，保留分段及其时间，不能用终点变换替代经过的路径。试件对正向、反向和多段组合做了对照，不涉及插值或画面。[复现实验](../../../../管理档案/实验/循环根运动/README.md)

## 一次正常回绕通过，不等于长帧也通过

Godot 4.6 的 AnimationMixer 文档把 `get_root_motion_position()` 定义为运动增量，另有用于读取混合结果的 accumulator；并明确提醒，循环时对后者作差可能产生跳变。[2] 在 Linux 的 Godot 4.6.3 上，用一根骨骼和手动推进的 AnimationTree 实跑上述 10→14 循环。相位回绕时两个 getter 如下：

| 推进区间 | 上下帧 accumulator 的差 | 引擎增量的 x |
| --- | ---: | ---: |
| 1.75 秒到 2.25 秒（跨一次） | −3 | +1 |
| 2.5 秒到 4.0 秒（恰到端点） | −1 | +3 |

另从相位 0.25 开始，推进相同的 4.5 秒。一次 `advance(4.5)` 读得根位移 +1；将推进拆成 0.25、1.75、0.25、1.75、0.5 秒，逐步读取并加总，得到 +9。两次的最终 accumulator 都是 11.5。这个对照说明，在该构建、该单轨和该用法下，单次跨多圈的结果不等同于按段推进；没有实测运行时所有循环模式、根旋转、引擎物理调用或项目常规帧时间，不据此给所有 Godot 项目判故障。

实际接入先决定长帧意味着什么。模拟确实要推进全时长，就使用在此范围内验证过的原生抽取、受控的分步推进，或保有完整圈数的自定义抽取。分步推进会多次求值动画，也可能影响事件派发和计算成本；如果游戏会限制本帧模拟的时间，抽取和模拟要使用同一段保留时间，别让姿势跟上墙钟而让角色少走。若引擎和平台每次最多推进一个安全的小区间，仍应拿最短的循环片段在最大有效步长下验证。

## 播放跳转不是走过中间那段路

播放到尾再接片头是同一条轨的推进。拖动时间条、网络校正、重进状态或播放节点直接换相位，则可能没有走过之间的路径。给控制器区分 **推进** 和 **重定位**：推进输出遍历段的增量；重定位清掉上一采样基线，取新相位作为下一步起点，不把跳过的区间变成角色位移。如果另有玩法命令需要传送，独立执行。用评估编号标明一份位移对应哪次更新，让运动层应用一次；重复读 getter 或多一层动画回调不应让角色走两次。若碰撞阻止前进，抽取量和实际走出的距离也要分开记，不能直接拿动画位移覆写世界位置。

验收时记录原片起止根姿势、推进或重定位类型、前后相位和圈号、抽取的局部变换、送到运动层的量、实际移动量：

1. 正常走与恰好到边界都应有连续的位移：设定一个根轨起点不为零、尾段和首段长度不同的跨圈例，和分段结果比较。
2. 单帧跳过多圈时，对照同总时长的多次小步；包含转弯的片段要比较完整变换，不只数世界 x。
3. 同一个相位差分别用正播推进、倒播推进、直接 seek 触发。前两者使用各自真实遍历区间；一次仅跳转的 seek 不向角色发根位移。
4. 给角色加一下碰撞阻挡，再核对提取量是否正确、运动层是否只应用一次和阻挡后的世界位移。若只有抽取值倒跳，查时间切片和坐标；若抽取正确但世界轨迹倒跳，再查位移应用和碰撞纠正。

脚落地的姿势时间可以很连续，世界路径仍会错；反过来也一样。如果轨迹正确但图像在接头处跛脚，应检查[步态落脚标记与阶段同步](../步态同步/循环步态的落脚标记与阶段同步.md)，而不是拿根位移补偿动作相位。
