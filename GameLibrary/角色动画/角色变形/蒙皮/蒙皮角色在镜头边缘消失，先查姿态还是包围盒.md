# 蒙皮角色在镜头边缘消失，先查姿态还是包围盒

角色在画面边缘挥动带骨骼的长袖。按当前姿势，袖尖应该先伸进镜头，但整件衣服突然消失；镜头向回挪一点，它又出现了。Animator 的播放时间仍在变，只能说明动画时钟还在走。要找到原因，需要把两件事分开：**当前骨姿有没有交给蒙皮器，渲染器又拿哪只盒子判断这个部件是否值得画。**

以下以 Unity 6.0（6000.0）的 Skinned Mesh Renderer 为例。针对的是主相机视锥附近整件蒙皮网格不见，不是袖子被墙遮住、材质被裁掉，或者独立武器渲染器选错了 LOD。

## 一只手臂有两条范围

剔除用的包围盒是渲染器判断网格可能在什么位置的代理；蒙皮后的网格位置才是应该进入画面的形状。Unity 导入时根据模型及相关动画预计算 Skinned Mesh Renderer 的默认包围范围。[1][2] 如果后来才加伸手 IK、运行时骨骼偏移或模型未涵盖的动作，手就可能伸出旧盒。如果旧盒整个在画外，实际还有一截袖子在画内，宽相剔除仍可能把整个 Renderer 排除。

用一个正交相机看横向 [0, 4]。角色根在世界 x = −1，其他两轴不裁切；导入盒的局部 x 是 [−0.20, 0.55]，所以它的世界右边缘是 −0.45。角色的袖尖沿骨骼伸到局部 x = 1.25，世界 x 已是 0.25。若本轮真正写回的却还是转开 60° 的旧姿势，袖尖在世界上只有约 −0.375。下面在相同机位和位置下区分这两种情况。盒“通过”只代表视锥不再凭这只盒排除它，不保证最终有像素。

| 用哪份姿态 | 用哪只局部盒 | 盒通过横向检查 | 几何横向进入视野 |
| --- | --- | --- | --- |
| 已写回的伸手姿态 | 导入范围 | 否 | 是 |
| 同一份伸手姿态 | 覆盖袖尖的范围 | 是 | 是 |
| 较早的转开姿态 | 同一个覆盖袖尖的范围 | 是 | 否 |

在项目里可能两项都错：旧盒先把网格判在画外，Animator 的可见性优化又使骨姿没写回。Unity 的 `CullUpdateTransforms` 会在渲染器不可见时跳过重定向、IK 和 Transform 写入；`CullCompletely` 会停掉动画。选择 `AlwaysAnimate` 是控制 Animator 求值的试验，不等于保证网格被提交。Renderer 上的 **Update When Offscreen** 则是另一个开关，会持续更新离屏蒙皮并重算范围。[1][3] 两者同时打开后画面恢复，不能判断究竟是哪一项出了问题。

## 把一次“恢复”拆成两个对照

1. **先抓到同一个部件和姿势。** 在测试场景用一台游戏相机，暂时固定 LOD、位置和机位，准备一个从正常到伸过屏幕边缘的可重放片段。在可见时先记录目标骨骼在模型层级中的坐标和预期动作。故障位置记录该网格的世界 `Renderer.bounds` 和相机范围，并在 Frame Debugger 或帧捕获里核对目标相机的主视图有没有提交该网格。不要用 `Renderer.isVisible` 替代这一步：阴影及编辑器 Scene 视图都可能让它为真。[4]
2. **固定姿势，只换盒。** 在测试副本让 Animator 持续求值，在实际 IK/骨修改之后确认使用的是同一份姿势。可把该帧固定下来，用 `SkinnedMeshRenderer.BakeMesh` 取出顶点快照；它在 Renderer 离屏且 Update When Offscreen 关闭时也可调用，但只对已有姿态做 CPU 蒙皮，不会补跑 Animator 或材质的顶点位移。[5] 最容易的诊断场景是层级缩放为 1、渲染器和根骨坐标对齐。一般场景应按 BakeMesh 输出相对 Renderer Transform 的约定和所用缩放选项转换顶点，再跟当前世界盒比较；别把世界坐标直接写入 `localBounds`，也别把缩放算两遍。[1][2][5] 两组都保持 Update When Offscreen 关闭，只在第二组给本 Renderer 一个临时诊断盒；核对两组骨姿确实相同。如果原盒在视锥外、有网格点在内、换盒才恢复主视图提交，就优先修可见范围。
3. **固定盒，只换 Animator 的可见策略。** 另做一次进出镜头的可重复测试，两组用同一只修正盒和同样的离屏蒙皮设置，在预期会运动的骨骼上检查已写回的位置和旋转，不只看状态时间。尽量用独立 Player，把副相机、反射和阴影对可见状态的影响排除。测试路线要有实际离屏的一段；若两组都仍被视为可见，没有差异不能排除 Animator 的剔除策略。若离屏时只有原策略下不写回，优先查动画优化、实际反馈给求值器的可见状态或读写顺序。若网格本来已提交但仍无像素，应转查材质、遮挡和顶点阶段；若改变盒连骨姿也变了，应回到第 2 步重新锁住姿势，不能把画面恢复全归给扩盒。[3][4]

## 按角色能达到的姿势交付包围范围

范围应包括可同时生效的动作过渡、附加层、程序 IK 和换装零件的实际形状。先给有疑问的网格做一份局部极值并集，保存最坏姿势的输入，不把一个通用距离填到所有角色上。只量姿势端点可能漏掉中间峰值。上面的袖尖长 1.25，若在 −60° 和 +60° 各采一次，两次局部 x 都是 0.625；扫到 0° 时局部 x 却到 1.25。两端测得再精确，也不能代替中间姿势。对没有解析上界的复杂混合，要验证过渡和 IK 的可达极端，给离散采样留有根据的余量，或在项目中限制输入使范围可证；更换骨架、零件或姿势范围后要复验。

如果当前角色的动作范围有稳定上界，优先维护每个部件自己的保守盒。脚本给 `localBounds` 的自定义值不会随场景或 Prefab 保存；需要在运行时设置，并检查重建或换装后实际使用的范围。可用 `ResetLocalBounds()` 移除脚本覆盖。不要一边期望由固定盒控制，一边把会逐帧重算局部盒的 Update When Offscreen 当作同一个方案。[1][2] 若变形难以用小的固定盒包住，才针对这类资产测试动态更新。离屏继续更新可能增加成本；把固定盒放得太大同样会让不该留在候选中的部件通过。决定前，用实际角色数量和目标设备分别观察动画/蒙皮时间与渲染提交，别从一个成功的截图推断预算。

验收至少保留两段：第一段从各相关边缘进出，在最伸展的姿势不整件消失；第二段让角色和伸出的零件都远离视野，检查临时大盒留下的多余候选能否被修正盒排除。这也能避免把“始终不过早剔除”误实现成“永远不剔除”。表中数据是可执行的[单骨几何模型](../../../../管理档案/实验/蒙皮角色的剔除包围盒/README.md)，不是 Unity 的帧测量。
