# 手臂扭转时变细，为什么权重归一化还不够

角色抬起手臂，转动手腕，前臂中间却像拧糖纸一样收细了。检查蒙皮权重，每个顶点的权重都非负，加起来也正好是 1。继续把权重归一化，外形却没有恢复。

这并不矛盾。权重归一化解决的是各影响份额如何合计，不保证混合后的变换仍然是一段旋转。若蒙皮把两个旋转后的位置直接平均，中间结果可能向旋转轴靠拢。

本文面向角色技术美术（TA）、技术动画与动画程序开发者。我们用同一顶点的手算说明这种收缩，再讨论何时值得比较蒙皮方法。开头是虚构制作问题，不是某个角色或引擎的故障记录；下文没有运行资产、着色器或性能测试。

## 顶点受两根骨骼影响，究竟混合了什么

**蒙皮**决定模型表面怎样随骨架变化。一个顶点可以同时受多个关节影响，权重表示每项影响所占的份额。

在线性混合蒙皮中，常称为 LBS（Linear Blend Skinning），可以先分别用各关节对应的变换移动原顶点，再把这些结果按权重相加。[1] 两项影响时，可写成：

```text
新位置 = w₀ × C₀(p) + w₁ × C₁(p)
```

这里 `p` 是绑定姿势中的顶点位置，`C₀`、`C₁` 是把这个位置映射到当前姿势的**有效蒙皮变换**。它们不是随手从动画面板抄来的两个局部旋转，也不是两份尚未考虑父级的骨骼局部矩阵。

接入时需要把骨架层级、绑定姿势的校正以及使用的坐标空间算清楚，使两个变换都接受同一空间里的 `p`，输出也处于同一空间。不同引擎可能采用不同的矩阵排列和坐标约定，本文不规定可直接照抄的乘法顺序。若这一步不同，后面的比较就不再只是在比较混合方法。

权重之和为 1，保证这里使用的是一组归一化份额。但“两个位置的平均”不一定位于原来的圆弧上。理解这一点，不需要先制作完整手臂。

## 同样的两个旋转，平均位置会向内缩

设一个理想实数例子：

- 顶点 `p=(1,0,0)`，到 Z 轴的距离为 1。
- `C₀` 不作变换；`C₁` 绕同一个过原点的 Z 轴旋转 120°。
- 两个权重各为 `1/2`，没有平移、缩放或剪切。
- 这两项已经是前面所说的有效蒙皮变换，不再另叠父级或绑定校正。

分别变换顶点：

```text
C₀(p) = (1, 0, 0)
C₁(p) = (−1/2, √3/2, 0)
```

两个位置到 Z 轴的距离都为 1。按 LBS 取中间值，却得到：

```text
p_LBS = 1/2 × C₀(p) + 1/2 × C₁(p)
      = (1/4, √3/4, 0)

到 Z 轴的距离 = √[(1/4)² + (√3/4)²] = 1/2
```

顶点向轴靠近了一半，尽管两个输入都只是旋转，权重也完全归一化。这是混合运算本身能够产生的结果，不能仅靠再次把权重之和调整为 1 消除。

论文用线性混合矩阵不一定保持刚体变换来解释这类问题，并给出扭转塌陷的例子。[1] 本文的 120° 数字是为便于手算选取的同类说明，不是论文模型的测量结果。它也不能据此诊断所有手臂收缩：真实资产还可能存在错误权重、绑定姿势、影响截断或导入差异。

## 对照：先混合旋转，再移动这个顶点

另一个思路是先得到一个混合后的旋转，再用它移动顶点，而不是直接平均两个终点。双四元数蒙皮将旋转和平移合在一种变换表示中混合；论文定义的归一化双四元数线性混合用于刚体变换。[2]

本例没有平移，因此双四元数的对偶部分为零，比较可以简化为普通旋转四元数。下面明确按 **`(x,y,z,w)`** 排列，最后一项是标量：

```text
q₀ = (0, 0, 0, 1)
q₁ = (0, 0, √3/2, 1/2)
```

这两份表示的点积为 `1/2`，本例不涉及半周旋转的方向平局。等权相加，先得到：

```text
q_mix = (0, 0, √3/4, 3/4)
```

它的长度是 `√3/2`。除以长度后得到单位四元数：

```text
q_unit = (0, 0, 1/2, √3/2)
```

这个旋转是绕 Z 轴转 60°，将原顶点送到 `(1/2,√3/2,0)`，到轴的距离仍为 1。

| 同一输入的处理方式 | 顶点结果 | 到 Z 轴的距离 |
|---|---|---:|
| 分别旋转后，线性平均位置 | `(1/4,√3/4,0)` | `1/2` |
| 本例的归一化旋转混合，再旋转顶点 | `(1/2,√3/2,0)` | `1` |

对照说明的是一种具体收缩可以来自混合方式，并不是“给 LBS 的输出位置归一化”就能修复。真实顶点的位置不是围绕坐标原点的单位方向，把它强行归一化会改变模型，不能冒充旋转混合。

也不要把这里的简化扩展成“旋转四元数平均，平移随便平均”就等于通用双四元数蒙皮。存在平移、不同旋转中心或更多影响时，需要所选方法的完整变换约定；本例没有实现这些情况。

## 制作软件正常、游戏里变细时，怎样比较才有用

先把同一个问题姿势固定下来。比起立即修改整条动作，角色作者与接入程序可以共同确认：两边是否真在使用同一份网格、骨架、绑定姿势、关节姿势和权重。动画时间相同但骨架结果不同，或一边已经截断了影响数量，都不是纯粹的蒙皮方法对照。

然后检查双方实际采用的混合方式，而不是只看“蒙皮已启用”。制作端的预览设置与运行端的实现可能不同；本章没有核验任何引擎是否支持某个模式，也没有证明交换格式会保存并传递该选择。

若条件允许，可以在保留同一份输入的情况下比较项目实际支持的替代方法。这是一项待执行的排查建议：

| 比较前先问 | 避免怎样的误判 |
|---|---|
| 有效蒙皮变换是否已在同一空间，包含相同绑定校正？ | 把坐标或层级错误归咎于混合算法 |
| 影响集合、权重与截断处理是否一致？ | 一边换算法、一边换权重，却只归因于其中一项 |
| 姿势是否含缩放、剪切或大角度扭转？ | 用纯旋转手算批准更复杂资产 |
| 希望保留哪段轮廓、服装关系和动作幅度？ | 只凭“不再变细”就认为制作目标全部达成 |

若收缩来自混合方式，继续涂权重可能只是把问题转移到另一姿势；但这不意味着权重永远不用改。修改权重、增加变形支持、制作修形或改变混合方式，都是需要结合实际资产判断的方案。没有同条件比较，不宜把其中一个宣布为通用修复。

## 替代方法也有适用范围

首先，基本双四元数表示处理的是旋转和平移，不直接表示缩放和剪切。2008 年论文专门提出两阶段处理，把非刚体部分与刚体部分分开，并讨论了额外实现与存储成本。[3] 因此，角色若通过非均匀缩放改变比例，不能简单丢弃这些变换，再声称已经完成同等替换。这里也不把论文中的局部缩放设计规定为所有骨架的规则。

其次，论文指出短路径选择在跨过半周旋转时可能使皮肤形状发生不连续变化。[3] 本文的 120° 对照刻意避开了这一边界；需要多圈扭转的内容，不能由这个算例获得批准。四元数的符号选择及相容性处理也属于实现的一部分，而不是对任意四个数直接求平均。

最后，**本例保持一个顶点到轴的距离，不等于整个角色体积保持**。网格上不同顶点可能有不同权重，从而应用不同的混合变换；整张皮肤不是统一受到同一个刚体变换。这里没有检查三角形形状、自交、服装碰撞、肌肉表现或观感，更没有今天目标设备上的性能数据。

回到手臂变细的问题，值得带去交接的不是一句“换双四元数”，而是更具体的结论：同一姿势和同一份影响数据下，哪一种运算造成了什么差异，角色还需要哪些非刚体变化，以及更换方法后哪些姿势和服装仍须回看。权重归一化是输入检查的一项，不是最终变形质量的证明。
