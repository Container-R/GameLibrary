# 大世界材质改用相机相对坐标，怎样让花纹仍固定在世界上

在一张很大的地图上，远离地图原点的石桥开始抖动。把计算改到相机附近之后，几何稳定了，但桥面上沿世界方向投影的条纹却随着镜头滑动。两件事都涉及坐标，却不是同一个故障：**修精度是为了保住局部的差值，固定材质是为了保住它在世界里的投影起点。** 直接拿新坐标做同一份材质运算，可能只修好了前者。

本文面向需要在大世界里固定周期性投影的技术美术和着色器开发者。示例只用一条世界轴和一个重复周期，便于分辨故障；同样的方法可用于两条投影轴，但不等于能复原非重复世界纹理的全局坐标。

## 先确认数值在哪里丢了，而不是先换着色器公式

设单位由项目约定，暂不和任何引擎的米或厘米绑定。相机在 10,000,000；同一小物体的两个点比它远 0.125 和 0.375 个单位。二进制单精度正常数有 24 位有效二进制精度；在这段数值范围，相邻可表示值间隔为 1。[1] 把这三个绝对坐标分别写进单精度时，它们都成了 10,000,000，之后相减只能得到 0，不能从两个一样的数恢复 0.25 的点间距。即使后来把单精度的数转换成双精度，低位也已经没了。

让主机用尚保留细节的绝对坐标先算物体到相机原点的差，再将较小的相对值转换成单精度，就仍能区分 0.125 与 0.375。在采用分块坐标的项目，也可在块号和局部偏移仍然分开时求差；不要先拼成大单精度坐标再拆。实际管线除了顶点位置，还要核对实例变换、用于投影的世界起点等值是在哪一步被写入单精度缓冲区。

相机相对的**世界轴**这里仍朝向世界的固定方向，换的是原点；旋转过的视图空间则会让轴随相机转动。用后一种空间作为世界条纹的投影轴，即使数值很精确，转动镜头也会改变条纹方向。Epic 的 UE5 大世界渲染文档将绝对世界、视图和相机相对世界空间分开，建议在适合的计算里尽早进入平移后的世界坐标。[2] 这不是建议所有材质都改成固定在相机上的投影。

## 保留相对小量，同时带上世界原点的周期相位

令 x 是世界轴上的点，c 是相机相对坐标使用的参考原点，p 是以世界单位计的重复周期且大于零。材质想要的不是 x，而是 x 在该周期里的位置，例如一条宽 0.75 的条纹里离开头多远。定义 mod 把数折回区间 [0,p)。把 x 拆成「相对于原点的位置」与「原点」：

- 相对小量：r = x − c。
- 原点在重复周期里的位置：a = mod(c, p)。
- 世界固定的相位：mod(r + a, p)。

如果艺术要求条纹从另一个全局标记处开始，把标记的投影坐标从 c 里减掉再求 a。重要的是在能保留原点低位的时候求 a，再上传小数值；不把已经折损的世界 float 当高精度数据。r 和 a 必须用同一份参考原点，按同一视图一起更新。镜头切换或多视图时，不能用这一帧的 r 加上一帧或另一个视图的 a。对于斜着的纹理投影，先按世界固定基向量求投影，再在对应轴处理周期，别将观察方向当成世界基向量。GLSL 的 mod 用向下取整，和一些语言保留负号的余数并不相同；对照负坐标、跨零和跨周期点，同时检查浮点误差是否把相位推到了临界边另一侧。[3]

这里给相机两个不会移动世界物体的参考原点，第二个比第一个前移 0.125。条纹周期仍为 0.75：

| 固定世界点 | 大世界 float 相减得到的相对位置（原点一 / 二） | 高精度先减再上传（原点一 / 二） | 只用相对位置得到的相位（原点一 / 二） | 保住世界锚点的相位（原点一 / 二） |
| --- | --- | --- | --- | --- |
| 10,000,000.125 | 0 / 0 | 0.125 / 0 | 0.125 / 0 | 0.375 / 0.375 |
| 10,000,000.375 | 0 / 0 | 0.375 / 0.25 | 0.375 / 0.25 | 0.625 / 0.625 |

用 Mesa llvmpipe（软件 OpenGL 4.5 core）实际运行一个顶点着色器，把四列结果经 transform feedback 写回并读出；上述数值都逐项核对。它不是屏幕截图，也没有验证硬件 GPU 的性能、贴图过滤或具体引擎实现。周期 0.75 和示例偏移恰好可用二进制准确表示；对实际材质仍需检查绝对原点能否算准相位，以及相对坐标是否已小到能保留最细纹理所需的步长。在另一组主机对照里，相对距离 1,000,000 的单精度步长还是 0.0625，比 0.01 的纹理周期还大；0.003 和 0.008 两种原点相位一加上去都被舍掉。此时即使原点余量算对也不够，要用更靠近该物体的局部参考点、为同一原点另算 a，或按分块保留小量。[复现实验](../../../../管理档案/实验/大世界材质相位/README.md)

不要用这一余量假装保留了完整世界位置。它适用于每个周期相同的图案；若每一格要用独立随机种子，或贴的是只出现一次的地形图，应在高精度或分块信息里另保留格子身份。相较于在整个材质图里一路带绝对大坐标，针对每个输入追问“要的是近处差值、周期余量还是完整身份”，更容易做出正确而且易验收的转换。

## 取模太早，修好相位也会在跨格时出错

若两个顶点横跨一个重复边，先在两个顶点分别取模，再把折回后的相位当平滑插值量传入片元，会从周期末端错误地插值到周期前端。精确有理数对照取 47/64 和 49/64、周期 3/4；正确中点 48/64 刚好落在重复边上，取模是 0。但先把端点折回成 47/64 和 1/64 后再求中点，得到 3/8，正好落在花纹中间。

给插值阶段的是仍连续的局部投影坐标；让片元取模，或在普通独立纹理使用可重复的采样器时，交给采样器处理跨格。按此处的世界单位，用 u = (r + a) / p 作为连续纹理坐标，使相隔一个周期的值刚好差 1；不能直接把米数当成每 1 重复的纹理坐标。若材质必须手工取模后再采样，并使用导数决定 Mip，先在未折回的连续坐标上求梯度再传给支持显式梯度的采样接口。[4] 这是避免拿取模断点当成大变化的办法；图集、非连续或随机拼贴还需要各自处理页边、过滤和梯度，不能只改一个 wrap 开关。示例表的读回不测试任何一条过滤路径。

## 区分三种画面异常，再决定改哪里

1. **几何轮廓自己抖动。** 给物体换成无纹理的常色材质，在近原点、远原点分别记录两个已知点之间的距离和相机相对输入。如果世界值上传前就合并，先查计算顺序和缓冲格式，而不是调纹理。
2. **几何稳定，花纹跟镜头滑。** 固定一个世界点，平移相机，读到的模式相位应保持一致；再在相机原地旋转时检查条纹轴是否随镜头转。如果几何坐标正常而相位变了，查究竟将哪个原点与世界投影一起传进来，是否拿了视图轴。不要用两张截图的同一屏幕像素替代同一个世界点。
3. **大部分时候固定，只在周期边界出条痕。** 使用一个跨格的三角形，查插值的是连续坐标还是两端余量；再拿常色或固定 Mip 做对照，分别排除几何和过滤问题。最后在负坐标、两个不同视点、支持的最远区域，以及项目确实使用的原点切换附近重测。原点切换影响历史帧或世界状态时，另验旧帧和新帧的坐标基准；本文只保证同一个世界点的当前材质相位应当不变。

别把“引擎支持大坐标”当作每个材质函数都换了表达。Epic 文档建议查材质节点的 World Position Origin Type；Godot 4.6 也列出大世界渲染仍不覆盖的情况，包括三平面映射和某些世界顶点路径。[2][5] 应在项目实际用到的材质链里验输入，不从软件驱动试件直接推断项目设置或画面收益。
