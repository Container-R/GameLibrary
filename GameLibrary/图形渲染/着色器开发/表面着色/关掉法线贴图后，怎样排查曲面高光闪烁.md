# 关掉法线贴图后，怎样排查曲面高光闪烁

一枚镜面金属扣，静止时只有一条细亮边，镜头平移时那条边却一跳一跳。把法线贴图换成平坦法线，闪点还在。此时不要先去改贴图的 mip 或把所有材质调哑：曲面自身的着色法线会在一个像素里变方向，比像素还窄的镜面峰值可能只被某一帧的中心样本踩中。另一类亮点则来自轮廓处像素覆盖率的变化。两者都出现在亮边附近，但需要不同的修法。

## 先让排查能区分表面内部和轮廓

保留同一份材质、灯光和曝光，关闭法线贴图；用固定相机轨迹，分别看一块平面、一个圆滑曲面和一条硬边。关闭或固定 TAA 抖动与历史、动态分辨率和自动曝光。不要把三个样例缩到不同屏幕尺寸后比较；像素看到多大一块表面，本来就是要控制的变量。

- 在曲面**内部**选一小片，要求相邻采样都属于同一连续表面。相机进行亚像素平移，记录中心样本的高光，以及同一像素范围内用密集采样算出的参考均值。若中心样本忽亮忽暗，而参考变化小得多，先查镜面峰值和足迹的相对大小。在平面上，单位法线不变；在相同的正交视角和远光下，平面可作零法线梯度对照。
- 在**轮廓**另记录几何覆盖。轮廓扫过像素时，物体占像素的面积会变；曲面高光滤波只改着色，不会让像素中心以外的几何被覆盖。高光变化如果伴随覆盖变化，别拿降低高光峰值误当作轮廓已经抗锯齿。硬边两侧是不同面，邻居法线差也不能直接解释为一段连续曲面的弯曲。

## 滤波宽度取自足迹，不是全材质加粗糙度

Tokuyoshi 与 Kaplanyan 的方法对微表面法线分布函数 NDF 滤波。[1] 在逐光源的前向实现里，先把光线与观察方向的单位半程向量 H 变换到切线空间，再对 **H.xy** 求屏幕导数。变化发生在哪个方向、一个像素里大约变多少，由这两个导数给出。不要按旧斜率空间写成 `H.xy / abs(H.z)`：当 z 接近零时，除法放大相邻片元间的差。举例说，两个单位 H 的 z 分别为 0.10 和 0.05、y 都是零，投影 x 只差约 0.00376，除以 z 的斜率却差约 10.025。这个比较说明导数为什么会被放大，不是证明某条轮廓一定变好。论文 Listing 2 的红色删除线正是去掉这个除法；论文还列有完整矩阵法和轴对齐近似。[1，§4.2–4.3]

延迟渲染的材质缓冲阶段通常还不知道灯光。论文为这一步用**单位世界空间着色法线**的差作为替代，给出只占一个粗糙度标量的近似：[1，§5.1–5.5，式 13 与 Listing 5]

```text
dx = 屏幕 x 方向的单位 N 导数
dy = 屏幕 y 方向的单位 N 导数
add = min((dot(dx, dx) + dot(dy, dy)) / π, 0.18)
filteredAlpha2 = clamp(alpha * alpha + add, 0, 1)
```

这里的 alpha 是 GGX 分布参数。若项目使用「感知粗糙度 r」且内部约定 alpha=r²，就在 alpha²=r⁴ 的空间相加；存回 r 的槽时再做逆换算，不能把 add 直接加到美术滑块。[2] 例如 alpha=0.10 时，若 x 方向相邻单位法线相差 10°、y 不变，差向量的平方长是 2−2cos(10°)≈0.03038，补偿约 0.00967，结果 alpha≈0.14025。平面两轴差为零，alpha 仍是 0.10。

平方差之和乘以比例系数后给出滤波核协方差的迹：它至少不小于最大特征值，所以在限幅之前能给最宽的变化方向留足宽度，但也会把窄的方向一起放宽。两方向都变化时，这种各向同性近似可能比必要的更软；0.18 是论文实现控制过度滤波的上限，不是所有材质的调优常数，也不保证限幅后仍足够宽。计算发生在材质/G-buffer 几何阶段，不等同于事后用相邻的 G-buffer 像素做差；后者可能取到另一个物体。一对 90° 的法线差会让上述补偿直接撞上限，但无法替你修复几何覆盖。着色器应在连续路径上先算导数，再根据已知边界和适用范围决定是否用它；不要把导数调用放进像素间分歧的条件分支。[1][3]

## 看波动，也看高光有没有被抹掉

固定 GGX alpha=0.015，关闭贴图，让单位球面在横向移动一个像素宽，取 41 个亚像素相位。CPU 试件只计算高光分布 D 项，不计算菲涅耳、可见性与真实光照，也不模拟遮挡。下表仅是球面内部同一个像素的 D 范围；参考是每个相位用 128×128 个等面积样本作盒平均。

| 取样办法 | 球面 D 最小值–最大值 |
| --- | ---: |
| 像素中心 | 157.70–954.04 |
| 用式 13 的相邻法线差来扩大粗糙度 | 138.20–236.84 |
| 密集盒平均参考 | 231.79–410.26 |

加了补偿以后数值更稳，但峰值也比参考低。平面条件下补偿始终为零。这组数据给出一个会改变采用决定的检查：先检查波动变小是不是靠压掉真实亮峰，再判断在目标镜头里值不值得牺牲这份锐度。不要只比较峰峰值，更不要把这些 D 数值换算成亮度或实机性能。

再用 OpenGL 片元着色器在 Mesa llvmpipe（CPU 软件实现）运行相同采样思路。用真正的 `dFdx/dFdy` 给无贴图的解析法线求差，输出同一组相位的中心、滤波、32×32 像素盒参考。球面内部的 D 峰值分别约为 954、237、410，再现了峰值压过头的现象；平面逐相位都无变化。实验页的五个相位用同一显示映射展示这三个版本。

在解析球面轮廓另取一个像素，其中心随相位在内外切换。带滤波和不带滤波的版本共用同一个中心覆盖掩码，都无法得到参考的部分覆盖；在这组边界试件里，补偿还抬高了 D 的尾部。这个着色器用全屏片元和解析球的覆盖判定，明确延拓轮廓外法线，不是实机网格的辅助片元行为。因此它能验证「改高光不等于改覆盖」，不能用来估计某引擎轮廓会变多亮。

落地时先在代表材质记录参考、原始版本、有限幅补偿三个结果，再决定是否采用，或改用能保留方向的核。若曲面内部已稳定但边缘仍缺覆盖，回头检查几何采样和时域重建；如果只有开启法线贴图后才出现问题，则回到纹理足迹和法线 mip，而不是继续调大几何核。[4]
