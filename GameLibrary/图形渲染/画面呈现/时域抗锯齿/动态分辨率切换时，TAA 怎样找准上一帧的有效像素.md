# 动态分辨率切换时，TAA 怎样找准上一帧的有效像素

画面从半分辨率升到全分辨率，相机和物体都没动，TAA 的历史采样却突然读出一条不属于场景的颜色。先别调整历史权重：如果两帧共用同样大的纹理分配，但上一帧只写了其中一半，用这一帧的尺寸查历史，就可能连正确的区域都没找着。把位置换算对了，边缘还可能被双线性采样带上无效颜色。

下面讨论历史随渲染尺寸变化、写在较大纹理子矩形里的做法。目标是能在帧捕获里区分三件事：重投影算错、上一帧有效区域用错、过滤跨界。

## 两次换算分别用什么尺寸

时域抗锯齿（TAA）会重用上一帧积累的结果。先把当前像素的位置换成当前视口内的归一化坐标，再用项目的重投影约定，求出它在**上一帧视口内**的归一化坐标 `h`。例如约定速度是“当前位置减上一帧位置”，并且两者已在各自视口的同一归一化约定中表示，便用 `h = currentLocalUV - velocity`。如果速度存的是像素，或速度不含投影抖动，先按生成运动数据时使用的尺度和抖动约定转换；不要先乘纹理分配比例再盲目减去速度。

这个 `h` 不是历史纹理的 UV。把历史有效矩形的起点和尺寸写作 `O` 和 `S`，历史纹理分配尺寸写作 `A`，各自以纹素为单位。统一 Y 轴方向后，按分量计算：

```text
历史纹理 UV = (O + h × S) / A
```

这里的 `O、S、A` 要与**正在读的那张历史图**一起保存和交换，不能在写本帧历史前拿当前视口参数把它们盖掉。Unity Core RP 的 RTHandle 文档就区分现帧和历史的尺度：示例中的 `rtHandleScale.xy` 用于当前帧，`.zw` 对应上一帧。[1] 这是这套接口的具体约定；带偏移的自建视口需要单独记录原点。

只看横轴：分配宽 128，上一帧写了左边 64 个纹素，本帧用满 128。零运动时，视口内的 `h = 0.75` 应落在历史纹理 UV `0.375`，也就是以纹素边界计的 `x = 48`。误用本帧的 128 会得到 UV `0.75`、`x = 96`，落到上一帧没写的区域。反过来从全分辨率降到半分辨率，误用当前尺寸也会取错位置，只是它可能仍读到有效颜色，因此不一定能靠边缘哨兵抓到。若原点是 12，仍写 64 个纹素，该点则在 `x = 60`；忘了偏移也可能只是取错颜色，而不越界。

## 坐标没越界，采样也可能越界

对于基级双线性采样，横轴上以纹素边界计的 `x` 要先减去半个纹素，才得到相邻纹素中心之间的位置。[2] 上例的历史合法索引是 0 至 63。取视口内 `h = 255/256`，得到 `x = 63.75`；减半得到 `63.25`，线性采样会从索引 63 取约四分之三、从索引 64 取约四分之一。索引 64 在纹理里，却不在历史视口里。普通的 `CLAMP_TO_EDGE` 只认识整张纹理，不认识其中的有效矩形。[2]

先判断重投影是否在上一帧视口内（本例中两个分量都须满足 0 ≤ h < 1）；不存在对应位置时，拒绝历史并使用当前结果。对仍在视口内的有效点，若接近边缘，可以将基级双线性取样位置限制在 `[O+0.5, O+S-0.5]` 再除以分配尺寸。它会延展最外一排或一列，有时会拉出边缘颜色。若这不适合画面，可以在采样脚印碰到有效区外时直接拒绝历史；代价是边缘更依赖当前帧，时域稳定性更弱。更宽的重建核、采自其他 mip 层或多个采样点时，要检查真正用到的纹素，不能把半纹素这个界限直接照搬。

视口检查只负责空间范围。场景刚显露的背景、相机切换、纹理被替换后内容未保留，仍需要各自的历史拒绝或重置。若时域超分的历史本来就保存在固定输出尺寸上，内部场景分辨率变化不必意味着历史矩形跟着变；检查实际读写那张图，而不是单凭动态分辨率倍率清空历史。

## 用哨兵颜色把两类错误分开

我在离屏 Mesa OpenGL 中分配一张 128×4 的 RGBA8 历史纹理，整张填洋红，再将有效区域写成绿，额外在参考位置写一个蓝标记。着色器使用基级双线性和 `CLAMP_TO_EDGE`，把采到的值写进浮点缓冲读回。这个实验只测纹理取样，没有运行游戏或完整 TAA。

| 上一帧有效宽 → 本帧宽 | 正确取 `h=.75` | 错用现帧宽 | 有效区右边缘内侧，未限制采样 | 内侧，限制采样至有效纹素中心 |
| --- | --- | --- | --- | --- |
| 64 → 128 | 绿蓝各约一半 | 洋红 | 洋红约 25%，绿色约 75% | 纯绿 |
| 128 → 64 | 绿蓝各约一半 | 纯绿，蓝标记丢失 | 纯绿 | 纯绿 |

在历史原点移到 12、旧宽仍为 64 的对照中，正确换算仍能找到蓝标记，未经限制的边缘仍混入哨兵。另取 `h=1.01` 则明确拒绝历史，没有硬拉到最右边一列。[复现代码和完整读回](../../../../管理档案/实验/history-viewport-scale/README.md)

接入时可固定相机和场景，强制切换两帧尺寸，先查看原始历史采样，别等它经过颜色裁剪、混合才判断。用定位标记验证升、降分辨率都落在同一场景位置，用哨兵验证过滤没有越过历史边界。再恢复运动与抖动，记录当前像素、上帧视口坐标、历史矩形、最终 UV 和拒绝原因。零运动都读偏，就先修矩形和过滤；只有运动时读偏，再回头查速度的符号、单位和抖动。这样也能避免拿[限制历史颜色](INSIDE如何限制时域抗锯齿留下的旧颜色.md)去掩盖取样位置错误。
