# D3D11阴影比较过滤的采样核设计与核对

把阴影读取循环写成九次 `SampleCmpLevelZero`，再除以 9，并没有完整定义一个“3×3 PCF”。如果 sampler 使用线性比较过滤，每次调用已经组合了邻近纹素的比较结果；九次调用叠加后，哪些纹素参与、各占多少权重，还要由坐标和寻址状态决定。把 sampler 改成点比较，可能保留了循环，却改变了整个采样核。

本文给出一种确定并核对这个算子的方法：先固定比较含义和读取状态，从 UV 展开一次线性采样，再合并外层调用的权重，最后用显式取深度的参考路径检查结果。读者需要了解 HLSL、归一化 UV 和基本阴影贴图流程。资源创建、光源投影、级联选择和软阴影算法不在本文范围内。

## 先把输入和“亮”的含义固定下来

假设项目已经有一张合法可读、非多重采样、非 tiled 的二维纹理，保存光源视角的深度数值。供本文读取的 SRV 格式为 `R32_FLOAT`，只暴露资源第 0 层；资源也只有这一层，没有额外的资源级 LOD 限制。目标设备及当前项目路径已经支持这种比较采样，不把 D3D11 这个 API 名称当作所有 Feature Level 的能力保证。底层纹理与深度写入视图怎样创建，不在这里给配方。

纹理尺寸记为 `W×H`，整数坐标从 `(0,0)` 开始。读取函数接受以下输入：

- `uv` 是当前视图中的归一化纹理坐标，不是像素坐标。调用者已确认接收点属于本次光投影的有效域，中心 UV 在 `[0,1]²` 内。
- `r` 是接收点的参考深度，与图中深度 `d` 使用相同编码。主例取近小远大，`r`、`d` 都是 `[0,1]` 内的有限值。
- 比较函数为 `LESS_EQUAL`，即 `r <= d` 时通过。通过记为 1，并作为亮的贡献；失败记为 0。
- `r` 已包含上游决定的深度偏移。本文算例偏移为零；外层所有调用使用同一个 `r`。

据此定义一次比较：

`C(r,d) = 1，当 r <= d；否则为 0。`

Microsoft 的比较采样文档明确规定：先对各个 tap（参与过滤的纹素采样项）进行比较，再过滤这些 0/1 结果。比较操作数是参考值在左、纹素 R 分量在右。[1][2] 因此，下文的输出 `V` 是**加权比较通过量**，可用于调制这盏光的直接光照贡献。它既不是新深度，也不自动等于真实面积光源的可见比例。

有效接收点与越界 tap 要分开处理。接收点在光源背后、投影除法无效或深度编码不匹配，应由调用者按渲染策略处理；sampler 的 BORDER 只规定过滤时越过纹理边缘怎样取值。尤其是浮点纹理的比较参考值不会自动限制到 `[0,1]`。[1] 不应以无条件 `saturate(r)` 掩盖投影错误，再把结果当作有效阴影查询。

## 从 UV 算出一次线性比较的四个贡献

暂时忽略硬件的有限精度，先建立一个能手算的理想模型。纹素 `(i,j)` 的中心位于 `((i+0.5)/W, (j+0.5)/H)`。把 UV 改写到“整数恰好对应纹素中心”的坐标中：

`p = uv × (W,H) - (0.5,0.5)`

`b = floor(p)，f = p - b`

这里 `b=(i,j)` 是四个候选纹素的左上地址，`f=(fx,fy)` 是两轴的小数位置。二维线性权重为：

| 整数地址 | 权重 |
| --- | ---: |
| `(i,j)` | `(1-fx)(1-fy)` |
| `(i+1,j)` | `fx(1-fy)` |
| `(i,j+1)` | `(1-fx)fy` |
| `(i+1,j+1)` | `fx fy` |

四个权重相加为 1。各地址先按所选边界规则取得深度，然后计算 `C(r,d)`，最后乘权重相加。这一模型对应规范的线性寻址与逐项寻址顺序；实际规范还规定坐标定点转换，稍后再处理其精度影响。[3]（§7.18.8–9）

以 `W=H=8`、`uv=(15/32,1/2)` 为例：

`p=(13/4,7/2)，b=(3,3)，f=(1/4,1/2)`

于是四个地址为 `(3,3)、(4,3)、(3,4)、(4,4)`，权重依次是 `3/8、1/8、3/8、1/8`。这不是四个纹素的等权平均。

现在令左列深度为 `1/4`、右列为 `3/4`，参考值 `r=1/2`。左列比较失败，右列通过。三种操作会得到三个不同结果：

| 操作 | 计算 | 理想结果 |
| --- | --- | ---: |
| 先比较，再按线性权重组合 | `3/8×0 + 1/8×1 + 3/8×0 + 1/8×1` | `1/4` |
| 先用同样权重过滤深度，再比较 | 过滤深度为 `3/8`，再判断 `1/2 <= 3/8` | `0` |
| 四次比较直接等权平均 | `(0+1+0+1)/4` | `1/2` |

比较是一个带门槛的非线性操作，不能任意交换到过滤之后。这个反例也说明，只检查“读了相同四个深度”仍不够，权重必须相同。

点采样另有地址规则。其理想地址是 `floor(uv × (W,H))`，没有上述 `-0.5`。本例中心点采样选择 `(3,4)`，而不是线性核左上角 `(3,3)`。规范分别定义了这两种寻址过程。[3]（§7.18.7–8） 写参考程序时必须使用 `floor`；把负数直接转成整数的截断不能替代它，纹理边缘恰好会暴露这个错误。

## 让 sampler、视图和调用共同表达这个算子

主实现采用整张纹理的 BORDER 寻址，边界深度为 1。在本例的 `LESS_EQUAL` 和 `r∈[0,1]` 约定下，越界 tap 比较通过，相当于把图外延伸为亮。这是明确选择的一种边界政策，而不是阴影贴图唯一正确的政策。

下面是 sampler 描述的核心 C++ 示例。各字段都显式设置；创建 sampler、绑定 SRV 与 sampler、检查返回值由已有渲染路径完成。min 和 mag 都使用线性比较，避免把选择不同过滤方式的歧义带进这个例子。[4][5]

```cpp
D3D11_SAMPLER_DESC desc = {};
desc.Filter = D3D11_FILTER_COMPARISON_MIN_MAG_LINEAR_MIP_POINT;
desc.AddressU = D3D11_TEXTURE_ADDRESS_BORDER;
desc.AddressV = D3D11_TEXTURE_ADDRESS_BORDER;
desc.AddressW = D3D11_TEXTURE_ADDRESS_BORDER; // Texture2D 不使用 W
desc.MipLODBias = 0.0f;
desc.MaxAnisotropy = 1;
desc.ComparisonFunc = D3D11_COMPARISON_LESS_EQUAL;
desc.BorderColor[0] = 1.0f;                  // 比较使用 R 分量
desc.BorderColor[1] = 1.0f;
desc.BorderColor[2] = 1.0f;
desc.BorderColor[3] = 1.0f;
desc.MinLOD = 0.0f;
desc.MaxLOD = 0.0f;
```

为什么还要设置 LOD，而不是只写 `SampleCmpLevelZero`？这个对象方法提供从零层开始的比较采样。[6] 对应规范条款说明，`sample_c_lz` 忽略导数、以 LOD 0 为起点，但 LOD clamp 或 bias 仍能影响选层；而 sampler 的第 0 层是相对 SRV 的，不一定是资源原始第 0 层。[3]（§5.8.2–3、§22.4.20） 所以本文同时固定单 mip、SRV 起始层、资源级限制、bias 和 sampler LOD 范围。换成别的视图时，尺寸 `W,H` 和 texel 步长也要随实际读取层级改变。

以下 HLSL 展示一次调用和九次调用的主路径。`texelStep` 必须由当前视图尺寸给出，等于 `(1/W,1/H)`，不能在非方形图上把两个方向都写成 `1/W`。代码是未编译的核心实现示意，不包含完整 shader 入口和引擎接入。

```hlsl
Texture2D<float> ShadowDepth : register(t0);
SamplerComparisonState ShadowLinear : register(s0);

float Shadow1Linear(float2 uv, float r)
{
    return ShadowDepth.SampleCmpLevelZero(ShadowLinear, uv, r);
}

float Shadow9Linear(float2 uv, float r, float2 texelStep)
{
    float total = 0.0;
    [unroll] for (int y = -1; y <= 1; ++y)
    {
        [unroll] for (int x = -1; x <= 1; ++x)
        {
            float2 q = uv + float2(x, y) * texelStep;
            total += ShadowDepth.SampleCmpLevelZero(ShadowLinear, q, r);
        }
    }
    return total / 9.0;
}
```

这里没有对每个 `q` 做 `saturate`，也没有因 `q` 越界就提前返回 1；两种写法都会改变 BORDER 对各个 tap 的处理。外层偏移通过 UV 表达，单层图避免了偏移步长与选层不一致的问题。

## 九个线性局部核怎样叠成一个核

把第 `k` 次调用的外层权重记为 `a_k`，它对纹素 `i` 的局部权重记为 `w_ki`。所有调用使用同一个参考值时，理想输出为：

`V = Σ_k a_k Σ_i w_ki C(r,d_i)`

如果同一纹素被多次覆盖，可以先合并权重：

`W_i = Σ_k a_k w_ki，V = Σ_i W_i C(r,d_i)`

这一步能直接回答优化前后是否保持了采样核：比较的是每个实际地址的累计权重及其比较输入，而不只是调用次数。非负权重且总和为 1 时，理想 `V` 位于 `[0,1]`。若以后给不同 tap 使用不同参考深度，这个简单合并不再适用，因为同一 `d_i` 参与的比较可能不同。

对于代码中的九次调用，`a_k=1/9`，偏移是横纵各 `{-1,0,1}` 个纹素。先看横向：中心线性核在 `i、i+1` 上的权重是 `1-fx、fx`。把它左移、保持、右移后各占 `1/3`，得到：

| 横向地址 | 来自三个局部核的权重之和，再除以 3 |
| --- | ---: |
| `i-1` | `(1-fx)/3` |
| `i` | `(fx + 1-fx)/3 = 1/3` |
| `i+1` | `(fx + 1-fx)/3 = 1/3` |
| `i+2` | `fx/3` |

纵向同理。由于本例的偏移和权重可以按两轴分离，二维累计权重就是横纵权重的乘积。把前面的 `b=(3,3)、f=(1/4,1/2)` 代入：

- 列 `2、3、4、5` 的横向权重为 `1/4、1/3、1/3、1/12`。
- 行 `2、3、4、5` 的纵向权重为 `1/6、1/3、1/3、1/6`。

因此，九次线性调用在这里覆盖的是一个 **4×4、非均匀权重** 的纹素集合。例如 `(2,2)` 的权重为 `1/24`，`(3,3)` 为 `1/9`，`(5,5)` 为 `1/72`。两轴权重各自和为 1，二维总权重也为 1。

九次点比较则不同。相同的九个查询坐标，按点采样规则选中列 `2..4`、行 `3..5`，每个地址占 `1/9`。它既没有第 5 列，也没有第 2 行。

用一张仅第 5 列深度为 `3/4`、其余列为 `1/4` 的 8×8 图，仍令 `r=1/2`，就能区分两条路径：

- 九次线性调用：只有第 5 列通过，理想结果是其横向总权重 `1/12`。
- 九次点比较：九个地址全部失败，理想结果为 `0`。

这比全亮或全暗输入更能检测核变化。若需求确实是指定中心周围九个纹素等权投票，应选择并核对点比较核；若需求是对九个查询位置的线性比较结果再做平均，就保留复合核。后者不能仅凭名字被当作前者的等价优化。

本例的“九次调用”“每次四个概念 tap”“十六个唯一地址”是不同计数。它们不能直接换算成 GPU 内存事务或运行时间，也不能单凭支持域较宽断言画面更好。

## 边界要按整个核检查，atlas 内边界另算

一次线性调用的中心在纹理内，不保证四个 tap 都在内。令 `uv=(0,1/2)`，仍用 8×8 图，所有图内深度为 `1/4`、`r=1/2`。横向 `p.x=-1/2`，左右地址分别为 `-1、0`，各占一半：

- BORDER、边界深度 1：左半权重通过，右半失败，理想输出 `1/2`。
- CLAMP：左侧地址也映射到第 0 列，全部失败，输出 `0`。

这是边界规则不同造成的正常差异。即使中心 UV 等于 0，BORDER 也不是“整次调用直接返回边界深度”；边界值仍要逐项比较并参与过滤。[2][3]（§7.18.9）

九次线性调用要检查更宽的范围。设中心 `b=floor(uv×(W,H)-0.5)`，则候选地址从 `b-(1,1)` 到 `b+(2,2)`。对于 `fx` 或 `fy` 等于零的位置，最外一侧可能是零权重；把整个候选矩形都纳入检查，是一个简单的保守做法。需要判断是否完全落在有效数据区时，应检查这个矩形，而不是只检查中心。

atlas 的 tile 边缘并不是整张纹理的边缘。假设 8×8 图的列 `0..3` 属于左光源，列 `4..7` 属于右光源。查询中心 `uv=(15/32,1/2)` 仍位于左 tile，却已有四分之一的单次线性权重落在第 4 列。若左 tile 深度为 `1/4`、右 tile 为 `3/4`，得到的 `1/4` 就含有右光源数据。把整张图设为 BORDER 不会拦住它，因为第 4 列是合法的整图地址。

本文主路径采用独立纹理：每张图只存一个查询域，BORDER 的资源边缘与这个域的边缘一致。若从上述 atlas 拆出左半张图，新尺寸是 4×8，局部坐标为 `(2u,v)`，偏移步长改为 `(1/4,1/8)`，并重新核对主例的 sampler 和 view。原本落到右 tile 的 tap 此时按边界深度 1 处理，不再读取另一光源。但它仍可能贡献亮；隔离其他光源与选对边缘延伸政策，是两个不同目标。

若必须保留 atlas，可以选择以下做法，代价也不同：

- 为 tile 提供足够 padding，并让光源投影真正生成这部分覆盖。可用中心范围、外层半径和内层线性范围共同决定所需余量；只在存储布局中留空隙并不提供正确深度。Microsoft 的 CSM 说明同时要求考虑采样范围与投影覆盖。[8]
- 显式按 tile 范围取深度，给越过 tile 的地址规定边界值或夹到 tile 边缘。这要求手动实现相应核，或采用能实现该语义的其他路径；普通整图 comparison sampler 不认识这个范围。
- 缩小允许使用该核的中心区域，超出时切换到已定义的后备路径。后备路径也必须有明确含义，不能只把中心 UV 随意夹紧。

复制边缘深度、丢弃越界 tap 后重新归一化、把越界视为亮，都是不同的边缘算子。应根据覆盖含义选择，再把同一选择写进参考路径，而不是用其中一个的参考值验另一个。

## 用显式 Load 路径核对，不让采样器验证自己

独立参考的关键是绕开待核对的比较过滤调用：自己确定整数地址与权重，取得原始深度，执行同一比较，再加权。`Texture2D.Load` 接受整数纹素地址和 mip 索引；它不接受 sampler，越界返回零。[7] 直接对负地址 `Load`，不会复现本例的 BORDER 深度 1。

下面的 HLSL 沿用前文 `ShadowDepth`，由调用者传入实际 `int2 size=(W,H)`。`CompareBorder` 在任何越界读取之前明确处理边界；`Ref1Linear` 实现四项理想核；`Ref9Linear` 则直接用合并后的 4×4 权重，避免再写一份相同的九调用结构。

```hlsl
float CompareBorder(int2 t, int2 size, float r)
{
    if (t.x < 0 || t.y < 0 || t.x >= size.x || t.y >= size.y)
        return (r <= 1.0) ? 1.0 : 0.0;

    float d = ShadowDepth.Load(int3(t, 0));
    return (r <= d) ? 1.0 : 0.0;
}

float Ref1Linear(float2 uv, float r, int2 size)
{
    float2 p = uv * float2(size) - 0.5;
    float2 base = floor(p);
    int2 b = int2(base);
    float2 f = p - base;
    float2 wx = float2(1.0 - f.x, f.x);
    float2 wy = float2(1.0 - f.y, f.y);
    float result = 0.0;
    [unroll] for (int y = 0; y < 2; ++y)
        [unroll] for (int x = 0; x < 2; ++x)
            result += wx[x] * wy[y] *
                      CompareBorder(b + int2(x, y), size, r);
    return result;
}

float Ref9Linear(float2 uv, float r, int2 size)
{
    float2 p = uv * float2(size) - 0.5;
    float2 base = floor(p);
    int2 first = int2(base) - int2(1, 1);
    float2 f = p - base;
    float4 wx = float4(1.0 - f.x, 1.0, 1.0, f.x) / 3.0;
    float4 wy = float4(1.0 - f.y, 1.0, 1.0, f.y) / 3.0;
    float result = 0.0;
    [unroll] for (int y = 0; y < 4; ++y)
        [unroll] for (int x = 0; x < 4; ++x)
            result += wx[x] * wy[y] *
                      CompareBorder(first + int2(x, y), size, r);
    return result;
}
```

这段参考代码同样未编译，是本文理想模型的浮点实现示意，不是逐位硬件模拟。CPU 参考也可以按相同步骤访问输入数组，用有理数计算下表中的分数结果。主路径与参考路径共享的输入约定仍需另外检查，例如两者都传错 `size`，并不会因为输出一致而变成正确。

要改为 CLAMP，参考路径应先把整数 `t` 夹到 `[0,size-1]`，再 Load 和比较，而不是直接 Load 越界地址。要核对九次点比较，应从 `floor(uv×size)` 开始，对整数偏移 `{-1,0,1}²` 的九个地址调用 `CompareBorder` 后平均，不应复用 `Ref9Linear`。

下面是一组有区分力的输入。除最后一行外，中心均为 `(15/32,1/2)`；尺寸为 8×8，`r=1/2`，主比较为 `LESS_EQUAL`。表中是理想计算值，用于确定应该检查哪一层。

| 深度图或查询变化 | 检查路径及理想值 | 主要用于发现 |
| --- | --- | --- |
| 全图 `d=3/4` | 中心一次线性、九线性、九点都为 `1` | 方向、输入或绑定的基本错误 |
| 全图 `d=1/4` | 上述三个内部核都为 `0` | 同上；应先排除全局错误再看权重 |
| 全图 `d=1/2` | 上述三个内部核都为 `1` | `LESS` 与 `LESS_EQUAL` 混用 |
| 列 `0..3` 为 `1/4`，列 `4..7` 为 `3/4` | 一次线性为 `1/4`；先过滤深度再比较为 `0` | 比较顺序、半纹素位置、权重 |
| 仅第 5 列为 `3/4`，其余为 `1/4` | 九线性为 `1/12`；九点为 `0` | 外层核与内层过滤不匹配 |
| 全图 `1/4`，改用 `uv=(0,1/2)` | 一次线性 BORDER 为 `1/2`，CLAMP 为 `0` | 逐 tap 边界及负坐标 floor |

先核对单次调用，再核对外层叠加。若单次结果已不符，扩大循环只会把错误混到更多地址中。对完全落在图内的核，让一个纹素的深度为 `3/4`、其余为 `1/4`；这张“单纹素通过图”的输出就是该纹素的累计权重。若核越过 BORDER 边缘，先用全失败的图测得边界贡献，再从单纹素通过图的输出中减去这个基线。逐个移动通过纹素，可以重建图内权重，而不依赖复杂场景画面的主观判断。

随后固定深度图，改变 UV 的小数位置，观察边缘权重是否按公式变化；再换非方形尺寸，检查横纵步长。边界测试最后移到 atlas 内部，检查是否把资源边界误当成 tile 边界。这样每次只改变一个能影响结论的条件。

## 理想核、规范精度与设备结果分别怎样使用

上面的分数证明两种算子不等价，却不承诺所有 GPU 都返回与有理数完全相同的位模式。D3D11.3 规范规定缩放后坐标至少具有 8 bit 的子纹素小数精度，即每纹素至少有 256 份细分，并规定过滤算术的要求；寻址过程中会把坐标转成定点形式。[3]（§7.18.7–8、§7.18.16） “至少 8 bit”也不意味着可以把所有设备一律模拟成一种固定的八位舍入实现。

本文刻意选用可精确表示的二进制分数输入，把最初的判断集中在核和比较顺序上。但九次求和后的除以 9、实际过滤权重、计算顺序，以及其他 UV 下的坐标量化，仍应与 native 返回值区分。参考 HLSL 中的浮点加权也会有自身舍入，不能把它升级为规范允许误差的证明。

换成 UNORM 深度格式时，还必须处理参考值向目标格式精度的转换。比较指令规定先按格式量化参考值，再与纹素比较；浮点格式则遵循相应的浮点比较规则。[2] 因而，拿 CPU 的任意精度 `r <= d` 直接充当所有格式的逐位参考，会在阈值附近给出错误的预期。本文不实现 UNORM 转换和特殊浮点值模拟。

如果要在项目中做原生核对，先保存能够重放一次查询的数据：实际资源与 SRV、层级和尺寸、图内深度、`uv/r`、完整 sampler 描述、所有偏移与外层权重，以及设备、驱动、Feature Level、shader 编译目标和输出 readback。分三步处理差异：

1. **地址或通过位不同。** 先比较每个整数地址、实际深度和比较方向，检查 view、步长、边界及相等规则。比如单列图出现第 5 列贡献与完全没有贡献，首先是核的区别，不应直接归因于浮点误差。
2. **地址和通过位一致，权重不同。** 检查半纹素位置、外层权重是否重复计算、point/linear 状态，以及 UV 的有限精度。特别检查靠近整数寻址分界的位置。
3. **仅剩数值小差异。** 根据采用的坐标精度、格式与运算路径建立容差，再报告该设备的观测范围。不把任意选的 epsilon 或“看起来接近”当成跨设备合规标准。

这里没有原生 shader 执行、GPU readback 或图像结果。正文交付的是可明确表达并进行对照的采样算子，而非某个驱动的精度报告。

## 采用之前，还要重新评估哪些条件

核对通过后，可以确认实现是否按预期组合了比较结果；仍不能据此认定所有阴影问题都已解决。扩大核会让同一个参考深度与更远位置的深度比较，接收面的坡度和轮廓会使这些位置的深度发生变化，因而原来的偏移设置可能不再适用。Microsoft 的大核 PCF 讨论也指出了邻近位置比较与深度偏移之间的关系。[8] 调大偏移又会改变接触关系，不能用本篇的权重正确性替代相应评估。

同样，光源投影随相机变化造成的采样格移动，发生在深度图生成阶段；它与给定图上的读取核是不同问题。[9] 最终画面的稳定性、边缘表现和运行成本，需要在实际场景、运动序列及目标硬件上分别检查。

因此，一次可复查的采样改动应留下三样东西：明确的输入、view 和 sampler 约定；可以展开到整数地址的权重公式与实现；能区分顺序、核和边界错误的小型输入对照。以后替换调用、合并 tap 或调整 atlas 布局时，就有具体算子可比较，不必只凭“也是 PCF”判断等价。
