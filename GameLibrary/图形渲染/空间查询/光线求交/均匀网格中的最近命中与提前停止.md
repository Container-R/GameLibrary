# 均匀网格中的最近命中与提前停止

给低模烘焙法线时，一种做法是从包围模型的投射笼发出射线，找到高模上最近的表面，再取得那里的法线。为了少检查一些三角形，程序把空间切成同样大小的格子，沿着射线逐格查找。

看起来，只要按由近到远的顺序走，第一次找到交点就应该够了。但这里有个差别：**先检查到的三角形，不一定先被射线碰到。** 一个斜跨多个格子的三角形，可能在第一格的列表里，真正的交点却在第三格；第二格还可能藏着更近的表面。

本文面向编写射线查询、烘焙工具或几何加速结构的开发者。我们先用两个三角形说明为什么不能过早结束，再讨论什么条件下可以安全停止。不比较硬件性能，也不试图用一个算例证明完整烘焙器正确。

## 格子保存的是名单，不是裁好的三角形碎片

均匀网格把一片空间分成等尺寸单元。每个单元通常保存可能与它重叠的图元；这里的图元就是待求交的三角形。若保存的是完整三角形的引用，测试它时得到的交点，不必落在当前格子内。

可以把名单理解为“这个三角形有一部分在这里”，而不是“这个三角形与任意射线的交点都在这里”。因此，遍历格子与排列所有交点，是两件不同的事。

PBRT 第二版及对应源码有一个明确处理：命中后保留当前最近位置，再比较下一格的进入位置，而不是无条件在第一次命中时返回。[1][2] 本文使用的停止推理针对这类完整图元列表；如果求交函数只接受当前格子区间，后面的规则也要随之调整。

## 一条射线，先发现远处 A，再发现近处 B

下面是原创手算例，没有运行查询。把 X 方向切成单位格子：C0 在0到1之间，C1 在1到2之间，C2 在2到3之间。Y、Z都在0到1的范围内。

射线从 `(0.25, 0.5, 0.5)` 出发，沿 X 正方向前进。用参数 `t` 表示从起点向前走了多少；在本例中方向长度为1，所以它也等于距离。一般射线的参数不一定直接等于长度。

放入两个三角形：

- A 是一片斜面，伸进 C0，但射线到 `x = 2.5` 才穿过它，即 `t = 2.25`。
- B 完全位于 `x = 1.5` 的平面上，射线在 `t = 1.25` 处穿过它。它不在 C0 里。

具体坐标在文末附录，可以检查这不是单凭示意想出的摆放。两次命中都在三角形内部，不落在格子边界；三角形不透明、双面，不作背面剔除。

进入 C0 后，程序查到 A，便得到一个有效交点。但 C0 的出口在 `x = 1`，从起点算只走了 `t = 0.75`。已发现的交点还在出口之外，不能确定中间没有别的表面。

继续进入 C1，程序查到 B，将最近候选改为 `t = 1.25`。C1 的出口在 `x = 2`，对应 `t = 1.75`。这一次，候选就在下一段尚未检查的空间之前。

| 处理完哪一格 | 当前最近候选 | 离开该格的参数 | 下一步 |
|---|---:|---:|---|
| C0 | A：2.25 | 0.75 | 继续；交点还在前方格子中 |
| C1 | B：1.25 | 1.75 | 在下节前提成立时，可以停止 |

A 也可能出现在 C1 的列表里；再次检查它，不应让2.25覆盖已经找到的1.25。保存的是所有已检查候选中的最近有效交点，而不是“最近一次求交返回的结果”。

## 停止时，需要证明前方不可能再有更近的交点

将当前最近交点记为 `t_best`，将进入下一段未检查空间的参数记为 `t_next`。一个充分的停止条件是：

```text
已经找到有效交点，并且 t_best < t_next
```

它依赖几项容易被遗漏的前提：网格覆盖查询几何，三角形没有被漏放到应该覆盖的格子；格子确实按射线参数递增访问；当前格子的候选已经全部处理；跨格保留了最小有效参数，并且只接受查询区间内的交点。

在这些前提下，尚未访问的空间都不早于 `t_next`。假如另有更近的交点，它应处于已经走过的区间，对应三角形也应该已在那些格子中被检查。于是当前候选可以确定为最近者。漏放图元或漏查名单时，这个推理就不成立；最后一个比较符号再正确，也救不了前面的遗漏。

这里用精确算术说明严格小于的情况。恰好相等时，还涉及格子边界的归属与同距图元的选择规则；并不是一见等号就必然不能停止，也不能随手加一个通用小数容差来结束讨论。实现中的浮点误差、退化几何和同时跨越多个边界，需要另行处理。

没有交点时，则继续到查询区间或网格结束。“这个格子不是空的”不等于“射线命中了它保存的某个图元”。

## 只问“有没有挡住”，可以采用不同的退出规则

假如查询只需回答一个布尔问题：指定射线区间里是否存在遮挡？那么找到一个符合条件的交点就足够了。它不承诺返回最近三角形，也不承诺返回适合烘焙的法线。

在前面的 A+B 例子里，最近命中应选 B；任意命中只需回答“有”。不能用后者的测试通过，证明前者也选对了表面。PBRT 固定版本的 `IntersectP` 与 `Intersect` 正体现了这两种用途的区别。[2]

还有一种实现会把求交结果限制在当前格子的射线区间内。这样可以建立逐格停止依据，但要同时考虑去重：第一次检查 A，发现它的交点不在 C0，于是丢弃；如果又记录“A 已经测过，以后不再测”，走到真正交点所在的格子时，就可能永远漏掉它。

要么保留那个未来交点作为候选，要么让重新测试政策与区间过滤一致。怎样缓存取决于实现，不能把“不重复测试”当成独立于正确性的优化。

## 看源码时，把命中上限的更新一起追下去

PBRT 第二版代码并非仅靠格子循环中的一个条件实现最近查询。固定版本中，构建器按图元世界包围盒覆盖的格子放入引用；当前格子逐项测试；几何图元命中后更新射线的 `maxt`，三角形求交又遵守这个参数上限。遍历层随后把这个上限与下一边界比较。[2][3][4]

只截出“沿格子前进”的几行，就会漏掉这条数据传递关系。本例并没有声称 PBRT 会自动把两个三角形构造成这里的单位网格；我们借它说明实现如何配合，而不是把原创几何冒充原程序结果。

GPU Gems 3 的法线烘焙章节是另一个相关背景，它描述了从投射笼寻找参考表面的流程。不过网页没有包含关键的射线求交辅助函数。[5] 因而不能凭网页摘录，判断完整应用是否缺少区间限制，更不能把 PBRT 的实现细节补写成 NVIDIA 示例的真实代码。

## 给实际实现准备几项小检查

在把这类查询接到烘焙器之前，可以先安排以下有限检查。它们是建议，本文没有执行。

1. 使用 A+B，最近查询应选 B；把每格候选及退出参数一起输出，确认没有在 C0 提前结束。
2. 同样几何改为任意命中，只要求回答存在，不要求返回 B。
3. 只保留 A，最终仍应得到2.25，检查区间过滤与去重是否把它漏掉。
4. 调换格子列表内的图元顺序，本例没有同距交点，最近结果不应改变。
5. 把查询参数上限设为1，两次交点都在范围外，应返回无命中，而不是继续使用无限射线上的结果。

这些小例子不能覆盖所有浮点或网格构建问题，但能把“遍历顺序看起来没错”变成可以检查的实际决策。性能则要另外测量：跨格继续走与重复测试可能增加工作，缓存又有自己的成本，不能从停止条件直接推导某个收益比例。

即使选中了正确表面，法线插值、切线空间转换和纹理输出仍可能出错。[法线变换的补充说明](../../../../research/source-notes/tangent-handedness-normal-transform.md)讨论的是其中另一部分。最近命中解决的是“选哪一个表面”，不是整张烘焙结果的最终质量。

## 附录：检查两个三角形确实能这样摆放

希望复核几何的读者可以使用下面的坐标；理解前面的退出规则不必先算完它们。

A 的三个顶点是 `(1/2, 9/10, 1/2)`、`(7/2, 3/10, 1/10)`、`(7/2, 3/10, 9/10)`。它们位于平面 `y = 1 − x/5`。按权重 `(9/10, 1/20, 1/20)` 加权得到 `(4/5, 21/25, 1/2)`，三权重全正、和为1，所以这是三角形内部点，并且在 C0 内。A 并非仅仅包围盒碰到 C0。

A 的重心为 `(5/2, 1/2, 1/2)`，恰好位于射线上，对应 `t = 9/4`。B 的顶点为 `(3/2, 1/5, 1/5)`、`(3/2, 4/5, 1/5)`、`(3/2, 1/2, 4/5)`；权重 `(1/4, 1/4, 1/2)` 得到内部交点 `(3/2, 1/2, 1/2)`，对应 `t = 5/4`。

这是精确几何手推，不是运行日志。射线的 Y、Z 方向分量为零，也不表示程序实现可以忽略除零与边界初始化问题。
