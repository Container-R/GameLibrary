# 树叶贴图缩小后为什么变稀：裁剪阈值与 Mip 覆盖率

树冠近看正常，拉远后枝条还在，同一批叶片却变得稀疏。先不要加叶片：如果网格和材质没有换，而叶片使用固定阈值丢弃像素，普通缩小过滤就可能让原本不透明的细叶落到阈值以下。这个问题适合从贴图的具体 Mip 层查起，不必先靠整棵树的远景截图猜原因。

## 平均透明度没变，通过裁剪的比例仍会变

设材质保留 `alpha >= T` 的样本，其他样本丢弃。对一层贴图逐个 texel 使用相同比较，通过的数量除以该层 texel 总数，就是这里说的**贴图裁剪覆盖率**。它不是屏幕上的叶片像素比例：屏幕结果还受纹理采样、视角、UV、几何和遮挡影响。

例如四个相邻的 alpha 是 `1,0,0,0`，以 2×2 方框均值缩小后只剩一个 `0.25`。在阈值 0.65 下，原区域有四分之一通过，缩小后一个也没有。均值把原先集中在一个 texel 的不透明度摊开，但先裁剪再求比例和先求均值再裁剪不是同一个运算。也可能往另一个方向出错：阈值足够低时，缩小后的整个 texel 通过，轮廓会更粗。

Ignacio Castaño 在《The Witness》开发记录中展示过远处树叶变稀，并提出让较小 Mip 的 alpha 缩放后尽量接近原始覆盖率。[1] 他的公式用严格大于；本文复算使用大于等于。管线必须明定相等时怎么判，否则恰好在阈值上的低分辨率 texel 可能使结果跳变。

## 用同一个阈值生成和验证 Mip

先在最清晰一层用实际裁剪阈值量一次覆盖率。再为各层寻找独立系数，把该层 alpha 乘以系数并限制到 0–1，然后仍以原阈值测试。可以按照 Castaño 的办法，在未缩放 Mip 的 0–1 取值范围内寻找一个最接近目标覆盖率的临时阈值，再把当前材质阈值与它的比值作为系数；遇到零阈值、并列取值或无精确解时，应重新数通过量，而不能直接除零或承诺精确还原。这里用一个选定系数说明为什么有效，并不复刻他的搜索算法。[1][2]

在原创的 8×8 二值纹理里，按 2×2 分组，有三组各含三个不透明 texel、三组各含两个、九组各含一个，另有一组全透明。[3]

| 检查 | 通过数量与覆盖率 |
|---|---|
| 原图，阈值 0.65 | 24/64，即 37.5% |
| 普通均值生成的 4×4 Mip，阈值 0.65 | 3/16，即 18.75% |
| 对该层 alpha 乘 1.4，阈值仍为 0.65 | 6/16，即 37.5% |
| 沿用 1.4，却在运行时将阈值改为 0.30 | 15/16，即 93.75% |

为什么第三行刚好可达？原来均值 0.5 的三组变成 0.7，刚从拒绝变为通过；原均值 0.25 的九组只到 0.35，仍不过 0.65。第四行说明不能拿同一份已校正的贴图任意复用到不同裁剪阈值。对多个材质共享的贴图，优先核对是否真的需要不同阈值；确实需要时，用各自适用的导入配置或分别验证，而不是改全局设置碰运气。

不是每层都能保持原比例。把四个粗 texel 设成 0.75、0.25、0.25、0.25，其原始二值图覆盖率仍可为 37.5%。提高同一个乘数时，三个相同的 0.25 会一起跨过阈值，只能得到 0%、25% 或 100%。在这个例子里 25% 最接近目标；让最小一层彻底保住细枝，就需要额外的表示或不同的视觉策略。覆盖率相同也不意味着位置正确；同样一个通过的 texel 从左上移到右下，计数不变，轮廓却已经变了。[3]

## 在实际资产上怎样排查

1. 先冻结网格、材质和相机路线，分别强制或检查相邻纹理 Mip。近景本身若已错，先查原始 alpha、透明度来源和实际裁剪阈值；只在换网格时突变，则先检查网格 LOD。
2. 对照导入器采用的覆盖率参考值与材质实际阈值。Unity 的默认纹理导入文档有 Mip 覆盖率及 Alpha Cutoff 配置；这是导入参考值，不会替你改材质的运行时设置。DirectXTex 也把参考阈值作为处理参数。[2][4]
3. 比较校正前后的每层通过比例和裁剪后的遮罩图。再用目标平台压缩设置重验：压缩可能让接近阈值的值跨过去；在实机或目标渲染路径看相邻 Mip 混合、移动镜头下闪烁、树冠轮廓与背景之间是否有错误增厚。只量离散 Mip 的整体覆盖率，不代表两层混合后的屏幕结果也会保持。

这套做法针对固定阈值裁剪的资产。半透明混合与多重采样中的 alpha-to-coverage 有不同的可见样本机制，不宜直接用这里的数值验收。本文只复算二值数据和方框平均，不声称测量了某个引擎、GPU 或植被场景的图像质量。
