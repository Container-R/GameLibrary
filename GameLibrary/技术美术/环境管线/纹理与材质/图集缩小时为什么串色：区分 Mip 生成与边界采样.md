# 图集缩小时为什么串色：区分 Mip 生成与边界采样

一批不透明地砖装进同一张图集后，近处看是干净的，远处的红砖边缘却染上了相邻蓝砖的颜色。把采样器设成 Clamp，或者给两个图块多留两像素，也许能治好某个镜头，却不能说明问题出在哪：**蓝色可能已被写进缩小版图像，也可能是采样时从相邻的两个干净像素混进来的。**

下面用固定坐标和已知颜色分开检查这两个环节，再决定改缩图、留边还是采样设置。讨论的是不透明、非重复、按矩形排在图集里的素材。透明轮廓还有 Alpha 和透明区 RGB 的问题；重复材质使用 `fract` 等折回坐标时，还要另查导数跳变，不能从本文的纯色对照推断这两类故障。

## 先看出问题那一级的原始像素

Mip 是同一纹理的一组逐级缩小图。设一张 8×4 图集每行左红右蓝，左边红块只占底图的第 0、1、2 列。用对齐的 2×2 箱式平均缩到第 1 级时，上一层第 2、3 列一起贡献给该级第 1 列，一个红、一个蓝。于是第 1 级即使只取一个像素，也会得到紫色。若红块改占第 0 到第 3 列，这一级恰好各算各的，得到两红两蓝；更粗的级别未必还保有这个条件。

这是**生成 Mip 时混色**。改成最近点采样，可以帮助定位，不能还原已经混色的像素。Khronos 的 OpenGL 规范规定生成 Mip 会做反复过滤缩减，不强制某个核；箱式平均是可用于理解和复现的一种选择，不能拿它的精确权重替所有项目作保证。[1] NVIDIA 的图集工具资料也区分了按各素材生成 Mip 后再装入图集，以及用规则尺寸与对齐限制全图缩图；尤其指出尺寸不同的素材能占用的级数不同。[2]

要诊断当前素材，先找运行中实际读取的级别和项目导入后的图集。把相邻两块暂时换成高对比不透明纯色；固定可疑的 Mip，逐点查看左、右两块边缘的 texel（该级存下来的一个像素）。在着色器中可以用有效范围内的整型坐标做明确的单 texel 读取，或者在图形调试器中查看实际 Mip 图。不要用一个仍然双线性采样的预览画面代替原始 texel。如果蓝色已经在左块边缘的 texel 里，应回到导入或生成环节，先不要改 UV。

## Mip 完全干净，采样仍可能越过子图边界

双线性不是拿 UV 所在图块的单个 texel，而是拿周围的最多四个 texel 按距离混合。仅看水平方向，当该级宽度为 W、归一化横坐标为 u，换算出的连续 texel 坐标为 x = uW − 0.5。整数 x 对应 texel 中心；在整数之间则会读两边。采样器只知道整张图的外框，Clamp to Edge 不知道每个子图的矩形。[1]

一个实际软件 OpenGL 对照固定 u = 0.46875、v = 0.5、LOD = 1。此时 W = 4，x = 1.375。坐标仍在红块的 UV 范围 u < 0.5 内，却在红色 texel 1 和蓝色 texel 2 两个中心之间，因此蓝色权重为 0.375。给左块名义边缘右侧留两个底图像素，并用同一块的边缘红色把它们填满，这一级的两个取样点都变成红色；同一个 UV 才读到纯红。

## 留多少边，不从底图的像素数单独决定

生产中会给子图留一圈隔离边，再用子图的边缘内容扩展过去，而非随便塞一个空白色。这样取样超出可见子图边缘时仍能读到属于它的颜色。采样只涉及哪一级、子图在该级的位置、缩图核读哪里、隔壁图块是否也有足够空间，这些一起决定所需边宽。Unity 的 Sprite Atlas 面板也把图块间距、Mip 生成和过滤方式作为不同选项。[3] 面板上的总间距不等于给每块分别扩展了同样多的像素，检查实际导出的数据，而不是用设置名猜。

在严格 2×2、逐级对齐的箱式模型里，第 L 级的一个 texel 沿一轴覆盖底图 2^L 个像素。要确认一个给定位置不会借到别块：

1. 找出该级双线性权重非零的 texel；另一轴同样检查。
2. 对每个 texel，找它覆盖的底图范围。若第 L 级的索引是 i，在这个简单模型中覆盖 [i·2^L, (i+1)·2^L)。每个参与的范围都应只含该素材及它的边缘扩展。错位的起始列会改变范围内有多少隔壁像素；2^L 不是可以直接填进所有打包器的间距答案。
3. 三线性时还要核对另一个实际参与的 Mip。例如两个底图像素的扩展在精确箱式模型里使某个位置在 Mip 1 不漏蓝，但在 Mip 2 漏 3/16 蓝；LOD 1.5 混合两级后仍漏 3/32。软件 OpenGL 试件也在 Mip 2 实读到部分混色，不过它没有开启三线性，不能拿其整数值替上述数学对照。

诊断可用纯色，因为任何串来的颜色都可测量；最后需回到真实纹理，看斜角、屏幕分辨率、Mip 偏置、各向异性和压缩后的结果。仅把顶点 UV 往图块内部挪半个**底图** texel，最多约束某些情况下的基础层采样；远处一个 texel 可能已经横跨多个底图像素，还可能读上下两级。按指定级把取样足迹限制在有效区可以诊断或隔离**运行时越界**，但可能缩掉正确边缘，并且不能修复已混色的 Mip。

## 让修复落在真正出错的环节

- **texel 已被污染：** 单独对素材缩图，非重复素材按自己的内容边界处理过滤，再把各级放入能由同一套归一化子图 UV 找到的位置。逐级保留该素材自己的边缘扩展。不能每级由打包器随意重新摆放，又期待原 UV 同时指向一块内容；布局容不下、最小级没法区分多个素材时，应分图集或停在各素材仍可用的级别。
- **texel 干净，但线性采样串了：** 修正子图 UV 与有效区，核查每级的保护 texel，而非整图 Clamp。控制图集的最低可用分辨率，或者在多个宽高相同、格式兼容的素材间使用纹理数组，让每层有独立边界和 Mip，避免图集相邻排布。[1] 数组需要统一层规格，可能带来空置区域；小图和大图混用时，按尺寸分组的多个图集也有维护及渲染管理成本。
- **只有自动选级、斜视或跨级时出现：** 先把两个相关级分开测，不用「关掉 Mip 以后消失」证明生成环节有罪。必要时以图集中最早失去独立 texel 的素材为约束，限制取样到已经验证的级别。若删掉粗级，纹理的可用级数配置也要匹配；采样器将 LOD 限在较细级，不等于缺级的纹理一定完整。验收时确认三线性没有再读到下一粗级。过早截断会牺牲远处细节的稳定性，出现闪烁或取样成本变化。用带不同相邻块的同一场景，对照近处、远处和斜看，不只验截图里一个站位。

最后用同一场景把相邻块的颜色换掉，参考对象用独立纹理或数组层。只要目标素材和灯光都不变，本块就不该跟着隔壁颜色变。先比较原始 Mip，再看同一级的点采和线性，最后放回完整的采样策略。这比反复调一个 padding 数字更容易找到能保留画质的改动。
