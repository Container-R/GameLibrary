# 模块墙的烘焙光照接缝：怎样区分烘焙值和采样串色

两块墙在网格上对得很齐，材质也相同。预计算光照打开后，拼接处仍出现一条亮线，或两侧整条边突然一明一暗。不要先把所有墙的光照贴图分辨率翻倍：差异可能来自几何、来自两侧已经写进贴图的光照，也可能直到贴图取样时才产生。这三类问题看起来相似，修的却是不同的地方。

这里讨论原本应平滑过渡的共面静态表面。实际有凹角、遮挡物、材料突变、不同法线或光照条件的地方可以有真实明暗边界。先确认设计要的是一面连续的墙，再开始排查。

## 先确定断线在哪一步出现

固定机位、曝光、灯光、可见遮挡物、烘焙质量与参与烘焙的 LOD。用不带法线和细节纹理的中性材质查看；必要时切到只看照明的视图，再比较一份临时关闭烘焙贡献的渲染。只看照明能帮助排除材质纹理，但不天然区分实时、直接和间接贡献。

- **几何或法线本就不连续**：在不依赖那张光照贴图的几何/法线视图，用线框、轮廓或法线缓冲核对缝两侧是否真的共面、有没有窄缝、重叠或插片，法线是否同方向。关掉法线贴图不等于去掉网格法线差异。若差异一直存在，先修拼接或法线。
- **光照贴图中已经有落差**：把缝两侧相邻的世界点映射到各自图表，在各自有效纹素内向里取几排样本。若线性亮度在到达边界前就稳定分成两支，先看光照求解、遮挡/法线和烘焙边界，不要假定图表间距是原因。原始贴图若经过曝光、RGBM 或其他编码，应解码到可比较的光照域；移动 HDR 曝光滑杆不能替代取样。
- **只在边缘采样时错**：确认烘焙用的是哪套 UV 和哪张图集。若图表里的数据连续而过滤后被另一块无关表面拉偏，再测试边缘填充、有效间距和实际采样层级。用同一份贴图对比调试用最近邻与实际过滤，或查看近远两个已经固定下来的采样层；最近邻只用于诊断，不是交付修法。如果基础层有效纹素正常，而问题 mip 的最近邻已偏，不要归成基础层烘焙落差或本次线性过滤；先查该级生成、填充和压缩后的数据。只在同一 mip、同 UV 下从最近邻换回实际过滤才出现差异时，再确认过滤足迹是否碰到非相邻的图表。远处变严重也可能来自 LOD 切换，不能只凭距离归因。

在烘焙墙面法线和光照几乎恒定的小区域上做剖面。记录世界单位的缝两侧固定距离、两个 UV 图表的实际纹素比例、去贴图测试结果、原始解码值和最终采样值。接近遮挡角或阴影边时先比较同一参考曲线的左右趋势；真实连续梯度在相距不为零的两点也会有差值，不该把所有有限间距的差都叫阶跃。

## 边距能隔开邻岛，不能让两边重新受同样的光

把图集上的纹素中心编号。用一个一维线性过滤试件，左右世界采样点都趋向同一条实体缝，但 UV 岛把它们送到图集中不同位置。未污染时两岛边缘的正确光照均为 0.60。左像素四分之一的权重不慎落到无关岛的 0.20 上，结果是 `0.75 × 0.60 + 0.25 × 0.20 = 0.50`，右侧保持 0.60。把左侧边缘向自己的保护区扩张后，两个采样结果均为 0.60。

第二个试件让有效图表已分别写入 0.48 和 0.66，保护区各自正确复制边缘。过滤不再跨进无关岛，接缝处仍相差 0.18。因此边距要解决的是**采样足迹不跨到无关数据**；它不会修正写入光照图表的相对亮度。取同一贴图不同分辨率或同一场景不同烘焙时，应把这两种变化记开。数值是演示，不是实际渲染结果，也不建议将 0.18 当检测阈值。

固定 UV 间距换成纹素数时还要用实际分配给这个表面的密度，不能沿用资产预览的数字。纹素尺寸、下采样层、压缩块、各级填充和运行时过滤都会影响采样是否溢出；不存在能套给所有引擎、平台及相机的固定安全纹素数。[1][2]

## 把“合并后好了”拆成可解释的对照

如果很多模块重复出现同一问题，可以从原场景复制两块做三组烘焙，只在副本里切换：
 
1. **分对象、分岛**是当前基线，记录两个网格的法线、实际图集/纹素密度和烘焙设置。
2. **一个对象、保留相同的分岛边界**先单独测试对象组织。对象打包可能随之变化；如果无法匹配两个图表的边距和单元密度，应注明依旧是混合对照。不能据此断言烘焙器因为对象 ID 采用了不同求解。
3. **一个对象、接边展开成连续图表**再测试减少 UV 边界。让两片精确共面、法线/材质一致、边缘确实是共边并检查两边 UV 连续；仅把两个网格挂到同一个父节点，既没有焊接，也不会把两个图表变成一张连续图。

固定的几何边与裁切位置是依据，不能同时动光源或为了合并把墙厚改了。如果合并改变了图册大小、采样密度、遮挡或法线，那么能下的结论只是组合修改有帮助。需要继续查原因时，回到缩小的对照，而不是把单次截图当成对象边界的证明。

Unity 6000.0 的 Progressive Lightmapper 可尝试 Stitch Seams（缝合），但文档限定同一 GameObject，并且是图集中水平或垂直的 UV 图表边界直线；世界里的墙横平竖直不代表 UV 边满足条件。[3] 要验证这个选项，只在满足条件、同一对象与同一分岛的副本上启闭并重烘。它不是两个独立墙体的跨对象焊缝。如果对照指向分岛而模块必须保持独立，可考虑把无缝大面积表面改为连续静态受光件，或把不可避免的边界放在实际转角、构件接头处。前者要重新检查复用、图集占用和可见性剔除，后者会改变关卡和美术设计。不能为了隐藏诊断失败而在实验中偷偷加一条遮缝装饰。

Unreal 的 Lightmap Density 用来看实际分配的相对密度；Lighting Only 用来看照明而不靠材质纹理读缝。若问题指向错误通道、生成时的最低分辨率或源 UV 自动排布，按[UE 光照 UV 检查文章](../../../美术设计/模型制作/贴图烘焙/Unreal自动生成光照UV后，为什么仍要检查切缝与分辨率.md)处理；不要为一处模块接缝重写所有资产的 UV 规则。[2]


## 实跑对照：同样的图表打包，只分开物体

在 Blender 4.3.2 的 Cycles CPU 中，把两个共面四边形按上述三档单独烘焙。三档几何位置、法线与白色漫反射相同，每个模块占 32×32 个核心纹素，匹配每单位纹素数和采样中心位置。分岛两档用同一套图集坐标，两片都保留各自顶点、共位但不焊接；只切换是否属于同一个物体。连续 UV 档则同时使用焊接共边和连续展开，所以它是参考组，不是单独检验 UV 切缝的对照。分别烘焙点光源的直接漫反射，以及加入上方漫反射板后的间接漫反射，关闭去噪；按世界对应位置读取原始浮点图集的内部值。Blender 把颜色与直接、间接漫反射分量分开，因此这里比较的是光照贡献，不是表面颜色。[4]

在直接光和两个不同种子的间接光对照中，同图表打包的单对象与双对象组逐一比较，2048 个核心样本完全一致。直接光下换成连续图表后，在边缘相邻纹素间观察到的最大额外差约 0.00043；间接光的不同打包组有较大采样变动，分岛的平均邻边差比连续图表大还是小，随种子反转。在这组场景、相同分岛与拓扑下，没观测到把两片放进不同物体所造成的差异。与连续图表的比较同时改变了共边连接和展开，且间接光有采样噪声，不能凭一次边差给其中一个变量归因。它不测游戏引擎的解码、过滤或 mip，也不证明其他光照场景不会变差。

## 用能回到原场景的证据收尾

在同一机位保留关闭烘焙、原始贴图剖面、实际过滤结果和修正后的成对记录；再到目标分辨率、相机距离、LOD 和压缩设置复查。若只有 UV 图集的调试视图好看，实际材质和拍摄条件下仍有缝，就不是完成。最后应能告诉下一位协作者：“两侧烘焙值一致，问题只在过滤跨岛，已按实际密度重排并验证近远镜头”，或“边缘值在过滤前已经分开，下一步核对几何/导入法线、遮挡和烘焙的对象边界”。这比“重烘后顺眼些”更容易复现。
