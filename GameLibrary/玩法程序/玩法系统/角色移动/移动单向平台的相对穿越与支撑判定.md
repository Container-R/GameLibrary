# 移动单向平台，为什么角色向上跳也会落地

横版关卡的升降台只允许从下往上穿过。角色本来就在台面上方，跳起时脚还在向上走，升降台却追上来把它接住。另一处，角色从台底经过，动画已经开始下落，碰撞却不应该在这个位置突然打开。两个现象都不能只看角色的世界竖直速度；真正要判的是，脚从台面的哪一侧、沿什么方向、在平台宽度的什么位置接近它。

下文以顶面水平、不旋转的平移平台、自定义角色移动判定为例，先解决顶面是否参与支撑。接住角色以后怎么搬运，或平台横向推到实心物体以后怎么处理，是另一道题，见[移动平台的搭乘与推挤](Celeste与TowerFall的移动平台为什么要区分搭乘与推挤.md)。

## 取同一时刻的脚和台面，再求相对运动

把一个物理步开始时的支撑点记为 `F0`，无碰撞的拟议终点是 `F1`。对平移平台，用一条顶面上的参考点 `P0/P1` 连到同一物理步的两端；采用向上的法线 `n`。在本例中 `F0/F1` 是角色脚点，不是角色原点：

```text
d0 = dot(F0 - P0, n)
d1 = dot(F1 - P1, n)
```

正值在支撑侧，负值在下方。对这一小段内线性移动、有清楚起点的情况，如果 `d0 >= 0`、`d1 <= 0` 且 `d1 < d0`，说明从上侧向下相对接近，并于步内达到平面。命中时刻的步内比例为 `t = d0 / (d0 - d1)`。从下往上的 `−2 → +2` 不算落地，即使角色在世界里下落。起点已穿透或处在容差带内是另一类状态，不能把负值都改成零再套公式。

例如脚从 y=4 升到 5，台面从 y=0 升到 6，距离从 +4 变成 −1，顶面在 `t=0.8` 追上了仍在上升的脚。在产品规则允许时，这是有效的上侧接触，不是世界坐标的「上升不能落地」。平台若在水平移动，还要在**同一个 t** 计算脚的横坐标相对平台原点，确认进入有限支撑区。只看步末横向重叠，可能把先擦过边缘、后来才对齐的一步误判为踩到了。在有宽度的角色上，要用实际支撑形状或按项目约定检查脚的横向覆盖，不要把试件中的单点当通用脚部检测。

这个交点只适用于同一小段内恒定法线、两端之间近似线性且没有中途方向反转的运动。台面旋转、曲线运动或物理求解改变了步内路径时，要用子步中真实姿态或合适的相对扫掠；相隔两帧的渲染位置不能替代碰撞用的数据。若用速度，比较的是脚速度减去支撑点速度在法线上的分量，不是把平台速度加到世界坐标后又减一次。实践中常见的假阳性，是平台已经更新到本步终点，却用旧脚位置与新台面计算 `d0`。

## 初次落地、保持支撑和主动下穿分别判断

**初次落地**需要从上侧进入、相对接近且候选处于顶面的有效范围。若从下方穿过仍有重叠，不能因为接触法线偶然朝上就立刻恢复顶面；角色需要按约定先完整到达允许落地的一侧，再接受后续新的上侧接近。高速度下要检查是否有对应扫掠候选；只处理引擎最终回调并不能补到没报告的接触。

**保持支撑**不能每帧都要求 `d1 < d0`：角色已经随平台移动时，两者沿台面法线的相对速率约为零。不希望被抖下去，可保留已确认的支撑身份，在容差内检查有效支撑面、横向重叠与相对分离。主动跳离、走出边缘或支撑面无效，应解除而不是继续吸附。被台面接住后，再由控制器处理剩余位移与搭乘，避免又算一遍平台整步平移。容差要用角色和场景尺度定义并记录；大容差可能把本应穿过或已脱离的接触也当支撑。

**主动下穿**要明确忽略哪一个平台或哪一组属于同一面的碰撞体。先取消当前支撑，再让该平台在角色离开有关几何之前都不参与顶面约束；不应关掉所有下方平台。如果用了最短忽略时间，时间到了而角色仍与上层重叠，不宜立即重启，尤其在平台跟着角色一起向下时。可用脚之上的角色最高可能碰撞部分与该平台实体的下界检查是否已完全离开（按项目的实际形状），并留出小容差；规则若允许从边缘横向离开，应另有明确分支。恢复后下一次接触仍按初次落地规则判断，别把旧支撑直接恢复。

Unity 6.0 的 Platform Effector 2D 公开了以本地向上为中心的有效表面角与多接触体分组，适合用来核对哪些是同一张面、哪些接触应一致处理，不意味着它使用了上面的公式。[1] Godot 的 `CollisionShape2D` 暴露单向碰撞标志和独立的单向边距；不要把边距直接等同于本文的保持支撑容差，更不要把单向碰撞与控制器继承平台速度混成同一个参数。[2][3]

## 先重放一个物理步，再看整段动作

录下脚点和台面两端、有符号距离、候选交点及本步支撑身份。先构造角色世界向上但相对向下的场景，再把脚沿水平方向移出相交点的支撑区；两次应有不同的接触结果。反向对照用本身下落、平台下降更快而从下侧相对穿过的角色。最后验证两条跨步轨迹：停在台上时用接近零的相对速度保持支撑；按键下穿时只忽略当前台以及它的形状组，等完全离开再恢复。若角色靠平台边落地的设计需要宽脚判据，要把不同足宽和平台宽度写进对照。

用 Python 3.12 的精确分数试件跑这组离线对照。两条路径的台面在竖直方向都是 0→6，脚都是 4→5；第一次命中时的相对横坐标是 3.2，落在宽 4 的平台上。第二次，宽 0.5 的平台向右移 5，脚的世界横坐标固定为 5；`t=0.8` 时脚相对左边缘是 1，错过顶面，而步末相对横坐标已是 0。只看步末会把后一次也判作落地。另跑了下侧上穿的对照，并分别用状态样本检查零相对法线速度的支撑和下穿后的恢复阈值；这些状态检查没有模拟整段按键轨迹。这些结果来自点足与有限线段的模型，没有调用引擎求解器。另用 Godot 4.7.2 做静态原生对照：相同角色从台底上行时穿过单向矩形台、撞到普通矩形台的底部；回落时单向台能接住角色。这只验证静态矩形场景中的方向，不据此宣称 Godot 的移动平台遵循上述模型。
