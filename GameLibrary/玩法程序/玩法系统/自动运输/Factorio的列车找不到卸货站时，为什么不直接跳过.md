# Factorio的列车找不到卸货站时，为什么不直接跳过

一列车已经装好货，准备前往按货物名称选出的卸货站。配置里却没有这个站。如果调度系统把这一项跳过，继续下一个任务，界面上的日程似乎还在推进，货物却没有送达；列车甚至可能又回到装货环节。

这篇案例面向实现自动运输、任务队列与条件调度的玩法程序员和系统策划。我们分析 Wube 在2023年末至2024年初为 Factorio 2.0介绍的开发设计，说明**生成了一个目标、能够前往目标和完成配送，不是同一件事**。本文不是当前补丁的设置教程，没有运行游戏或检查私有寻路源码。

## 条件决定临时任务，常规日程仍然存在

FFF #389 介绍的列车中断，在列车准备离开当前站时检查条件；条件成立，就把目标站和等待条件加入日程，作为临时停靠。离开相应临时站后，那一项才被移除。[1] 这里的中断不是操作系统中断，也不能理解为列车随时在轨道上被任意抢占。

一个直观用途是：平时按常规日程工作，燃料不足时临时去补给。货运也可以采用类似结构，让“车上有什么”决定临时配送目标，而不是为每一种货物单独维护一套完整路线。

FFF #395 进一步介绍 `Any item` 占位信号：逐项检查车上的物品，用第一个通过条件的物品替换目标名称及等待条件中的占位部分。[2] 因而，共用的规则可以生成某一辆列车当下要执行的具体任务。原文没有规定这里的物品枚举次序；下文只给一种货物，不讨论混装时谁先被选中。

## 名称能生成，不表示那个站已经存在

从条件和模板得到“铁板收货”，只能说明本次规则产生了这个目标名。它没有自动创建车站，也没有证明存在符合这个名称的可用目的地。

FFF #395 指出，旧的跳站行为会使已装货列车跳过缺失的卸货目标，再去装货。作者介绍的2.0设计将不存在的站点留在 `No path` 状态，而不是静默跳过。[2] 原文用1.1的跳站行为作对照，并不是说1.1已经具备这套通用货物中断。

这项取舍并没有让缺失的车站凭空出现。它改变的是失败怎样影响后续任务：**没有完成配送，就不把这次未执行的配送当成已经过去的一步。** 停下来仍需要玩家修正配置，不能把它称为自动修复或畅通保证。

## 用一辆载着40件铁板的车，看清哪里丢失了含义

下面是原创纸面例子，不是游戏运行记录或蓝图。常规任务只有“去装货”；列车当前已有40件铁板。我们不加入其他货物、燃料规则、车库规则或中断嵌套。

1. 离站决策看到铁板，按本例的名称模板生成临时任务“去铁板收货”。
2. 检查配置，发现没有这个目的地。
3. 如果把“目标找不到”处理成“删除当前任务、继续常规日程”，列车就会带着原来的40件铁板，再次进入装货意图。
4. 如果保留尚未完成的配送意图，并明确报告目标缺失，调度虽然暂停，记录仍表达真实情况：这批货还没有交出去。

两条处理路径的差别，不是最终日程索引有没有增加，而是这个增加代表了什么。错误路径把“无法开始”压成了“无需再做”，因此后续状态不再反映仍待配送的货物。

本例选择保留配送意图来解释历史设计的动机，没有规定引擎内部必须怎样保存数组、对象或错误码。项目也可以设计其他恢复办法，但应明确是谁决定取消配送、剩余货物怎样处理，以及恢复后从哪里继续，不能让一次查找失败偷偷替这些决定划勾。

## 缺站与暂时不接车，不能合成一个失败分支

同名站点不存在，和站点存在但被禁用，是两种不同输入。FFF #395 对所述2.0设计另作区分：禁用站按列车限额为0处理；新派往它的列车进入 `Destination full` 等待，而已经前往该站的列车会继续过去。[2]

可以把三个情境并列看：

| 发现问题时的情况 | 历史设计说明中的处理 |
|---|---|
| 目标名称根本不存在 | 不跳过目标，进入 No path |
| 准备前往一个已经禁用的站 | 进入 Destination full 等待 |
| 已在前往途中，目标站随后被禁用 | 继续前往原站 |

这张表限定为原文明确说明的情境，不是完整列车状态机。尤其不能把“缺站会进入 No path”反过来读成“所有 No path 都是名称缺失”，也不能把出发前的接车限制直接套到已经在途的车上。

对玩法实现而言，这提示我们同时记录**原因和阶段**。只留下一个“目标不可用”的布尔值，很容易让配置错误、暂时容量不足和途中发生的变化进入同一套后续处理。至于不同原因应等待、改派还是取消，仍然是具体游戏的规则。

## 怎样检查自己的条件调度，而不靠日程一直前进来判断成功

如果自己的游戏也会按货物、角色状态或任务参数生成目的地，可以先做一组很小的设计检查。这里给的是未执行的检查方向，不是 Factorio 的完整配置步骤：

- 固定货物与条件，只改变目标是否存在，核对系统有没有把缺失目标误记为完成。
- 保持同一个目标名称，改成“存在但暂不接收”，看错误原因是否仍与缺失配置分开。
- 分别在任务形成前和已经开始前往后改变接收状态，检查两种阶段是否需要不同政策。
- 同时观察常规任务、临时任务、货物和失败原因。即使队列索引前进，也要确认期望的交付效果真的发生。

这些检查不能替代实际寻路、站点容量与交通测试。保留未完成任务可能让车辆继续占据当前位置；增加等待状态也不会自动消除所有堵塞。若要改派到其他地方，必须另外定义那条路径的接收条件和货物处理，不能仅因原目标失败就宣布另一任务成功。

这个案例可迁移的认识，是让调度的推进条件与任务效果保持一致：一个名称解析结果只是意图；目标资格决定能否开始；完成条件决定什么时候能退出。把这三项分开，才能决定失败应该留在哪一步。
