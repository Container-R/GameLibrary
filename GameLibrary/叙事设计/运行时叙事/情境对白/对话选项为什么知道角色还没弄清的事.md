# 对话选项为什么知道角色还没弄清的事

站务员换了电车站台，世界模拟里，车确实会从西站台开。然而主角只见过旧告示，回去和站务员对话时，选项却突然冒出「问西站台怎么走」。另一名可操控角色连告示都没看过，切到他也有这句。再添加一个「去过车站」的开关治不了这个问题：剧情条件用了世界真相，界面却写成了角色在说自己知道的事。

这个问题的解法不是让游戏记录每一句台词。对会改变选项或角色反应的线索，写清**谁通过什么途径获得哪条信息、这条信息还能支持什么说法**。下面用一个非线性调查例讨论角色视角的对话，不要求旁白、导览地图或玩家百科必须遵循同样的视角。

## 先写清台词在主张什么

开的是哪个站台，是世界事实；「有人说电车从东边开」，则是某个角色收到过的一份说法。即使两者当前碰巧相等，也不要写到同一个布尔变量。作者可以先给每个有后果的选项填一行规则：

| 选项 | 谁可以这么说 | 对方怎样回应 |
| --- | --- | --- |
| 「请问现在从哪边上车？」 | 还没有可靠的新线索，也能询问。不把答案写进选项、预览或隐藏选项提示。 | 知情的站务员可以回答，只有实际传达才写入角色记录。 |
| 「我听说在东站台，是真的吗？」 | 发话人拿到一条来自他人的旧消息。 | 站务员可查证或拒答；被转述 ≠ 已得到可靠证明。 |
| 「我看的告示写着东站台。」 | 发话人真正看过旧版告示。 | 当前若已改站，可指出告示过时；说者不会预先知道新版内容。 |
| 「我看过新版，应该去西站台。」 | 发话人收到且能引用新版公告。 | 可核对新版，不把上一版的判断静默改成西。 |

在世界里改站，应该改变电车去哪儿，也可能改变已经知情的 NPC 怎样回答；不应该让不知情的人自动获得一条新的可选台词，更不能让旧记录突然变成新值。有的项目会让选项标题代表玩家的操作意图，不要求角色已经知道答案。那可以主动设计成「查问是否换站」；但 UI 的信息范围需清楚，尤其别用禁用选项的明文把答案先露出来。

《Elsinore》的 Connor Fallon 记录过从许多场景分支改用可携带的 Hearsay：主角见证事件获得信息，可以在不同时间呈交给其他角色，角色反应可以改变后续事件。[1] 团队在 AIIDE 的说明还把手写场景的触发条件与角色心理状态相连；在之后介绍正式游戏时，也提到「已经根本不适用的消息不再允许呈交」等收束规则。[2] 这给出了另一种可行政策：在作者明确知道说法不可能再成立时，限制某些呈交。上面的车站例特意保留「引用旧告示」作为可理解的追问，不代表该游戏采用相同规则。若要用世界真相直接移除选项，先确认玩家能否从选项突然消失推断尚未揭晓的变化。

## 把交付点写在内容里，而不是挂在场景开始上

选一次进入对白、打开告示、悬停回顾、将一句配音排到队列，只能说明准备呈现。假如玩家在透露站台之前就离开、字幕没有显示到关键句、配音被打断，就不应因为访问过该节点而给角色写入知识。inkle 的 Ink 允许把节点的访问次数用于条件，也能用专门变量判断角色是否得知某事；访问次数能满足「去过」，但它自己的用途不等于外部演出完成的保证。[3]

让作者指定一处能改变规则的**交付标记**，以及可用渠道：

1. 文字告示可以在包含站台的正文显示时交付；告示面板只打开了标题不算。对逐字呈现的内容，标记应在能传达完整线索的那部分。
2. 若配音或字幕任一足以传达，二者可发出同一标记。用「本次播放实例＋接收人＋标记」识别一次交付：同一段内容关闭再开，要发新的实例编号；预览或没启用的渠道无权交付。每个合法标记只提交一次；不能把字幕显示和配音结尾记成两个发现。
3. 跳过与无障碍是显式规则。可在跳过时交付一份可立即访问、内容等价的摘要，或保留可重访的资料入口；前者只有在游戏约定摘要就是获得线索的渠道时才记条目。不要靠实际听到声音作为唯一入口，也不要把内容画到屏幕上当作实测玩家理解。
4. 以作者可查的记录提交变更：发放对象、线索内容或编号、来源、版本、交付标记。有存档时把记录和防重复的标记一起保存；恢复未完成的演出可以重排，但不要把被取消、属于上一次播放或另一角色的回调当当前交付。回到更早的存档时，应以那份存档的事实、线索与已交付标记为准，不沿用另一时间线的队列。

一个合成回放用同一线索走了两条路：预览、聚焦旧话题、排队取消和重新进入都没有获得新站台；在有效演出里真正送出的字幕更新了记录，随后配音回调以及重新载入这份存档后的重投皆没有再更新。只开配音的另一条路径也能在标记到达时写入。测试的是规则和预期效果，不是证明玩家读懂或听懂了这条线索。

## 先判「能不能说」，再挑「现在说什么」

生成候选时，根据发话角色持有的线索和听话对象能否提供帮助来判断台词最低条件。用已知的内容过滤重复、已问过的选项或写成确认进度的另一句。然后**只在仍然合格的候选里**依当前地点、刚发生的事、玩家刚查看的旧记录排优先级；排名再高，也不能让不合格的句子出现。

Inkle 的 Jon Ingold 在《Heaven’s Vault》的制作笔记里区分必需条件、让问题多余的条件、以及近期想起什么决定的相关性。玩家翻看已经解锁的时间线条目，也能让角色随后聊起这件事。这里触发的是已知内容变得相关，不是玩家因为打开时间线又获得一份新知识；他把逐 NPC 实例化独立知识模型写成可探索方向，并非描述当时已经实装。[4]

有些对话从菜单显示到选择、再到实际播放之间隔着几帧或更久。提交前重新核对发话人、已选择的证据和必要对象仍适用。车站例在换人后即使点了缓存的旧告示选项，也不会替新人引用；在同一人手上，如果新版到了而旧版已从列表退下，要么刷新为仍合规选项，要么把「比较旧版」单独写成作者允许的操作。不要直接拿新的站台值悄悄填进旧按钮。对话可能因他人不愿应答或补充证据而中断，关键剧情要有中性询问、可重复查阅、等价摘要等替代入口。

## 用两次只改变一件事的回放找泄漏

先给关键线索做少量对照，不必为世界里所有角色和事实建一张全表。若候选另有近期话题、位置或随机排序，固定这些输入再比较；选项换了顺序不必然是知识泄漏：

- **固定同一份角色记录，改变隐藏真相。** 角色视角的台词和提示不应提前变成新的答案。真正有权回答的 NPC 在说出答案后，才通过清楚的交付点更新记录。
- **固定世界真相，改变谁收到过什么。** 亲眼读到、听同伴复述、看过面板标题后退出，应该能走向不同强度的说法。切换角色、解散再重开界面，检查角色身份没有被全局玩家档案遮盖。
- **固定实际听到的内容，交换事件顺序。** 重复字幕和语音回调、跳过、保存后重回、旧选项迟到都不应重复给线索，也不应把另一条演出的标记当成这条的。
- 记录「哪条条件没满足、哪份证据触发、消息来自谁、何时交付、为什么没有显示或为何退回」。同一个未知答案在剧情暗示、日志标题和禁用选项里也各查一次。[两组可复现对照](../../../../管理档案/实验/对白线索交付/README.md)用合成角色和车站数据核对这些边界，没有运行商业游戏或 Ink。

只有少数调查线索影响选择时，给它们定义来源、接收人和可用性就够了。要追踪每个人对每句传闻的相信程度、拒绝和再传播，就要为冲突与撤回补作者规则。一个以《Elsinore》为对象的独立简化研究尝试用动态认知逻辑管理角色信念，并未发现显著减轻其写作与调试复杂度。[5] 工具的首要目标是让设计师在测试轨迹上看得见「这句从哪儿来的」，而不是用更多状态遮住问题。
