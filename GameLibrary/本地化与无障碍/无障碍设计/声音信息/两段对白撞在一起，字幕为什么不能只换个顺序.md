# 两段对白撞在一起，字幕为什么不能只换个顺序

角色正解释怎么开门，无线电里另一位队员同时报出第二道操作。两个说话者都关系到下一步；字幕文件里也确实有两条。普通字号时刚好一人一行，大字号下无线电那句换成了两行。此时把晚到的字幕排在后面，虽然能避免屏上出现三行，却可能让玩家在无线电说完之后才知道是谁报了什么。

这是字幕编辑、音频和界面团队需要一起解决的排布问题。先区分**对白何时说、字幕至少显示多久、实际占多少行**，再判断是否有只改排布就能交付的解。

## 有两个有效时间段，不等于有地方放两条字幕

可用一种简单的交付表记录每条对白：说话者、音频使用的开始和结束、允许提前或延后出现的范围、需要的连续可见时间、译文，以及目标字体和区域下的行数。允许范围不能随意从字幕顺序推断；如果一句话暴露的操作或答案还不能告诉玩家，它不能只为腾位置抢先显示。说话者不清楚时，身份线索也要计入排版。例如文本加上「无线电」标签后，原先的一行就可能折成两行。

WebVTT 是时间文本格式，规范中有两个有效时段部分重叠的例子。[1] 它能记录同时有效的内容，却不能让游戏里的一处字幕区凭空多出空间，也不代表某个引擎使用 WebVTT。Xbox Accessibility Guideline 104 建议通常同时不超过两行、例外可三行，还要求考虑可调大字号和避免遮住重要界面。[2] 因此，可把「最多同时两行」定为项目的一个预算，在最大字号、目标语言以及相应场景里实际排一遍。两行预算不是所有游戏所有字幕区域都适用的定律。

## 先找一组同时满足的时刻

以下例子假定屏上只安排一个两行字幕区，所有时间按评审用的 0.1 秒档位表示。角色 A 的一句话必须从 0.0 秒开始显示到 2.2 秒，占一行。无线电 B 有 1.0、1.1、1.2 秒三个允许起点，每次连续显示 1.2 秒。假定它在这几种起点都不提前泄露信息，也不超出允许的声画对应；这些是给算例指定的条件，不是对真实语言读速的建议。

对每种组合，把显示时段画在同一条时间线上，检查同时可见的行数。一条在 2.2 秒结束、另一条恰在 2.2 秒开始，按结束时刻不再占位的约定，它们不会同占空间。

| 同一段内容的三种安排 | B 的允许起点 | 同时占用峰值 | 按两行预算可用 |
| --- | --- | ---: | ---: |
| 普通字号下 B 占一行 | 1.0 / 1.1 / 1.2 秒 | 2 行 | 3 种 |
| 大字号下 B 占两行 | 1.0 / 1.1 / 1.2 秒 | 3 行 | 0 种 |
| 重新安排对白 B 的播放，重新给出可显示时刻 | 2.2 / 2.3 秒 | 2 行 | 2 种 |

第二行不是字幕优先级排错了：三个允许起点都落在 A 还在屏上的时段。把 B 插到 2.2 秒才显示，已经跳出了原对白允许的范围；把 A 提前收走，又没有满足它应保留的时间。**没有可用排布时，改队列不能同时满足原条件。** 第三行的做法是真正推迟了声轨或对白事件，在剧情允许的情况下重新定时，并非只让字幕晚到。

## 把失败交给能改变条件的人

- **可以只改排布时，**先尝试在语音允许的范围内选另一开始时刻。若考虑分区，检查字幕和说话者的对应关系、两块区域会不会挡住信息、玩家是否必须同时扫两处。多开一个区域不自动降低阅读负担。
- **大字号或译文导致超量时，**让本地化和界面一起看有问题的字幕，尝试更合理的断句或简化，但不要丢关键信息、说话者线索，也不要悄悄缩小玩家选定的字号。连续显示若拆成多段，需要把每段的新时间和内容当作新的方案验收。
- **两段本就无法在同一时段读完时，**找对白或任务作者改两人的开口时机，或让玩家在允许的时候回看内容。回看可以保住持久信息，不能算作及时提供必须当场做决定的指令。

测试时保留出问题的语音事件、目标语言、字号、分辨率和安全区域，记录字幕实际开始与结束、换行和遮挡。用能代表最大字号及长译文的构建看实际界面，不只核检查表。固定算例过关，只证明列出的时间和行数能排出，不代表在其它设备或语言也能排出，更不能替代玩家能否理解并及时行动的测试。
