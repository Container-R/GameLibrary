# 窄文本框换行，为什么不能按字符数硬切

任务提示「拿取道具，继续」在窄屏上把逗号挤到了第二行。团队给换行加了一条“每行至多四个字符”的规则，结果没有修好中文，还让别的语言偶尔拆坏附标和表情。换行其实要问三件事：**哪里允许断、断开的单位完整吗、断成这一行以后有多宽？** 这三个答案不能用同一个字符数代替。

## 可以切开，不等于适合换行

以原始字符串的逻辑顺序为准。Unicode 的换行算法（UAX #14）辨认必须换行、可以换行和不应换行的位置；选哪一个可选位置，还要由排版器结合宽度决定。文字分段规则（UAX #29）给出扩展字素簇边界，也就是默认情况下不宜从中间拆开的文本单位。例如 `e` 加组合重音，或者由肤色修饰符和零宽连接符组成的一串表情，可能各自占多个码点，但在下表中分别是一个字素簇。字素簇不是固定宽度，也不等同于一个字形。不同语言和排版政策可以调整默认换行规则。[1][2][3]

下表把 ICU 76、Unicode 16.0 数据的两种分段实际跑了一遍。数字是 **UTF-16 码元之间的偏移**，包括首尾锚点；0 不是“可以先换一个空行”，结尾也不自动等于强制换行。

| 原文 | 字素边界 | 行边界 | 这个结果怎么用 |
| --- | --- | --- | --- |
| 拿取道具，继续 | 0, 1, 2, 3, 4, 5, 6, 7 | 0, 1, 2, 3, 5, 6, 7 | 偏移 4 在逗号**前**，虽是字素边界却不是此配置的软断点；若 5 放不下而 3 放得下，断在 3，得到「拿取道」和从「具，」开始的下一行。 |
| a👩🏽‍🔧b | 0, 1, 8, 9 | 0, 1, 8, 9 | 1 到 8 是整个表情；不能在 2 到 7 中挑一个看似能塞下的前缀。 |
| éclair（`e` 后接 U+0301） | 0, 2, 3, 4, 5, 6, 7 | 0, 7 | 正常模式不拆词；只有该组件允许紧急拆词时才考虑 2 等字素边界，绝不在 1 切。 |
| `A B C`（A 后是 NBSP） | 0, 1, 2, 3, 4, 5 | 0, 4, 5 | A 与 B 构成应一起保留的组；字素边界会出现在不换行空格两侧，但不要把它们都加入紧急断点。 |
| `A\r\nB` | 0, 1, 3, 4 | 0, 3, 4 | 3 是这组数据中的强制断点；CR 和 LF 之间不是两个各自的换行。 |

如果引擎的富文本 API 使用 UTF-8 字节、语言接口使用 Unicode 码点，别把表里的数字直接交给它。先解析控制标签，以参加排版的可见文本（包括占位对象等需要布局的内容）作为分段输入；维护它与原文、样式和对象的索引映射，写回样式或交互范围时才不会误切标签、码元或对象。双向文本也应按逻辑文本选断点，再交给排版器处理每行显示顺序，不要先构造一份“视觉顺序的字符串”再去截取。[4]

## 合法断点还要过宽度这一关

不妨把 `iiiiii` 和 `WWWWWW` 都塞进 54 像素宽的框。二者同为六个码点、六个字素。在当前环境，用 Pango 1.56.3、DejaVu Sans 16 像素量同一行的逻辑宽度，分别是 **24 和 96 像素**。这解释了为什么估一个“每行六个字符”的数字没有用。在此工具中，只按词断的模式会让后者整行保留并超宽；允许词内按字素退让时，后者得到两行 `WWW`。这个对照测的是不同排版策略的行结果，不是所有游戏都该拆词，也不代表实际墨迹边界或字形裁剪。[5][6]

把允许位置交给使用项目字体、回退、字号、语言方向和样式的排版器，量**候选行**的逻辑占宽。不要拿字符的独立宽度相加：字距调整、连写、字形替代和回退都可能改变结果。有的塑形数据在分行处需要重新计算：HarfBuzz 的 `UNSAFE_TO_BREAK` 告诉调用者在那个边界切分时不能直接复用整段的塑形结果，并不是 Unicode 在此禁止换行。最终以断开后的排版结果为准。[7]

## 没有一处既合规又放得下时，怎么收尾？

对多行提示，先在下一个强制换行之前，从合法候选中找能放下的行尾；如果可以由现有排版器完成，别在组件外另造一份按字符数截断的结果。若没有正向可用断点，先看是否允许给文字更多空间、改经过审校的短文案，或改为展开后读完整内容。允许紧急拆词的组件可单独尝试安全的字素边界，但仍要保留项目声明的不拆分组（例如 NBSP 连接的数量和单位、按键图标和说明）。候选都要重新量宽；不要假设把一个标志加到原字符串上就有空间。如果完整的一个簇或保留组比整个框还宽，不要继续往簇内部找位置，改走组件约定的扩容、可滚动或可展开路径。

单行非关键标签可以用能取到全文的省略模式；省略号也占宽，不能在塞满之后再追加。任务目标、关键状态和完整操作说明不应无替代地被隐藏。无论选哪种退让，确认排版循环每次都消费一个合法范围，或者明确退出到退让策略，避免对同一不可放入的分段不断重试。

验收时固定文本、字体链、字号、缩放与可用宽度，记录：分段索引单位与候选、实际采用的断点、每行逻辑宽度、触发了哪种退让。先在逗号断点两侧各试一个宽度，再加一个连整个表情都放不下的宽度，另测带 NBSP 和手动换行的提示。用目标引擎和设备字体最后核对样式、裁剪和获取全文的方式；本文探针没有渲染游戏界面，也没有检验目标字体能否显示该表情。
