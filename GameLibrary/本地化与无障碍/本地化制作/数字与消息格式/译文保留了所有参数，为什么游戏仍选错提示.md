# 译文保留了所有参数，为什么游戏仍选错提示

组队大厅里，一间房可以既是私密房，又只剩一个位置。游戏约定优先提示「仅邀请可加入」，避免玩家看到「还差一人」就以为能直接进房。翻译改了消息模板，两个参数名字都在，测试也没报错，但这个房间现在显示「还差一人」。问题不在变量丢失，而在模板把两个规则的优先级对调了。另一种故障恰恰相反：提示看着没变，运行时却已经报错。下面用 Unicode MessageFormat（MF2）把这两种错误分开验收。

## 看选择器顺序，不看文案行序

以下是合成的大厅模板。模式和空位档位都是字符串；这里的 `one` 是上游计算的档位，不是英语复数类别。双大括号内的 `PRIVATE` 等文字是调试用分支标签，正式模板会换成玩家看到的句子。

```text
.input {$mode :string}
.input {$slots :string}
.match $mode $slots
private * {{PRIVATE}}
* one {{ONE}}
* * {{DEFAULT}}
```

`.match` 的两个位置分别对应每条变体的第一、第二个键。星号在该位置兜底；它不要求值等于字面上的星号。当输入是 `private / one`，前两条都能匹配完整一行。规范按选择器先后比较候选：在第一个位置，`private` 比 `*` 更具体，因此选 `PRIVATE`；不必再看第二列。把三条变体从下往上排，优先级不变。[1]

再把选择器换成 `.match $slots $mode`，同时把每行两个键对调。各行仍表达原来的条件，但第一列现在是空位档位：`one *` 先于 `* private`，同一输入从 `PRIVATE` 变成 `ONE`。这不是译文调换短语词序，而是改变了两条可用分支的裁决顺序。若把原表的第一行改成 `private many`，`private / one` 也会选 `ONE`，但原因不同：第一行的第二个键不匹配，整行根本不是候选。前一列的精确匹配不能挽救后一列不匹配的行。

## 同一句兜底文案可能正常，也可能掩盖错误

在原模板里，`public / many` 合法且没有专门文案，走全星分支 `DEFAULT`，没有诊断。如果给了 `public` 却漏传 `slots`，仍会走 `DEFAULT`，但不能因此说数据没问题。漏传时若房间刚好是 `private`，第一行仍可由第二列的星号匹配，画面还是「仅邀请可加入」，照样有诊断。以下用 Node 24.22.3 的 `messageformat` 4.1.0 实跑，读取 `format(params, onError)` 的回调，不从日志猜结果。[2]

| 条件 | 分支标签与诊断 | 验收判断 |
| --- | --- | --- |
| `private / one`，无改动；或只倒排变体行 | `PRIVATE`，无 | 两者都保持重叠条件的优先级。 |
| `private / one`，选择器和键列同时交换 | `ONE`，无 | 参数没错绑，但违反「私密优先」。 |
| `public / many` | `DEFAULT`，无 | 合法的全星兜底。 |
| `public / 缺失` | `DEFAULT`，`unresolved-variable` | 同样的文案掩盖了缺参。 |
| `private / 缺失` | `PRIVATE`，`unresolved-variable` | 专门分支也可能掩盖缺参。 |

诊断不是所有库统一的字符串。本实现缺参报告 `unresolved-variable`；一个已成功解析但不提供选键能力的值，则可能报告 `bad-selector`。用已注册的试验性 `:datetime` 格式化有效日期做反例，日期能格式化但不能参与本例选键，程序报告 `bad-selector` 并仍选 `PRIVATE`；如果连该函数都没注册，例中还会观察到 `unknown-function`。这组反例是为了区分数据缺失、函数注册和选择能力，不是建议用日期实现空位条件。[1][2]

## 把分支身份和诊断一起写进验收

先让系统设计者明确重叠条件该给哪条提示，再用带稳定标签的验收模板运行项目实际的格式器。标签用来标记分支用途，不是翻译用词；调试时只替换各变体的文案，保留被测译文自己的选择器声明和键表，否则又测回了源模板。至少保留三种输入：两个条件同时为真、合法但只命中兜底、缺一个必需参数。每例同时核对分支及诊断；缺参例应在测试中验证诊断确实能传到接收方，而不是让有诊断的译文通过。

标签版只测试选择器和键表。替换文案也会移除该分支里的插值和格式表达式，所以要把相同输入再跑一次未经替换的译文，另行核对输出和诊断。例如标签版成功选中 `PRIVATE`，真实句子却可能因为漏传房名而报错。模板构造阶段抛出的语法或结构错误也要单独记为失败，它们不会经过 `format` 的回调。

如果分支与产品约定不符但没有诊断，先核对重叠条件、选择器次序和该行的全部键。如果分支看着对却有诊断，先定位调用方入参或格式函数。最后由语言审查核对胜出分支的实际句意：选择器测试不要求各语言共享相同句式，也不能证明「仅邀请」没有被翻反。这里的星号是**同一条消息**内部的分支兜底；目标语言没有交该消息键而加载了另一语言资源，是进入格式器之前的另一类检查。
