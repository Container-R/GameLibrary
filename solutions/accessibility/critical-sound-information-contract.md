# 对白字幕齐全仍不够：关键非语音声音的信息等价验收

## 问题与边界

“所有对白都有字幕”可以成立，而玩家仍不知道右后方的攻击即将发生、远处机关已经解锁，或音乐突然变调意味着场景进入危险阶段。缺口不是对白文本遗漏，而是声音承担的**决策信息**没有可用替代通道。

本文给音频、玩法、UX、本地化、叙事和QA一份可交接的合同：逐项定义声音实际传递什么、什么时候有用、替代呈现应保留多少信息，以及如何发现漏报、迟报、过度揭示和信息拥挤。重点是非语音声音；对白仍需完整处理，但不是本稿全部对象。

以下遭遇、字段、优先策略和验收流程均为原创设计提案。配套[假设遭遇与覆盖矩阵](../../research/case-notes/critical-sound-encounter.md)是静态内容分析，**不是游戏运行、听力模拟实验或玩家测试结果**。没有证明任何人群的胜率、可读性或满意度提升，也不提供平台认证保证。无障碍需要多种需求共同参与，不用“打开字幕”代表所有残障玩家。

## 1. 原始证据支持什么

- **XAG104 [S1]** 区分对白字幕和涵盖音频信息的captions，讨论重要非语音声音、来源方向、可配置呈现以及开场前可用的设置。这说明对白覆盖不能替代声音信息覆盖；它不替项目选择每个事件的具体文本和优先级。
- **XAG103 [S2]** 讨论跨感官传递关键信息，明确颜色不能单独承载信息，触觉也应配合另一种提示，因为设备可能不支持或玩家会关闭。多个视觉提示仍不是多个感官通道。
- **Game Accessibility Guidelines [S3]** 提出声音以外的重要信息渠道，并用静音首次体验作为发现遗漏的内部方法。本稿仅采纳它作为问题发现线索，不把静音测试等同聋人/重听玩家研究。
- **Naughty Dog的原始功能说明 [S4]** 展示了听力预设与可单独调整选项，以及HUD、字幕方向和振动等组合。这是2020年开发者发布的功能事实，不是本库运行观察或独立效果实验；不从该案例推出所有游戏都应复制同一套界面。

后续的“信息粒度”“相对时间窗口”“拥挤处理”和责任划分是本库原创工程推导，不是上述机构规定的统一算法。

## 2. 以信息单元为资产，而不是给每个音效贴一行字

先做一次由玩法与音频共同主持的声音审计。分析单位是“玩家应当能获得的一项信息”，不是WAV文件数、音频voice数或字幕行数。

例如十次脚步采样可以共同表示“有某个移动声源在右后方接近”，不需要十行重复文字；同一警报采样在两种上下文可能表示“马上爆炸”或“任务失败”，不能靠音频文件名自动确定意思。纯装饰声和决定成败的提示也不能只按响度分类。

每个信息单元至少交付：

| 合同项 | 需要回答的问题 | 常见错误 |
|---|---|---|
| 决策信息 | 事件发生、来源类别、动作阶段，哪些会改变玩家决策？ | 只写`alarm_03.wav`，没人知道警报的用途 |
| 重要性理由 | 不获知会漏目标、失去行动机会，还是只损失氛围？ | 把所有声音都标最高优先级 |
| 可知范围 | 谁可获得信息？来源何时能被辨认？是否被遮挡、剧情或玩法隐藏？ | 直接把引擎对象名输出成敌人真名 |
| 空间粒度 | 原提示传递左右、前后、上下、远近中的哪些信息？坐标参考是谁？ | 把模糊声源换成精确穿墙雷达 |
| 时间窗口 | 从何时可获知，到何时仍有行动价值？结束后是否还需确认？ | 伤害之后才出现“即将攻击” |
| 替代渠道 | 文本、图形、触觉或其他辅助分别承担哪些信息？ | 两个图标被当成对盲人也有冗余 |
| 并发/重复规则 | 与其他提示重叠时如何显示？能否合并？何时失效？ | 重要警告排在环境字幕长队后 |
| 内容交付 | 本地化键、上下文、短长形式、术语、不可透露字段 | 翻译只有“咔哒”，不知道是门锁确认 |
| 验收证据 | 用哪个场景、设置组合和观测证明可获得这项信息？ | 勾选“字幕已做”就关闭任务 |

可以用表格、资产标签或项目数据表维护，不要求安装新工具。自动检查只能发现缺字段/缺引用，不能证明内容合适或玩家理解。

## 3. “等价”不是照搬波形，也不是拒绝合理辅助

### 3.1 基础替代与额外辅助分开定义

基础替代力求让依赖不同通道的玩家获得足以作相同类型决策的信息；不是要求所有人接收逐比特相同信号。若玩家听到明确敌人类型、方向和接近趋势，只有“有声音”就丢失了关键内容。反过来，模糊的金属摩擦声未揭示身份时，字幕直接写“刺客甲正在你背后3.2米处拔刀”可能提前公开剧情/位置。

**额外辅助不是错误。** 游戏可以有明确说明的敌人探测、延长反应时间、方向引导等选项。它们应由设计团队主动定义并让玩家选择，而不是因为把内部对象字段接进字幕而意外出现。多人竞争中的披露规则需另做产品/公平性审查，本稿不宣称某种辅助天然公平或违规。

### 3.2 方向必须有参考系和可信度

约定箭头相对屏幕/相机、角色朝向还是世界方位。第三人称镜头转动时，两种方向并不相同；HUD和文字应共享合同，否则“右侧”与箭头可能互相矛盾。配套案例选择屏幕相对方向，仅为该例规则。

**空间信息还需要时间有效范围。** 离散脚步记录的是该次允许感知事件的粗粒度方向/位置快照，而不是连接隐藏实体的持续追踪器。提示保留期间，可按约定将同一已知快照重新投影到当前相机参考系；不能读取已经无声移动的实体位置刷新箭头。只有新的允许感知事件，或原声音确实持续提供的空间变化，才更新这类信息；连续探测也可作为明确披露的额外辅助另行设计。若原事件只给出方向扇区而没有距离，保存和重投影也必须保留这个不确定范围；可以随镜头旋转调整参考系，但不能用隐藏实体的精确世界坐标或镜头平移暗中补出距离。若产品不保留位置记忆，则结束时移除方向提示，不必强制做重投影。实现与QA应分别检查“镜头转动”和“无新声音但实体移动”，不能把两者当成同一种更新。

在回声、遮挡、非空间化音乐或无线电中，不一定能可靠定位实体。原本只表达“附近不明声音”的提示，不应自动赋予精确方位。保留不确定性可用“附近”“方向不明”或不显示方向；不能为了填满字段编造精度。

### 3.3 距离不等于音量

响度可能来自混音、音色、遮挡或戏剧强调，不能自动按音量阈值生成米数。仅当设计有意通过声音表达远近/接近趋势，才为替代渠道定义对应粒度，例如“远处→正在接近”，并由音频与设计联合审查。精确距离、倒计时、敌人数量都需要显式批准的信息来源。

### 3.4 时间是信息的一部分

为提示定义`最早合理披露时点`、`可行动截止条件`和`事后保留用途`。用相对游戏事件约束，而不是给所有游戏规定同一个毫秒预算。攻击预告必须在仍能反应时到达；门锁成功确认可以在操作完成后保留；未知台词身份不能早于故事揭示时点。

对短反应窗口，长句字幕即使及时出现也可能来不及读。可选方案包括已学习的简短图形配合简洁文字、可选触觉提醒、重复确认或显式辅助选项调整时间窗口；不能声称“改成三个字”已证明可读。原有机制若无法在适当通道表达，需修改机制或提供辅助，不应把不可读压力全交给本地化。

## 4. 运行时接入：从被允许感知的游戏事件生成提示

推荐由语义化的声音/玩法提示描述驱动各通道，而不是对混音输出做关键词猜测。描述中不直接暴露隐藏对象信息；生成之前先确定该玩家在该场景允许知道的类别与空间粒度。这个建议不是要求另建一套庞大事件框架。

要避免两个相反错误：

- **字幕跟着实际播放voice生灭**：音频被虚拟化、设备静音或混音通道关闭时，重要提示也消失。能否呈现替代信息应依照语义/感知合同，而非扬声器是否真的发出声音。
- **字幕跟着全球所有音频事件走**：把远处、未发现或本不应传达给该玩家的事件都显示出来。是否符合本地玩家感知范围仍需判断，不能绕过遮挡、距离和游戏披露规则。

这两个合同可能不同：静音是用户偏好，不应自动把所有caption关闭；但世界中隔墙且设计上不可知的事件也不因“caption开启”而无条件公开。必要时使用专门为可访问性设计、可解释的感知规则，而不是盲目复用某个音量阈值。

在开发版本记录：提示语义ID、所属玩家、可知字段、发出时点、呈现开始/结束、所用渠道、被合并/取消/替换的理由。不要记录无关聊天内容或玩家隐私。此日志用于区分“内容没配置”“路由没到”“已到但呈现太晚”；**日志到达仍不证明被人看到或理解**。

## 5. 并发与拥挤：保住决策，不把一切堆进字幕队列

以下是需要项目明确、通过场景验收的选择，而不是普适算法：

- 把需要即时反应的警告和可稍后阅读的叙事/背景信息分配不同呈现区域或表达方式；不要用单一FIFO让紧急提示等待长对白。
- 合并语义相同的重复环境声，但不要把来自相反方向、不同危险阶段的声音合并为失真信息。例如“右侧接近”和“左侧接近”不能合成一个右箭头。
- 为每项提示规定结束/取消条件。攻击被取消后继续显示“即将攻击”是错误信息；已发生伤害后才补播完整预告也不能算及时覆盖。
- 背景叙事可以使用回顾记录，但事后日志不能替代当时的行动窗口。可回顾也不代表允许提前显示未听到/未揭示的后文。
- 重要性不是响度排序，也不只是战斗覆盖剧情。遇到必须同时理解的内容，应减少场景信息负荷、改变时机或提供可选减速/暂停，而不是静默丢弃其中一项。
- 允许用户调整细节和类别；对预设、关闭效果与可重新开启的入口给出清晰说明。用户主动关闭某通道不等于产品可强行覆盖其偏好，也不保证其剩余组合能覆盖全部信息；应明确支持范围，而非宣称任何设置组合都无障碍。

## 6. 渠道和设置：提供选择，不指定唯一“正确玩家”

| 渠道 | 适合承担什么 | 不能独自承诺什么 |
|---|---|---|
| Caption文本 | 事件含义、说话者、必要上下文和不确定性 | 短窗口下无需阅读时间；盲人一定可获得 |
| 图形/空间指示 | 快速来源方向、已学习的危险类别/阶段 | 图标天然直观；仅靠颜色就能区分；多个视觉表达覆盖视觉障碍 |
| 触觉 | 吸引注意、区分少量已学习提示；可选补充 | 所有设备存在或所有人能感知；自动表达完整语义或空间位置 |
| 辅助音频/语音 | 为依赖听觉的玩家表达视觉信息或朗读内容 | 为无法依赖听觉的人解决原有声音缺口 |
| 机制辅助 | 为额外需求调整信息或行动条件 | 与基础等价替代完全相同；未经说明可无限透露隐藏信息 |

在开场关键内容前提供可用设置；支持类别开关、文字大小/背景/位置等可配置项，并检查它们与HUD缩放、本地化和剧情场景共同工作。[S1] 预设是起点，允许单项覆盖，不把“听力预设”当成所有听力需求的唯一答案。[S4] 触觉关闭或设备不支持时，不应让本来宣称可通过其他通道获得的关键提示悄悄失效。[S2]

聋盲、多重需求及不同辅助技术可能需要额外交互方式；本文这组字幕/图形/触觉提案不构成全部覆盖承诺。应与有相关需求的玩家和专业人员共同验收，不能用作者自己静音玩一遍代替。

## 7. 跨岗位接收标准

| 负责环节 | 必须交付的判断/材料 | 不允许以什么代替 |
|---|---|---|
| 玩法/关卡设计 | 哪项信息改变决策、行动窗口、支持的辅助、并发场景 | “音效已经做了” |
| 音频设计 | 声音实际传递的类别、阶段、方向/远近可信度、触发与感知范围 | 文件名或响度表自动当语义 |
| 叙事 | 身份/关系/危险信息何时可揭示，模糊来源如何表述 | 内部角色名直接输出 |
| UX与可访问性 | 渠道组合、图形说明、配置与预览、最大文本布局 | “加了一个图标” |
| 本地化 | 上下文、术语、语序/方向表达、短长文本和歧义反馈 | 只交无上下文音译词 |
| 程序/技术音频 | 语义路由、玩家感知过滤、日志、可复现场景入口 | 回调执行次数当内容验收 |
| QA/用户研究 | 场景矩阵、遗漏/迟报/过度披露记录；真实参与者测试的适当方法 | 字段完整或静音自测当用户效果证明 |

接收时至少同时查看**一个普通场景和一个并发/边界场景**：屏外声源、相机转动、同类多来源、取消攻击、无线电/未知说话者、文本扩展、最大字体、触觉关闭。这个范围是建议的风险起点，不是固定认证清单。

## 8. 从静态覆盖到真实验收：不得跳级

1. **静态信息审计（本稿实际做了）**：对原创假设遭遇逐项比对白字幕方案与信息需求，指出具体缺口，检查提案没有凭空揭露身份/精确坐标。它证明表述中的缺项，不证明运行行为。
2. **集成观测（未做）**：在实际游戏内记录声音/提示语义时点与呈现，验证窗口、方向参考、感知范围、取消和设置组合；保存版本、关卡、语言与录屏定位。
3. **呈现评审（未做）**：在支持的屏幕、字体、缩放和背景上检查遮挡/可读性、提示相互竞争；文字/图形/触觉的含义不能只由实现者自证。
4. **适当玩家研究（未做）**：与相关需求的参与者检验是否能获得并理解信息、是否负担过高，结合定性观察与任务目标；不预设提升百分比，不把少量样本外推全部人群。

发布当前条目为source-backed；后续某个游戏内测试通过也只提升相应情境的证据，不把全篇自动改成“所有玩家已验证”。
