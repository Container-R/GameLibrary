# 实时特效美术：把视觉表现交接为有明确含义的游戏信号

## 定位与责任边界

实时特效美术不仅制作火焰、光轨或爆炸，也参与决定玩家在动作发生时能看见什么信号：来源、方向、范围、状态变化，以及哪些信息应优先引起注意。本文聚焦有玩法含义的特效；环境氛围和纯演出效果也有价值，但不能把它们的审美验收直接当作战斗信息的验收。

**效果被画出来、画面符合作者意图、信息与游戏状态一致、玩家实际理解了它，是不同的证据。** 单独播放时很醒目，不能证明复杂场景里仍然可辨认；一段演示视频也不能证明玩家及时作出了正确反应。

岗位名称不自动授予碰撞、伤害时序、渲染底层或发布权限。特效师可能编写材质、制作原型或兼任 TA，但是否能改动共用 shader、状态接口与技能规则，必须按具体项目确认。本文不规定通用组织结构或引擎工具链。

## 工作案例与来源支持范围

- **BNS，《Tales of Arise》，2021。** 小岛武史介绍节奏调整，并与 shader 和程序人员合作，在华丽表现与不妨碍游戏之间处理取舍，使用强调轮廓的风格化表现等方法。[S1] 这是制作经历，不是已公开的玩家实验或完整实现说明。
- **Riot，《League of Legends》，2021。** 开发文章强调信息层级；其中可读到的具体修改是山海绘卷烬的大招边界在展开阶段淡出、不易看见，随后改为保持可见。[S2] 这是来源文字报告的历史修改，不是本库逐帧检查或当前版本行为验证。
- **Riot，《VALORANT》，2020。** Brandon Wang 描述该项目中特效创作与系统性渲染问题的协作界面，并区分烟雾的玩法边界和高画质下的装饰性细节。[S3] 不能由此推出所有项目都采用同一烟雾实现，或所有画质档位天然具有相同可读性。

**原创推论：**验收不能只看效果最强烈的一帧。若关键线索在需要决策的阶段消失，后面的华丽峰值不补回那段信息；但要认定它实际影响玩家决策，仍需相应观察，而不是凭作者直觉补上结论。

## 常见任务与交付物

以下接口为原创建议，未在团队实施，不是上述工作室的内部模板。

| 输入与任务 | 建议交付 | 接收方与边界 |
|---|---|---|
| 技能、状态或反馈需求 | 本效果表达什么、给谁看、在哪个阶段有意义；尚未确定的规则单列 | 设计/玩法负责人确认含义；效果不能自行定义权威伤害范围 |
| 视觉方向和角色主题 | 主线索、辅助装饰、形状与节奏层级、原型及候选身份 | 美术审核意图；越亮越大不必然越有用 |
| 运行时接入 | 状态到表现的对应关系、触发与结束条件、必要上下文 | 程序与集成人员确认映射；成功触发不等于状态语义正确 |
| 实际场景审查 | 指定镜头、背景、重叠效果和画质下的观察及缺口 | 特效、设计、QA 对照目标；专家审查不是玩家理解率 |
| 变体、优化或修复 | 哪些信号保留、哪些装饰变化、受影响情境及复查依据 | TA/图形/玩法按原因接收；性能改善不能抵消必要信息丢失 |

## 原创有限工作表：地面预警到底在说什么？

**完全假设、尚未实现或测试：**某地面预警在展开时边界短暂消失，装饰粒子仍在。此例用于组织接收问题，不复现烬的实现，也不声称存在玩家失误。

| 记录层 | 本例要回答的问题 | 不能越界的结论 |
|---|---|---|
| 实际游戏状态 | 当前是前摇、有效危险还是结束残留？范围和状态时间由哪份规则/运行记录确认？ | 不能用特效圆环的大小反推权威判定 |
| 作者意图 | 边界表示未来危险区域、当前危险区域还是纯装饰？哪个阶段必须看见？ | 不能默认所有圆形都表示可躲避范围 |
| 实际显示 | 指定候选、镜头、画质及背景中，相关阶段显示了什么？有无状态与表现错位？ | 截图只能支持其捕获时刻，不能证明整段时序正确 |
| 情境审查 | 同时出现其他效果时，关键边界是否仍可辨认，是否抢占更重要信号？ | 审核者“看得见”不是目标玩家“能理解并响应” |
| 玩家理解 | 若项目需要这一结论，安排什么真实任务、参与者和观察方法？哪些提示会改变结果？ | 没执行研究时填未验证，不填写假想成功率 |
| 修改接收 | 是调整表现，检查状态映射，处理系统性渲染问题，还是重新定义线索含义？ | 没定位原因前不能把问题全部分配给特效作者 |

### 接收与修改顺序

1. **先确定信息契约。** 设计和玩法责任人确认边界表达的含义及必要阶段；VFX 提出如何呈现，而不是用一张效果图代替规则约定。
2. **配对实际状态和显示。** 保存同一候选、同一情境下的对应证据。若只有独立效果预览，就明确尚未检查游戏内映射。
3. **检查需要信息的阶段。** 至少覆盖本例提出问题的展开阶段，并声明其他阶段是否检查；不能只提供最亮的峰值画面。
4. **分开局部和情境判断。** 独立播放符合意图后，再看声明的背景、镜头和重叠组合。选择有限代表场景时记录选择依据及未覆盖项，不声称穷举所有战斗。
5. **按变化层接收问题。** 表现调整由 VFX 接续；状态或触发差异由玩法/集成接续；若证据指向系统性渲染，再交图形或 TA。人员可兼任，但判断层次仍需保留。
6. **复查含义而非只复查外观。** 保留边界后可能增加遮挡或争夺注意，必须看受影响情境。减少装饰也应确认没有误删实际承载信息的部分。

工作表没有给出通用亮度、颜色、时间容差或辨识率阈值。这些需要产品规则、目标情境和适当证据。它也不替代可访问性检查；颜色、闪烁或其他感知风险不能因“专家觉得清楚”而被视为已解决。

## 核心技术、工具与典型难题

工作涉及形状、明暗、色彩、运动与节奏，以及将它们绑定到运行状态的能力。特效编辑器、材质工具、状态记录和可回看捕获分别帮助创作、接入和定位问题；工具名称不能证明表达有效。也不应把某个项目的 shader 分工写成全行业权限表。

典型难题不是只有粒子太多：提示结束与状态结束不同步；装饰盖过重要反馈；新皮肤改变既有形状含义；降级保留了华丽层却移除了主线索。每项都需要先确定观察对象和缺失信息，再决定是设计、资产、接入、渲染还是研究问题。

## 职业交叉关系与后续研究

- [技术美术](../technical-art/technical-artist.md)：支持可重复的资产与工具流程，不替代具体信号意图的确认。
- [图形与渲染程序](../../管理档案/历史正文/roles/rendering/graphics-programmer.md)：接收系统性绘制问题；不能仅凭一个效果不清楚就要求改渲染器。
- [玩法程序](../programming/gameplay-programmer.md)：提供状态与行为契约；特效可见不证明判定正确。
- [试玩干预与证据边界](../../管理档案/历史正文/solutions/production/playtest-intervention-evidence.md)：若开展玩家理解研究，应保留提示和干预，不能把被解释后的识别当成自发理解。

下一步有价值的验证是选择获准的真实或原创效果，明确一个信号契约和有限情境，再分别取得运行对应、视觉审查及必要的玩家研究证据。本档案没有这些运行结果，不为凑测试数量建立无视觉判据的粒子模型。它只补充一个 VFX 岗位接口，不宣称完成全学科矩阵。
