# 游戏动画师：从动作表演到运行时角色组合的验收交接

## 定位与责任边界

本档案聚焦游戏中的 3D 角色动画制作：让动作表达角色、意图和游戏情境，并与实际使用它的角色及运行系统衔接。**动作在制作环境中成立，不等于它在所有身体比例、服装、头发和运行时组合中都已验收。** 动画师的工作不应被简化成“交出一段能播放的文件”；反过来，也不能把所有角色表现问题都归给动画师。

这里的游戏动画师、3D Animator 是研究入口，不是跨工作室统一编制。Technical Animator 通常涉及相关技术支持，但不是本文岗位的自动别名；绑定、蒙皮、工具、程序化动画及运行时接入可能由不同人员承担。小团队可以兼任，仍需分别说明作者、修改者和接收者。谁有权修改共用骨架或批准表演方向，不能只凭职位名称推断。

## 工作案例与证据

**具体项目经历。** Bandai Namco Studios 于 2021-12-03 发布的岗位介绍中，吉武敬一朗谈到《偶像大师 Million Live! Theater Days》：基于动捕的动画需要针对角色比例人工调整姿势，进入引擎后也继续调整，尽量避免服装和头发的表现破绽。[S1] 这说明动画制作可能延伸到集成后的角色表现；来源没有披露具体绑定算法、故障率或完整组合覆盖，不能据此声称问题已被彻底消除。

**协作者职责样本。** Ubisoft Montréal 的 March of Giants 技术动画岗位描述涉及与动画师、绑定人员合作，技术检查、引擎集成和动画/物理原型。[S2] BNS 的招聘职责页则分别描述动画表演、过场制作及技术动画的绑定与制作环境支持。[S3] 两者说明可能的分工，不能合成一套两家公司共同执行的流程，也不证明真实项目每天按招聘文案运作。

以下方法是**原创工程建议，未在团队或角色资产上执行**。它借助上述责任边界提出可操作的接收问题，不是工作室内部验收规范。

## 常见任务与交付物

| 输入与任务 | 动画侧应推动形成的交付物 | 接收者与判断边界 |
|---|---|---|
| 角色设定、动作目的和游戏情境 | 表演目标、关键姿势与节奏说明、预期观察角度；争议点保留待定 | 动画指导、设计确认表达目标；不由工具默认值替代表演判断 |
| 身体比例、模型与绑定条件 | 可供制作的角色版本、动作需要的控制能力、无法表达的姿势记录 | 绑定/模型负责人评估支持条件；动画师不必独自修复所有变形 |
| 动作制作或动捕编辑 | 源动作修订、参考表现、关键时间区间和已知限制 | 技术动画/集成人员确认消费对象；动捕真实不等于风格化角色表现合适 |
| 进入角色和运行环境 | 指定身体、服装、头发、绑定、动作及播放上下文的观察记录 | 动画、技术动画、模型、程序共同定位变化；导入成功不是表现验收 |
| 发现差异并修正 | 原意、观察差异、修改对象、影响组合与复查结果分别留存 | 对应专业接收问题；不能以一个局部修复隐式批准共用资源变化 |

源修订和导入身份的记录方法复用[技术美术档案](../technical-art/technical-artist.md)，不再复制整套资产管线清单。本文新增的是：**哪种表现被认可、在哪些组合中检查过，以及一个修正会不会改变其他组合的表现。**

## 原创有限工作表：抬臂动作与袖口

**完全假设，尚未制作或测试：**角色抬臂动作在制作环境的基础身体上看起来符合意图；进入游戏后，一种服装的袖口穿入躯干。观察本身不能证明是动画姿势、蒙皮、绑定、导入、程序化处理或物理造成的。

| 要记录的对象 | 本例需要填写的内容 | 可以支持的判断 |
|---|---|---|
| 表演意图 | 抬臂用于向同伴示意；保留角色姿态和可辨识轮廓；由指定表演审核者确认 | 后续“修复”不能只消除穿插，却无说明地破坏动作意图 |
| 源表现基线 | 源动作及角色/绑定修订、出现问题的时间区间、制作预览上下文 | 能回看相同动作；预览不是所有运行时条件的替身 |
| 目标组合 | 实际身体、服装、头发、蒙皮/绑定版本、动作、导入设置及运行时播放条件 | 避免把不同组合的结果混成“这段动画没问题” |
| 配对观察 | 同一相关姿势在源端与目标端的观察；标明视角、时间定位和不同条件 | 缩小变化发生的位置；配对不自动证明因果 |
| 当前缺口 | 哪些组合未检查，是否有混合、程序化处理或其他运行因素尚未隔离 | “尚未排除”不等于已认定根因 |
| 修改与复查范围 | 拟改动作、绑定/蒙皮或运行设置中的哪一项；谁接收；受影响的共用对象 | 避免通过局部补偿掩盖输入或系统问题，并明确需要重新看的组合 |

### 有区分力的接收顺序

1. **固定观察对象。** 先确认失败组合及可回看的时间区间；如果问题尚不能定位，就保留待诊断，而非立即重做整段动作。
2. **核对源端与目标端。** 若源端同样存在不符合意图的姿势，先由动画侧判断；若只有目标组合出现差异，仍需技术侧检查实际差别，不能直接认定导入器出错。
3. **按证据交给合适接收者。** 表演改动交动画审核；变形支持问题交绑定/蒙皮负责人；播放或运行处理差异交集成/程序负责人。此分派是假设项目约定，不是行业固定权限。
4. **显式选择取舍。** 若技术限制要求调整姿势、服装或使用范围，记录原意损失和决定者；不要把“看不到穿插”当作唯一合格标准。
5. **复查共享影响。** 共用动作或绑定修改后，针对明确的受影响组合复查，保留未覆盖范围。一个服装修好，不证明其他服装、身体或镜头都保持正确。

这不是穷举所有角色组合的保证。先按项目风险选有限集合，例如实际出现问题的组合与受同一修改影响的代表组合；选择依据和遗漏范围必须可见。本文没有证明某种采样策略足够，也没有提供通用穿插容差或帧数阈值。

## 核心技术、工具和典型工程难题

需要理解姿势、节奏、角色比例与表演，同时能与绑定、蒙皮、导入和运行时播放责任人讨论具体条件。DCC 预览、曲线编辑、版本对照和引擎内检查分别回答不同问题；软件品牌或“播放成功”不构成整体质量证据。

工具应帮助定位同一动作、同一角色组合和相关时间区间，而非只生成更多预览视频。运行时的混合或程序化处理可能使最终姿态不同于单独片段，但是否实际发生、由哪个环节造成，仍需具体证据。没有视觉观察的骨骼数值测试，也不能单独认证轮廓、角色感或服装表现。

### 曲线交接例：片段减速时，为什么只改关键帧时间还不够？

动画侧先要说明“减速”保留什么。以下只讨论**重写单个 glTF 平移 CUBICSPLINE 采样器的存储数据**：关键值不变，所有时间间隔乘同一个正数 s，并希望相同归一化进度的平移值不变。它不是对所有 DCC 曲线的通用规则，也不是完整角色姿态保证。

glTF 的该模式为每个关键帧存储入切线、关键值和出切线；段内求值会把切线乘以段时长。[S4] 记两端关键值为 v₀、v₁，起点出切线为 b₀、终点入切线为 a₁，段时长为 Δt，归一化进度为 u，则 Hermite 形式为：

`v(u) = h00(u)v₀ + h10(u)Δt b₀ + h01(u)v₁ + h11(u)Δt a₁`

其中 `h00=2u³−3u²+1`、`h10=u³−2u²+u`、`h01=−2u³+3u²`、`h11=u³−u²`。同一 u 下基函数不变，所以把 Δt 改成 sΔt 时，将相应入／出切线除以 s，才能保持原来的两个切线乘积。这是规范公式的代数推论，不是已实现的重定时工具。

**原创手算反例：** 只取平移 x 分量，另外两分量及其切线均为零。原关键时间为 0、1 秒，x 为 0、1，b₀=2，a₁=0。在 u=1/2 时：

- 原曲线：`1/2 + (1/8)×1×2 = 0.75`。
- 结束时间改为 2 秒，切线不变：`1/2 + (1/8)×2×2 = 1`。
- 同样改为 2 秒，同时 b₀ 除以 2：`1/2 + (1/8)×2×1 = 0.75`。

三者端点相同，中间值却不同；比较的是同一**归一化进度**，原片段时间为 0.5 秒，重定时片段为 1 秒，并非同一绝对时间的三次测量。因此“关键姿势没改”不足以说明只是变慢。动画与技术动画／工具接收者应先约定保留平移曲线还是重新设计缓入缓出，再选择数据变换；动画师不必独自实现导入器。

如果只是让运行时播放时钟走得更慢而不改资产时间，这属于另一条路径，不应再按本例缩放存储切线。上述理想实数推导也没有证明 float32 编码可表示、结果有限、时间仍严格递增，或时间 accessor 的 min/max 已正确更新；这些仍是资产处理要检查的条件。这里没有生成或播放资产，不覆盖旋转、非线性变速、分段不同倍率、事件、根运动消费、混合或完整角色表现。

## 职业交叉关系与后续研究

- [技术美术](../technical-art/technical-artist.md)：提供可重复的资产与技术支持；本文关注动作意图和具体角色组合的接收，不替代其管线规范。
- [玩法程序](../programming/gameplay-programmer.md)：连接规则与运行状态；角色动作表现正确不证明玩法规则正确，反之亦然。
- [原地转身脚滑](../../solutions/animation/turn-in-place-foot-sliding.md)：包含根运动与足底接触分析，以及有限根运动/LookAt 引擎观察；不能用那些观察证明本例的袖口表现或服装系统已验证。
- [游戏 QA](../qa/game-quality-assurance.md)：帮助保留复现、覆盖与未决风险；艺术意图仍需指定的专业审核者判断。

后续应选择获准的真实角色或原创资产，建立一组可回看的源端/运行端组合，再决定是否需要姿势、变形或运行时专项研究。当前未建立该资产或视觉判据，不以虚构测试替代。此档案只补充 ANIM 的一个岗位接口，全学科岗位矩阵仍未完成。
