# 游戏 UI 美术：组合状态如何分配图形通道

## 定位与责任边界

本档案聚焦一项工作：**在受限的视觉风格中，为同一控件可能同时表达的含义分配图形语言，并把组合与图层作用范围交给实现者。** 交付物不只是单独看起来完整的图标，也包括图标、文字、选择提示和状态覆盖组合后，各自仍要表达什么。

UI 美术可以参与概念、设计、实现协作及迭代，不是必须等 UX 全部定稿后才上色。岗位也不自动拥有玩法规则、输入焦点或可访问性验收权。团队可以兼任职责，但需分别回答“是什么意思”“如何画出来”“运行时是否对应实际状态”“用户能否理解”。

## 公开工作样本

- **PlatinumGames，Hisayoshi Kijima，2017-08-25。** 《UI Design in NieR:Automata》的作者以 UI/机甲设计师身份说明设计、数据交接和游戏内迭代；受限配色下用字重、明暗区分数值，芯片类别则增加颜色差异。[S1] 这些是该项目的制作选择，不证明某种配色普遍更易读。
- **Bandai Namco Studios，铃木佑梨。** 《Tales of Arise》段落说明较克制的基础 UI 与情境强调，以及繁忙战斗画面和语言布局带来的考虑。[S2] 此来源已用于本库 UX 档案，这里复用其视觉表现段落，不计作新发现或新的独立证据。

S2 标题日期为 2021-11-15，页尾另标截至 2023-12 的信息及 2024 年 4 月工作安排提示，不能合成为新的发布日期。以下方案不是两家工作室的内部表格，没有分析其图片或认定其产品存在组合状态缺陷。

## 原创交付单元：先分含义，再分图形通道

**完全假设，未制作或测试：**装备列表的一行含图标、名称和比较数值；项目允许查看暂不可装备的物品，所以“已选中”“当前不可装备”“比较数值上升”可能同时成立。

可用性不是可选择性：不能从一层灰色推导该行禁止选择。选中也不必然等于键盘/手柄焦点所在；项目若区分二者，必须另行定义其表现和更新来源。下表先讨论选择，不以画出的边框证明焦点已取得。

| 独立含义 | 本例候选图形通道 | 与程序约定的作用范围 |
|---|---|---|
| 物品身份 | 图标轮廓、名称及类别标记 | 身份层，不承担“能否装备”的唯一说明 |
| 当前选择 | 行外侧标记或独立边框 | 选择层；是否独立于内容淡化须明确 |
| 当前不可装备 | 原因文字或状态标记，可附加内容层弱化 | 指明影响哪些内容；不能默认整行及所有子层一起降透明度 |
| 比较数值变化 | 数字、正负号或方向标记，可辅以明暗/颜色 | 比较层；说明比较基准，以及上升是否真的代表更有利 |
| 装饰 | 纹理、光泽等非语义表面处理 | 装饰层；不能擅自承担唯一状态信息或覆盖必要标记 |

这些是候选而非通用正确答案。形状、位置、字重、颜色、明暗和动态强调都是可分配的资源，不能因为多用几种便宣称可访问。若只能用同一种变暗同时表示“未选中”和“不可装备”，应先暴露含义冲突，而非让程序猜优先级。

## 组合表比孤立状态图多回答什么

只交一张选中图和一张不可用图，没有回答两者同时发生时怎样组合。下面三行是拟议接收问题，不是已通过的检查：

| 必需组合 | 本例提出的组合政策 | 要交给实现者的问题 |
|---|---|---|
| 已选中＋不可装备 | 保留选择标记，同时显示不可装备原因；局部内容可弱化 | 淡化作用于内容层还是整行祖先？会不会连选择标记一起改变？ |
| 已选中＋比较数值上升 | 选择标记与比较提示并存，不用同一亮度变化代替两者 | 数字/方向标记是否来自当前比较基准，而非选中动画？ |
| 已选中＋不可装备＋数值上升 | 三种信息仍有各自位置；数值上升不取消不可装备说明 | 空间不足时先返回布局/优先级问题，不静默隐藏其中一种含义 |

本例选择“不互相替代”，不意味着所有游戏都必须如此。如果设计有意隐藏不相关比较，需把隐藏条件写成业务决定，而不是美术效果叠加后的偶然结果。

### 图层范围是制作接口，不是画面保证

UI 美术可交付带图层标注的样稿、切图/矢量资源和组合说明；UI 程序需要确认实际组件中的透明度、着色、裁剪与装饰效果作用于哪里。这里的“层”是责任划分，不规定一定对应独立节点或某种渲染架构。

例如，若实现者把不可装备的淡化放在整行祖先上，即使选择边框的原始资源未变，最终组合也可能改变。应先检查作用范围，而不是直接重画图标或擅自让物品不能选择。这只是待验证的集成风险，没有在来源游戏或本库界面中观察到。

接收分两层：美术样稿是否表达了约定组合；实际候选是否按同一图层政策呈现。二者都通过，也不能替代真实焦点/设备操作、翻译布局和玩家理解的检查。静态对照只帮助发现需要提问的冲突，不能建立误读率或因果收益。

## 典型任务、取舍与后续工作

此工作涉及视觉层级、字体/图标与布局、受限风格的一致性、资产拆分及实际组合沟通。工具可以是设计软件、资源导出流程或引擎 UI 编辑器；使用哪个软件不是验收标准。

扩大视觉词汇会增加制作和维护成本；反复使用同一通道则可能让多个含义无法区分。来源不提供最优通道数量或可读性阈值。下一步若获准，应只为上述三种必要组合制作候选，确认真实业务状态和图层范围，再分别安排艺术、实现及用户证据，不扩成没有目标的全排列样稿。

- [游戏 UX](../ux/game-ux-designer.md)定义流程及状态/行动含义；本档案细化同一控件的同时表达，不重写确认/取消流程。
- [环境概念美术](environment-concept-artist.md)处理图像意图与建造信息；这里的重点是可复用图形语言和组合政策。
- [实时特效美术](../vfx/real-time-vfx-artist.md)处理时序与场景中的信号；本文没有测量动态效果或注意力。
- [模态焦点恢复](../../solutions/ux/modal-focus-recovery.md)研究实际焦点边界，其结果不是本文选择样稿的验证。
