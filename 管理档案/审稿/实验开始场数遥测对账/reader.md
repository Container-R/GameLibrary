## 自拟调查任务

业务想知道新版是否让玩家更少开启训练，并希望继续解释完成率。预先约定的开始口径是“服务器正式接受”，不是本地点击。原分配为 C 组 C1、C2 和 T 组 A、B，全部时刻 0 入组，窗口 `[0,60)`。原总体包括全部四账号；实际查询却要求提示曝光，T 组仅 A 满足。

C 组两账号各有两次接受、正常收件和解析，共 4 次，权威完整性已独立确认。以下所有阶段的 C 组均为 4，原成员与最终成员均为 2。

T 组首次收集截止为 100。权威导出当前只见 A1、A2、A3、A4、B1、B2、B3，发生时刻分别为每账号的 10、20、30、40 秒（B 当前只导出前三条）。导出负责人尚不能证明全部分片齐备，故这 7 条不是完整目标。单独权威索引确认 Z 在 70 秒接受，属于窗外；ID B4 尚无匹配，窗口归属未知。

截至 100 的 T 组原始归档如下。每账号只有一个安装代次 e，事件序号等于 ID 中的数字；除明确列出的异常外，账号、时间、标签等字段均匹配。收到时间均不晚于 100。

## 第一次快照的实际处理

1. 冻结开始窗口、100 的截止、原分配和权威导出版本。保留全部 9 份归档，不先按客户端时间删除 A2。
2. 依据截至该版本可用的权威索引分类：窗口内 7 份，窗外 `{Z}` 1 份，未知 `{B4}` 1 份。这里 7 是副本数，不是不同 ID 数。
3. 窗口内 ID 集为 `{A1,A2,A4,B1,B2,B3}`，大小 6。A1 的重发 payload 完全相同，没有冲突，可去重。不同 ID 之间也没有复用同一账号、代次、序号。
4. A2 因接受时间 payload 不符隔离；B2 因标签不符隔离。它们都是已经收到的证据，不是网络未见。B2 按账号原分配记在 T 组，不挪入 C 组。
5. 解析集为 `{A1,A4,B1,B3}`，大小 4。应用错误的提示资格后，最终集为 `{A1,A4}`，大小 2。成员差集为 `{B}`。

因此 T 组阶段报告为：原成员 2、最终成员 1；已观察权威 7；确认窗口内原始收件副本 7；解析去重 4；最终观察 2；目标接受数 **未知**。同时交接正常窗外 1、未知窗口归属 1，不能把未知归属当零或忽略。

具体差集与处置：

- 已观察权威 ID 减已确认窗口收件 ID：`{A3}`。仅可说截至 100 未见；没有投递终结证据，不能称永久丢失。
- 已确认窗口收件 ID 减解析 ID：`{A2,B2}`，原因分别为时间 payload、分组标签冲突，转交客户端生成链路调查。
- 解析 ID 减最终 ID：`{B1,B3}`，原因是查询排除 B。恢复原总体后，已有资料足以把最终观察数从 2 改为 4。
- B4 的问题在窗口归属层，不放进解析拒绝，也不以“无权威匹配”断言不存在。
- A 的解析序列为 1、4，内部缺口 2、3；原始窗口收件序列为 1、2、4，只有 3 未见。因此解析序号缺口 2 是加工造成，3 才对应当前已知未收件 A3。
- B 的解析序列 1、3 缺 2，而原始窗口收件已有 1、2、3。B4 目前是未知归属，不能由已见最大序号 3 推断整个 B 序列完整。

最终观察的 T 人均开始数若错误地除原成员数为 1，C 为 2；若又除筛后成员数，T 为 2。两种报表都不能用来认定目标接受数下降。原成员数相等不解决事件损失，人数筛选又改变了比较总体。

## 第二次快照：哪些能继续，哪些不能

到 160，收到 A3 的迟到副本（收到时间 130）；权威导出补上 B4，接受时刻 40、账号 B，且负责人提供独立的完整分片覆盖和接受持久化依据，证明此窗口的接受记录完整。保持原研究窗口和原分配，新建来源版本，不倒填第一次快照。A2、B2 的错误尚未修复。

现在 T 归档有 10 份，窗口内 9 份，窗外 1，未知 0。窗口 ID 集是 A1–A4、B1–B4，共 8；多出的一份是 A1 重发。解析去重 6，具体为 `{A1,A3,A4,B1,B3,B4}`。错误提示资格下最终为 A 的 3 条；改回原总体则最终观察为 6。权威减原始窗口 ID 的差集为空；原始窗口 ID 减解析仍为 `{A2,B2}`。

新快照合同成立，目标接受数为 8。按原分配重建后，A、B 各 4 次，T 人均 4；C 仍为总计 4、人均 2。表面上 T 较少的现象消失，描述性的服务器接受数反而更多，但四账号不足以证明处理效果，本文也不承诺推断方法。

交接应分别保存：旧最终观察 2、后续快照在原错误查询下的观察 3、修正资格后的观察 6、权威重建目标 8。若以已修正资格的观察 6 为基线，本次权威补齐 ID 是 `{A2,B2}`；旧快照的 A3 是后到收件，B4 是权威补导后解决未知归属，不能把它们统称同一类“新增玩家行为”。每条变更附来源版本。

我选择：

- **继续分析服务器接受数量**：第二次快照中目标语义、窗口、权威身份时间和完整性均有依据，可以重建。客户端错误仍作为质量问题保留。
- **补充采集及核查**：继续修复 A2 时间和 B2 标签生成，检查实际配置下发与生效，不能从原分配推定玩家确实运行指定版本。完成率还需挑战结果、结果跟进窗口及其采集完整性，目前没有这些证据。
- **保持未知**：第一次快照的目标总数、两次快照的本地点击总数、完成率均不能由现有资料确定。若原问题其实是点击意愿，则第二次的权威完整接受表也不足以恢复，需独立点击证据，无法追溯则考虑重跑。

这不是把作者单个变体重复一遍：同一组里同时存在导出未齐、未知归属、时间异常、错误标签、合法重发、迟到与查询筛选，且完整性状态随来源版本改变。若仅比较总量，第一次的权威 7 与窗口内副本 7 恰好相同，会漏掉重复和缺收件抵消；逐 ID 才能拆开。

## 会改变处置的条件

假如 A1 第二份副本并非合法重发，而是序号或安装代次不同，即便其它字段一致，也已满足同 ID 不同逻辑 payload 的冲突条件。依据本文保守策略，我会停止这份快照的完整分析，输出冲突，不拿后到副本覆盖前一份，也不继续发布上面的完整阶段结论。待来源核清后再算。它与“只有一份 B2 错标签，隔离单条”不是同一种处理。

若到 160 仍无法证明接受表完整，则已观察权威为 8、归档匹配良好，也不使目标总数自动变成 8。这时仍能修正查询、记录解析缺口，不能补零或声称恢复了总量。
