## 独立工程判断与反例

我选择的案例不是作者的两个独立范围覆盖顶点数组：一张彩色玻璃网格的主透明 pass 和阴影 pass **别名同一个完整索引区间**；阴影 pass 本身允许 cache 换序。即使二者使用统一顶点 remap，阴影 pass 的原地 cache 仍会改变主 pass 面序。因此“每个 draw 分别批准，再统一 fetch”独自不足以保证等价。处理应为复制阴影索引流再重排，或整个共享区间遵循主 pass 的保序限制。

审查期间收到作者告知最终稿更新，重新读取全文相关上下文：审批表前新增的“重叠片段”段明确要求独立索引副本或最严格保序，另覆盖完整三元组边界和 baseVertex 顶点域解释。该反例已被最终稿直接处理，故不再构成退稿项。这里不是因为作者宣称完成而撤销问题，而是核对了实际新增文字与后续伪代码的前置关系。

第二个工程判断：运行时稳定按三角形中心深度排序时，两片交叠异色面深度键恰好相同，离线 cache 改变输入次序后，稳定排序会保留新的 tie 顺序，因而不能批准 cache。最终稿审批表明确保留并列风险，并要求最终序列等价；有稳定原始面身份并用其作一致 tie-break，才可能重新批准。这也说明单纯“运行时会排序”不足以消除离线风险。
