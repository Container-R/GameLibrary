# 每帧都做 Lerp，为什么换个帧率追随速度就变了

一个界面数值要慢慢追上目标，程序每帧执行 `x = Lerp(x, target, 0.5)`。看起来只是取中间值，可换到更高刷新率后，它会更快接近目标。原因不是插值函数突然变了，而是每秒执行了更多次“消掉一半差距”。

这里讨论的是**把上一次输出作为下一次起点的递归追随**。它不同于固定步长显示：后者拿两个已经完成的模拟状态，用余量与步长的比值 `A/h` 决定显示位置。也不同于从固定起点到终点、按总进度播放的一段动画。三者都可能调用 Lerp，但权重的含义不能互换。

## 固定比例描述的是一次更新，不是一秒

先只看一个数。设当前值为 `x`，目标为 `b`，普通线性插值的权重为 `a`：

```text
x_new = (1 - a) * x + a * b
```

目标不动时，更新后的差距等于更新前的 `1-a` 倍。因此，只要每次都用同一个 `a`，更新次数就会决定追随速度。

下面用很低的更新次数，方便直接看清差别。这是手算示例，不是某款游戏的测量结果：初值为 0，目标为 1，每次权重都是 0.5。一秒内只更新一次，结果是 0.5；同一秒更新两次，先到 0.5，再到 0.75。高刷新率的真实场景只是把这种次数差异放大了。

Rory Driscoll 的原文讨论了这种追随方式，并提出按经过时间计算剩余误差比例，而不是为每次调用指定同一个比例。[1] 下面用独立的数字例子说明这一区别，以及它不能解决的采样问题。

## 把权重乘上 dt，仍不等于精确的按时间衰减

一种常见修改是 `a = k * dt`，其中 `dt` 是本次经过的秒数，`k` 的单位是每秒。它让权重随本次经过的时间变化，但并不使不同分步得到完全相同的结果。

仍从 0 追向固定目标 1，取 `k=0.5/秒`，总共经过一秒：

| 怎样更新 | 每次权重 | 一秒后的值 |
|---|---:|---:|
| 一次更新一秒 | 0.5 | 0.5 |
| 两次各更新半秒 | 0.25 | `1 - 0.75² = 7/16 = 0.4375` |

这里所有权重都在 0 到 1 之间，差异与越界无关。`k*dt` 可以用作近似的离散更新，但不能据此承诺相同总时间必有相同终点。

具体 API 还要单独看文档。例如 Unity 6000.0 的 `Mathf.Lerp` 会把权重夹到 `[0,1]`；权重大于 1 时会取终点，而不是继续外推。[2] 不能把这个行为推广到所有同名函数，也不能把钳制当作消除上述分步差异的办法。

## 用半衰期表达“过多久消掉一半差距”

若想要一种一阶追随：**只要目标不动，每过半衰期 h，剩余差距减半**，就可以直接按时间计算剩余比例。这里 `h>0`，`dt≥0`，两者使用同一种时间单位：

```text
remaining = 2^(-dt / h)
a = 1 - remaining
x_new = x + a * (b - x)
```

例如半衰期是一秒，从 0 追向 1。一整秒更新一次，差距剩下 1/2；分成两个半秒，每次差距乘以 `2^(-1/2)`，两次相乘仍是 1/2。

更一般地，两个时间段的剩余比例满足：

```text
2^(-dt1 / h) * 2^(-dt2 / h) = 2^(-(dt1 + dt2) / h)
```

这就是固定目标下分步一致的理由。也可以写成 `a = 1 - exp(-lambda * dt)`，其中 `lambda = ln(2)/h`。[1] 这描述的是误差按指数衰减的一阶追随，不是带速度状态的弹簧，也不是惯性化中任意初始位置和速度都能满足的“位置每秒减半”。

上述相等关系指实数数学：目标和半衰期保持不变，而且更新之间没有额外限速、钳位或重置。实际浮点实现不因此获得位级一致保证；极小时间步、非有限输入和数值精度仍需实现者处理。这段公式也不是碰撞安全或镜头观感的保证。

## 目标会动时，还要问“这一帧用了哪个目标”

指数权重解决的是固定目标下的时间分段问题，不能自动恢复两帧之间没采到的变化。

考虑同一个目标信号：前 0.75 秒为 0，之后跳到 1。当前值初始为 0，半衰期为一秒。假设每次更新都读取**本段结束时的目标**，再把这个值当作整段内的固定目标：

| 更新划分 | 实际使用的目标 | 一秒后的值 |
|---|---|---:|
| 一段：0 到 1 秒 | 读到 1，按整整一秒追向它 | 0.5 |
| 两段：0 到 0.5 秒，再到 1 秒 | 第一段读到 0；第二段读到 1 | `1 - 2^(-0.5)`，约 0.2929 |

两种更新面对的是同一个真实目标，却对它何时变化作了不同的近似：前一种把 1 用了一秒，后一种只用了半秒。所以终点不同，并不违背上一节的公式。若希望按真实的 0.75 秒跳变拆段，系统首先要知道那个时刻，而不是指望指数权重从当前值猜出来。

接入项目时，先辨认自己是在两个已知状态之间插值，还是反复追向新目标。若是后者，再决定追随速度怎样按时间定义，以及目标何时采样、突变是否需要单独处理。不要为了“帧率无关”把固定步长显示中的 `A/h` 换成指数权重；那会改变原来要显示的状态，而不是修复同一个问题。
