# 阴影深度先插值再比较，为什么不能代替比较过滤

读取阴影贴图边缘时，一个位置可能涉及几个邻近纹素。程序先线性采样它们的深度，再用接收点的深度比较一次，看起来也做了“过滤”。但这与先分别比较各个纹素、再过滤通过结果，不是同一种计算。

本文用一个能够手算的例子解释两者的差别，再对照Microsoft的比较采样文档。它只讨论比较与过滤的顺序，不解决完整阴影渲染、深度偏移或视觉质量问题。数值是原创教学输入，没有运行GPU或渲染画面。

## 比较采样器过滤的是通过结果

先固定本文的深度约定：同一光投影下，较小的深度代表较近的位置。接收点的参考深度记作r，某个纹素记录的深度记作d，两者采用相同的深度编码与数值范围。本例规定`r <= d`时比较通过，记为1；不通过时记为0。这里没有深度偏移，也不讨论相等处的浮点误差。

Microsoft的`SampleCmp`文档明确描述了比较过滤的顺序：对被采样的各纹素产生0或1，再按采样器的过滤规则混合这些结果。[1] 对应`sample_c`文档还明确了操作数顺序，是参考值在比较函数左侧，纹素R分量在右侧；比较函数和过滤模式都来自配置。[2]

这为PCF（percentage-closer filtering）提供基础操作：过滤多次比较的结果，而不是先混合深度再决定一次通过与否。也不能把“混合结果”一律说成平均四次比较；各次结果怎样参与，取决于所采用的过滤规则。

## 同一组深度和权重，交换顺序就不同

下面只考虑纹理内部、单一层级的四个深度值，不涉及越界、其他mip或真实采样器精度。参考深度r为1/2。

两行深度都相同：左边为1/4，右边为3/4。为教学明确指定理想双线性权重：横向在两列之间的四分之一处，纵向在两行中间。这里说的是四个样本之间的插值位置，不是整张纹理的归一化UV坐标。

| 样本 | 深度d | 指定权重 | `1/2 <= d`的结果 |
|---|---:|---:|---:|
| 左上 | 1/4 | 3/8 | 0 |
| 右上 | 3/4 | 1/8 | 1 |
| 左下 | 1/4 | 3/8 | 0 |
| 右下 | 3/4 | 1/8 | 1 |

权重合计为1，但不是四个1/4。按“先比较再过滤”，得到：

`(3/8)×0 + (1/8)×1 + (3/8)×0 + (1/8)×1 = 1/4`

若把同样的权重先用于深度，则得到：

`(3/8)×(1/4) + (1/8)×(3/4) + (3/8)×(1/4) + (1/8)×(3/4) = 3/8`

此时只比较一次，`1/2 <= 3/8`不成立，结果是0。输入、比较方向和权重都没变，只交换顺序，就从1/4变成了0。

另外，若直接平均四次比较，会得到`(0+1+0+1)/4 = 1/2`，同样不等于本例指定权重下的1/4。因此，这个例子同时区分了三种操作：过滤比较结果、比较过滤后的深度，以及不顾原权重的简单平均。

原因在于比较是带门槛的判断，不是线性运算。先合成一个深度再过门槛，不能普遍代替先让各深度过门槛，再组合判断结果。某些输入恰好给出相同答案，并不使两种实现等价。

## 1/4不是新的深度，也不是实测的可见面积

本例的1/4是按所列权重得到的通过结果。它没有位置或长度单位，不是重建出的深度，更不是已经测得四分之一的真实光源面积可见。将它用于画面时，还要明确后续计算把通过当作亮还是暗，避免再把含义反过来。

这些权重为推理而指定，不是承诺任意GPU、接口或采样位置都会返回精确的1/4。实际接入还涉及纹理格式、参考值精度、mip选择、过滤方式、寻址和边界处理。`sample_c`文档分别讨论了格式精度与越界样本的来源，[2] 本文刻意没有把它们混进这个有限算例。

因此，如果两条真实实现不同，先检查它们是否真的读取了相同样本、使用相同参考值和过滤规则，再调查其他原因。不能只看shader末尾都有一个“小于等于”，就认定操作相同。

## 排查时先确认过滤对象，再调整画面

可以从接收点的一次判断往前追：

1. 这次读到的是普通深度采样结果，还是比较采样返回的通过结果？是否又对已经比较过的数值做了第二次深度比较？
2. 比较函数两侧是谁？参考值与纹素值是否来自同一深度约定？若近远次序改变，应重新核对相应比较，而不是只翻转纹理数值。
3. 这次过滤使用哪些样本与权重？有没有把加权过滤换成等权平均，或在重写时改变层级、坐标和边界规则？
4. 最终值交给哪一步使用？它是过滤后的比较结果，不应再当作几何距离或精确面积。

上述是未执行的接入检查建议，不是完整shader或采样器创建配方。本文没有根据某张故障画面认定原因，也不保证换用比较采样就一定更快或更好看。

几个相邻问题仍应分开：

- [阴影采样格稳定性](镜头移动时，为什么静止物体的阴影仍会晃动.md)处理横纵格子的平移、尺度与覆盖。改变过滤顺序不会把已经移动的格子恢复原位。
- [深度金字塔的保守界限](缩小深度图时，为什么不能总取最小值.md)为另一类查询保留界限和覆盖，不是用min或max替代这里的加权比较。
- [深度与距离的区别](深度纹理里的差值，为什么不能直接当作距离.md)处理数值编码、位置重建及长度含义。比较过滤不会把深度编码变成线性长度。
