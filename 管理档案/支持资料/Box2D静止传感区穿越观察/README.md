## 首次失败没有被改成成功

第一次编译器退出0，但出现73条上游 `B2_UNUSED` 相关诊断。原协议要求stderr为空，因此整次构建失败，未运行引擎。独立核对全部诊断和固定源码后，第二版只允许空stderr或与[已审诊断全文](reviewed-build-stderr.txt)完全相同的字节。没有修改源、fixture、六步预期或编译参数，也没有按警告类别宽泛放行。两次后续构建使用这条明确修订的门槛。

[诊断审查](BUILD-DIAGNOSTIC-REVIEW.md)说明依据与边界。它不证明整个上游无缺陷。此前纯工具测试还保留了优化模式mock配置修正、返回进程清理和复制产物执行前身份检查的发现；这些不是物理行为失败。[实现审查](INDEPENDENT-IMPLEMENTATION-REVIEW.md)区分这些阶段。

## 如何复现这个有限输入

本包不是已安装的Box2D库。需要C17编译器、Python3和常见Unix数学/线程链接能力；本次编译器自报GCC14.2.0，不作为安装来源认证。没有运行CMake、下载第三方调度器或安装依赖。

为保持原始输入文件不变，可在自行选择的工作目录中采用以下相对布局：把本包内容放入 `box2d-sensor-native/`，将固定官方提交中**仅SOURCE-MANIFEST列出的84个原文件**放入相邻的 `box2d-sensor-native-gate/upstream/`，保留各自相对路径。不要把整个Git克隆目录混入upstream：多文件、缺文件、换行或字节身份不符都会被拒绝。协议内旧的单元名是这个相对布局，不是私人机器位置。

在 `box2d-sensor-native/` 中先做纯工具检查：

```sh
python3 -B -m unittest -v test_validate
python3 -B independent/challenge.py
```

这些是合成数据和mock子进程检查，不会执行物理引擎。然后分别构建和运行，不能将旧尝试目录当作新结果：

```sh
python3 -B run.py build --attempt build-local \
  --manifest-sha256 bd4b97e9b3676378ccc00ebfa1927c75cbaf25f950ff8a33860c08ba33e03a8f \
  --sources ../box2d-sensor-native-gate/upstream

# 先审查新构建receipt确为pass，再单独执行：
python3 -B run.py execute --attempt execute-local \
  --manifest-sha256 bd4b97e9b3676378ccc00ebfa1927c75cbaf25f950ff8a33860c08ba33e03a8f \
  --build-attempt build-local
```

构建限120秒，行为限20秒。不同编译器产生的诊断可能导致精确门槛拒绝；这应作为新的复现条件审查，不能改掉日志来冒充同一次接受。任何设置或事件不符都保留首错并停止，不增加世界步或调参。`validation.json`只代表消费者局部通过，整次接受还需要最终receipt通过全部源、代码、构建收据和产物前后身份核查。
