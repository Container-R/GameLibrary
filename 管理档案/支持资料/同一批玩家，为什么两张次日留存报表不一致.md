# 同一批玩家，为什么两张次日留存报表不一致

两张报表使用同一批玩家、同一份回访日志，却给出不同的次日留存率。先别急着认定有一张漏了事件：“次日”可以指下一个日历日期，也可以指从起始事件经过24到48小时。换了区间，同一次回访就可能换了归属。

本文面向策划和数据分析人员，只讨论指定一天内是否回访的口径。下面是原创纸面例子，没有调用分析服务或使用真实玩家数据；它帮助核对定义，不证明任何游戏的留存表现。

## 先固定回访条件，再比较两个“次日”

约定以玩家首次进入游戏的指定事件作为起点，以之后的指定游玩事件作为回访。每个玩家只入组一次，同一窗口内回访多次也只算一个人。这里的事件和身份规则是例子的前提，实际项目需要单独确认，不能把任意后台消息都当成玩家回来游玩。

以下全部使用 UTC，不涉及夏令时，并采用左端计入、右端排除的区间：

- 日历 D1：起始日期之后的下一日期，从零点到再下一日期的零点之前。
- 精确时长 D1：从起始时刻加24小时，到加48小时之前。

这两条都是声明清楚的指标定义，没有哪一条天然更正确。Amplitude 官方文档也区分按日历日期和按24小时窗口计算留存；日历口径由图表时区决定，默认采用项目时区。[1] 日历规则与固定时长的通用区别，可另读[每日任务重置，为什么不能总是再加24小时](每日任务重置，为什么不能总是再加24小时.md)；本篇不重写时区实现。

## 同一份日志，算出两种结果

假设三名玩家的起始事件都发生在2026年11月1日23:00 UTC。每人只有下表所列的一次回访；我们已观察到11月4日00:00，例子还假设日志完整。

| 玩家 | 唯一回访时刻（UTC） | 日历 D1 | 精确时长 D1 |
|---|---|---|---|
| A | 11月2日00:30 | 计入 | 不计入，仅经过1.5小时 |
| B | 11月3日00:30 | 不计入，已经是日历 D2 | 计入，经过25.5小时 |
| C | 11月2日12:00 | 计入 | 不计入，仅经过13小时 |

日历 D1 的回访集合是 A、C，结果为 **2/3**；时长 D1 的集合只有 B，结果为 **1/3**。分母没有换人，日志没有变化，差别完全来自回访区间。

A 与 B 还说明：不能断言日历留存总是更高。有的回访只属于日历 D1，有的只属于时长 D1，哪个比例更高取决于事件分布。也不能把午夜前后的两次动作自动理解成玩家隔了一整天回来。

端点要同样明确。对本例起始时刻，11月2日23:00恰好经过24小时，计入时长 D1；11月3日23:00恰好经过48小时，不计入。日历 D1 则在11月3日00:00结束，该时刻不再属于它。

## 平台写着“24小时”，仍要核对时间精度

上面的精确时长定义不是所有平台的逐秒实现说明。Amplitude 文档明确指出，每日24小时模式会先将事件时间向下取整到最近的小时，再按第24个递增小时起、到第48个递增小时之前判断。[1]

因此，另设一个起始在11月1日23:45、回访在11月2日23:10的玩家：实际只经过23小时25分钟，不符合精确24小时下限；按文档描述的小时取整，两个时刻都落在各自日期的23:00，回访会满足24个递增小时的边界。这是文档规则的推演，不是服务实测。

前三人的起始恰在整点，回访也没有靠近这些小时边界，因此按该取整规则，表里的分类不变。若要核对真实报表，应保留起始与回访事件、时区、时间精度和端点条件，而不是只比最终百分比。重复起始事件怎样形成多个观察桶，也须另查平台规则；本例的一次入组假设没有覆盖它。

## 没等到窗口结束，暂时没有回访不等于最终为零

现在把上表的观察截止提前到11月3日00:00 UTC。日历 D1 已结束，但时长 D1 要到当天23:00才结束。此时还没看见 B 在00:30的回访。如果把当时的时长0/3，与已经完整的日历2/3当作最终结果比较，就又混入了观察是否结束的差别。

Amplitude 会把未完整的区间标为未完成，并从整体留存计算中排除相应数据。[2][3] 这是平台的报告规则，不意味着所有工具采用相同处理。自己的报表也应说明哪些窗口已经完整，不能只把提前回访者放进分母，却排除仍有机会回访的人。

窗口结束与日志已经到齐仍是两回事。晚到事件怎样修订历史结果，见[如何计算关卡完成率](../../GameLibrary/数据分析/指标设计/玩家行为/如何计算关卡完成率.md)的发生时间与收集截止说明。等待时长足够，不会自动证明遥测完整。

## 先确认“当天回来”，还是“当天及以后回来”

本文采用 Return On：只问指定区间有没有回访。Return On or After 则允许该区间及之后的回访，两者不是同一个问题。[2] “滚动24小时窗口”描述怎样划分一天，不能只因同样出现“滚动”字样，就把它与不限定后续某一天的留存混为一谈。

这也影响曲线解释。Return On 各天的回访人数可以独立变化，即使观察完整，D2仍可能高于D1。在同一数据截止时刻，用固定同一批人作分母的 Return On or After，因“当天及以后”的回访集合随天数增大而逐步收窄，具有非增关系；总体报表如果各点纳入不同的完整批次，就不能直接套用这一判断。[2] 这只是已固定观察范围内的集合关系，不代表未来还会发生的回访已经可知。

交接两张报表时，先写清楚：**同一批什么玩家，以什么事件为起点和回访，按哪个时区及区间计数，采用什么时间精度，数据看到什么时候，以及哪些窗口已经完整。** 定义一致之后，才值得继续调查剩下的差异；不同口径的百分比不能直接用来判断设计改善。
