# 旋转向量的变化率为什么不等于角速度

动画过渡代码里，一个三维变量叫作 `v`，插件接口也要求填入三维“角速度”，两者是否可以直接相接？名称和分量数都相同，仍不足以判断。前者可能是旋转参数的变化率，后者却要求物体真正的角速度。如果把它们混用，位置或姿态接上了，转动速度仍可能没有接上。

这份补充面向动画程序，解释一种具体表示的差别，不提供完整旋转惯性化实现。Holden 的弹簧文章展示过以缩放轴角表示旋转差额的思路；这里不判定那段演示有缺陷，而是说明移植时需要确认变量含义。[2]

## 先分清三种三维向量

**旋转向量**写成 `φ=θa`：`a` 是单位旋转轴，长度 `θ` 是旋转角，单位为弧度。三个坐标共同描述一次轴角旋转，**不是依次绕三个轴转动的欧拉角**。`φ̇` 是这三个参数坐标随时间的变化率，单位为弧度/秒。

物理角速度则描述物体此刻怎样转动。同一角速度可以用物体自身坐标表达，记为 `ω_body`，也可以用固定世界坐标表达，记为 `ω_world`。设旋转矩阵 `R` 把物体局部坐标映到世界坐标，则两者满足 `ω_world=Rω_body`；只是换坐标，长度不会变。[1]

下面采用右手系、Hamilton 四元数乘法，四元数按 `(w,x,y,z)` 排列，标量分量在前。时间用秒。换引擎或数学库时，不能只搬公式而不核对乘法和坐标约定。

## 已转过90度，再改变另一个参数

考虑一条原创、未执行的旋转参数曲线：

```text
φ(t) = (π/2, βt, 0)，β=1弧度/秒
```

只看 `t=0` 附近的一小段，使旋转向量长度仍小于 `π`，不跨越旋转对数的分支。在这一刻，姿态是绕 x 轴正向转90度，参数变化率却为 `φ̇=(0,1,0)` 弧度/秒。它不是从零开始绕一个固定轴转动。

若直接把这个变化率当作角速度，会得到长度1。真正求导却得到：

```text
物体坐标角速度 ω_body  = (0, 2/π, −2/π)
世界坐标角速度 ω_world = (0, 2/π,  2/π)
```

二者长度都是 `2√2/π≈0.9003` 弧度/秒，不是1。因此，差别不只是“忘了把向量转到另一个坐标系”：单纯旋转 `(0,1,0)` 无法改变它的长度，也就不能修复这里的混用。

这些数值来自下面的纸面导数，不是播放器、插件或引擎测量结果，也没有声称所有变化方向都会产生差别。

## 怎样核算，而不是记住一个特殊答案

令 `α=π/2`，`r=√(α²+β²t²)`。把轴角写成单位四元数：

```text
q(t) = (cos(r/2), α sin(r/2)/r, βt sin(r/2)/r, 0)
```

在 `t=0`，`r` 的导数为零。记 `c=cos(α/2)`、`s=sin(α/2)`，便有：

```text
q = (c,s,0,0)
q̇ = (0,0,βs/α,0)
```

在前述约定下，Solà 给出的角速度关系是：物体坐标角速度取 `2q*⊗q̇` 的三维虚部，世界坐标角速度取 `2q̇⊗q*` 的三维虚部；`q*` 是共轭，`⊗` 是四元数乘法。[1] 次序不能互换。

将上面两个四元数代入，得到：

```text
ω_body  = (0, 2βcs/α, −2βs²/α)
ω_world = (0, 2βcs/α,  2βs²/α)
```

再用 `2cs=sinα`、`2s²=1−cosα`，就得到前面的两个结果。这个核算不需要模拟一帧，也没有把有限时间的旋转简单相加。

更一般地，旋转向量导数与物体坐标角速度之间由一个矩阵联系：`ω_body=Jr(φ)φ̇`。这个矩阵称为右雅可比，它把参数坐标的微小变化换成当前姿态上的微小旋转。[1] 在原点的连续极限，或导数与旋转向量同轴时，这种差别可以消失；只检查同轴转动，因而可能看不出接入错误。

## 接到动画系统时，先问变量代表什么

遇到名叫“速度”的三维量，先确认它是参数导数还是物理角速度；若是后者，再确认它用哪个坐标系表达。不要先作四元数或向量运算，再靠动画看起来顺不顺去猜约定。

这里尚未处理“旋转差额乘上一个也在转动的新目标”。那时最终姿态由两个随时间变化的旋转组成，必须另外按乘法次序求导，不能把本例直接当成完整的切换初始化公式。近零数值处理、分支切换、速度估计和骨骼层级也不在本补充范围内。

原来的[惯性化正文](../../../GameLibrary/角色动画/动画运行时/动作过渡/用惯性化平滑被中断的动画过渡.md)仍是一维位置与速度的推导。本补充解释为什么将它推广到旋转前，需要先补上速度含义这一层，而不是把三个标量直接改名为角速度。
