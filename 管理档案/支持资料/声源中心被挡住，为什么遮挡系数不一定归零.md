# 声源中心被挡住，为什么遮挡系数不一定归零

同伴仍在用切割器开门，玩家向门框旁边挪了一步。如果系统只检查听者到声源中心的一条线，这条线从畅通变成被挡时，几何判断就会从一端跳到另一端。项目也可能希望把切割器视为具有一定范围的声源，而不只是一个点。两种处理回答的并不是完全相同的问题。

这篇说明面向技术音频和接入程序员，用 Steam Audio 4.8.1 的固定源码解释一种体积遮挡采样。它不是声学传播的完整模型，也没有实际播放切割声；例子的用途是帮双方读懂参数和采样结果，而非证明哪一种听感更好。

## 单条线与一组点，分别检查了什么

在该版本的 Raycast 模式中，实现检查听者与声源中心之间是否被场景挡住：被挡返回0，未挡返回1。这里的数值是用于遮挡处理的系数，数值越大表示这一项保留得越多，不是“0表示没有遮挡”。[1]

Volumetric 模式则在声源周围一个球体内取得多个样本点。球体的大小由声源半径决定，因而不再只询问中心点是否可见。官方插件文档将这个半径称为声源的表观大小，并说明更多采样通常以额外 CPU 工作换取更平滑的遮挡变化。[2] 这不是把场景里的切割器模型真的变大，也不保证每次增加半径或样本数，得到的系数都会上升。

还有一个容易漏掉的步骤：**并非球体内所有样本都会进入最后的分母。** 固定实现先检查声源中心到每个样本点之间是否被挡。若某点越过了墙或地板边界，使中心看不到它，就跳过这个点；只有通过这一步的点，才继续检查听者能不能看到。[1]

因此，中心点被门框遮住时，仍可能有其他有效样本对听者可见。反过来，把球体伸进墙后的另一空间，也不意味着那些点会直接贡献声音：中心到样本的检查正是在排除这一类跨表面取点。

## 六个点，为什么算成二分之一而不是三分之一

下面是假设的可见性查询结果，专门用来手算源码中的计数关系。它不是 SDK 在某个场景实际生成的六个点，也没有验证对应几何或声音输出。

| 样本 | 声源中心能看到？ | 听者能看到？ | 怎样计数 |
|---|---|---|---|
| A、B | 否 | 不再检查 | 不进入分母 |
| C、D | 是 | 是 | 进入分母，也进入分子 |
| E、F | 是 | 否 | 只进入分母 |

有效样本共有4个，其中2个对听者可见。实现得到的遮挡系数是 **2÷4=0.5**，不是拿全部6个点作分母得到的约0.333。

若本次没有有效样本，固定实现返回0，不会进行零分母相除。[1] 这个返回值不能独自说明为什么没有有效样本，更不能替代对几何、采样设置和调用条件的检查。

这一例子也说明，为何调参前要先看清被计数的对象。只记下“用了6个样本”和最后一个系数，未必足以解释变化；中心可见的有效点数发生变化，分母也会改变。调大半径并不是简单地在原有分母上追加更多可见点。

## 采样比例不是绕过门框的完整声学路径

这段实现查询的是中心到样本、听者到样本的几何可见性，并没有在这里求声波如何绕过边缘。**衍射**指波在边缘附近传播的效应，不能把多发几条可见性射线就叫作已经模拟了衍射。这里的范围判断只针对所读函数，不是对 Steam Audio 其他功能的总评。

穿过遮挡物的传输也由另一部分处理。固定版本的直达效果在同时启用遮挡与 transmission 处理时，会把遮挡系数与传输系数组合；启用遮挡而不启用 transmission 时，才在相应分支直接用遮挡系数乘增益。[3] 所以前面的0.5不是“玩家听到原来一半响”，0也不能直接解释成整个声音立即消失。距离、过滤、增益变化过程、其他声音支路和最终输出仍可能参与结果。

接入切割器时，可以先把问题拆成三项：用于查询的几何和位置是否符合预期；所选模式及半径代表什么范围；查询出的系数最终被哪条音频路径使用。三项分别核对后，再按项目目标试听门前、门旁和墙后的变化。本文没有执行这些检查，不给出通用半径或样本数推荐。

如果当前问题不是几何查询，而是直达声变弱后混响也一起断掉，应转看[直达处理与混响发送的取样位置](挡住直达声后，为什么混响也断了.md)。改变遮挡采样，不能自动修正信号路由。
