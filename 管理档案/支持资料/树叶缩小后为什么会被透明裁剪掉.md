# 树叶缩小后为什么会被透明裁剪掉

一张叶片贴图近看完整，远处却只剩零星片段。若材质使用 **alpha test（透明度测试，也常称透明裁剪）**，应先检查缩小图像里的 alpha 怎样通过阈值，而不是立刻把 RGB 改成预乘。

mip 链是一组分辨率逐级降低的纹理图像，用于纹理在画面上缩小时的取样。透明裁剪按条件保留或丢弃样本；普通 alpha blending 则用分数参与颜色混合，两者不是同一运算。下面限定严格的 `alpha > 0.5` 测试，只做原创手算，没有导入纹理、生成图像或运行引擎。

## 平均 alpha，不等于平均通过比例

设一张 2×2 小图的四个 alpha 为 `1、0、0、0`。每个纹素测试一次，只有一个超过 0.5，通过比例为 `1/4`。若把四个值等权平均，生成一个 1×1 mip，所得 alpha 为 `0.25`；它没有超过同一阈值，通过比例变为零。

平均运算保留了这组值的平均数，却没有保留“超过阈值的数量”。这解释了一种细小叶片在缩小层级被裁掉的机制，不是对某张真实贴图的诊断。逐纹素预乘 RGB 也没有改变这里的 alpha，因此单独修正颜色预乘顺序，不能改变这次测试结果。

## 保留覆盖率是目标，不是每一级都能精确兑现

Castaño 的原文提出：在生成 mip 后调整 alpha 的尺度，使通过指定阈值的比例尽量接近原图；同时明确指出，离散问题通常没有精确解。[1]

上面的最小 mip 就说明了限制：无论怎样缩放唯一的 alpha，再做一次二元测试，都只能得到通过或不通过，即比例 1 或 0，无法恰好得到 `1/4`。所以不能从“Preserve Coverage”这个名称推导每级都精确保留原比例。

这里计数的是纹素各测试一次，不是屏幕上叶片覆盖的面积。实际采样位置、过滤、跨 mip 混合和实现采用的覆盖率估计都可能不同；即使某种比例相近，也不保证叶片轮廓和空隙的位置相同。

## 把导入参考值与材质实际阈值配对

Unity 6000.0 的 `TextureImporter.mipMapsPreserveCoverage` 用于对生成的 mip alpha 重新缩放；`alphaTestReferenceValue` 指定计算所用的参考值，文档要求它与实际 alpha test 的 cutoff 匹配。[2][3] 这是该接口的约定，不说明所有引擎都采用同一算法，也不表示导入选项会自动修改材质。

接入时可依次确认：

1. 这张纹理用于透明裁剪，还是普通混合？不要将裁剪覆盖率目标直接套给所有半透明资产。
2. 材质真正使用哪个 cutoff、怎样处理等于阈值的情况？将这些条件与导入参考值核对；材质阈值改变后，重新检查原来的导入目标是否仍适用。
3. 在目标管线检查实际生成的较小分辨率 mip 和最终采样表现，而非只看原图或开关状态。压缩、过滤与其他处理仍可能影响结果。

调整 alpha 会改变外观。是否接受较粗的叶片、丢失的小孔或不同的远处形状，需要结合目标素材和镜头复核，不能把启用开关当成万能修复。本文解释的是下一步该查什么，没有验证 Unity 输出、实际叶片质量或性能。
