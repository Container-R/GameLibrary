# EnTT旧观察的保留标识补充检查

2026-11-02。本目录是**事后补充消费者**，不是旧v2/v3执行输入，也不是一次新的原生观察。旧协议、检查器、回执和四份输出不作修改。

## 为什么需要补充

原八行消费者把完整值不等于4294967295作为非null的一部分判断。但固定EnTT v3.13.2的null比较只看索引部分，tombstone比较版本部分。因此，完整值1048575（保留索引、版本0）不等于上述全1整数，却仍属于null；完整值4293918720含保留版本，也不能当本协议普通创建的活跃实体。合成记录可同步改动身份及归档字段，原消费者仍接受，表明它的拒绝条件不够严格。此发现不是EnTT运行故障。

补充函数先验证随包冻结checker和oracle的原始字节，再调用原消费者，最后检查已知来自普通创建的source、seed及载入后的mapped_now/mapped_initial：索引不能为1048575，版本不能为4095。**曾经正常创建不等于现在有效**：外部删除后的旧句柄仍应保留，不能要求它重新变成valid。加载前的规范null映射和未观察initial继续允许。该补充不推断任意EnTT配置、hint创建或其他实验的合法身份。

源码依据为固定提交 `78213075654a688e9da6bc49f7f873d25c26d12c` 的 [entity.hpp](https://github.com/skypjack/entt/blob/78213075654a688e9da6bc49f7f873d25c26d12c/src/entt/entity/entity.hpp)：null_t、tombstone_t比较与traits::next跳过保留版本。实际复核已绑定官方单头中的对应实现；没有安装、编译或原生执行。

## 材料和复查方式

- `frozen_checker.py` 是旧v2/v3 checker逐字副本，SHA256 `788f72e5e978b90a14047822cd28d023e49c7495d75119cc856525a8cc78d732`。
- `frozen_oracle.json` 是旧独立oracle逐字副本，SHA256 `90169423b365a0a3a553462caff0be05ebb6672de6f58758959b9a5c139497cf`。
- `check_supplement.py` 只读取指定的观察文件；不启动compiler、runner、原生进程或网络操作。输出只含内容摘要和补充接受结果，不回显观察路径。必须提供至少一个输入；缺文件或拒绝时非零退出。
- `test_supplement.py` 是合成消费者回归，不是原生输出生成器。

从本目录可运行：

```text
python3 -B test_supplement.py
python3 -B -O test_supplement.py
python3 -B check_supplement.py <已有观察文件>
```

脚本要求原依赖字节精确相同，不应为了通过而改其摘要。公开包清单若随后创建，也不应被称作历史执行输入清单。

## 本地已做的有限检查

普通Python和-O各运行同一5个测试方法：1个合法记录（含stale及加载前未观察值）；8个一致改动的保留身份反例（source/seed/旧映射/重载映射，各索引或版本保留），先确认旧checker接受，再确认补充拒绝；14个身份字段位置各两种保留值，共28个字段反例；5个原严格条件反例；checker及oracle各一次字节变动拒绝。各方法均通过。方法数不是原生场景数，两模式不是两倍独立覆盖。

另只读消费既有v2两份、v3两份原始stdout，普通和-O均通过补充检查。四份各为8行，SHA256均是 `504bdd9c35c4bd06a9c589e14c662206ce87768c316495559b299172aa2b3843`。这些真实记录的source/seed为0，旧映射为1，重载映射为1048577，不含上述保留身份。**补充检查没有使旧观察失效，也没有修复旧v2环境准备的流程缺口。** 它只增加对现有字节的拒绝条件；不把旧回执重签成新执行，不证明所有错误都能检出。

本补充已通过[独立审查](REVIEW.md)，接受范围仅为纯 Python 消费者与既有观察字节的事后检查，不是独立原生复跑或新的执行回执。
