## 3. 回调、记录与接收演示

全部输入回调和 context 在调用前有效；不测试空回调或错误输入。getNumFaces 返回 2，各面顶点数 3。输入数组读取前校验 face/corner；输出 basic callback 同样校验范围、重复、数量和有限值，保存到 `3*face+corner`，并另外记录实际到达顺序。只安装 basic 输出回调，完整输出回调置空。

生成返回真且六个键各收到一次后，打印数字 JSON。缺失、重复、非有限或范围错误直接失败，stderr 保存错误，不继续读取未初始化数据；此时可能没有完整观察 JSON，不能把缺失归为成功。未对分配失败注入、崩溃或所有可能调用序列作测试。

行 schema 为 15 数值：face、corner、old、P.xyz、N.xyz、UV.xy、T.xyz、sign。raw 以面角键列出，callback_order 记录实际顺序但不要求未来实现沿用。reindexed 是六记录经新索引 F0=(0,1,2)、F1=(3,4,5) 查回的完整记录。

调用结束后才作两个明确的应用接收演示：按面角键 0→5 写回四旧槽并逐角查回；另按键 5→0 重放。它们名为 forward_readback/reverse_readback，不是重排生成器输入或宣称其回调顺序不同。四个旧槽在每次读取前都已被该顺序写入。

## 4. 独立字面预期与判据

`expected.json` 是执行前冻结的六行手算，独立审者须另读／确认而非从实际输出学习。F0 参数化 (u,v,0)，F1 (u,-v,0)，所以两面 T=+X，N=+Z，重建副切向所需 sign 分别 +1 和 -1。

- 六条 raw 与六条重索引查回记录的 P/N/UV、face/corner/old 均与字面表一致。
- sign 精确为预期 ±1。T 的三个分量仅在本输入允许绝对误差 ≤1e-6；任何数值必须有限，布尔值不是数值。没有相对误差或执行后放宽。
- forward 六角符号依次 [-1,-1,+1,-1,-1,-1]，仅 (0,0)/(0,1) 与原角不符。
- reverse 符号 [+1,+1,+1,+1,-1,+1]，仅 (1,0)/(1,2) 不符。
- 以上错误接收中的 P/N/UV/T 仍逐项核对，不能只数两个冲突。
- callback_order 必须是 0..5 的排列，且 output_count=6；不固定实际到达顺序。
- 固定输出字段集合、六行结构、整数身份；JSON 重复键、非有限常量、额外／缺失记录拒绝。

consumer 只读观察和冻结字面 oracle，不导入 C 夹具逻辑。验证入口内部先核对 oracle 原始字节的固定 SHA256，不接受调用者传入另一个 oracle；摘要不符即停止。返回的 expected_fixture_calls=1 是协议的调用次数要求，不是消费器独立测出的原生调用计数。其正常 Python 与优化模式应同样依靠显式检查而不是 assert；本阶段尚未执行。
