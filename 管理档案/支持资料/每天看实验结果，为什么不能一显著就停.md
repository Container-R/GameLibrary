# 每天看实验结果，为什么不能一显著就停

闪避教程增加了一张提示卡，团队把符合条件的新玩家随机分到原版与新版。原计划等约定样本收齐，再判断完成率有没有变化。实验还在进行，报表某天第一次显示“显著”，于是有人提议马上结束，宣布新版有效。

问题不在于打开了报表，而在于**是否让眼前的结果决定什么时候作出统计结论**。如果原来的检验只保证在预定样本量下使用，现在改成“每天看，第一次显著就停”，分析规则已经变了。[1] 本文解释这项区别，不提供可直接上线的实验平台、通用样本量或停止阈值。

## 同一批数据逐渐变多，不等于只检验了一次

先分开两个判断。检查服务是否崩溃、日志是否丢失，是运行和数据质量监控；判断新提示是否改变完成率，则是效果推断。不能因为效果检验需要遵守规则，就要求团队对故障视而不见；也不能把一次为保护玩家而中止的实验，自动解释成新版已经获得统计胜利。

Microsoft 的实验实践文同时强调早期监测和对重复查看作统计处理，并举出因严重故障而提前关闭实验的例子。[2] 这支持的不是“任何中途显著都可宣布胜利”，也不是“实验结束前什么都不能看”。如果质量或护栏告警本身也是反复按显著性触发，它同样需要合适的统计规则；监控目的不同，不等于可以忽略重复判断。

在检验中，通常先提出一个待检查的假设，例如两组真实完成率相同。p 值衡量在这个假设及模型条件下，当前结果有多不寻常；它不是“新版无效的概率”，也不是“新版有95%的概率更好”。低于某个事先选定的阈值，可以作为相应检验的拒绝条件，但这个条件属于一整套分析规则，不能脱离何时查看、何时决定来理解。

连续累计的报表共享了早先的记录。因此，第一天与第二天的检验并不独立。不过，“不独立”也不会自动消除多次寻找过线机会的问题。下面用一个能够逐项算完的例子说明，为什么既不能把每日检查当成独立抽签，也不能当成只看最终一次。

## 一个只看两次的精确反例

为避免混入玩家行为和两组比较的细节，暂时离开教程，考虑20次独立的公平抛硬币。这里是数学模型，没有真的抛硬币或采集玩家数据；它不是教程 A/B 检验的计算配方。

待检查的假设是“每次正面概率为一半”。我们采用双侧精确二项检验：给定已经观察的次数，正面特别少或特别多都算偏离。把拒绝阈值选为0.05，仅是本例的设定。

只看前10次时，正面为0、1、9或10次才满足该拒绝条件；只看全部20次时，正面不超过5次或不少于15次才满足条件。比较两种规则：

- **只在20次后判断。** 无论前10次怎样，都等到固定终点。
- **在10次时先判断。** 若已满足拒绝条件就停；否则继续到20次，再按同一阈值判断。

公平硬币下，所有长度20的正反面序列共有 `2^20 = 1,048,576` 种，概率相同。即使第二种规则提前停下，仍可用尚未观察的后10次作为数学上的可能延续来计数，不需要真的继续实验。

| 满足的条件 | 完整序列数 |
|---|---:|
| 前10次会被拒绝 | 22,528 |
| 全部20次会被拒绝 | 43,400 |
| 两个时点都会被拒绝 | 8,996 |
| 至少一个时点会被拒绝 | 56,932 |

最后一行是 `22,528 + 43,400 - 8,996`，扣掉同时满足两次的重叠。固定终点规则的误报概率约为 **4.14%**；显著就停的两次查看规则约为 **5.43%**，已经高于所选的5%。这里“误报”指硬币本来公平，却按规则拒绝了公平假设。正面次数是离散的，所以固定检验实际达到的误报概率可以低于所选阈值，不必恰好是5%。

这不是把两个5%简单相加，也没有使用两次检查独立的假设。数字只属于这个具体、离散的两次查看例子，不是所有游戏实验的误报率或膨胀倍数。它说明的事情很有限，却足够重要：每个固定时点各自满足原来的约束，不代表“任一时点过线就宣布成功”的整体规则仍满足它。

## 需要提前决定，就把提前决定纳入方法

对于提示卡实验，先确认团队采用哪一种安排。如果使用固定样本方案，应事先确定分析对象、主要指标、所需样本和结束条件，并按该方案解释结果；不能看到差一点显著就多收一些，刚好过线又立即收工。样本量还涉及希望发现多大的变化、检测能力及业务成本，本篇不替项目给一个统一数字。

如果产品确实需要边收数据边决定，可以选择为这种使用方式设计的序贯方法。Johari、Pekelis和Walsh讨论的 always-valid p 值，要求在符合模型条件的数据依赖停止时点仍控制误报；这比每个固定时点单独有效更强。[1] 它不是把普通 p 值不断取最小值，也不是给报表改个标签。具体实现和适用条件需要统计方法与实验平台共同核查，本文不实现论文算法。

另外，允许持续监测一个指标，不等于允许任意增加指标、反复挑子群或改写假设后仍沿用同一保证。论文另行讨论多重检验及其条件。[1] 新手完成率、后续留存、耗时和不同设备子群分别在回答什么，应在报告中说清；“总有一项显著”不能代替原先的问题。

## 报告中保留作出决定的过程

回到教程，如果团队已经根据中途结果提前结束，先记录原定方案、实际查看和停止的规则，以及为什么改变；不要把这次结果重新包装成从未看过中间数据的固定终点分析。是否还能作出有效推断，需要按实际规则重新评估，不能在本篇凭一个最终 p 值补办保证。

即使方法允许提前停止，统计上的变化也不自动等于值得发布。效果大小、玩家体验、实现成本以及数据质量仍需分别判断。看报表并不是过错；真正需要避免的是，已经改变了挑选结论的方式，却继续沿用原来那句“误报风险受控”。

## 计算说明

若要复算拒绝集合，本例的双侧 p 值为 `p(n,k)=min(1, 2×Σ(i=0…min(k,n−k))C(n,i)/2^n)`，其中 n 是已观察次数，k 是正面次数。

上表以正面数分块核算。前10次有 `a` 个正面，后10次有 `b` 个正面，对应 `C(10,a)C(10,b)` 条完整序列；`C(n,k)` 表示从 n 个位置选 k 个的组合数。遍历 `a,b=0…10`，分别判断 `a` 和 `a+b` 是否落在上述拒绝集合，再累计权重。两次都满足的8,996条也可写成 `2×[C(10,0)×Σ(b=0…5)C(10,b) + C(10,1)×Σ(b=0…4)C(10,b)]`。

这是原创精确有限计算，经独立代数与全序列枚举核对，不是随机模拟、引擎运行、真实实验结果或论文数值的复现。它只检验一个已知概率的单样本假设；真实两组完成率比较另有模型和设计要求。
