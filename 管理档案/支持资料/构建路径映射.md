# 构建目录变了，为什么只改调试路径还不够

GCC 14.2 分别处理调试信息中的源码位置与 `__FILE__` 宏展开。前者帮助调试器找源码，后者可以进入程序自己的日志；改了前者，不能据此认为日志里的文件名也统一了。[1]

假设输入文件名是 `/build/game/weapon.c`，希望记录为 `/src/game/weapon.c`。以下路径全是虚构的，表格描述选项用途，不是运行结果。

| 要调整的位置 | 对应设置 |
| --- | --- |
| 调试信息 | `-fdebug-prefix-map=/build/game=/src/game` |
| `__FILE__` 宏展开 | `-fmacro-prefix-map=/build/game=/src/game` |

映射不搬动源码，调试器仍可能需要另设源码查找位置。这也不是完整预处理文本或最终二进制的相等承诺。[1]

回到实际交付，还要检查生成工具写入的路径、随机文件名和保存的编译参数。它们可能另行影响结果，不能把一个编译选项当作全局文本替换，更不能因此宣布整包可复现。[2] 本节没有编译、调试或二进制比对。
