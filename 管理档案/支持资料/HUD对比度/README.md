# 黑背板与白字：有限 SDR 数值示例

这是独立的纯 Python 教学算术，不读取图片、引擎输出或显示器，不作游戏运行、截图测量或无障碍认证。代码只使用标准库，无网络或文件测量。

## 输入与含义

- `srgb_decode(channel)`：输入归一化的 **sRGB 编码**分量，返回线性分量。
- `srgb_luminance(red, green, blue)`：输入三个编码分量，先各自解码，再求相对亮度。不是接受任意引擎 RGB 的通用函数。
- `panel_luminance(alpha, background_luminance)`：黑背板覆盖不透明背景，在线性工作域得到 `(1-alpha)*background_luminance`。
- `white_text_contrast(alpha, background_luminance)`：文字本体始终是不透明白色，返回 `1.05/(背板后亮度+0.05)`。不包含文字边缘覆盖率；背板不会同时淡化白字。
- `minimum_panel_alpha(target_ratio, maximum_background_luminance)`：调用者给定背景线性亮度上界，返回理想最小 alpha 的浮点近似。上界不是本程序采样或证明出来的。

所有输入只接受内置 `int` 或 `float`，不接受布尔、字符串、复数、其他数值类型；必须有限。分量、alpha、背景亮度及上界均在 `[0,1]`，目标比例在 `[1,21]`。非法类型抛 `TypeError`，非法数值抛 `ValueError`；不截断非法输入。上界为零时无需背板；目标为1时也无需背板。对正背景，目标21要求全不透明黑背板。

## 数学与精度

在指定模型中，背景越亮，白字比值越低。因此用上界 B 求最坏值。B>0 时，由 `(1-a)B <= 1.05/T-0.05` 得到最小值 `max(0, 1-(1.05/T-0.05)/B)`；B=0 单独处理。

手算例：alpha=0.5、背景0.1 得10.5；背景改为1 得21/11。目标4.5、上界1的理想边界为49/60；alpha=0.85、背景1得5.25。编码分量0.5解码约为0.214041，而不是线性0.5。

实现使用 Python 浮点运算，包括解码的非整数幂。**最小 alpha 返回值不是向上舍入的安全界**，舍入可能落在精确边界下方；不得将该近似直接当作达标承诺。本例没有“通过”判定接口、没有阈值容差、没有输出小数位四舍五入后再比较。测试的近似数值断言只是检查数值实现误差，不用于对比度达标。专门的反例确认略低于4.5的比值即使显示成4.50，仍然小于4.5。

## 实际依据

2026-11-01 定向重读以下固定原文，未分析其图片：

- [WCAG 2.2，2024-12-12 Recommendation](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-relative-luminance)：Definitions 的 relative luminance 与 contrast ratio；解码分界0.04045、线性权重、比值公式及1至21范围。
- [Compositing and Blending Level 1，2024-03-21 CRD](https://www.w3.org/TR/2024/CRD-compositing-1-20240321/#simplealphacompositing)：§5.1 与 §9.1.4 source-over。它支持合成算术，不证明某个游戏引擎按这里选定的线性域合成。

黑背板、白字与给定背景上界的组合及求解是此示例的限定推导，不是标准推荐所有 HUD 使用同一 alpha。排除 HDR、广色域、曝光/色调映射、后期、量化、字体与大小、抗锯齿边缘、玩家阅读能力和平台认证。所有函数仅返回数值，不返回全局合规结论。
