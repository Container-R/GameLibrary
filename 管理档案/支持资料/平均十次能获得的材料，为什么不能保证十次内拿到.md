# 平均十次能获得的材料，为什么不能保证十次内拿到

一个单机配方还缺一件材料。策划表写着“每次完成遭遇有10%概率掉落，平均十次获得”，后续关卡便按“完成十次后，玩家已经能制作”来安排。这里少检查了一件事：**后续内容需要的是平均进度，还是十次以内一定有材料？**

在每次独立、概率固定的规则下，平均十次确实成立，但完成十次后仍缺材料的概率约为34.87%。如果制作是后续内容的必要条件，这部分可能性不能从成长预算中消失。

下面只讨论无付费、无玩家交易、材料没有交易价值的单机例子。配方的其他条件已经满足，只等这一件材料；所有规则和数字都是教学假设，不是某款游戏的配置或推荐比例。

## 先说清楚怎样算一次

从尚未获得这件材料开始，每完成一次规定的遭遇，就进行一次掉落判定：有10%概率得到一件，否则不掉落这件材料。没有完成遭遇就不计这一次，也不进行该判定。这里的“掉落失败”指完成后没有得到材料，不是战斗失败。

先假设每次判定相互独立，成功概率始终为 `p=0.1`；没有失败后加概率、计数保底或其他获取途径。为了计算等待，模型允许一直继续，直到第一次得到材料。

用 `T` 表示首次获得所需的总尝试次数，**包含获得材料的那一次**。第一次就获得时 `T=1`，前九次没有、第十次获得时 `T=10`。在上述条件下，T服从几何分布。[1] 查资料时要留意另一种计数习惯：MIT的相关讲义用X数成功前的失败次数，从0开始；换成本例就是 `T=X+1`，不能把X的均值直接当作总尝试次数。[2]

## 平均十次，为什么仍可能等得更久

可以从“会不会走到下一次”理解平均等待。第一次一定需要，走到第二次需要第一次没得到，概率为0.9；走到第三次需要前两次都没得到，概率为0.9²。依此类推，把每一次需要发生的概率相加，就得到平均总次数。这是非负整数等待数的尾和计算方法。[1]

```text
平均总次数 E[T] = 1 + 0.9 + 0.9² + ……
                = 1 / (1 − 0.9)
                = 10
```

这里的平均按各种等待结果及其概率计算，既包含很早就拿到的情况，也包含超过十次的情况。它没有规定每条路径都在第十次结束。

要判断十次以后能否制作，应直接算“十次都没有得到”。每次失败概率为0.9，各次独立，因此：

```text
P(T > 10) = 0.9¹⁰ = 0.3486784401 ≈ 34.87%
P(T ≤ 10) = 1 − 0.9¹⁰ ≈ 65.13%
```

第一行表示十次后还缺材料的概率，第二行表示十次以内已经获得的概率。65.13%是这个模型的计算结果，不是测得的玩家占比；更不是“每一组十次必有一次”的规则。

## 已经失败十次，下一次也不会自动补上

如果一个存档已经连续十次没掉材料，不能因为“平均十次”就判定下一次必得。在原先固定、独立的规则中，前面的结果没有改变下一次判定。把“已知前十次失败”写进条件，可直接得到：

```text
P(T = 11 | T > 10) = (0.9¹⁰ × 0.1) / 0.9¹⁰ = 0.1
```

竖线右侧表示已经知道的条件。分子是前十次失败且第十一次成功的概率，除以前十次失败的概率后，下一次仍是10%。这正是几何等待的无记忆性质。[1]

这一结论依赖前面规定的机制。如果游戏根据失败次数提高概率，就已经换了规则；不能先改变规则，再引用“过去失败不影响下一次”解释它。

## 把成长要求写成三种不同的检查

设计与实现交接时，“十次获得”至少可能表达以下三种意思：

| 想要检查的要求 | 本例给出的结果 |
|---|---|
| 平均首次获得次数为10 | 成立，E[T]=10 |
| 十次以内获得的概率达到某个指定比例 | 应把要求与约65.13%比较，不能只看均值 |
| 任何完成十次合格遭遇的存档都已获得 | 不成立，十次全失败仍有正概率 |

如果后续关卡在第十次结束后默认配方一定可用，它依赖的是第三种要求。只给出第一种平均数，无法支持这个安排。固定独立10%规则下，任何有限次数后仍可能没获得；把期限往后挪，并不会自动变成确定保证。[1]

因此，检查成长依赖时，应同时保留计数起点、哪些完成算有效、所用概率规则，以及要求属于表中的哪一种。先判断配置能否满足要求，再检查实现是否遵守配置；有限次模拟恰好都成功，不能证明所有路径都有上限，也不能证明实际判定相互独立。

## 加上第十次必给，平均数也会改变

只为比较机制，假设把规则改成：前九次仍按独立10%判定；如果前九次全失败，第十次强制给这一件。拿到首件后便结束本次等待。这不是推荐保底配置，而是用一条明确的新规则检验前面的数字还能不能沿用。

令新等待数为 `T′`。原先十次以内获得的路径不变，所有原先需要十次以上的路径现在都在第十次结束，所以 `T′=min(T,10)`。新规则有了十次上限，但平均值也要重算。

仍从“是否需要走到这一次”来加总：第一次一定发生，第二次以0.9的概率发生，直到第十次以0.9⁹的概率发生。第十次一定结束，因此后面不再有其他项：

```text
E[T′] = 1 + 0.9 + 0.9² + …… + 0.9⁹
      = (1 − 0.9¹⁰) / (1 − 0.9)
      = 6.513215599
```

新平均约为6.51次。这里相加的是是否需要进行第十次，所以最后一项为0.9⁹，不乘0.1；旧规则的第十个尾和项也一样。由于新规则在第十次必给，0.9⁹又恰好是第十次才首次获得的概率，第十一次及以后不再发生。新规则既消除了十次之后的等待，也缩短了平均等待，不能把它描述成“保持平均十次，只增加一个上限”。

这份比较只回答规则能否支持成长要求，不判断哪种规则更有趣。它数的是合格完成次数，不是分钟；遭遇耗时和玩家是否继续都尚未建模。真实玩家可以停下来，所以即使某条规则规定“最多十次完成”，也不能据此保证每个人都会实际拿到材料。
