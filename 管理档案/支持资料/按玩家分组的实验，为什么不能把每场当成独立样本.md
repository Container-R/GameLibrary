# 按玩家分组的实验，为什么不能把每场当成独立样本

新提示按玩家分组：同一玩家无论玩多少场，始终使用同一个版本。报表却把每场结果铺成一行，用行数作为独立样本数。即使这些都是不同场次、没有任何重复上报，统计判断仍可能出了问题：**随机分配发生在玩家身上，不是每一行记录身上。**

这与“完成次数有没有数对”不同。描述本批场次的完成比例，可以保留所有合法场次；判断两组差异有多不寻常，则还要考虑这些场次怎样归属于玩家，以及分组允许哪些变化。Microsoft 的历史实验实践明确提醒，同一用户的会话或页面观察可能相关，按独立观察计算，可能因此低估不确定性。[1]

下面用一个可以全部列完的原创数学例子说明这项区别。没有真实玩家数据，也没有运行游戏或线上实验。读完需要作出的决定不是删掉重复游玩的记录，而是：**把分配单位及其所属记录交给分析方法，不要让日志行数悄悄替代它。**

## 四名玩家，真正允许的分组只有六种

假设只有四名玩家 A、B、C、D，每人各有十场不同的合法场次；每场结果用完成记作1、未完成记作0。为隔离分组问题，作以下刻意简化的设定：

- 不论分到原版还是新版，A、B 的每场结果都固定为1，C、D 的每场结果都固定为0。
- 每人始终有这十场，分组不改变场次数、结果或观察范围；玩家之间没有相互影响。
- 从四人中等概率选出恰好两人使用新版，其余两人使用原版。分配不依据场次结果，每名玩家的十场始终属于同一组。

第一条比“两组平均效果相同”更强：它假设改版对每名玩家的每场结果都没有影响，统计上称为**尖锐零假设**。在这个例子里，无论怎样分组，全部结果都已由假设固定；唯一变化的是哪两人被选到新版。

指标暂定为每组所有场次中的完成比例，差值是“新版比例减原版比例”。每组都有两名玩家、二十场，因此可以逐项算出全部六种分配：

| 新版玩家 | 原版玩家 | 新版完成比例 | 原版完成比例 | 差值 |
|---|---|---:|---:|---:|
| A、B | C、D | 20/20 | 0/20 | +1 |
| A、C | B、D | 10/20 | 10/20 | 0 |
| A、D | B、C | 10/20 | 10/20 | 0 |
| B、C | A、D | 10/20 | 10/20 | 0 |
| B、D | A、C | 10/20 | 10/20 | 0 |
| C、D | A、B | 0/20 | 20/20 | −1 |

如果实际抽到 A、B 使用新版，报表会显示新版100%、原版0%。但在上述完全无效的设定下，出现绝对差值至少为1的分配有两种，概率是 **2/6，也就是1/3**。这里1是比例差，等于100个百分点；它不是相对提升百分比。

这个数字只来自所列假设及六种等概率分配，不是对任何游戏的效果估计，也不是四名玩家足以开展实验的建议。

## 把四十行重新分组，会算进不可能发生的实验

若另一种计算把四十场当作四十个独立分配对象，再任意选二十场贴上“新版”，就可能把 A 的前五场放入新版、后五场放入原版。这不属于原来的六种分配，实际设计根本不允许它发生。

因此，按行重新分组得到的参考分布，并不是本例玩家分组产生的参考分布。问题不在于四十行都是假记录，而在于计算假定了一种没有发生过的分配方式。同一玩家的十场结果在这个例子中完全一致，而且分组标签必须一起改变，不能因为场次标识不同，就当成十次独立的分配机会。

**这不意味着多玩几场永远没有信息。** 真实玩家每场结果可能不同，更多场次可以帮助了解该玩家的表现或其他预定指标。本例故意把玩家内结果设为完全一致，是为了让错误一眼可见。额外观察提供多少信息，取决于相关性、指标与设计，不能一律按行数增加，也不能一律算成零。

关于独立尝试模型为什么不能直接套到重复玩家，可先读[十次都过关，为什么还不能说以后一定过关](十次都过关，为什么还不能说以后一定过关.md)。本篇进一步指出：当分配已经按玩家进行时，计算还必须尊重这种分配。

## 交给统计分析的，不应只有两列场次结果

实际工作可以先保留玩家的原始分组，以及每条结果与玩家的对应关系，再明确纳入对象、固定观察窗口、场次定义和指标。若目标仍是所有合格场次的完成比例，可以为每名玩家汇总两个量：完成场次数与合格场次数。每组的比例仍是“完成场次总和除以合格场次总和”。这是一种保留原指标的汇总方向，不是已经验证的生产查询。

不要为了凑成“每人一行”，直接改成各玩家完成比例的简单平均。场次数不同时，这会改变权重，也就可能换了问题。零场玩家的纳入规则也要另说清楚；不能悄悄删除他们，或把没有定义的个人场次完成率填成0。

Microsoft 的方法论文区分分配单位与指标单位，并讨论用玩家等群组的总量和计数保留原指标、再估计不确定性的办法。[2] **汇总正确不等于推断已经正确。** 应让分析人员结合玩家间关系、分配规则、样本规模和指标，选择适用的群组分析方法；若采用重抽样，也不能不经判断就逐场抽取。

本例的六种分配能够精确列完，是因为设计和无效假设都极其明确。它没有验证大样本近似，也不能拿四名玩家的数据套用某个渐近公式后宣称方法可靠。本文不提供通用显著性阈值、样本量或上线标准。

## 玩家归并只解决了其中一层问题

同一玩家是否被多个账号或设备拆开，必须先核对身份规则。若队友或对手会互相影响，按玩家汇总也不会自动让玩家之间独立；需要重新考虑分配、实际体验与分析目标。实验中途改版、跨组经历、漏报和受处理影响的参与条件，同样不是加一列玩家标识就能修复的。

另外，按正确单位分析，不代表可以每天重复检验、首次显著就停。何时作出判断仍属于分析方案的一部分。相关资格、组队暴露与停止规则，可回到[游戏数据分析师如何支持设计决策](../../GameLibrary/数据分析/指标设计/岗位与协作/游戏数据分析师如何支持设计决策.md)继续阅读。

交接报告时，应能说清：多少玩家怎样分组，产生了多少场次，指标按什么单位加权，不确定性如何尊重玩家内关联，以及哪些额外假设仍需核查。四十条正确记录，可以准确描述四十场，却不会仅凭行数就变成四十个独立分配对象。
