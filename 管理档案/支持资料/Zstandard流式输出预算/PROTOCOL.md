# 小输出块、累计额度与结束状态：有限 C API 观察协议

**状态：PREPARED_NOT_EXECUTED。** 此文件是执行前协议，不是运行结果。固定源码到齐、输入清单冻结及独立审查后仍需另行批准执行；后续结果另存，不能把本文件状态改成已运行。

## 问题与边界

每次只提供8字节输出空间，不能代替应用的32字节累计接纳额度；解码器完成一帧，也不能覆盖应用拒收决定。反过来，输入文件已经读完不证明帧已经完整。

仅使用 Zstandard v1.5.7，提交 `f8745da6ff1ad1e7bab384bd1f9d742439278e99` 的官方 decoder-only 合并源。`harness.c` 直接包含 `vendor/zstddeclib.c`，不链接系统 `-lzstd`。源生成身份与原始依赖清单由源准备记录另行提供；具体 SHA256 记录在冻结 manifest 与 vendor/source-origin.json；原始依赖可按其中公开身份另行取得。

不运行压缩器、字典训练或网络服务；无私有资产。本观察不是性能/内存测量、解压炸弹测试、所有压缩路径验证、字典配套验证或完整资源加载器。raw block 是合法未压缩块，不据它证明熵编码/引用路径已覆盖。唯一不完整输入是下面明确规定的截断例，不扩展随机或恶意输入。

## 固定输入与独立 oracle

三个 `fixtures/*.hex` 为十六进制字节文本；harness 拒绝非法字符、额外字节、结构或字面内容不符。不是自由指定文件的解码器。

明文字面 oracle：`abcdefghijklmnopqrstuvwxyz012345`，ASCII 32字节；33字节版本只追加字符 `6`。不含 C 字符串末尾零。每个成功调用产生的字节还须与对应字面前缀比较，不能由解码结果生成预期。

完整帧头：`28 b5 2f fd 00 00`。descriptor=0 表示无帧内容尺寸字段、非 single-segment、无字典ID、无校验；window descriptor=0 表示1024字节窗口。末尾 raw block 的三字节小端头是 `(N << 3) | 1`，32/33时分别为 `01 01 00` / `09 01 00`。这里只因完整 raw 内容没有字典引用而不需要字典，不能用ID缺省泛化此结论。

| case | 输入 | 字节数 | 预期发布决定 |
|---|---|---:|---|
| R32 | 32字节 raw 内容的完整帧 | 41 | 只有帧完成、输入耗尽且逐字产出/接纳32后才接受 |
| R33 | 33字节 raw 内容的完整帧 | 42 | 应用累计预算拒绝，即使库已返回帧结束也不发布 |
| R32_truncated | R32仅删除末尾一个载荷字节 | 40 | 不完整或实际库错误；未完成、不发布 |

三个输入均查询 `ZSTD_getFrameContentSize` 并要求 `ZSTD_CONTENTSIZE_UNKNOWN`。截断例的32是 **raw Block_Size**，不是帧头声明 FCS。查询未知尺寸不是截断判定。

## 调用与判定

每例创建、初始化并释放独立 DStream；检查初始化、解码及正常退出的释放返回；初始化失败时尝试释放并直接失败，不另区分清理错误。每次输出容量8、output.pos重置0；保留 input.pos，继续呈交剩余输入。最多64次解码调用。

记录每次输入前后位置、库本次产出、累计应用接纳、返回类别（error/pending/frame_end）。最终分别记录 frame_complete 与 asset_accepted，并记录实际累计产出、接纳、输入消费量。不预填每次必产8、截断必产31或B必接满32。

先检查库错误；错误时不消费其输出、不再调用该流。非错误时逐字核对产出，先确认累计接纳未超预算，再用 `新增量 > 32 - 已接纳量` 判定。超额整块拒收，旧前缀也不发布。输出量、库返回数字和应用额度是三件事。

正常成功必须同时满足 ret=0、全部输入消费、总输出32且逐字正确。R33必须确实发生应用预算拒收，实际产出总量超过32；不能用输入长度或预设标签代替观察。截断例只接受未完成且字面前缀不超过31字节；EOF时正返回且输出未填满表明当前可刷新内容已排出，可结束为输入不完整。其它无进展、调用上限、异常长度或字节不符为 FAIL，不改成预期拒收。若截断例实际返回库错误，记录该类别并停止，不预言特定错误名称。

## 构建、运行与证据分层

`runner.py` 只在冻结 `manifest.json` 的文件白名单、SHA256、PREPARED_NOT_EXECUTED状态全部吻合时继续。manifest包含本协议、harness、runner、三个hex、合并源码、LICENSE及source-origin.json九项输入；后者固定生成源的原始依赖证明，不伪称这九项已包含从零重新生成上游合并源的所有文件。

执行配置命令为 `cc -std=c99 -O1 -Wall -Wextra harness.c -o observe`；这是源码配置，不是对本机编译器实际路径/版本的观察。运行命令为 `./observe`。不安装依赖；缺编译器或编译失败直接停止。构建120秒、运行5秒上限；超时停止进程组，保留失败分类。每次 `--run-name` 必须新建且不能复用目录，不继承旧 PASS。

runner将固定输入复制到新目录，随后重新计算工作副本九项文件的摘要并逐项与manifest比较；不符则在编译前失败。只有该检查真实通过，结果才记录 `copied_inputs_verified=true`。这是一次复制后身份核验，不是完整竞态防护。通过后在该目录构建；HOME、XDG配置/缓存/数据/状态/运行时和TMP均为该次新目录，XDG运行时目录权限0700，环境仅含明确 PATH、C locale和这些隔离位置。不采集本机路径、机器指纹、PID、二进制摘要或实际编译器版本。进程号仅用于内部超时终止，不记录为证据。

`private-logs/` 保存原始编译/运行stdout和stderr，仅本地；可能包含诊断路径，不作为公共包直接上传。公开候选 `result.json` 只记录输入身份、技术选项、退出码/超时类别、stderr是否为空和成功输出身份；失败不伪造成功，不抹去本地原始错误。`output.txt` 只在harness通过、运行退出0、stderr空且输出有界时产生。发布前仍需人工检查结果字段和输出，不直接复制整运行目录或可执行文件。
