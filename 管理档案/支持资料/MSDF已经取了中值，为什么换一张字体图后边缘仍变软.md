# MSDF已经取了中值，为什么换一张字体图后边缘仍变软

界面使用多通道距离场字体。程序已经按说明对RGB取中值，字形轮廓看起来也没有偏移；替换了一次生成出来的字体纹理后，边缘却变得更软。继续挪动0.5阈值，只会把字变粗或变细，没有找回原来的过渡。

这里需要分开检查两步：**三个通道怎样重建形状，以及重建数值怎样换算成屏幕上的距离。** 前一步正确，不会自动让后一步使用的单位也正确。本文面向接入字体材质的界面与图形程序员，用原创纸面例子说明这一区别，没有生成字体、运行着色器或测量画面。

## RGB存的是形状信息，不是三个可以平均的颜色

有符号距离场（SDF）用一个数描述点位于轮廓哪一侧，以及离轮廓多远。多通道距离场（MSDF）把与不同边有关的信息放进多个通道，以改善尖角的重建。本文约定形状内部为正、外部为负。MSDF重建值不能在所有位置都当作精确欧氏距离，特别是角点附近；后文的距离计算会单独限定为理想直边。[1]

作者的方法使用三个通道的**中值**，也就是排序后居中的数，不是三个数相加再除以三。固定版本msdfgen的示例在纹理采样后取中值；CPU参考渲染路径也是先插值，再组合三个通道。[2][3]

用一个自选的局部直角模型说明平均为什么不等价。形内要求同时满足 `x≥0` 和 `y≥0`，坐标单位取纹理像素。为解释交集，暂把三个通道的距离写成 `(x, y, min(x,y))`。这不是完整MSDF生成算法，也不是某个字形实际导出的样本。

在点 `(-0.2, 0.8)`，三个距离为 `(-0.2, 0.8, -0.2)`：中值是−0.2，仍在形外；平均值却约为+0.133，变成形内。如果先按下文的对称范围4编码，三个值是 `(0.45, 0.70, 0.45)`，中值低于0.5，平均值却高于0.5。**改成平均，可能改变内外判断，不只是“稍微模糊一点”。** 论文的三通道模型解释了中值如何表达这类交与并关系；这里的坐标与数值是原创演示。[1]

本篇假设这些通道按线性数值读取，不进行sRGB颜色解码。它们虽然借用了RGB存储位置，却不是一张普通彩色字形图片。若输入解释已经改变，后面的范围计算也无从对应原编码。[2]

## 0.5对应轮廓，但它不说明一格数值是多少像素

设生成时的正数全距离范围为 `R`，单位是距离场纹理像素。这里限定对称范围：`R=4` 表示从−2到+2，而不是每一侧都有4个像素。msdfgen的 `Range` 单参数构造和距离映射源码明确采用这种全宽含义。[4][5]

取中值后的编码数记作 `m`。在这项约定下，解码为纹理距离是：

`d_texture = R × (m−0.5)`

因此m=0.5表示零距离，但m与0.5差0.05究竟是多少距离，仍取决于R。R=4时是0.2个纹理像素，R=8时是0.4个纹理像素。

接着要换单位。令 `k` 表示一个距离场纹理像素对应多少屏幕像素，只讨论二维均匀缩放。把一张完整的32×32独立纹理绘制到64×64屏幕区域，便有k=2。屏幕上的全范围为 `Q=kR`，于是：

`d_screen = Q × (m−0.5)`

为了得到一条有限的抗锯齿过渡，作者示例把 `d_screen+0.5` 限制到0至1，作为前景与背景的混合权重。[2] 下文记作a。a不是对任意曲线、任意像素覆盖面积的精确证明，也没有规定整个引擎后续的颜色混合流程。

## 换了生成范围，旧参数会把过渡拉宽

继续使用同一张32×32独立纹理的尺寸和64×64绘制区域，k仍为2。旧素材用R=4，材质中的屏幕范围Q为8；现在重新生成素材，保持几何尺度和零距离轮廓不变，只把全范围改成R=8。正确的Q就应变成16。

在一段理想直边附近，把屏幕法向有符号距离记作p，单位为屏幕像素，形内为正。新素材的编码满足：

`m = 0.5 + p/16`

若材质同步使用Q=16，得到 `a=clamp(p+0.5, 0, 1)`。如果仍保留旧Q=8，则变成 `a_wrong=clamp(p/2+0.5, 0, 1)`。其中clamp表示把结果限制在给定上下限内。

| 距离轮廓的位置p | 正确范围的混合权重 | 误用旧范围的混合权重 |
|---|---:|---:|
| −0.5屏幕像素 | 0 | 0.25 |
| 0，正好在轮廓 | 0.5 | 0.5 |
| +0.5屏幕像素 | 1 | 0.75 |

正确的0到1过渡跨越 `[-0.5,+0.5]`，宽度为1个屏幕像素；错误版本要跨越 `[-1,+1]`，宽度变成2个屏幕像素。**轮廓中心没有移动，过渡却被拉宽了。** 所以只检查0.5阈值，发现不了这项失配；挪动阈值是在改位置，不是在修复距离换算的比例。

这个结果来自理想实数直边推导，不是对真实字体“模糊程度翻倍”的测量。生成范围增大本身也不必然使显示变软；本例出错的条件是素材编码已经变了，接收它的参数却没有同步。真实素材还会受到量化、有限分辨率和其他处理影响。

## 把范围和实际缩放一起交给材质

排查时可以先保留一项简单的二维绘制，逐项核对：

1. 素材是MSDF、单通道SDF，还是带其他信息的格式？不要仅凭PNG有RGB就选择解码方式。
2. 是否先采样再取三个通道的中值？不要把平均或预先合成的单通道图当成同一条路径。
3. 当前素材的范围是全宽还是上下界？材质使用的值是否来自这份素材，而不是上一次导出的常量？
4. 一个纹理像素实际对应多少屏幕像素？范围与这个缩放相乘后，才是本例使用的Q。

导出时把范围及其单位与纹理一起保存，载入时同步到材质。不要把形状单位的范围和纹理像素范围作为同一个数交接。

如果字形只是大图集中的一个子矩形，不能把字形屏幕宽度直接除以整张图集宽度来冒充k。应依据实际取用的纹理跨度及对应的屏幕跨度换算；上面的32→64专指整张独立纹理。非均匀缩放或透视下，也不能继续使用这一常数k替代局部尺度。

非对称编码范围同样需要另行处理。源码允许指定不同的上下界，此时零距离未必编码成0.5，应按实际映射解码，不能照抄本例的减0.5。[4][5]

上述检查是建议的接入方法，尚未执行。本例Q为8或16，不覆盖屏幕距离范围不足时的抗锯齿退化。取中值和范围匹配都正确以后，薄笔画、低分辨率、缩小采样、图集边距、角点误差修正等仍可能造成问题；作者论文也讨论了有限表示的局限。[1] 本篇没有验证这些情况，不把增大范围当作通用修复，也不把字形像素清晰等同于字体塑形、排版或玩家可读性已经合格。
