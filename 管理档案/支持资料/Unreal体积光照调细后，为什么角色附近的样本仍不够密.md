# Unreal体积光照调细后，为什么角色附近的样本仍不够密

墙边角色的间接光照不符合预期，于是你把体积光照的采样单元尺寸调小，重新构建后，却没有看到想要的局部采样密度。下一步应该继续调小，还是增加内存？

先不要二选一。**设置要求的细度、构建实际留下的样本，以及角色最后的画面，是三个不同的检查对象。** 数值改过，只证明提出了新的要求。

本文面向使用 Unreal 预计算光照的技术美术和图形程序，仅讨论一个不采用 World Partition 的单关卡工作流，前提是项目已确认使用文档所述的 Volumetric Lightmap（体积光照贴图，简称 VLM）及其构建设置。依据为 UE5.6 文档，不提供完整启用教程，也不判断 GPU Lightmass、Lumen 或其他版本的兼容性。以下场景与比较均为原创建议，未运行引擎。

## 小尺寸与内存上限，管的是不同的事

VLM 为动态物体提供预计算的空间光照。文档中的 **Detail Cell Size** 控制最高密度处的采样单元尺寸；**Maximum Brick Memory Mb** 则限制砖（brick，一组采样单元）数据的内存，高密度砖可能被裁掉。文档还列出另一种原因：区域光照近乎相同，也可能不保留高密度砖。[1]

因此，看到局部样本少，不能直接写下“内存不足”。同样，把尺寸减半也不能直接写成“这里的样本已经加密”。前者提前确定了原因，后者把输入要求当成了输出结果。

检查这类问题时，要留下具体区域和对应构建结果，而不是只截设置面板。至少能回答：这次看的是哪一份构建，目标区域在哪里，改变了什么，实际观察又是什么？

## 从同一个基线比较两次，而不是连续盲调

设项目选定一面隔开明暗区域的墙，并固定角色位置、材质、曝光、灯光、墙厚与光照范围。记录当前采样单元尺寸为 **d**、砖内存上限为 **M**，保存基线的构建结果。这里的字母只是项目现值，不是推荐参数。

接下来准备两个分支，除列出的设置外保持条件一致：

- **甲：尺寸改为 d/2，上限仍为 M。** 重新构建，查看目标区域的样本。
- **乙：尺寸同样为 d/2，上限改为项目批准的 M2，且 M2 大于 M。** 再构建并比较同一区域。

Epic 提供了 Show → Visualize → Volumetric Lightmap 的样本显示入口。[1] 这能帮助查看构建结果，但本文没有取得甲乙两次结果，不能替它们填写“变密”或“没变”。

如果乙比甲留下更多局部样本，这可以支持继续调查预算对本次结果的影响，但还不能批准角色画面。增加的数据是否改善目标区域，以及代价是否可接受，仍要分别检查。

如果两者密度相同，也不能立刻认定设置无效。先核对是否真的完成并查看了相应构建，再考虑区域光照是否近乎相同等候选条件。**M2 大于 M，不等于 M2 已经足够**；没有变化，并未自动排除预算问题。

这组比较不承诺找出全部原因，也不把两次结果差异等同于完整诊断。尤其不要把“尺寸减半”换算成实际总内存必然增加八倍：那需要额外的布局与保留条件，本例没有这些证据。

## 最后验收角色，而不只是样本

样本显示回答“留下了什么”，角色画面回答“是否适合这个用途”。即使前者更密，后者仍可能没有达到目标。若预算已经不能提高，应把这个约束交回制作决策，而不是承诺继续调小尺寸就能解决。

比较最终输出还要明确平台。文档所述 GPU 路径按像素插值；移动端则在对象包围盒中心由 CPU 插值。[1] 因而不能将前者对角色内部空间变化的描述直接套到移动端，也不能用某一平台的结果替另一个平台验收。

一份能继续工作的结论可以写成：“甲乙使用相同采样单元尺寸，只改变砖内存上限；已记录目标区域的实际样本，下一步检查角色输出和预算。”如果尚未观察，就保留为待检查，别写成“已修复”。
