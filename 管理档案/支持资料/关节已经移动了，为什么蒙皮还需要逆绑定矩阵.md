# 关节已经移动了，为什么蒙皮还需要逆绑定矩阵

读取 glTF 时，关节编号与权重都正确，顶点却在尚未播放动画时就偏出去一截。一个容易漏掉的原因是：程序把网格里存的顶点直接交给关节的当前全局矩阵，却没有先把它换到这个关节的绑定坐标空间。

下面只解释这个坐标转换。我们采用固定修订的 glTF 2.0 核心规范，以一个单顶点、单关节的理想例子区分逆绑定矩阵、关节层级和网格实例节点的变换。没有制作完整资产，也没有运行导入器、引擎或 GPU。

## 当前关节位置，不等于顶点应当移动多少

全文使用齐次**列向量**：三维点写成 `p=(x,y,z,1)ᵀ`，矩阵放在左边。因此 `M B p` 表示先算 `B p`，再算 `M` 对所得位置的变换。这里讨论乘法的数学约定，不把内存中的行主序、列主序与行向量、列向量混为一谈。glTF accessor 中矩阵元素按列主序存储；接入另一种数学库时仍须核对该库的向量约定。[1]

设绑定时的关节在全局 X=2，顶点在 X=3，顶点完全由这一个关节影响，权重为1。本例特别约定：**顶点初始坐标与所选场景全局坐标一致，没有额外的绑定形状转换**，也没有旋转、缩放或形变目标。用 `T(a)` 表示沿 X 平移 a 的矩阵，绑定时关节的全局矩阵就是 `G_bind=T(2)`。

顶点在该关节的绑定空间中位于 X=1，而不是 X=3。把全局坐标中的绑定位置换到这个空间，需要先抵消关节绑定时的偏移：

```text
B = inverse(G_bind) = T(−2)
B × (3,0,0,1)ᵀ = (1,0,0,1)ᵀ
```

现在把关节移到 X=5，当前全局矩阵为 `M=T(5)`。同一个关节内偏移1应落在全局 X=6：

```text
正确：M B p = T(5) T(−2) (3,0,0,1)ᵀ = (6,0,0,1)ᵀ
遗漏B：M p  = T(5) (3,0,0,1)ᵀ       = (8,0,0,1)ᵀ
```

遗漏 B 的算法把原来的全局顶点坐标3错当成关节内偏移，额外带入了绑定时的2。甚至在关节尚未移动、仍位于 X=2 时，错误结果已经是5；正确结果则仍为3。这也给出一个直观检查：在这个限定例子中，绑定姿势应满足 `G_bind B=I`，其中 I 是单位矩阵。上述数字是原创手算，不是某个模型的故障观测。[2]

**这个等式的假设不能丢。** 导入文件时，不应从当帧节点的平移、旋转、缩放重新猜一份 B。当帧未必是绑定姿势；规范也说明，制作管线的绑定形状矩阵可能已合入网格数据或逆绑定矩阵。真实文件应按它所属的 skin 读取数据；省略 `inverseBindMatrices` 时，规范规定使用单位矩阵，不是让读取器自行对当前关节求逆。[3]

## glTF 的配对顺序决定该用哪一个 B

对一个影响项，先用顶点的 `JOINTS_n` 分量取得 skin 内编号 j，再通过 `skin.joints[j]` 找到关节节点。该节点的当前全局矩阵是 Mⱼ，同一个 skin 的逆绑定矩阵 accessor 中第 j 项是 Bⱼ。这里的 j 不能直接当作全场景的节点编号。[3]

关节的全局矩阵仍须包含层级：有父节点时，它是父节点全局矩阵乘自身局部矩阵；根节点的全局矩阵就是自身局部矩阵。[1] 因而三个量各有职责：

- 局部关节矩阵描述它相对父节点的姿势。
- 当前全局关节矩阵 Mⱼ 把关节坐标放入当前场景。
- 逆绑定矩阵 Bⱼ 先把原始顶点送到该关节所需的绑定坐标空间。

有多个影响项时，固定规范给出的有效矩阵是各项 `Mⱼ Bⱼ` 的加权和：[4]

```text
p_global = (Σᵢ wᵢ Mⱼᵢ Bⱼᵢ) p
```

所有项都接受同一份原始顶点 p，并输出到同一个场景全局空间，才能相加。这正是“有效蒙皮变换”必须先说清输入和输出空间的原因。它不解决权重解码，也不消除线性混合本身的扭转收缩。

## 不再额外乘网格节点，不等于忽略场景层级

固定 glTF 规范在 **Skinned Mesh Primitives** 中明确：被实例化为蒙皮的 primitive 不使用实例化该网格的节点全局变换，而使用上述逐顶点矩阵。[4] 因此，对于这套已经输出场景全局位置的公式，不应再像普通网格那样额外乘一次网格实例节点全局矩阵。

但这不等于可以从场景树删掉这个节点的变换。如果该节点同时是关节的祖先，其变换仍会通过关节的全局矩阵 Mⱼ 产生影响。这是层级关系的作用，不是对蒙皮结果再附加一次网格变换。`skin` 所引用的关节共同祖先也不能因此省略。[1][3]

这个规则还限定于实际具有蒙皮属性、按 skin 实例化的 primitive。同一节点引用的 primitive 若没有蒙皮属性，规范要求按没有定义 skin 的情形实例化。[4] 不能把“此处不额外乘网格节点”推广成所有网格、所有引擎或应用程序外层变换的通则。若引擎内部选择另一输出空间，必须重新推导空间转换，不能只摘走公式中的一项。

排查时可以先问三个小问题：原始顶点现在属于哪个空间？每项 B 是否与同一个 skin 的关节顺序对应？所得位置已经在哪个空间，之后是否又被重复变换？先用上述单关节例子把答案写出来，再比较多关节混合，通常更容易区分坐标错误与混合算法固有的问题。
