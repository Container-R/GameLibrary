# 双向索引与 UTF-16 输出：历史观察的有限衍生说明

这份说明及配套 `observation-summary.json` 只保留两个固定用例的技术观察。它不是原始运行包，也不提供新运行结果。整理日期为 2026-11-01。

## 读者可以据此判断什么

在固定段落级别 1、默认重排模式/选项 0、写出选项 0 下，两个历史运行都记录：

| 输入 UTF-16 码元 | visual→logical 映射 | ICU 写出码元 | 按 map 逐码元搬运 |
|---|---|---|---|
| 05D0 05D1 | [1,0] | 05D1 05D0 | 同左，编码合法 |
| 05D0 D83D DE00 05D1 | [3,2,1,0] | 05D1 D83D DE00 05D0 | 05D1 DE00 D83D 05D0，编码非法 |

第二行 map 的下标都合法且是一一排列，朴素搬运仍把同一补充字符的代理项拆反。坏结果来自原创适配器，不是 ICU 出错。“写出安全”在这里仅指这两个输出保持 UTF-16 完整，不表示已经排版正确。

每次历史运行是一子进程、一加载、19 次导出调用：一次版本查询与两套九调用生命周期。每次八个带状态返回均为 0，两次 close 完成，长度为 2 或 4，输出容量 n+1，终止码元 0 在分配范围内。两次合计 38 调用；同样两个配置重复一次，不是四种配置，也不是两套独立 BiDi 实现。库版本返回为 **76.1.0.0**，仅为被调用程序自报。

两个 map 恰好自逆，因此不能只凭这些数值辨认映射方向；方向还依赖固定 API 契约及所记录的实际绑定。未调用级别 getter，不能把源码推导称为实测级别数组。没有字体、塑形、字素/光标、组合符/控制符、布局、无障碍、目标语言质量或引擎文本组件验证。对已执行 BiDi 的渲染组件，不应仅因这两个用例成功就改送预重排文本。

## 没有删掉的失败

原生运行前的 Python 审查曾发现两处控制流缺陷：

| 纯模拟条件 | 原问题 | 有限修正及原记录结果 |
|---|---|---|
| timeout 后再次发生写流错误 | 次要 OSError 覆盖外层首要 TimeoutExpired | 最终保留 timeout 为首因、记录次要存储问题；原版和修正版都失败退出，没有成功摘要 |
| 模拟创建成功后 communicate 抛 OSError | 错标启动失败，未尝试有界清理 | 改为已创建后的失败，尝试有界清理/回收；仍失败退出，无成功摘要 |

这些是 mocked Python 探测，没有实际 ICU 超时或真实进程信号注入。首次探测自身还曾因导入路径设置而失败，那是测试搭建问题，不能算 ICU 缺陷。后续两次原生记录均为成功路径，没有测试原生错误、警告、timeout 或 close 失败。

最终作者与独立复制套件记录每种 Python 模式各八个测试方法通过；独立归档合成检查每种模式包含一个控制和十项拒绝变异，字面值检查包含两个控制和十二项拒绝变异。这些都只是相应有限输入的记录，不证明全面安全、清理可靠或 Unicode 一致性。本次没有重跑这些测试。

## 固定原始依据

比较源码为 ICU release-76-1 提交 `8eca245c7484ac6cc179e3e5f7c1ea7680810f39`，不把当前滚动版本当作这个版本。

- [ubidi.h](https://github.com/unicode-org/icu/blob/8eca245c7484ac6cc179e3e5f7c1ea7680810f39/icu4c/source/common/unicode/ubidi.h)：visual map 方向与容量，以及相邻 logical map 说明中的代理项提醒；writeReordered 的多码元完整性、缓冲区和选项合同。
- [ubidiln.cpp](https://github.com/unicode-org/icu/blob/8eca245c7484ac6cc179e3e5f7c1ea7680810f39/icu4c/source/common/ubidiln.cpp)：`ubidi_getVisualMap` 的奇数 run 码元索引分支。
- [ubidiwrt.cpp](https://github.com/unicode-org/icu/blob/8eca245c7484ac6cc179e3e5f7c1ea7680810f39/icu4c/source/common/ubidiwrt.cpp)：默认逆向写出按完整字符回退、正向复制该段码元。
- [Unicode 16.0 DerivedBidiClass](https://www.unicode.org/Public/16.0.0/ucd/extracted/DerivedBidiClass.txt)：原协议选定字符的 R/ON 属性依据。属性及源码推导与实际记录保持分开。

固定源码支持机制解释，不证明历史所用程序就是该提交的构建。读者应先判断谁负责逻辑文本、索引映射和最终显示，而非照搬本说明中的测试配置。
