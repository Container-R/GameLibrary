# 同一段音乐分块重采样，为什么不能每块从头开始

[返回PCM音乐循环区间正文](../../GameLibrary/声音与音乐/音频制作/循环素材/如何标记和检查PCM音乐循环区间.md)

一段连续音乐需要换成另一种采样率。程序每次从文件读一小块，转换后把结果接起来。输入没有漏读，循环端点也标得清楚，却还不能据此认定转换正确：**读取缓冲区的边界，不一定是声音重新开始的地方。**

这里面向接入音频转换的程序员与技术音频人员，使用 libsamplerate 的接口说明两件事：连续转换的状态怎样保留，以及下一次从哪里继续读取、向哪里继续写入。下面的数量只是原创交接算例，没有运行库、转换音乐或试听。

## 换一块输入，不等于换一段独立声音

重采样不只是给当前块换一个帧数。转换过程可能需要前面数据留下的历史和当前采样位置，才能继续处理后面的声音。

libsamplerate 的官方 FAQ 明确区分两种用途：`src_simple` 面向一次处理完整的一份音频，不适合对同一连续流的每个片段分别调用；流式处理应使用能够保留状态的接口，例如把同一个 `SRC_STATE` 交给多次 `src_process` 调用。[1]

固定0.2.2源码也能看到这个区别：`src_simple` 每次创建状态，把本次输入标为结束，处理后删除状态；它不是暗中替调用者保存上一块历史。[3] 因此，把独立转换的输出简单拼接，不能当成连续处理已经成立。

`src_reset` 则把已有转换器重置到刚创建时的内部状态。官方 Full API 将它用于切换到另一份独立、不相关音频。[2] 对同一连续音乐，不能因为“下一块读到了”就惯例性地 reset。比如固定线性转换分支会保存前次位置和各声道的末值供后续处理；这只是一个具体源码例子，不表示所有转换器具有相同历史长度或滤波方式。[4]

反过来，状态也不是越久保留越好。真正换成另一段无关音频时，需要按接口重新开始；这与音乐设计上是否交叉淡化是两项决定。本文不替项目选择转场方式。

## 输入推进多少，输出接上多少，要分别记

一次 `src_process` 调用涉及两组不同的数。[2]

- `input_frames` 和 `output_frames` 是本次提供的输入帧数及输出容量。
- `input_frames_used` 和 `output_frames_gen` 是处理后实际消费的输入帧数、实际产生的输出帧数。

函数返回值用于报告是否出错，不是产生了多少帧。应先确认调用成功，再按实际计数处理结果；错误时不能继续拿旧计数当作本次成功进度。

假设使用左右交错的双声道浮点数据，每帧是同一时刻的左、右两个值。**只为解释位置计算**，设一次成功调用的交接记录如下；这些数字不是某种转换器或倍率的实测输出：

| 项目 | 帧数 | 双声道浮点值数量 |
|---|---:|---:|
| 本次提供输入 | 100 | 200 |
| 本次输出容量 | 120 | 240 |
| 假设实际消费输入 | 60 | 120 |
| 假设实际产生输出 | 55 | 110 |

这时仍有40帧输入没有消费，应从原输入偏移60帧处（以0为起点）继续保留和交接，不能直接跳到下一块并丢掉它们。若按浮点数组位置计，输入起点前移的是120个值，不是60个值。

输出这边只有55帧可以接到结果中，写入位置前移110个浮点值。其余65帧容量不能当成有效声音，也不能把容量120记成已经产生的长度。输入、输出的位置分别按自己的实际计数前进；固定源码的回调封装也按各自帧数乘声道数来调整两侧指针。[3]

应用仍须保证缓冲区有效、不重叠，未消费数据没有被下一次读文件覆盖。上表解释计数，不是一份处理分配、错误恢复和所有结束条件的完整循环。

## 采样率比不是每次调用的收据

`src_ratio` 表示输出采样率除以输入采样率。[2] 它描述转换关系，却不能替代这一次实际消费、实际产出的字段。

官方 FAQ 对 `SRC_SINC_*` 举出转换内部延迟的情况，说明首次调用未必立即交出按理想倍率期待的全部数量。[1] 这里不沿用其示意数字作为承诺，也不把同样延迟套给所有转换器。

因此，不能以“提交了100帧，倍率是某个值”直接更新输出位置，也不能为凑满预期输出而认定输入已全部用完。保留状态与正确记账必须同时成立：同一个转换器对象不会替应用修复丢弃剩余输入或错误拼接输出。

## 当前块结束，不代表整段输入结束

`end_of_input` 表达的是后面是否还有输入，不是“这次缓冲区已经填到末尾”。连续音乐还有后续数据时，不应把每一块都标成整段结束。[2]

真正到达输入末尾，还应按所选转换器和接口的结束处理要求，确认应取得的输出已经处理完。读文件到末尾、最后一块被消费、输出接收完成是不同问题；不能在文件读取结束时立即用删除或 reset 代替收尾。这里不提供未经核对的统一排空次数、零输入调用配方或最终帧数保证。

接入时可以记录每次提交量、实际消费量、实际产出量和结束标志，检查未消费输入是否保留、输出是否只接上有效部分。这些是待执行检查，不是本文取得的运行记录。若出现不前进或错误，应按接口和应用的失败处理调查，不让循环无条件重试。

最后再回到音乐交接：转换后的帧坐标需要按新数据重新确认，声音是否自然衔接仍需目标工程试听。本支持不重复 Opus 预滚或循环端点换算，也不证明实时回调安全、设备时钟同步、无爆音或某种转换器音质更好。
