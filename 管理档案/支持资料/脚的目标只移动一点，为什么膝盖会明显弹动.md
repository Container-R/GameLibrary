# 脚的目标只移动一点，为什么膝盖会明显弹动

脚已经朝正确的地面目标修正，腿却在快伸直时突然显得僵硬，下一帧又明显弯下去。这不一定是目标点大幅跳动，也不一定是计算出了不连续的解：两段固定长度的骨骼，在接近完全伸直时，本来就需要较大的角度变化才能再增加一点距离。

这份说明供正在排查足部 IK 的技术动画与玩法开发人员阅读。它先用平面内的两根等长骨骼解释近伸直时的敏感性，再补充不等长两骨的距离边界，不实现角色控制器或某个引擎求解器。接触时段、目标坐标和整体运动仍应先按[脚滑排查正文](../../GameLibrary/角色动画/角色移动/脚部接触/排查原地转身时的脚滑.md)检查；这里接着回答“目标没有大跳，为什么姿态变化仍很明显”，并检查目标是否落在两骨的可达范围内。

## 用一米长的简化腿看清角度

设大腿和小腿各长 0.5 米，髋关节固定，踝目标沿同一方向远离髋。膝关节只在一个固定平面内弯曲，不考虑碰撞、关节限位、脚掌朝向和其他骨骼。令 `d` 表示髋到踝的直线距离，`θ` 是膝处两段骨骼的内角：完全伸直时为 180°，不是 0°。

由三角形的余弦定理，两段长度均为 `L` 时：

```text
d² = L² + L² − 2L² cos(θ)
d  = 2L sin(θ/2)
θ  = 2 asin(d/(2L))       0 ≤ d ≤ 2L
```

最后一个式子把目标距离转换为本例的膝内角。`asin` 的结果先按弧度理解，下表再换成度；长度单位必须一致。

下面两次都把目标远移 1 厘米，骨长保持不变。它们是本文原创计算，不是论文图线采样，也不是运行角色所得：

| 髋到踝距离变化 | 膝内角变化 | 需要增加的角度 |
|---|---:|---:|
| 0.70 → 0.71 米 | 88.854° → 90.470° | 约 1.616° |
| 0.98 → 0.99 米 | 157.043° → 163.781° | 约 6.737° |

相同的距离变化，第二种姿态需要约四倍的角度变化。这不是误差放大系数的通用常数，只是这两组输入的比较。越接近一米的最大伸展距离，再增加距离就越难单靠转膝实现；超过一米时，这个固定骨长模型根本没有可达解。把反三角函数的输入裁到合法范围，只能避免计算越界，不能让腿真的够到更远目标。

也可以看距离对角度的变化率（θ 用弧度）：`d′(θ) = L cos(θ/2)`，在接近 180° 时趋近零。因此，距离变化很小，并不意味着需要的角度变化同样小。这里讨论的是同一弯曲方向内的几何敏感性，不是膝盖从角色前方翻到后方的另一类选解问题。

## 两段不等长时，目标太近也可能够不到

前面两段恰好等长，所以只遇到了外侧的一米边界。若两段固定长度分别为正数 `a`、`b`，根部位置不变，两个关节可在平面内自由转动，末端只需到达一个位置，那么根部到目标的距离还必须满足：

```text
|a − b| ≤ d ≤ a + b
```

外侧边界来自完全伸直；内侧边界来自两段反向折回。较短的一段即使完全折向根部，也只能抵消较长一段的一部分。因此，长度不等时，根部附近会留下一个到不了的区域。Hauser 的两转动关节模型分别推导了这两种无解情形。[2] 这里说的是没有角度限制、碰撞和末端朝向要求的几何范围，不是角色骨架最终能采用的全部姿态。

换一组原创纸面数：两段长0.6米和0.4米，目标离根部0.1米。总长虽然有1米，最近仍只能到0.2米，因而不能在保持这些条件时精确命中目标。把反三角函数的输入裁到合法范围，不能使原目标变得可达，也不会把0.2米变成0.1米；提高迭代次数同样不能创造不存在的解。

这与“本来有解，但求解器没有在预算内找到”不同。排查时先比较实际骨长与目标距离；通过距离检查后，仍要看关节限位、碰撞、脚掌朝向等额外要求。若几何范围已经不允许，再讨论能否改变目标、根部或骨长，而不是只提高 IK 权重。上述数值不是角色运行结果，也不评价任何具体求解器的实现。

## 平滑目标和提高权重，不会改变这项几何关系

若目标距离在近伸直区域反复轻微变化，精确跟随它的角度也可能反复变化。目标平滑可以改变输入，但不会取消固定骨长的关系；更高的 IK 权重同样不会凭空增加可达范围。诊断时可一起画出髋踝距离、两段骨长之和与膝内角，先看明显姿态变化是否恰好发生在接近伸直的阶段。

接下来应决定允许改变什么，而不是立即寻找一个万能阻尼数值：目标能否稍微偏离接触点？角色整体位置或动作能否调整？接触是否本就应释放？骨架与网格是否允许有限长度变化？这些选择分别影响接触、碰撞、动作意图或形变，不能由这张数学表替项目决定。

Kovar 等人的 2002 年足滑清理方法提供了一种特定取舍：在接近伸直时限制膝角修正，再允许腿长变化来满足踝目标；它还会平滑根位置调整，并处理接触约束开始、结束时的过渡。[1] 这不是“所有角色都应拉长腿”的建议，更不是仅开一个锁脚选项就实现了整套算法。

论文以已有足部接触标记为输入；标记错误仍可能造成不合适的贴地。算法使用邻近的未来帧，作者讨论的在线应用需接受额外延迟，也没有把地面接触自动变成正确的全身重心表现。[1] 因此，不能直接把该后处理思路当作无延迟玩家控制方案。本文没有实现或复现论文，也没有验证骨长变化在任何现有角色上看不出来。
