# 双位置更新顺序：有限模型

[返回读者正文](../../../GameLibrary/引擎与工具/运行时系统/并行模拟/分块模拟中，为什么写不同位置仍可能互相影响.md)。

这不是 Noita 代码，也不是并发压力测试。初始 x=1、y=2；A 先读 x 再写 y，B 先读 y 再写 x。解释器在单线程中逐项执行六种满足各自先读后写的事件顺序，比较读取当前可变状态与读取独立初始快照两种策略。每个读写都是模型规定的不可分动作。

从仓库根运行，依赖仅为 Python 3 标准库：

```sh
python3 -B 管理档案/支持资料/双位置更新顺序/check.py
python3 -B -O 管理档案/支持资料/双位置更新顺序/check.py
```

[执行前协议](PROTOCOL.md)先写明六种顺序的期望结果；[执行前独立审查](PRE-REVIEW.md)在运行前核过数学和实现。[输出](result.json)是实际执行顺序解释器生成的安全 JSON，只含模型事件与数值，不含机器或进程信息。作者普通与优化模式输出逐字相同，六种事件顺序与五个非法输入控制是同一批条件，不因运行模式变成两倍不同覆盖。

这些结果不能认证真实线程、语言内存模型、任意输入类型、任意双缓冲模拟或 Noita 的安全性与性能。解释器输出 (2,1) 既可能来自快照，也可能来自先完成两次读取的原地事件排列；仅看数值不能确定实际程序采用的存储策略。
