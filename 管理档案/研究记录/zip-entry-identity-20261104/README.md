# ZIP 成员选择：四个有限观察

这是支持说明所用的原创复现材料。2026-11-04，按先审查、再冻结的规格，由同一操作者分别启动两次新进程；两份完整观察一致。另有独立的协议及结果审查，没有第三次独立原生运行。没有加载真实游戏包、解压文件或测试引擎。

## 文件与执行

- [执行前规格](PROTOCOL.md)保留四个案例和预期，批准身份见 [FREEZE.json](FREEZE.json)。规格中的准备阶段表述是执行前记录，不是对当前结果状态的判断。
- [probe.py](probe.py)只构造内存中的小型原始测试输入。
- [run_probe.py](run_probe.py)检查冻结的三个原创文件摘要后启动观察，记录完整输出并判断是否符合预期。
- [第一次输出](run1.json)与[第二次输出](run2.json)均绑定同一冻结输入。文件中的 `pass` 仅指符合该规格，不表示实际游戏交付合格。

在保留此包的独立副本中，从包目录分别执行 `python -B run_probe.py run1` 和 `python -B run_probe.py run2`。相同标签会替换该副本中的旧输出，因此不要在唯一的历史记录副本上重跑。运行器对子进程设置10秒超时；捕获上限是事后检查，不是操作系统输出配额。

这份规格限定解释器自报版本为3.12.14；它不是对二进制来源的认证。其他版本会报告环境不符，不能据此断言其成员读取行为错误。需要调查另一版本时，应保留原记录，另建版本明确的新规格，而不是改写此次预期。

公开包只含原创规格、代码和输出，不含第三方库源码、私有安装路径、进程号或本机指纹。原始协议审查曾发现输出缺少输入摘要绑定，已在首次运行前修复；未执行的草稿不算失败的库观察。原始输出未作数据删改。
