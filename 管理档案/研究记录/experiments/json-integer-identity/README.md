# JSON 数字身份：普通 JavaScript 接口的有限观察

两项物品即使各有不同的十进制编号，工具在读取 JSON 时也可能先把它们变成同一个数。本支持包观察一种具体情况：普通 `JSON.parse` 接收数字 `9007199254740992` 与 `9007199254740993`，之后能否继续区分它们。两数来自 ECMA 原例，不是本库发现的特殊数字；物品身份场景只是用途说明，没有运行游戏或库存服务。

## 实际看到的结果

实际已完成 **4 次同环境、同条件调用：2 次作者、2 次独立审者**，每次恰1个 Node 子进程，没有单独版本命令；不是4种配置或跨机器验证。[独立验收记录](NATIVE-REVIEW.md)逐项记录了该条件的实际调用与读取范围。本包已收录四组结果。四次外部 parent 与 child 退出码均为0，实际 stdout 完整，parent/child stderr 均为零字节。

四次 Node 均自报 `v24.22.1`；这是版本自报，不认证安装文件等同于某一上游源码。实际观察为：

|路径|观察|
|---|---|
|两个 JSON 数字分别普通解析|均为 Number，十进制表示同为 `9007199254740992`，严格相等，均非安全整数|
|两个 JSON 字符串分别解析|仍为两个不同的字符串|
|从已解析 Number 再转 String 或 BigInt|两者仍相同，不能恢复原文本的区别|
|从两个原始十进制文本直接转 BigInt|两者不同，这是另一输入路径|
|默认序列化第二个原文本构造的裸 BigInt|实际抛出 `TypeError`；没有修改 `toJSON` 或提供 replacer|

第一整数本身在本例可精确表示，不能说两个整数都被改变。结果也不意味着所有 JSON 解析器都采用相同数值表示，或字符串 ID 自动具有正确归属、有效性、授权和永久身份。

四次 stdout 字节相同；调用次数依据实际分别启动与外部退出记录，而非从相同文件推断。读取 [作者1输出](author-1/stdout.txt) 、[作者2输出](author-2/stdout.txt)、[独立1输出](reviewer-1/stdout.txt) 和 [独立2输出](reviewer-2/stdout.txt) 可看完整字段；相应目录另存正式 receipt、实际空 stderr 和外部 parent 的结果/退出记录。

## 来源预期、观察程序和消费者各做什么

`fixture/EXPECTED-INDEPENDENT.json` 是实现前由独立审者按固定 ECMA-262 第16版（2025）及 RFC8259推导的字面表，不从运行输出生成。依据包括 ECMA §21.1.2.5–6、§25.5.1、§25.5.2.2，以及 BigInt 转换规则；RFC8259 §6提供 JSON 数字和实现精度限制的范围。来源文本不是运行结果。

`observe.mjs` 只使用内建接口，实际记录解析、类型、转换、相等比较和异常类别，没有读取预期文件或输出预制 PASS。`consume.py` 严格检查 JSON 键、类型、顺序和值，读取实际空 stderr、源输入绑定和回执；它验证档案一致性，不认证真实执行。实际接收还必须核对对应 `parent.exit.txt` 为0及外部结果，不能单独相信 receipt 或消费者。

最终输入清单 SHA256：`4651e746d0b81904251e63c0725edb9850d3447989a8edb2d021533bfe35bd22`。其中7个输入逐字保留；本包未改写协议、程序或实际输出。协议里的“执行仍待批准”是实现前冻结时的历史状态，不是本包当前执行次数；四次实际调用发生在后续明确批准后。

## 如何阅读或在自有环境复查

在本目录下做**静态档案检查**，不启动 Node：

```sh
python -I -B fixture/consume.py author-1
python -I -B fixture/consume.py author-2
python -I -B fixture/consume.py reviewer-1
python -I -B fixture/consume.py reviewer-2
```

消费者只读正式 `receipt.json`，不把 pending 文件作为完成记录。清单内包括协议和独立表；复制时不能只取 JS 而把完整归档消费称为已复核。

若在自有环境重新观察，先准备可用且自行确认的 Node 路径，将 `NODE` 设为该绝对路径，将 `OUT` 设为父目录已存在、末级尚不存在的新绝对输出目录，再执行：

```sh
python -I -B fixture/run.py --node "$NODE" --output "$OUT"
```

每次使用新的 OUT；另行捕获 parent stdout、stderr 和外部退出码，失败停止，不用本包输出填补未运行阶段。此命令说明不表示本次额外执行。runner准备并启动前验证五个新空 HOME/XDG/TMPDIR 位置，最小环境不继承 Node 加载覆盖；这不是沙箱。运行等待10秒、TERM/KILL各最多2秒；不能保证初始进程创建可中断、检测逃离拥有组的后代或解决所有存储故障。收尾不确定时失败并保留目录，成功也保留工作目录供调用方管理。

## 预执行发现与修正没有被抹去

- v1独立静态审查发现超时首因可能被清理或诊断保存错误替换；协议首段也残留过时状态。修改为首因与次级错误分开，并保留原稿。这不是发生过的 Node 超时。
- v2独立纯 mock 发现：正式回执已写出PASS而保存再报告失败时，parent返回1，但仅读该回执的消费者仍能接受。不是实际磁盘故障或 Node 失败。
- v3改为临时回执成功关闭后再替换正式回执。纯负例在替换前模拟关闭报告失败，正式回执保持非PASS，消费者拒绝。它不证明掉电耐久性或任意发布之后错误都能回滚；外部退出码仍必须核对。
- 独立审者初次纯测试把布尔字段数量写为10，实际为9；计数断言失败后只修测试计数，不改观察条件或字面 oracle。原始失败保留在内部审查记录，不伪称所有初稿都一次通过。

作者最终纯消费者 normal/`-O` 各10方法通过，最终纯 runner mock 各6方法通过；此前正常/优化的中间4、5方法轮次也保留于内部历史。独立审者还做了自己的纯消费者检查与关闭前失败模拟，不能与作者测试或 Node 调用混算。这些只覆盖有限合成异常；没有真实注入磁盘、超时、系统权限或崩溃故障。本公开包只保留有用的安全事实摘要，不复制包含执行环境信息的历史诊断，也不重新解释历史绑定。
