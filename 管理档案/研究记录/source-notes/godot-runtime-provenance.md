# Godot 运行证据的身份边界：自报版本不等于构建来源已认证

核对日期：2026-10-31。此记录澄清本库已安装 Godot 二进制的来源对应，不改变原始日志、哈希或已经观察到的行为，也不据此宣称二进制不安全或引擎存在缺陷。

## 分开记录的事实

- 本地可执行文件（原路径省略） 的版本查询自报 `4.6.3.stable.official.7d41c59c4`。新动画夹具的 `Engine.get_version_info()` 自报完整提交标识 `7d41c59c457bd5a245092b4e7eb2d833e3b3f8c3`。
- 该二进制的实测安装指纹在本公开衍生说明中省略；集成者于本次核对再次读取文件并计算同一摘要。摘要标识实际文件字节，不证明谁构建或签发了它。
- GitHub 插件读取 `godotengine/godot` 的 `4.6.3-stable`，实际解析为 [`35e80b3a8822a9df9be390814b62f44c0a9c69e8`](https://github.com/godotengine/godot/commit/35e80b3a8822a9df9be390814b62f44c0a9c69e8)，提交日期为 2026-05-20。集成者独立重复读取该标签得到相同结果。[取证摘录](godot-runtime-provenance/tag-resolution.json)
- 研究者用公开 GitHub 插件查找自报完整提交标识，返回 `422`，错误为 `No commit found for SHA: 7d41c59c457bd5a245092b4e7eb2d833e3b3f8c3`。[查询记录](godot-runtime-provenance/author-lookup-receipt.json)明确标记人工转录；另保留[当次完整工具错误响应](godot-runtime-provenance/lookup-422-raw.json)，未为取证反复重试。

**早期固定步夹具的特别缺口：** 当前 `godot-fixed-step/results/summary.json` 没有归档当次二进制 SHA-256，只保存版本等记录。后续共享环境中的文件摘要不能回填为它当时已经测得的证据；其运行身份应以当次实际保存字段为限。

这些事实没有建立“官方标签源码 → 本地二进制”的精确构建对应。本研究没有核验该二进制的官方下载链、签名、可重现构建或完整源代码。自报字符串中的 `official` 不是本库独立认证结果。单次公共仓库查询未找到提交，也不足以确定不对应的原因。

## 对既有实验的影响

固定步、暂停输入、焦点身份、资产导入、导航查询及后续动画方法事件的结论，应限定为**各次记录所能标识的本地程序、环境与夹具输入的实际观察**；不能用后一次更完整的身份记录补齐前一次缺失字段。对于已归档二进制摘要一致的复跑，它们只提供同一文件身份下的重复观察；早期缺摘要运行仍按其原记录限制解释。两者均不是所有官方 4.6.3 发行物或其他平台的复现。

官方 4.6 文档仍作为其公开 API 说明引用；固定到上述官方提交的实现可作独立语义参照。但不能把二者与本地运行结果拼成“已证明这段源代码正是本地执行的代码”。若后续取得可信构建来源或在可确认身份的发行物上独立复现，应新记环境、哈希、差异及结果，不倒改旧日志使其看似同一来源。

因此不删除已有行为证据，也不把文章整体自动升为 `verified`。一致性校验器检查文件/记录是否一致，不能补上来源真实性认证；它的 65 项历史检查与此身份问题是不同层次。
