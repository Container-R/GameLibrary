# 按玩家分组的场次完成率比较：复现材料

这些材料复算正文的原创教学账表，不代表真实玩家数据、在线实验或区间覆盖率校准。正文中的目标、假设、推导和分母解释才是方法说明；脚本不替代实验设计及数据质量审查。

## 文件

- `player-ledger.csv`：十二名玩家的完整结果账表。
- `compare_player_ratios.py`：Python 3 标准库程序，使用 `Fraction` 计算残差、样本协方差与比例代入方差，再以浮点平方根输出标准误。
- `reference-output.json`：2026-11-06 使用 Python 3.12.14 执行所保存的标准输出。分数以字符串保存；浮点数只用于标准误及其百分点值。

进入本目录后运行：

```bash
python3 compare_player_ratios.py player-ledger.csv
```

程序只向标准输出打印 JSON，不创建或覆盖任何结果文件。失败时向标准错误输出原因并以状态码 2 退出。复核时将当前标准输出与保存的 JSON 对比，不需要改写保存结果。

## 输入含义

CSV 一行对应一名原定玩家，字段如下：

| 字段 | 含义 |
|---|---|
| `player` | 全表唯一的玩家标识 |
| `arm` | 原始分配，取 C 或 T |
| `successes` | 规定结果窗口内的已知完成数 |
| `starts` | 规定开始窗口内的合格开始数 |
| `unknown` | 合格开始中尚未确定的结果数 |
| `mature` | 本计算要求填 `yes`，表示观察窗口已成熟 |
| `quality` | 本计算要求填 `verified`，表示输入提供者已核实记录完整性与身份等条件 |

`mature` 与 `quality` 是输入方的声明，脚本无法自行证实。没有匹配日志不等于确认零场。程序拒绝重复玩家、无效分组、非负整数以外的计数、完成与未知之和超过开始数、存在未知、未成熟或未核实的行；还要求每臂至少两名玩家及正的开始总数。通过这些检查只说明这几个输入约束成立，不证明人员清单完整、随机分配正确或玩家独立。

## 核算范围

程序按原分配计算 `K、ΣS、ΣN、S̄、N̄、R̂`、零场人数及最大玩家场次占比，再计算每名玩家的残差 `U=S−R̂N`。它检查残差和为零，并核对残差方差与样本方差/协方差展开一致。两臂方差相加要求正文声明的独立玩家模型，不能当作任意随机化设计的精确方差。

保存输入得到 C 为 `8/16`、T 为 `5/8`，差值 `1/8`。各臂代入方差分别为 `3/256`、`3/128`，差值代入标准误为 `3/16`。程序不输出 p 值、置信区间、等效性或上线判断。

作者还执行了有限的输入拒绝检查，并核算确认零场删除与不等臂人数的变体。这些是实现与算术核对，不是独立审稿，也不校准抽样近似。脚本没有运行生产查询、统计平台或原论文程序。
