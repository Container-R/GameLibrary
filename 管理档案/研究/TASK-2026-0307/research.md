## 本轮结论与范围

建议题目：**游戏 UI 配置回归的约束建模与组合覆盖**。

读者为能执行回归的 QA 与 UI 程序；不要求事先会组合生成算法。文章帮助他们把支持矩阵、离散设置和布局风险转为可核对的配置计划，并把每行接到实际检查。交付是可重建的模型、明确分母的覆盖报告和带判据的执行设计，不是证明游戏无缺陷，也不是 ACTS 操作手册。

真正困难有三处：产品限制可能经第三个参数间接排除一个对子；配置压缩可能遗漏风险所需的三元条件；配置生成成功仍可能没有经过设置应用路径、没有到达检查点或没有判断布局。因此主线必须连续讲完“模型→覆盖目标→合法性及覆盖复核→实例化→结果与空缺”，不再只用四行二元表解释 111 缺失。

## 原创有约束模型与实际验证

以下是虚构产品约定，不是现实平台限制。只检验稳定设置后的字幕预览布局，固定构建、同一预览内容包和默认存档，不研究设置操作先后。

| 参数 | 域 | 本例含义 |
|---|---|---|
| P 平台配置 | desktop, handheld | 两个测试产品配置；handheld 在本范围内只支持内置紧凑视口 |
| V 视口 | compact, wide | 固定1280×720和1920×1080的测试视口，不代表所有分辨率 |
| U 界面缩放 | 100,125,150 | 三个产品离散档位，单位百分比 |
| T 字幕字号 | normal,large | 固定24与36逻辑单位；实际渲染换算另由UI规范给出 |
| C 安全区 | 0,5 | 四边分别内缩对应视口宽/高的0%或5% |

两条产品约束：

1. P=handheld ⇒ V=compact。
2. U=150 ⇒ V=wide。

第二条在本例表示产品不提供紧凑视口150%档位，不是把发现的布局错误排除掉。实现误允许这个档位时，属于限制执行/非法输入测试，应另测拒绝、回退或提示；不能通过覆盖模型把它假装不存在。

本模型原始笛卡尔积48行，完整合法行28行。间接排除 `(P=handheld,U=150)`：前者要求compact，后者要求wide，无法同时满足。若检查一个对子时只读取直接提到这两列的约束，就会漏掉此矛盾。

对于参数组 J，合法需求集合定义为 `R_J={r在J上的投影 | r是满足全部约束的完整配置}`。某个局部 tuple 合法，当且仅当至少能扩展成一行完整合法配置。先求分母再检查候选行；不要拿生成器输出反过来定义“所有合法需求”。大模型无法穷举时需要合适的约束求解/覆盖测量工具，本例穷举是为了让方法透明，不声称可扩展到任意产品。

覆盖目标：所有五列的全部合法两两值组合，加上 `(U,T,C)` 的全部合法三元值组合。本例假设本次改动共同改变缩放后的布局宽度、字幕行高和可用区域，因此单独加固这组三元关系。P、V的风险仍按全局两两处理；若改动涉及平台专用布局且与三项同时交互，应扩展目标，不因已有计划就固定强度。

逐组合法对子数：PV=3，PU=5，PT=4，PC=4，VU=5，VT=4，VC=4，UT=6，UC=6，TC=4，总45。UTC三元合法值组合12个。两个集合中的成员带参数组标识，因此目标共57项，不把不同阶数的目标混成一个“风险百分比”。

运行 `python3 check_model.py > model-result.json`。Python标准库脚本先从48行筛出28行，贪心选行；随后用另外一段枚举逻辑按每组值域询问是否存在合法补全，再核对候选投影。两段逻辑仍共享同一产品约束函数，不是独立审稿或对需求本身的独立认证。完整合法行、合法tuple清单、候选行和负对照缺口均保存在 JSON。

## 从一行变成一次可判断的测试

下面是文章应展开的原创测试设计，不是已经执行的记录。

以第12行为例，测试目标是固定预览语料在大缩放、大字幕、内缩区域中的稳定布局。先规定语料：一个短句、一个指定长句、一个带说话人标签的双行样本，保存具体文本与内容版本，不能运行时随机换一句。所有12行使用同一内容包；若每行有3个分别判断的内容样本，则执行工作量至少是36个内容检查，不是“12次就测完”。新语言/新字体加入时应评估是否需要作为参数或独立测试套件，不把这三个样本代表成全语料。

1. 使用指定构建，恢复每行的默认存档与预览关闭状态，载入对应平台/视口夹具。建立起点后，按固定步骤通过产品设置入口应用U/T/C。直接改内存会绕过设置应用机制，除非此次目标明确只测布局函数。
2. 读取最终生效值与视口，确认与计划行一致。UI显示150%而布局仍使用125%，不能把该行算作150%已覆盖。读取值最好包含渲染使用的值而非只读配置文件。若夹具无法提供目标设备，不得用desktop替代后仍记录为handheld。
3. 等待明确完成条件，如布局版本号对应本次设置应用且资源加载完成；超时上限由项目预算定义。超时作为未到检查点/待调查，不能当布局通过。等待完成不覆盖异步切换瞬间。
4. 在每个预览样本显示后、下一步改变UI之前检查约定规则。例：字幕内容与样本一致；必须显示的文本未截断；字幕可见字形及背景在要求的安全区内；说话人标签不覆盖正文。换行和最大行数需产品明确，不能拿上一配置截图逐像素相同当普遍期望。
5. 判据可以由语义文本、字形/控件包围区域和人工截图复核组合实现。文本节点存在不证明画面可读，包围盒落在安全区不证明没有其他控件遮挡；文字/视觉判据的盲区要明确。截图作为证据不自动给出正确结论。
6. 每个检查记录计划行、实际值、构建/内容/模型版本、检查点是否到达、判据版本、结果和必要证据。失败、未运行、夹具阻塞、判据无法判定分别保存。一个内容检查失败也不等于该配置没有被执行；“执行覆盖”与“通过率”分开。

覆盖应从指定判据实际到达检查点的记录重新计算。若第12行设备受阻，计划仍是45/45和12/12，但实际检查需要重新投影已执行行并列出缺口；不能将未执行行留在已执行集合。不同判据的执行覆盖也可能不同，例如文字检查完成而截图复核未做，不宜给整行一个万能“已测”。

## 拟正文大纲

1. **设置选项都单独测过，为什么布局仍缺联合条件**：从同一预览布局变更切入，说明本文终点是可执行回归计划。
2. **把产品支持范围写成参数、取值和约束**：五参数示例，取值与连续边界的区别，合法性与临时不测的区别，间接PU不合法推导。
3. **按改动机制选择需要覆盖的参数组**：全局两两加UTC三元的理由、替代全枚举、成本由配置建立及判据执行共同决定。
4. **先列合法需求，再检查选出来的行**：完整合法配置投影定义、45+12需求、12行表和8行基线比较、删默认行负对照。正文保留关键数字和一个投影解释，完整集合放附属文件。
5. **生成表之后，逐行建立真实检查**：第12行端到端步骤、内容夹具、有效值回读、等待条件、布局判据与证据。
6. **执行少一行时，覆盖报告怎样改变**：计划、实际执行、检查结果分开报告；模型变更时重新验证旧行，旧日志仅在版本兼容明确时复用。
7. **配置不包含抵达它的操作顺序**：简短界定另一个模型，不带入L/S/P大段排列；列出本范围剩余风险。
8. 来源与复现材料。

这已是可写成完整方法文的研究基础，但尚非候选正文：仍是编辑笔记语体；布局规则需要在正文中更清楚界定为案例规格，ACTS只作为可选生成器说明，不能使读者误以为本例已导入其界面。没有必要为了发表去补一段虚构的引擎执行。
