[返回正式方法](../../../../GameLibrary/项目管理与测试/制作管理/交付计划/小型可玩版本的依赖计划与交付判断.md)。正文已包含必要活动、输入、公式和时间表，附件不替代方法解释。

## 运行和实际副作用

使用 Python 3 标准库，无需安装依赖。在保存这些文件的目录中运行：

```sh
python3 reproduce_case.py
```

程序先执行教学自检，然后向标准输出打印结果，并在**脚本所在目录写入或覆盖** `case-data.json`、`calculation-results.json`、`dependency-network.svg`、`resource-timeline.svg`。如需保留原文件，请先在单独的复现目录复制脚本。程序不联网、不安装软件，不更改远端或项目计划。

活动输入实际定义在脚本的 `TASKS` 常量及明确的计划变量中；`case-data.json` 是该输入的导出快照，不是由程序读取的外部配置。修改 JSON 本身不会改变计算。原版脚本的输出应与保存的 `calculation-results.json` 一致；两个生成的 SVG 对应正文的原创图，可用已有 SVG 查看器查看。PNG 查看副本不随本批发表。

## 核对范围

脚本检查固定教学网络的前后推、路径长度、共享浮动、两个资源顺序、局部时长变化及一次状态更新；用明确的区间检查 FS、所列单人占用和 QA 不可用窗口。交接 U 的第二名人员另作显式检查；构建机、测试机各只有一次已声明占用，按正文人工核对。

它不是通用多资源日历求解器，不解析真实项目记录，不搜索全局最优，不预测概率，不验证输入接收或游戏质量。代码中的断言不是软件或制作验收；运行时不要启用会移除断言的 `python -O`。全部任务、时长、资源和变更都是原创教学假设，没有真实游戏、排程产品或真人测试。
