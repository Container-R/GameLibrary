# 未发表效用选择器研究包窄评审

评审范围：模型辅助审查，阅读 protocol.md，并按 input-manifest.json 所列冻结提交定位读取旧支持与三篇邻接正文；同时核读 selector_model.py 与 results.json。结果文件记录 Python 3.12.14 下六项协议断言通过；本次未独立重跑，未重新核读外部原始来源。本结论只评实验设计和证据能支撑的范围，不是人类验证或正式发表审稿。冻结起点以协议所列提交为准。接续任务为 TASK-2026-0309，不改变旧支持任务 TASK-2026-0231 的历史状态。

## 最重要的三条结论

1. **值得继续，但真正新增的问题是“惯性属于哪个候选”，不是再次证明加分能减少小幅切换。** 实验 1 能构成重要反例：动作类型相同、目标不同，给类型加相同奖励不会改变两目标间的排序；给 (类型, 目标) 加分才保留这次具体选择。这补上旧文“当前选择”未明确的粒度，并与对象条件篇形成有用区别：对象条件讨论读取谁的事实，本研究讨论记住谁的选择。不要据此推出目标身份就足以表示一次执行，或所有项目都应该锁定同一目标。
2. **六组实验能验证有限选择规则，却尚未形成完整的接入任务。** 实验 2–5 大多把旧文已明确的边界变为可执行检查；实验 6 有新增价值，但它把有效性输入、检查与释放都设为及时且同步，因此只证明两种调度可以分开，不能证明运行时安全、真实响应时间或低成本。若最后只有六张分数表，仍是比旧文严谨的玩具提醒，不足以独立支撑一篇新的工程文章。
3. **最小补强不是搭架构，而是让一个持续行为走完“保留目标—资格改变—退出—恢复”的验收任务。** 保留现有确定性实验，增加一个有明确开始、继续、退出语义的同步行为夹具，并至少加入开始资格与继续资格不同、评分尚未刷新但旧目标失效两项反例。最低持续时间先作为另一个明确的选择政策与加分对照，不扩展异步执行协议。这样能交付可接入的选择契约和回归记录，而不重复邻接文章。

## 各实验能排除什么，不能推断什么

### 1. 类型奖励与具体候选奖励

该对照能排除“给当前动作类型加分就能稳定具体目标”的误解。现有代码两种策略均从 A 出发，结果已记录候选键：候选奖励保留 A，类型奖励切换六次。此处证据充分；若只记录动作名，两次输出都叫“采矿”，会掩盖目标切换。

应另记录目标切换造成的实际 start 次数。协议已规定只在候选键改变时 start，但现有代码只记录 transition，未实现 start/stop 调用，尚不能检验调用侧是否遵守这一约定。反例的分数、奖励与换目标成本都是自定，不能把较少 start 自动解释为更高产出、更好战斗行为或玩家更满意。

后续 900 对 400+50 只证明这个具体大分差可越过奖励，不证明所有紧急事件都可及时抢占。若紧急候选根本没被刷新或枚举，再高的分数也不会被比较。

### 2. 资格删除、零分和空集合

此实验能证明资格集合与分数必须按本规则分别表达，但“从输入字典删除旧目标”本身已假定资格判断正确。最重要的缺口是开始资格和继续资格：例如角色已占用唯一充电接口，此时“接口空闲”变为假，不应仅凭此中止自己的充电；反过来，接口损坏则应使继续资格为假。只测试外部删除无法发现把开始谓词误用作继续谓词的问题。

需分别检查三件事：合法零分候选仍可被选、无效旧候选即使有奖励也不能留下、空集合不暗中复用上次选择。None 是选择结果，不天然等于执行器已经释放资源。

### 3. 迟滞扫描

两候选且当前候选仍合格时，固定 D=U_B-U_A：当前 A 在 D>h 时换 B；当前 B 在 D<-h 时换 A。在等号处保留，确实产生两个不同切换边界。

现有扫描从 A 出发、步长为 10，包含 -50、+50；结果在等号处保留，且仅在 +60 和 -60 记录切换，已覆盖协议边界。多于两候选时，不能把这条往返轨迹当作所有循环切换的完整解释；本篇也不需要扩展到任意候选稳定性理论。

### 4. 大幅交替与最低持续时间

每一步分差跨过奖励，可反驳“h 保证最短行动时间”。这是反证，不是最短持续时间政策的实现或评价。还应给每步明确的时间戳，避免读者把“步数”当作时间。

若题目承诺区分最低持续时间，建议只加一个小对照：候选仍合格时，显式截止时间前不因普通分差切换，到时恢复比较；候选失效则按预定例外退出。必须写清这是“有效期间的普通切换锁定”，不是任何情况下都持续满 T。若设计要求真的不可中断，需改成执行层合同，超出本研究。

### 5. 缩放

固定加法 h 对统一正比例缩放不保持相同选择，连 h 一起乘相同正数则保持比较关系。这是规则的代数性质。现有代码使用基础分 500/530、当前 A，得到 A→B→A 的三组对照，已展示这种跨门槛变化。不能任取输入后凭未改变的结果否认尺度依赖。

不能从统一乘 10 推广为任意评分曲线变换、分项重新加权、截断或归一化均可用同一个办法补偿。也不能反推乘法奖励天然更好。

### 6. 评分与资格检查分频

现有 40ms 失效恰好落在 10ms 检查点，只能展示最好对齐的一个样本。增加 41ms 失效：按所设检查节奏，下一次检查应为 50ms，而非 41ms。这能让读者区分真实失效时刻、输入可见时刻、检查时刻与模型释放时刻。

现有实现每个检查点直接构造带分数的资格字典，并在失效时立即再次 select。它相当于失效触发额外选择，而非严格只有每 100ms 才能重选；也没有模拟评分缓存或真实评分成本。接入时还须明确旧分数缓存如何与新资格集合组合：旧目标被删除时不再竞争；新增合格目标没有分数时，是立即触发评分、等待普通评分，还是暂时返回 None？选一种简单政策并测试，不必同时设计三种。否则“高频资格检查”可能被读成“高频获得了完整的新选择”，而当前结果只证明预先可用分数下的重新选择。代码中的释放只是变量置 None，随后同轮赋为 B，并非执行资源释放。

不能据此声称有效性检查总是便宜、感知无延迟、10ms 是推荐预算，或真实动作会同步停止。邻接 Killzone 3 文章已经承接停止握手、迟到结果和部分效果，这里应链接而不再造取消框架。

## 将研究接成一个完整工程任务

建议具体任务：**给双矿点与充电点之间的持续移动行为接入目标级保留规则，并交付可重放回归用例。** 不要求游戏引擎，仍可在现有标准库夹具中完成，但必须展示从输入到执行调用的完整有限闭环。

1. 固定项目合同：候选键=(动作类型, 目标)，目标不复用；哪些条件只允许开始，哪些允许继续；零分合法；无候选时退出当前行为并等待；同候选不重复 start；退出同步。明确这是测试模型合同，不是行业通用要求。
2. 保持六组规则实验作为单元证据。补上继续资格区别、非对齐失效时间，以及缓存分数遇到新资格时采用的唯一政策。写出预期结果再运行，失败保留并解释。
3. 增加一条连贯轨迹：A/B 小分差变化仍走向同一矿点；另一个点明显更优时切换；当前目标失效时不受奖励保护；无候选时停止；恢复一个候选后重新 start。记录选择原因、目标、基础分、奖励、资格原因、评分时间、检查时间、start/stop 次数，不只记录最后赢家。
4. 加分与最短持续时间只比较一个共同轨迹，说明两者回答不同约束。若后者不是文章承诺，则删去实现，只保留现有反证并明确“不实现持续时间保证”。
5. 验收限定为模型规则正确、重复启动被避免、失效候选不被保留、同候选恢复/退出语义无歧义。效率和游戏效果必须有真实项目记录才能另下结论。

这项任务的交付物是短小选择器、单个同步执行夹具、逐步输入输出和一个用例说明。不要增加通用调度器、对象生命周期系统、取消管理器或性能基准体系。若不能完成上述闭环，优先把现有实验并入旧文的可执行补充，而不是仅凭更多表格另立新篇。

## 证据与发表边界

当前原始来源可支持惯性、评分尺度、上下文保留等背景；候选键、严格门槛、分频调度及测试结果都是作者自定模型的论证。未重新核验来源前，不增加“原作者建议此算法”一类归属。即使全部断言通过，也只能称“确定性模型回归通过”，不能称引擎复现、生产验证、参数推荐或游戏体验改善。
