# 同步候选行为夹具：运行前验收协议

本协议先于首次执行写定。全部分数、目标事件与工作次数均为原创人工输入，不是游戏测量或原始文献算法。候选键为 `(mine, A)` 与 `(mine, B)`，目标身份不复用；恢复表示同一对象恢复可用。

## 合同

单角色 actor、单决策所有者，无并发。开始资格为目标可用且空闲；继续资格为目标可用且被 actor 占用。start 成功占用目标并创建一次执行；stop 同步释放目标；update 只加一人工工作计数。新执行计数重置，计数不是游戏收益。失败的 start 无副作用。本合同不处理部分成功、异常、异步停止、目标 ID 复用或外部抢占。

每 10ms 先检查当前继续资格与执行完成（两者都读，失效理由优先），必要时 stop 并清空。然后仅当 t % 100 == 0 时重新获取当前时刻资格与基础分。当前候选用继续资格，其余用开始资格，候选级奖励 h=50；严格更优才替换当前，等分保留。无当前时按稳定键破平局。非普通评分时不使用旧分数补位。换候选先同步 stop 旧行为，再尝试 start 新行为；只有成功才写 current。失败保留 None，不在同一轮重试。最后若有 current 才 update；由本次 update 达到完成门槛将在下一次检查清除。

## 预期的连贯轨迹（0–630ms，步长 10ms）

- 0ms：A/B 都可用，600/590，start A。
- 10–90ms：A 继续，不能因 A 已占用而重复 start 或退出。
- 100ms：600/620，小反转仍保留 A；110–190ms 继续。
- 200ms：600/700，大反转，stop A 后 start B；210–240ms 继续。
- 241ms：A/B 均变为不可用，信息立即可见，但不是调度检查点。
- 250ms：检查发现 B 无效，stop B、释放占用、current=None；不得 update 或立即重选。
- 260–290ms：等待。300ms：新鲜评分候选为空。310–350ms：等待。
- 351ms：A 恢复可用。360–390ms：尚不评分、不 start。
- 400ms：新鲜评分 A=0，合法零分仍 start A；400/410/420ms 各 update 一次。
- 430ms：检查完成，stop A，清空；440–490ms 等待。451ms A 不可用、B 恢复。
- 500ms：B=900，可开始但注入一次 start 失败；保持 None，目标不被占用；510–590ms 不重试。
- 600ms：重新评分，start B 成功；600/610/620ms 各 update 一次。
- 630ms：检查完成，stop B，清空。

成功 start 4 次、start 尝试 5 次、stop 4 次、update 31 次。占用数始终不超过一；每次成功执行都有唯一编号，同一执行中不重复 start。241→250ms 的 9ms 仅为已设检查时钟的样本，不是引擎延迟测量。

## 附加断言

1. 开始后的 A 满足继续资格但不满足开始资格；普通评分仍收录 A。
2. 600+50 与竞争者 650 相等时保留当前；无当前时反向插入字典的同分 A/B 仍选 A。
3. 补充失败换候选检查：A 运行时 B 明显更优但 start 失败，必须先 stop A，current=None，两个目标均释放，本轮不能回退重启 A。
4. 复用原分数反例，不扩展框架：600/610 与 610/600 六步交替，候选奖励保持 A；类型奖励六步均换。500/560 与 560/500 六步交替，候选奖励也六步均换。以 100ms 标记各比较时刻，不代表最低持续时间保证。
5. 每个 tick 输出 guard、普通评分快照（或 null）、调用顺序、最终 current、占用、计数与累计调用次数，确保完整回放而非仅最终赢家。

这些检查只验收此同步合同，不验收寻路、动画、物理、性能、体验或生产安全。未实现最短持续时间政策。
