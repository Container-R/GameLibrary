# 主持人提示后的通关，不能验证无提示关卡引导

> **历史技术补充（迁移衍生），不是当前读者书。** 当前阅读请见[《主持人提示会怎样影响关卡测试结论》](../../../../GameLibrary/项目管理与测试/玩家测试/关卡引导/主持人提示会怎样影响关卡测试结论.md)。以下保留旧正文的完整技术上下文、来源和未执行范围；此次只增加历史标记并调整链接，没有重新运行或重新认证历史主张。原路径与前后文件绑定见[迁移记录](../../迁移记录-source-group.json)。


## 这条结论究竟限制什么

研究问题若是“首次进入关卡的目标玩家，能否只依赖发布版本已有信息找到出口”，主持人说出出口方向后的完成，只能证明**在包含该帮助的条件下，发生了完成行为**。它不能单独证明原有引导足够，也不能反向证明玩家永远不可能自行找到出口。援助发生时，原本无额外提示的观察条件已经改变。

这里的“无提示”准确说是**无研究人员额外提供的解题信息**，不是禁止游戏内提示、玩家选定的无障碍功能、翻译或正常辅助设备。评估对象可以本来就包括内置提示系统；需把该配置写进研究问题。让主持人救场以继续研究后续内容也可以是合理选择，问题在于不能把不同条件的证据合并成一句“引导通过”。

本稿是一份窄范围方法研究，不是试玩研究实绩。下文记录、场景、决策卡均为原创假设，没有实际参与者、计时结果、成功率或改版收益。

## 原始资料支持到哪里

**S1：Valve开发者经验。** David Speyrer与Brian Jacobson的原始幻灯片把设计与实验质量分开审视（PDF第3页），在模拟居家游玩的条件下建议不提示、不回答问题（第10页），建议非诱导式提问（第11页），并提醒看趋势、避免过度修正（第19页）。这是开发者方法经验，不是本文方案的对照实验。[原始PDF](https://cdn.akamai.steamstatic.com/apps/valve/2006/GDC2006_HL2DesignProcess.pdf)

**S2：另一种研究目的允许救场。** GDS的“Design the tasks / Run a session”建议目标说明中不泄露解法、主持人大多观察聆听；同时允许参与者完全卡住时帮助其继续，以获得后续信息。这是公共服务可用性研究指导，不是游戏行业验证报告。[原始方法页](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)

这不是必须选边站的冲突。两者提示应先定义测试条件与要回答的问题。**以下观察分层、干预标记和接收流程是本稿原创的工程化推导，不是Valve或GDS指定的统一编码标准。**

## 先锁定一个可以被反驳的主张

不要从“这个关卡好不好”直接跳到“加一盏灯”。把本轮要判断的主张缩小：

> 在指定构建、入口存档、默认导航配置和目标玩家经验条件下，未接触该关卡的玩家是否能够识别可用出口，并完成门交互，而无需研究人员泄露解法？

“识别”“操作”“完成”不是同一事件。玩家可能知道出口在哪，却不知道交互键；可能会操作门，却以为门不是目标；也可能在不知道方向的情况下随机碰到终点。不要让一个终点触发器替代全部认知证据。可观察行为能支持一种解释，但不能直接读取玩家的心理状态；必要时用事后、非诱导追问补充。

测试前留下：构建与存档标识、任务原文、可用游戏内帮助、目标玩家经验、是否接触过路线、成功终点、结束/救场规则、待区分的其他原因。时间限制如有，应是该轮预先定义的可执行边界，不是事后为了漂亮结果移动的门槛；本稿不提供通用秒数或样本数。

## 五栏分离：不要把结论写进原始观察

| 层 | 应记录 | 常见混淆 |
|---|---|---|
| 可观察行为 | 对象/动作/顺序、构建与对应记录位置；必要时保留参与者原话 | 把“走回入口两次”直接写成“没有看懂灯光” |
| 主持人/设备介入 | 发生时点、原话或操作、谁提出、改变了什么信息/输入条件 | 只记录最终进门，遗漏“试一下右边的门” |
| 解释与竞争假设 | 可能是出口不显著、目标不明、交互问题、探索意图或实验条件问题 | 由一次绕路断言所有玩家迷路 |
| 设计决策 | 选择的改动、负责人与成本/风险、为何优先；哪些假设仍未排除 | 把“团队同意加灯”写成“加灯已解决” |
| 改后验证 | 新构建、保持/改变的条件、实际新观察与未解问题 | 让已经听过答案的人再过一次，就宣称首次引导有效 |

观察定位可以用视频时间码或事件序号；后者不假装测过秒数。没有录制授权时不要求录制，按允许方式记录。公开案例不应包含可识别参与者的数据；本稿的虚构记录也不能混入真实研究库。

## 自动编码：粗标签一致，不能替细工单验收

**S3 的有限启发。** Ostrovsky、Ungermann 与 Donkin（2025）的案例是 31 人词语识别记忆研究，不是游戏试玩。标签评估随机抽取 10% 的测试试次，由论文作者阅读同一批转录文本，使用与模型相同的候选标签评分。八标签精确一致为 36%；将双方标签合并为“确定／不确定”后，一致为 82%。这不是更换模型后的进步，也不是可迁移到游戏的基准；作者将评估定位为概念验证与内部检查示范。[出版商全文：Methods；Text analysis / Effectiveness test；Evaluating the efficacy of the framework](https://link.springer.com/article/10.3758/s13428-025-02800-5)

下面是原创集合推导，不是对该研究数据的复算。对同一批非空条目（N > 0），设人工细标签为 H、模型细标签为 M，双方采用同一固定、确定性的合并函数 f，则：

`H = M ⇒ f(H) = f(M)`，反向不成立。

因此，按相同条目逐项等权计数、均以正数 N 为分母时，粗标签的精确相等比例不会低于细标签的精确相等比例。这一论证不是对 kappa 或类别平衡指标的保证。原先不同的标签被归入同一类，就可能增加一致；单凭这个增加，不能断言系统更理解玩家。若同时换了样本或权重，也不能套用这个比较。

**一个未执行的生产反例：** 团队把“目标不明”“路线线索不显著”“不知交互键”都归入“需要帮助”。假设人工给第一类、模型给第三类，粗标签相同，却分别指向目标说明与交互提示的不同工单。这里没有判断哪位评分者正确；反例只说明粗一致没有检查这项分歧。即使细标签一致，也仍不等于确诊玩家心理或改动根因。

接收人应先写清输出将触发什么决定：

- **只进入复看队列：** 可以按“需要帮助”这个粗筛任务核对遗漏与误收，并明确仍由复看决定修改什么；本文没有为它提供合格阈值。
- **分别派发修改工单：** 必须核对会改变工单去向的细类别区分，不能拿粗筛的一致率代替。如果主动放弃这些区分，就也应放弃由这些细标签自动选定改动。

同一转录文本上的标签比较还共享了文本输入：若文本已经漏掉否定词或混入主持人提示，双方标签相同也不能单独揭示该输入问题。应继续保留五栏中的原始观察定位和介入边界，把机器标签放在解释层，而非重新命名为“玩家原话”。这不是完整转录验收方案，也没有新增音频处理、模型运行或游戏研究结果。

## 干预应显式标注，但不要把所有支持都污名化

建议按**是否改变本轮所考察的信息或操作条件**分类，而非一概把“主持人说话”计为失败：

- **任务条件澄清**：重复既定任务，仍需记录；若措辞新增了路线信息，应升级为解题提示，不能因为口头称它“澄清”就例外。
- **非解题的研究互动**：提醒表达想法、询问当前意图，可能打断注意或改变行为；记录时点，不假定完全中性。对紧张战斗可选择事后追问。
- **解题援助**：指出门、确认正确路线、讲解被测交互或演示操作。此后的相关行为归入援助条件。
- **技术恢复**：崩溃重启、恢复损坏存档、接回设备。将受影响段标为技术中断；不能仅据此归因为被测关卡引导失败，也不能当作完整无干扰成功。若崩溃或设备兼容性本身属于产品问题，应另记缺陷与体验影响，而不是从研究报告中删除。
- **预定参与支持**：翻译、辅助设备或约定协助。只要不额外泄露待测解法，它们可以是目标使用条件的一部分；若同时提供了解题信息，另记实际影响。
- **停止/退出**：尊重参与者停止与不适，不为维持“自然观察”拒绝必要帮助。结束本轮问题的观察，并不要求结束所有可能有价值的后续访谈。

干预污染的范围也不是整场一刀切。讲出出口位置影响这段路径发现及后续同路线首次学习判断；它未必破坏一个独立菜单任务。但若后续依赖已泄露的知识，应保留依赖标记。不能把救场后下游成功补填成上游成功。重载存档只重置游戏状态，不会抹去玩家已经学到的路线；不能把同一人回到检查点后的完成重新归为首次无额外提示发现。

## 一个可以直接推翻错误汇报的静态反例

假设关卡只有“水泵房出口”这一研究任务。以下只是人为构造的事件序列，不来自真实游戏：

| 序号 | 假设事件 | 允许的记录/推断 |
|---|---|---|
| E1 | 玩家进入水泵房；既定任务为离开该区域 | 起始条件；没有要求看特定物件 |
| E2 | 玩家巡视平台并返回入口 | 发生了回访；不知道其意图，不能先定性为迷路 |
| E3 | 玩家问“是不是已经没有别的路了？” | 原话表达疑问，不自动代表所有线索不可见 |
| E4 | 主持人说“右侧灯下面那扇门可以开” | 明确新增路线和可交互信息；援助条件从这里开始 |
| E5 | 玩家走向该门并打开，进入下一区域 | 援助后完成；不能回填为独立发现出口 |

错误摘要：“本轮玩家顺利通关，所以当前关卡引导已验证。”

合格摘要：“在研究人员指出门位置与可交互性后，假设记录出现完成。此前的独立发现问题没有被该完成事件回答；需要区分目标理解、路线显著性与交互可见性。”

也不要改成另一个过强结论：“原关卡一定不可解。”E4截断了继续无援助观察的机会；本例没有那个反事实结果。若预定判据要求在某边界前完成，可以报告该边界内未达到判据，但不扩展成无限时失败。即使需要统计，也应分别披露未援助完成、援助后完成、退出、技术中断及各自分母定义；不能删除被提示者再夸大独立完成比例。本例不计算任何实际比例。

## 从现象到小步生产决策

对E2–E5，一个可讨论的改动是增强门与环境的区分；它只是候选，不是已确诊根因。另一些可能性是任务目标含混、门交互约定未学会、玩家有意探索。主持人给的是位置加功能的复合提示，因此不能从E5区分究竟哪部分帮助奏效。

把生产工单写成可审查的决策卡：

1. **问题与证据**：指向原始事件和干预边界，不只写“玩家迷路”。
2. **假设与替代解释**：声明增强门的辨识度要验证什么，仍不能解释什么。
3. **最小变更**：选定一个可识别的改动及构建；若同时改灯光、任务文本、路径与交互提示，记录它是组合方案，后续不能独占归因于灯光。
4. **风险与接收人**：关卡设计负责意图，美术负责视觉语言，QA验证功能与回归，研究负责观察条件，制作负责优先级和成本。修复功能缺陷与验证玩家理解各自留证。
5. **复测门槛**：测试新的引导主张时，优先安排未见过解法且符合研究目标的参与者；重返者能研究记忆、操作或回归，却不能自动代表首次发现。配置、任务措辞和版本变化都需披露。
6. **尚未完成**：改动落地不等于证据闭环。实际复测若仍有相同现象，应保留，而非改写原目标为已通过；若没有复测预算，状态是“已改待验证”。

不要求一次小规模观察证明总体比例或因果收益。它可以足以暴露一个值得修复的风险，是否立即改动取决于影响、置信度、成本与可逆性；决策有理由不等于结果已证实。反过来，未复现也不能证明不存在，因为招募、路径与运行条件都可能不同。

## 本稿的实际验收状态

- 已做：两份独立机构原始方法资料及一项非游戏记忆研究的定向核对；构造并分析援助后完成、标签合并与工单分歧的逻辑反例。
- 未做：真实招募、试玩、录屏分析、任何版本改动、改后复测、统计或收益估计；未运行模型、处理参与者音频或复算论文数据。
- 可直接复用：五栏记录结构、干预边界、决策卡字段；使用前应按项目和研究问题调整。
- 不应复用为事实：虚构水泵房事件；不能拿它填真实项目的成功率、问题频率或人员表现。
