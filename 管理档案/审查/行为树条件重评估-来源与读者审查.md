# 行为树条件重评估：来源与读者审读摘要

2026-11-02。支持稿 SHA-256 `a37459d420b91b3cf2a1a58793fd8cfb953e03f75807ac7e6b6b2b0a9a8f01aa`；主文当前 SHA-256 `80ffb44904f88fae8878ed27d0529c06bc8f1ea5e7782c9d29800478c499e5a5`。独立机制审查与全文读者视角审读接受纯条件加一个 Stateful Move 的两次 tick 对照。不是实际机器人、游戏、计时或原生测试。

固定 BehaviorTree.CPP 4.6.2 提交 `2a8a226fbbd99f524f0796e0d8a3145773c61c06`。实际完整读取普通 Sequence、ReactiveSequence、ControlNode 相关实现，并核 TreeNode 执行、停止路由、前置条件与 StatefulActionNode tick/halt。首次条件成功后 Move 返回 RUNNING；下一次普通 Sequence 继续当前索引，而 ReactiveSequence 先重新检查条件。失败对仍 RUNNING 的 Move 触发停止钩子，并不证明外部移动已停止或位移已撤销。

两节点例排除额外脚本、注入回调、外部 halt 与动作自身条件检查，并要求上层确实再次 tick、条件看到更新值、函数正常返回。额外 `_while` 可改变路径；反应式结构前面的副作用也可能重新执行。未将此具体库说成 Killzone 3 使用的实现，也没有重复把一般取消建议当新发现。

固定头文件中 reset_on_failure 与多运行子节点异常的注释不能替代本版 cpp 的实际逻辑；本文不依赖该配置假设。初稿“通道一关闭就开始”收窄为“观察到通道关闭后”，并将“孩子”改成“子节点”；原稿保留于编辑记录，不当运行失败。

主文只增加一段可选源码对照入口，其余历史案例正文逐字保留。现有书目与任务数量不增加。此公开摘要保留审查范围，不含内部执行资料，也不冒充所有来源的重新认证。
