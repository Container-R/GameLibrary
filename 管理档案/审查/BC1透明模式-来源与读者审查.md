# BC1透明模式：来源与读者审查

本次维护为既有 BC 数据量文章增加可选支持，不增加图书或修改历史 DDS 观察。

独立去重全文读了 BC 预算、预乘透明度两主文及三个相关支持。现文已覆盖预算、过滤和覆盖率，尚未解释编码格式的逐纹素 alpha 表达限制。支持用黑白端点及一行编号连接这个缺口，而不是重复整条 mip 算术。

独立来源审读核对 Khronos OpenGL Registry 固定提交 `6af574a14089ccfee87efe230ebcdd8742859813` 中扩展 v1.6 的 RGB／RGBA DXT1 完整规则和 Issues 4、5，以及 Microsoft 的块布局和模式说明。两种 OpenGL 内部格式、相等分支、打包端点与逐分量插值的区别均有依据。Microsoft 后段示例仅写小于，本稿采用完整 if/else 与固定规范的相等边界。

独立读者视角审读要求读者能够区分：字节预算正确、编码能否保存所需透明度、过滤后的中间 alpha、最终混合方式。它不是实际素材质量测试或真人可用性测试。

支持正文 SHA256：`3fcb7414ade7523eda93a510b0926bd362e2038ccaaa5744ea26498d1706d2d2`。

黑白端点与编号是原创解释例，没有生成 BC 文件、运行编码器／解码器、进行 GPU 观察或比较替代格式质量。旧 DDS CPU 结果不作为本次透明能力实验。原始参考仍在支持正文底部，预算原文及其既有来源保留。
