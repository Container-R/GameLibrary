# 半透明三角形顺序：来源与读者审查

[glTF正文](../../GameLibrary/技术美术/环境管线/模型导入/读取glTF交错顶点数据时的偏移与步长.md)只增加一句可选[半透明重排支持](../支持资料/半透明三角形重排为何会改变颜色.md)。保留原字节布局、属性与索引、面角切线、稀疏替换和历史运行的适用范围，不新增书目。

作者之外的独立代理实际读取固定 meshoptimizer 0.25 源码快照 `6daea4695c48338363b08022d2fb15deaef6ac09` 的 README 三优化节与 API 说明，以及 W3C 2024-03-21 Compositing and Blending Level1 CRD 的§5.1与§9.1.4。前者支持三角形重排与顶点存储搬移的区别，后者支持 source-over 代数；没有把 Web 规范当 GPU 三角形调度规范。

原创场景明确假定两片段覆盖同一采样点、均参与合成，使用固定线性RGB、不透明黑底，并按给定列表逐一source-over且无后续排序。红色alpha1/4、青色alpha3/4，红后青得到(1/16,3/4,3/4)，青后红得到(1/4,9/16,9/16)，最终alpha均1。正确预乘不消除这项次序差别；各面的内部绕序保持不变。

这不是优化器对该输入的实际输出，也不是官方透明禁用条款或任意渲染器的默认行为。顶点完整属性重映射仅用于区分操作，不宣布任意依赖编号的shader保持画面。没有通用排序或性能结论。
