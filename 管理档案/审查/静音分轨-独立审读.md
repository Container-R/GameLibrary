## 先读后的复述与可读性

读者要解决的是：裁掉一条轨道的零值尾部，为何连另一条轨道都变响。关键不是“零有没有声音”，而是归一化还把哪几条输入算在参与集合里。先手算缩放，再说明输入结束、队列耗尽、处理块和输出时长，最后把三种有限旧观察及实际剪尾选择接起来，顺序自然。

文中解释 stem、normalize 和 PCM 帧，不强迫读者先理解 FFmpeg 内部对象。没有把表格数字写成试听效果，也没有把所有软件的混音规则统一成除以轨数。最后的交接说明服务素材变更，而不是另建一套管理审批流程。

## 独立原源及反例检查

本次通过 GitHub 只读连接器实际成功获取 FFmpeg 官方仓库固定提交 `3a0867c2bfda4a4d4309ca1a8cbdc6175e67f587`，不继承作者的网页失败/成功记录作为自己的阅读证据。

1. [`libavfilter/af_amix.c`](https://github.com/FFmpeg/FFmpeg/blob/3a0867c2bfda4a4d4309ca1a8cbdc6175e67f587/libavfilter/af_amix.c)：180–250、430–510；另主动补读251–430，以核对初始 scale_norm、实际乘加、首路块尺寸与 active/duration 的关联。返回文件 blob `bc97200926123c077001db5f95ce94cf3b71d6ed`。
2. [`doc/filters.texi`](https://github.com/FFmpeg/FFmpeg/blob/3a0867c2bfda4a4d4309ca1a8cbdc6175e67f587/doc/filters.texi)：2476–2575 中 amix 完整选项/例子，3142–3185 中 asetnsamples 完整说明。返回文件 blob `428986a1e905255b768c5999916340a5c148a2f1`。没有将相邻未使用章节算入论证。

具体判断：

- 两路等正权重1，初始参与集合不变时各乘1/2，因此 `0.5/2 + 0/2 = 0.25`；只剩 A 且缩放调整完成时得到0.5。关闭 normalize 在本例权重1下各乘1，A仍为0.5。新文限定等正权重，不把源码的绝对权重/符号行为泛化为任意权重公式。
- calculate_scales 看 INPUT_ON 和权重，不看样本是否恰好全零；实际输出再取 FIFO 样本并乘比例。零值与输入已退出的区分成立。
- activate 收到 EOF 先置结束标记，只在 FIFO 空时移除 INPUT_ON；output_frame 另受第一路块尺寸、其他队列可用样本和 EOF 影响。因此原文“EOF 不等于最后数据已混完”正确，不能只拿文件长度推定所有调度下的逐样本分界。新书已明确2048的精确边界仅属该旧配置。
- dropout_transition 是重新缩放的过渡参数，duration 是输出终止政策；二者作用不同，但并非无关的独立系统。书中没有声称任意 duration 都能观察同样后半段。shortest 会提前结束输出，不能直接套用 longest 表。
- 零过渡在源码中仍经过浮点除法及夹限，而不是独立整数分支。新稿没有把手算当零过渡实现的形式化证明；旧证据边界明确保留非有限值/不同字节应失败的前提。无需把这项历史验证器细节强插入读者主线。
- asetnsamples 的 n 是每声道样本数，p=0 不补最后块；4096/256=16、2048/256=8，例子没有不完整末块。新书区分 PCM 帧和音频处理块，避免“256帧”两种含义混用。
- normalize=0 的固定实现仍使用权重，不是无条件忽略所有增益。本文限定权重1，并明确多路非零求和须另查余量、格式和削波，没有把诊断配置推荐成生产通用修复。

这些原源核对支持机制与限定，不重新证明旧安装程序就是该提交构建，也不证明三配置旧输出真实通过。历史表是已发表旧文的忠实转述：三条件、两次重复，而不是六个独立场景；没有新增测试计数或听感结论。
