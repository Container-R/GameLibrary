## 来源与执行前审查

官方 Lua 5.4.8 发行归档的字节数和 SHA256 与官方索引一致，许可为 MIT。既有固定 Git 提交的 lcorolib.c、lfunc.c、lstate.c、ldo.c 与发行包对应文件逐字相同，未认定整个仓库与归档等同。实际来源定位及许可见[包内来源](../支持资料/Lua协程关闭观察/SOURCE.json)。

主审和独立审查者分别读固定关闭/恢复路径、完整协议、夹具、运行器和输入清单。冻结 manifest SHA256 为 `abca9985262bfe5198b453ac737260f969ccdabdfed6fbff68f1f337fce47f75`。静态核对 33 个 C 源文件、27 个头文件及预先写出的七行结果，不把静态检查称为运行。

执行前保持 generic 构建，将编译诊断与运行结果判定分开；未根据运行结果修改预期。环境隔离、输入复制核验和有界进程组准备在第一条原生命令前完成。这些措施不是安全沙箱，也没有实测超时清理故障。

## 两次实际观察

主轮与独立代理各在全新目录编译、运行一次。同一宿主、同一冻结输入，独立代理已知主轮结果，不是盲测或跨平台。每轮三个分支、七个阶段；两份输出和回执逐字相同。没有失败原生尝试或消警重跑。

- 正常恢复：先暂停、关闭零次；恢复到结尾后经过普通代码并关闭一次。
- 暂停时关闭：跳过暂停后的普通代码，但关闭方法记录一次。
- 原始错误后关闭：错误使协程先进入 dead，关闭记录仍为零；显式 close 后记录一次，却仍返回假和同一个原错误。

返回值数量、状态、错误对象身份和事件顺序分别核对。普通表记录不代表真实游戏资源已释放，原文 acquire_scene_resource 例仍未执行。

两轮编译退出为零但存在 tmpnam 安全警告；运行退出为零且运行 stderr 为空。完整诊断已分别读取，其涉及的临时文件接口未被夹具调用，不因此认证该接口安全。原回执中的待审标志未改；后续[诊断审读](../支持资料/Lua协程关闭观察/DIAGNOSTIC-REVIEW.md)单独闭合有限判断。公开不包含原始环境相关日志、归档源码或二进制。

## 独立读者视角审读

完整阅读主文、支持说明与 11 件公开包文件。主文仅一段入口及来源前言变化，逆变换逐字恢复原文。支持能解释为什么 dead、close 真/假和实际收尾记录不能互相替代；没有将三分支写成七个案例，没有把关闭自身再报错混入第三支。

按目标目录核对主文 → 支持 → 包 → 两轮输出/回执及返回链接。公开包四件冻结输入、四件观察均与实读原件逐字一致；官方归档需要另从原来源取得，已明确说明。完整载荷检查未发现私有执行信息。该审查为代理读者视角，不是真人可用性测试，也不是所有 Lua 分支或引擎集成认证。
