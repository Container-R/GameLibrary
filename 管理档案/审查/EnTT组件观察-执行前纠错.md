# EnTT 组件字段观察：执行前纠错与未完成范围

2026-11-02。本项仍在代码审查，**没有编译或执行组件夹具**。既有无组件 v2/v3 记录不用于证明组件字段的载入行为。目标是加深现有实体句柄文章中的一个小节，不另造重复书目。

## 原始来源读错的调用形状已纠正

固定 EnTT v3.13.2 提交 `78213075654a688e9da6bc49f7f873d25c26d12c` 的 [snapshot.hpp 第78–110行](https://github.com/skypjack/entt/blob/78213075654a688e9da6bc49f7f873d25c26d12c/src/entt/entity/snapshot.hpp#L78-L110)使用 std::apply 把参数交给 lambda，但 lambda 内是逗号折叠：逐个参数调用 archive。初审曾将其误读为一次双参数调用，协议作者与主编重新读原源后纠正，原审查及撤回说明保留。不是上游接口变化或原生试验失败。

拟定条件只有两个来源实体、其中 holder 持有简单 Link 字段，目标预置一个 seed。其 writer 有实体4个、组件3个有类型条目，也对应7次单参数调用。字段保留与 owner 映射是不同路径；[官方扩展测试](https://github.com/skypjack/entt/blob/78213075654a688e9da6bc49f7f873d25c26d12c/test/entt/entity/snapshot.cpp#L757-L807)在自定义 archive 中显式转换 target，不是默认加载器自动遍历任意成员的证据。当前只完成来源与协议审查，不是执行过这些官方测试。

## 合成消费者的保留值缺口尚待新版本闭合

首个组件消费者仅排除完整值 0xffffffff。独立挑战把 R/H/S/B/L 五个已声明活跃身份分别一致改成保留索引或保留版本，10例均被误接受；原有81个反例被拒不能抵消这10个失败。所有反例是合成数据，没有启动 C++ 或 native。

[entity.hpp](https://github.com/skypjack/entt/blob/78213075654a688e9da6bc49f7f873d25c26d12c/src/entt/entity/entity.hpp#L220-L275)的 null 比较只看索引；普通创建及版本后继还排除保留值。因此需对本条件已知活跃身份补充索引、版本检查，不能误拒加载前的规范 null 映射，也不固定未来分配整数。失败的候选及初审撤回记录保留；修复后须重新冻结并复核，当前不宣称组件原生验证完成。

旧无组件消费者另有同一简化写法。其真实输出不含上述保留身份；已独立审查的[补充消费者](../支持资料/EnTT映射存在与当前有效性/reserved-identity-check/README.md)只增加事后内容检查，不改旧代码、回执或原始观察，不把合成缺口夸大为引擎故障或旧数据无效。
