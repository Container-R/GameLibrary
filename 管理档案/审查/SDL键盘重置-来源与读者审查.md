# SDL 键盘重置与玩法提交：来源和读者审查

2026-11-03。已有固定步、玩法、无障碍和焦点文章已说明失焦、暂停、恢复及积存输入的设计政策，因此不重复扩写一般失焦规则。本批只补一种具体接入风险：SDL 清理按下状态时产生的 up，不自动等于玩家提交蓄力攻击。

## 固定来源与实际范围

官方 release-3.2.8 tag 对应提交 f6864924f76e1a0b4abaefc76ae2ed22b1a8916e；主审读取同提交版本宏和选定键盘、窗口、事件头声明与实现。独立来源审者从官方取得并核对所述段落，不以本地安装库或当前滚动 wiki 代替该源码身份。

ResetKeyboard → SendKeyboardKey → 内部按键处理的路径支持状态清理与 up 生成；事件启用、过滤与入队结果限制实际交付。旧键盘焦点转为 null 的分支先调用 reset，再请求发送失焦通知，但两个非空窗口互切不满足这一重置条件。调用路径顺序没有被扩大为所有平台或应用回调的最终顺序。未审平台后端、内部完整事件队列或所有输入来源。

## 原创接入推演

支持用仍有效的蓄力说明正常释放、应用取消与已经接受攻击的区别。主动上下文切换时先禁止旧动作提交、取消蓄力再做输入重置，是本例的应用安排；不是 SDL 默认战斗规则，也不是自动失焦的通用解决办法。公开字段 which 为0不被当作重置专属标记。

独立读者审读要求能解释为什么清理按键仍可能误出招，以及为什么较晚收到失焦通知后再取消未必足够。主文只增加一个可选入口，原岗位与虚构蓄力斩正文、来源及未执行边界保留。按拟位置核入口和返回；远端导航另在提交后确认。

没有编译或运行 SDL、输入设备、实际窗口焦点、玩法状态机或任何原生实验；没有测量事件时间或证明跨平台恢复安全。独立代理审读不是玩家测试，源码解释也不认证一份完整输入适配器。
