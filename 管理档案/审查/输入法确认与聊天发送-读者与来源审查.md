# 输入法确认与聊天发送：读者与来源审查

[正文](../../GameLibrary/界面与体验/交互设计/文本输入/确认输入法候选时，为什么不该顺便发送聊天消息.md)针对一个虚构聊天场景，区分按键、组字中的内容、编辑组件接纳的草稿和业务发送。它补充了原焦点恢复与伪本地化书没有展开的输入过程，没有复制一套通用编辑器实现。

独立读者视角全文审读与关键原源复核接受此有限范围。固定 UI Events 工作草案的退出按键序列支持纸面反例：同一次按下用于结束组字，其松开时的当前标志已变化，不能仅据 false 推断另一次发送。组字完成或取消都不等于消息发送；组字期间也可能产生 DOM input，不能将每个 input 都解释为最终文字接纳。

Unity Input System 1.11 页面本次标示1.11.2；只采用文本输入、组合串和启用状态的接口职责。WHATWG HTML的默认按钮激活保留隐式提交的条件，不宣称每个输入法确认都会提交表单。两份固定 W3C 工作草案对 beforeinput/compositionupdate 的顺序表述不同，正文没有合并成通用实现规则。

独立审查特别排除了“吞掉结束后的下一次 Enter”、只拦一个自定义监听即覆盖全部提交入口，以及把网页序列当Unity实测的误导。实际组件能否给出足够的动作归属信息，仍需按文中的目标操作检查；这些检查未执行。
