# 透明纹素过滤顺序：来源与读者审查

现有预乘透明度文章只增加一个可选支持入口。原文的合成、颜色域、CPU 历史观察与 sRGB 采样说明不改；新材料没有扩张为另一本文档主线。

[支持稿](../支持资料/透明纹素的颜色为什么会混进边缘.md)比较同一线性工作域中不透明红和全透明蓝的等权平均。比较对象始终为预乘颜色贡献：逐样本预乘后平均得到红贡献 0.5；先平均 straight 再乘平均 alpha 得红、蓝贡献各 0.25。两者 alpha 同为 0.5。透明区改黑后，后一种顺序仍只得红贡献 0.25，故不能据此建议批量清黑素材。

独立去重审查确认旧文没有解释这一具体顺序差别；独立读者视角全文审读复核了数值、例外和原始接口范围。OpenVG 1.1 Revision 1 的图像插值采用预乘，但颜色空间是图像自己的空间，不是所有引擎或采样器的默认线性保证。Porter–Duff 原论文仅作表示定义依据，不把原创过滤算例归给论文。

这是来源与纸面推导，不是 GPU、浏览器、图像库、真实素材或视觉效果测量。旧 Pillow 和 LittleCMS 观察未重跑，也不能用来验证新过滤条件。并非任意输入或特殊滤波都出现相同问题。原文新增入口和支持返回由整合同树检查确认；代理审读不等于真人可用性测试。
