# 完赛日报的迟到与版本复现

[返回正文](../../../GameLibrary/数据分析/指标设计/玩家行为/昨天打完的比赛今天才上报，日报该怎么改.md)

使用 Python 3.12.14、SQLite 3.53.1。运行 `python3 probe.py`，只读写内存，输入是合成记录。固定宽度的 UTC 文本用于简化示例，不建议照抄为生产的时间类型。

- [完整试件](probe.py)、[实际输出](observed.txt)。
- 两个日期、三次快照，同一份完赛事件重发一次。比较发生日和首次接收日，显式测未去重结果。
- 模拟两个已在快照中可见的导出检查点，验证到封账时钟但第二个分区仍落后时继续临时；分区均跨日界才封账。
- 回补增加旧日修订，不挪到新日；旧、同版重试不改变当前值，冲突 payload 和使用陈旧收件截止的新版本号另测。
- [来源和限制](../../来源笔记/late-match-telemetry-20261126.md)。未执行 Beam/PubSub 等分布式工具、未接触真实玩家数据。分区检查点是给定输入，而非从 SQLite 模拟出框架水位线。
