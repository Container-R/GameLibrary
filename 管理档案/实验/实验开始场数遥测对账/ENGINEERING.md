# 故障注入对账包

2026-11-10。Python 标准库，原创确定性教学模型，无网络、真实玩家或生产查询。仅在本目录写文件。本附件配合正式路径中的正文使用，不构成统计估计方法或上线建议。

## 文件与运行

- `inputs/`：十二份可观察输入，可先自行分析，再核对保存输出。
- `analyze.py`：只读取指定 JSON 的可观察字段，输出阶段差集、原成员账表、原分配汇总、内部序号缺口。没有 oracle 导入或外部真值读取，也不依据文件名分支。
- `make_fixtures.py`：输入生成器，包含故障设计。
- `oracle/hidden-worlds.json`：隐藏过程说明，与分析器隔离。`oracle/expected.json` 为部分预期检查索引；完整断言在测试中。
- `test_experiment.py`：模型自动测试；不代替对正文的独立审稿。
- `outputs/`：每个输入实际执行的 JSON 结果。
- `run-record.json`：解释器、执行命令和输入/输出/源码 SHA256。

在此目录执行：

```
python3 make_fixtures.py
python3 -m unittest -v test_experiment.py
python3 analyze.py inputs/case-08.json
```

入口使用显式 ValueError 校验模式、成熟窗口、权威与收件时间，以及唯一性；普通和 `-O` 两种模式各14项测试通过。这个模型仍不是生产 schema 验证器。生成器重建本目录指定输入和 oracle，输出脚本只向 stdout 打印。

## 可观察链与修复边界

服务器接受记录先提供目标定义与独立锚点；客户端收件只提供“客户端记录服务器已接受的开始”在快照内的观测，不是所有本地点击流。目标换成点击并不改变来源语义；no_authority_match 是待核查状态，不证明点击不存在。分析器检查台账标签、权威身份及开始时刻后去重，再应用显式最终查询。错误标签不会把 T 玩家改入 C 组；不自动修补客户端记录。全批收件先检查相同 id 的不一致 payload（包括好/坏标签混合），冲突即 ValueError 终止整份分析；每(player, epoch, seq)也必须唯一映射事件id。单个不匹配权威的记录可隔离，不计为重发。

输出 `authority_observed` 是该快照的锚点数；只有目标为 server_accept 且完整性合同为真，`target_N` 才以它计算，包括可证明的0。否则 target_N=null，不能读成0。`final_observed` 始终是查询产物的观察计数，不可自动拿来替代目标数。目标已知时可以从可靠权威表重建开始数，但这不重建任何完成结果；本实验没有生成完成率数据。

`anchor_not_received_at_snapshot` 仅表示截至快照未见客户端记录，不区分永久丢失和迟到。输出 parsed_sequence_gaps 明确在解析后的记录上检查；错误标签等解析拒绝也可造成缺口，需结合 received_not_parsed 与原始收件差集定位，不能自动归为上传丢失。序号合约限定为每个(player, epoch)专门对客户端生成的服务器已接受开始遥测计数，新逻辑事件逐条加1、重发沿用原值；不覆盖其他事件或全部点击，起止完整性仍未知。序号只检查同一玩家/epoch 已观察到的最小与最大序号之间的缺口，不推断不可见 epoch 或尾端。我们没有采用 Skype 的最短序列阈值或任何丢失容忍率。

## 实际结果摘要

- case-01：C/T 权威目标开始为6/4，链内对齐。支持在给定服务器接受口径下开始数下降，不识别行为原因或因果显著性。
- case-02：T 权威开始6，客户端缺 T1-2，内部序号缺2。原成员均保留。
- case-03：T2 被功能后条件排除；其三条已解析记录不进入指标。原台账仍保留该成员，不能把最终人数1替代原人数2。
- case-04 与02的观测记录相同（流系列标识不同）：一个隐藏过程是迟到，一个是永久丢失。case-05 收集截止为200，补到同一事件，原04文件未变。
- case-06：重复 T2-3 去掉一份；case-07：同 id 的错误 C 标签隔离，按原分配统计而不污染 C。
- case-08：T2整个客户端序列不可见，没有该 epoch 的内部序号缺口条目；三条服务器锚点揭示未收到。无缺口不等于完整。
- case-09/10 可观察 JSON 完全相同，隐藏客户端点击分别12/15；多出的点击未到服务器，其中有完全不可见 epoch 与尾端。分析结果相同，目标开始数均未知。
- case-11/12 可观察 JSON 完全相同，且明确没有权威完整性保证；隐藏服务器接受分别12/15。锚点和客户端共同漏掉整段时，分析器不能识别该差别。

09/10 的实际隐藏点击列表及接受/遥测映射保存在 `oracle/click-worlds.json`；生成器的 project_click_world 分别投影两世界，测试核对集合不同、点击数12/15且投影相同。11/12及02/04仅是同观测记录与不同解释的纸面反例，没有独立隐藏事件级投影，不把它们称作故障生成验证。分析器不读取这些隐藏信息。09/10证明仅使用该输入的确定性分析不能区分两种点击真相。这是有限可识别性反例，不是对真实游戏丢失率的估计。

## 自测与局限

测试包含三主机制、迟到/永久丢失观测等价、重复、错误标签、整段序列、两对隐藏世界、未来记录拒绝、序号冲突拒绝、权威 payload 重发冲突失败闭合、右边界窗口拒绝、确证零值。它验证教学代码行为，不验证上游来源理论或生产管线可靠性。
