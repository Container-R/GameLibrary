# 音游的判定与输出时钟：合成试件

[正文](../../../GameLibrary/玩法程序/玩法系统/时间与模拟/音游明明踩在拍上，为什么总被判晚.md)

```sh
node clock.js
```

- [clock.js](clock.js)：Node 24.22.3，使用一组手工设定的单调时钟记录与两个歌曲位置锚点。对照音频混合游标、带事件时间的输出映射、错用收到事件的逻辑帧。窗口 ±30 歌曲毫秒，含两端，补偿先减后映射。
- [clock.observed.json](clock.observed.json)：预混游标领先 60；同帧按事件仍可区分 +45 与 −28；改设备锚前报告不准备就绪，旧映射对新输入会错 +80，换锚后误差 0。也断言 seek 的旧代际输入不进入新代际，以及一个新段内报告经补偿落到锚的有效范围之前时不能外推。
- 不连接真实音频、显示或输入设备，不测操作系统事件精度，不模拟完整判定队列。谱面只含一个固定目标拍，批次过滤只检验两个到达同一帧的输入是否落窗；漏击截止一节只计算边界，并没有运行提交队列，也未模拟变速。
