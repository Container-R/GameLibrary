# 异步寻路结果接纳：受控完成顺序复现

[返回正文](../../../GameLibrary/游戏人工智能/移动导航/路径查询/异步寻路结果何时还能交给%20NPC.md)

使用 Python 3.12 标准库。在本目录执行：

```sh
python3 state_fixture.py > /tmp/async-path-observed.txt
cmp /tmp/async-path-observed.txt state_fixture-observed.txt
```

- [测试脚本](state_fixture.py)
- [原始输出](state_fixture-observed.txt)

脚本不调用真实寻路引擎。它用符号 A、B、C 代表路径及目标，用同步的测试代码注入等价于排队的完成事件。断言直接检查已经安装的路线、移动状态和等待中的请求号；有错误会抛出异常。无校验版本作为反例，校验版本把结果匹配、消费和状态写入交给同一个所有者。

受控组合包括过期成功、过期失败、真正的当前失败、旧完成先入队后被替换、旧工作只释放单独的在途槽位而不安装路线、同目标重查、重复回调、对象池复用。六种顺序是在 A、B、C 均已提交之后注入，检查最终状态，不代表 UE 一定乱序或给出了其运行中的调度比例。区域分为 east/west，位置是一维整数；`2` 是夹具中的阈值，不能作为生产环境绕墙或重新接入路径的判据。
