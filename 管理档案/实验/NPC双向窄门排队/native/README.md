# 单人通道：Godot 碰撞探针

版本：Godot 4.7.2.stable.official.ed1daf0bf。执行：

```sh
sandbox=$(mktemp -d)
XDG_DATA_HOME="$sandbox/data" XDG_CACHE_HOME="$sandbox/cache" XDG_CONFIG_HOME="$sandbox/config" \
  godot --headless --path . --script bottleneck.gd --disable-render-loop --fixed-fps 60
```

试件使用真正的 `CharacterBody2D.move_and_collide`，有两段静态墙和两只半径 30 px 的圆，通道从 x=0 到 x=200，内侧净宽 110 px。两方案初始位置相同：东行 A 在 (-50,0)，西行 B 在右侧等待位 (250,90)。A 每次最多向右申请移动 2 px；B 获准移动时，先在 (250,0) 并入，再每次向左申请移动 2 px。每帧先尝试 A 再尝试 B；没有运行导航路径查询或 RVO，也没有绘制角色。420 个物理推进是固定观察窗，不是实时性能测量。

- **无入口许可**：B 从一开始即尝试并入并西行。没有谁完全通过狭段。676 次移动调用返回碰撞；两个圆心采样最小间距为 58 px，低于 60 px 直径，因而不能称这个基线无重叠。记录的是推进末的圆心，不诊断这一暂态重叠的原因。
- **有入口许可**：A 先通行；第 140 帧整圆清出狭段。继续留住许可直到第 183 帧 A 的圆心到 x=316、圆尾为 x=286，西行 B 在 x=250 的合流线此后有足够间隔。B 在第 367 帧整圆清出左端。零次移动调用返回碰撞，推进末的最小圆心间距是 66 px。这个有限轨迹不证明任意速度、半径、障碍或更新次序下安全。

[实测日志](observed.txt) 来自连续三次逐字节一致的运行。返回碰撞的调用次数不等于碰撞对数，选定阈值只适用于此几何。试件不测试有限批处理、动态障碍恢复或人群调度的公平性；那些规则需要独立测试。
