# 教学进入者分母：SQLite 复现

需要 Python 3 标准库，执行 `python3 reproduce.py`。测试环境为 Python 3.12.14、SQLite 3.53.1。[原始输出](observed.txt) 随附；版本首行可能因系统而异。合成数据仅用于说明分母和连接方式，不是某款游戏的数据、统计功效或显著性展示。

- **分配台账是分母。** 200 个唯一账号，两组各 100；各组 50 位熟练、50 位新手。A 人人进入；B 只有 50 位熟练和 10 位新手进入。熟练进入者的完成率均为 80%，新手进入者均为 20%。全分配完成率 A 50%、B 42%；进入者完成率 A 50%、B 70%。后者比较的是不同组成，不能证明教学本体变好。
- **保留账号一行再聚合。** 观察窗口为分配时刻起的半开区间 `[assigned_ts, assigned_ts + 100)`；数据必须在报告截止时已收到。先按账号选择有效的进入和之后的完成，再左连接分配台账。一个 B 玩家有 2 条进入投递与 3 条完成投递，直接连原始表会得 47/65 条记录，而正确结果是 42/60 人。额外控制提前的完成不能遮蔽后来的有效完成，入口不早于分配、完成不越过窗口。
- **预先定义的资格只是子样本。** 合成开关在分配前确定，并以同一规则写入两组：50 位熟练和固定 40 位新手合格，两组各 90。这个子样本 A 48/90、B 40/90；互补样本分别 2/10、2/10。这个数据是构造出的，不能把补集里估计为零当作真实实验的无影响证明。
- **未知不算不完成。** 另一次读取模拟一条按时发生却到报告之后才到达的完成和一个观察窗口尚未收齐的账号。截止 120：B 41 个确认完成、57 个确认未完成、2 个未知，其中一人已成熟但数据迟到，一人尚未成熟。41% 到 43% 暂估完整 100 人队列的最终范围，将两类未定状态一起计入；它不是成熟队列指标，也不是统计置信区间。仅分析 99 位成熟账号时，应用范围 41/99 到 42/99，并另列 1 位待成熟。试验先定义完整的分配台账，所有分配都已在本次查询的截止时点前发生；生产查询需另限定截止时点与分组可比的成熟批次。截止 150：42/100，未知清零。示例里的覆盖表是独立的完整性凭证；现实里不能仅凭日志缺一条便默认为完整。
