# 重叠贴花的遍历顺序：数字模型和项目里的对照

对应正文：[同一面墙上的重叠贴花，为什么会互换上下层](../../../GameLibrary/技术美术/环境管线/纹理与材质/同一面墙上的重叠贴花，为什么会互换上下层.md)。

## 已运行的位掩码模型

运行 `python3 -B mask_probe.py`。[源文件](mask_probe.py)用小键填充记录把红 A（键 8）和蓝 B（键 10）向后移；只有 A/B 写入采样点的掩码。循环依次访问字，再取字内最高置位，按 0.5 权重混入黑底。Python 3.12.14 的[原始输出](mask-observed.txt)保留了索引、十六进制字、访问结果和线性颜色。将 A/B 的输入顺序交换不变；各自单独打开只得到各自颜色；全不透明最后只留下最后处理的颜色。

这是以源码为依据的算术重建，不调用 Godot、Unreal 或 GPU，不包含视锥剔除与配额，也不预测色调映射后的截图数值。填充能进入贴花记录、A 与 B 都覆盖目标点是显式前提。

## 可在项目里做的 Godot 4.7.2 对照（此处未执行）

1. 固定 Forward+、同一个相机和同一不透明墙面。把红蓝贴花指向墙，选相同的可接收层，仅用基色。单独开启时确认目标位置都有颜色，关掉距离和法线淡出，固定机位、曝光和光照，以免把变色误判成光照变化。
2. 保持红蓝两张的变换和排序偏移，逐批增减位于同一视图、排序键小于两张测试贴花的填充贴花，每张都用有效基色贴图，不用空 Decal。把投影体积布置在另一面墙或窗口另一侧，不改目标点。能读渲染缓冲区时，先验证 A/B 的相对 CPU 顺序没变，再记录实际索引和目标区域颜色；先找 30/31、31/32、32/33，不用节点总数代替记录索引。没有捕获工具时，可在固定版本的调试构建中用两张目标贴花的位置区分记录，在填充缓冲区的循环与簇登记处各打印一次对应索引；不要假定跳过的记录也会登记。
3. 对照组让填充退出视图或临时隐藏并核查它们确实不再进入列表。若两张单独显示有变化，先排查接收和投影；若索引没跨字，这次不验证表中翻转。不要把 Mobile 或另一个 Godot 版本的输出拿来宣称本实现已验证。
4. 项目修复后恢复生产材质，验证标记与普通污渍各自的侧向覆盖、关卡布景密度和移动机位；也检查用于避免重叠或在材质内合成的实际成本。
