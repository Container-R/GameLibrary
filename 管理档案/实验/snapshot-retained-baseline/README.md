# 增量快照基准缓存复现

[返回正文](../../../GameLibrary/网络与在线服务/实时同步/消息传输/增量快照包到了，客户端为什么还是不更新.md)

Python 3.12.14，无第三方依赖。两个脚本使用单个合成状态流和可视的时序，未打开套接字、未运行实际游戏或测带宽和延迟。

```sh
python3 model.py
python3 window_probe.py
```

- [丢包和恢复流程](model.py) · [实际输出](observed.txt)：先丢 101；基于末次发送快照的链会断，基于仍保留的 100 可以还原 103；随后独立更新恢复缓存。
- [接收窗口与精确基准](window_probe.py) · [实际输出](window_observed.txt)：8 槽覆盖最早仍合法的基准；5 槽发生取模碰撞，精确身份拒绝。分开测试有用包缺基准、过期包丢弃和迟到的旧全量不清恢复请求，并枚举多组 D/R。
- [来源及适用条件](../../来源笔记/snapshot-retained-baseline-20261126.md)。脚本使用无限整数直接比较，不是定宽网络序号实现，也未实现多代、多流、快照队列传输或丢失恢复请求的重试定时。
