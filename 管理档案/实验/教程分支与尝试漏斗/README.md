# 教程分支与尝试漏斗

对应正文：[教程可以跳过和续学，完成率应该怎么算](../../../GameLibrary/数据分析/指标设计/玩家行为/教程可以跳过和续学，完成率应该怎么算.md)。

运行 `python3 -B trial.py`。它在内存 SQLite 执行 [events.sql](events.sql)，固定输出见 [output.json](output.json)。已在 Python 3.12.14 的 SQLite 3.53.1 重复运行。无真实玩家数据，不访问网络。

- 六个有效样本账号 A 至 F：按玩家保序得到 A、B、C、D；按会话保序得到 A、B、D；按尝试判断后投回玩家集合是 A、B、C。后两者总数同为三，名单不同。
- A 至 F 有 7 次业务尝试：3 完成、1 跳过、1 作废关闭、2 未结束。C 通过合成业务顺序将晚到移动、回看说明和跨会话确认还原；D 两个尝试不拼接。
- G 同序号不同内容、H 同尝试混版本、I 初始收到 1、2、4，均未知；随后补到 I 的第 3 条“跳过”，才将 I 判为跳过。合同约定序号连续从 1 开始。
- 试件只有一个教程；`DISTINCT (player,attempt,seq,kind)` 是为给定重复载荷写的简化，不等于生产事件 ID 去重。有效对照另外提供合成跨尝试发生顺序，不从各自的 `seq` 反推统一时钟；G/H/I 不参加 A–F 的集合对照。没有模拟截止窗口或进度存档事务。
