# 显示换帧间隔与连续超标：复现

[正文](../../../GameLibrary/图形渲染/渲染开发/帧性能诊断/P99%20一样，为什么一段偶尔卡、另一段连续卡.md) · [来源核对](../../来源笔记/frame-interval-episodes-20261125.md)

```sh
node probe.js
```

[试件](probe.js)用整数或半数刷新节拍表示合成输入，毫秒在打印时才换算。[输出](observed.txt)由兼容 JavaScript 的运行时执行该代码得到，未启动 PresentMon、Perfetto、游戏或图形设备。脚本用单个已知连续的显示流，未对真实 CSV 补洞或归并多流。

- 两组各 601 个显示时刻形成 600 个间隔，包含 594 个一节拍及 6 个三节拍间隔。总时长 10.2 秒。最近秩 P99 等于排序第 594 项。阈值严格大于 2 节拍，长间隔排在一起时只合并时间相接的区间。
- 六帧提交保持等距，在故障支路中 C/D 明确没有显示。只有当 B 到 E 之间的显示观察范围已知完整，才可确定 B 停留 3 个节拍。窗口 [2,5) 对全流重建后再求交；错误的先裁事件版本故意留作对照。
- 有意的 30 fps 对照每 2 个 60 Hz 节拍换一帧，验证阈值须从项目规定的上限来解释。这里只测算术和边界，不规定感知或平台容差。
