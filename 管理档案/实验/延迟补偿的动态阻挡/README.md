## 已执行：同一查询，只换门的样本

运行 `python3 -B gate_time.py`。Python 3.12.14 执行[脚本](gate_time.py)，五组断言通过，[输出](gate-observed.txt)同时保留判定与按距离排序的交点。门前缘与靶前缘分别为 15/4、31/4；进入线段的几何才产生交点。两者都开放给几何比较，随后游戏规则只认第一个阻挡。分析阶段的交点列表不等于实际 API 返回列表。

没有运行 Valve、Photon、Unity 或网络；脚本仅验证两个时间策略如何影响结果，不含时间换算、历史缓存、遮挡优先级并列或传输。

## 项目中的核对方法（待在项目运行）

- 每组用同一条已记录的输入与相机路线，记录目标的采样位置和形状、查询范围、各对象 ID、距离与实际时间来源。先证明无门时靶会被查询到，静态关门能挡。若项目没有暴露中间量，只把可控试件推断视为推断。
- Photon Fusion 2 的历史门试验只登记正确捕获姿态的门 Hitbox，并避免普通 Collider 在同一层再次参加查询；当前门试验只纳入该门的普通 Unity 3D Collider，通过 IncludePhysX 检查。保持查询形状、层、触发器和游戏的阻挡规则一致。若多个 Runner 共处一个实例，另核对所属物理场景。
- 门开→关和关→开各运行，再用静态关门、无门和靶移出查询线校验。若目标不相交，不用该次判断门的效果。若历史值已正确但门的 Collider 来源不符合配置，先修配置再讨论是否更改项目规则。
