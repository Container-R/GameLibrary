# 用真实增量调度复现导入规则覆盖遗漏

依赖：Python 3、Pillow、GNU Make。用 Python 3.12.14、Pillow 13.0.0 和 GNU Make 4.4.1 实测：

```sh
python3 reproduce.py
```

临时目录由脚本创建与删除。两种模式都调用相同的 Pillow 像素转换，源图为 1024×768；引入或删除平台覆盖时，源图、默认规则和音频控制文件的原始字节不变。构建端遵从「存在平台规则则覆盖默认规则」的优先级。

- **旧图**：精灵目标只声明默认规则，导入器真正运行时却读取平台覆盖。默认规则是最大边 256，第一次产出 256×192。新增覆盖使最大边应为 1024，但 Make 不运行精灵配方；对同一输入另做冷构建则得到 1024×768。
- **修复**：每次进入 Make 前都重算有效规则。解析器只在用于转换的值变化时原子替换 `effective.json`，Make 把它当精灵目标的普通先决条件，转换配方也从同一份清单读取设置。新增覆盖重建成 1024×768，删除后重建成 256×192，没有变更时跳过配方。音频目标只声明自身实际输入，没有被连带重建；脚本断言音频产物字节和 mtime 保持不变。

[实测输出](observed.txt)。这里验证的是 GNU Make 基于先决条件和时间戳的**调度**以及真实输出尺寸，不是 Unity、共享缓存或内容寻址键。解析与导入在同一进程链中顺序运行，不测试并行构建修改同一清单；生产系统需为缓存键和导入器提供同一个稳定输入快照，并对清单之外的新增输入有发现机制。
