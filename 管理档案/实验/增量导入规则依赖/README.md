# 增量导入规则依赖：复现材料

两种试件分别识别「构建没有安排任务」与「安排后请求仍命中错的缓存键」。两者共用 256 到 1024 的覆盖场景，但不是同一个构建系统；512 是模型另加的规则修改对照。

## 真正的增量任务与图片输出

```sh
cd native
python3 reproduce.py
```

[原理与运行要求](native/README.md) · [实测输出](native/observed.txt)。Python 3.12.14、Pillow 13.0.0、GNU Make 4.4.1。真实像素导入中，旧依赖图没有因覆盖文件加入而安排任务，因此保留 256×192；同样输入做全新的构建生成 1024×768。修复后有效规则清单只在值改变时替换，覆盖增加和删除分别重新生成 1024×768 和 256×192，贴图规则不使音频的字节或修改时间变化。音频文件是独立的复制控制，不是对音频导入质量的测试。

## 缓存键与同一输入快照

```sh
python3 cache_model.py
```

[实测输出](cache-model-observed.txt)。Python 标准库，七种冷热用例。尺寸字段只是模型值；它分别比较遗漏规则、固定基础规则和使用有效规则三类键。另测键和实际生成过程读取不一致快照，构造 256 的键复用 512 的错误。不是共享缓存或 Unity 原生试验。
