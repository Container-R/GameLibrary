# Android 音频焦点状态：应用策略试件

```sh
node probe.js | cmp - observed.json
node queue_probe.js | cmp - queue_observed.json
```

第一组执行八条指定事件序列，比较无条件在 Gain 启动和检查请求代次、场景、前台规则与玩家意图。平台授予、后台转换、丢失和系统增益变化都是人工输入。状态字段 `playing` 只是模型标记，系统增益 0.2 也是示意值，不代表实际音量、拍点或设备输出。前台是例子的产品策略，不是对 Android 15 准入条件的模拟。主动暂停与混音器滑块零音量用不同字段。

第二组同一场景同次请求内，输入 Gain 排队 Play、玩家暂停、引擎消费三步。只查身份的对照产生错误开播，实际执行前另查播放决策版本和意图的对照不会开播。这是应用下游队列的判例，未执行真实引擎。

均为原创 JavaScript 模型并实际重跑；未接入 Android 设备、真机焦点实现或声音播放。初组永久丢焦后采用等玩家再次发起的策略，且须取得新请求许可；未运行 SDK 的 FAILED 分支，由正文另列为集成验收项。
