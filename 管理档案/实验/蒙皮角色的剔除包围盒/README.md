# 蒙皮角色的剔除包围盒：几何对照与 Unity 验收

对应正文：[蒙皮角色在镜头边缘消失，先查姿态还是包围盒](../../../GameLibrary/角色动画/角色变形/蒙皮/蒙皮角色在镜头边缘消失，先查姿态还是包围盒.md)。

## 已运行的单关节对照

在本目录运行 `python3 -B pose_bounds.py`。Python 3.12.14 运行[脚本](pose_bounds.py)得到[九行原始结果](observed.txt)并通过断言。固定正交相机横向 [0,4]，不在其他方向裁切；局部网格由躯干范围和一根完全绑定在一根旋转骨骼上的袖尖代表。在所给角度范围，袖尖 x = 1.25 × cos(角度)。旋转区间 [−60°,60°] 包含 0°，因此可用 1.25 作为此模型右界，而不是把有限采样本身当作证明。

* 根 x = −1，伸手姿态不变：导入盒拒绝，修正盒通过，实际袖尖仍在 +0.25。
* 同一修正盒，换到旧转开姿态：盒通过，实际网格完全在界外。
* 同一伸手姿态移到根 x = −3：临时巨盒通过且几何不在内，局部修正盒拒绝。
* 试件是区间相交计算，不是 Unity 的 Animator 求值、原生视锥或画面实测；网格进入条件也不等于最终有像素。

## Unity 6.0 上的复核流程（未执行）

选有一个清楚伸出轮廓、确由骨骼驱动的网格部件。先用单位缩放与重合的 Renderer、根骨基准隔离坐标；固定单个游戏相机、层掩码、LOD、位置路线与输入，必要时在独立运行用固定的帧记录，移除额外视图、阴影可见性和遮挡等干扰。

1. 找到可稳定复现的边缘截图，在该正确骨姿改用 `AlwaysAnimate` 以便可靠重放。确认实际用于变形的骨骼最后状态，再用 BakeMesh 对比快照顶点转换后的世界范围与 Renderer.bounds。用 Frame Debugger 对比两组目标相机中的主视图提交。
2. 保持 Update When Offscreen 关闭以及动画、IK 和其他状态不变，只在第二组给该 Renderer 设置覆盖预期姿势的 `localBounds`。记录实际范围与骨姿，建立只换盒的证据。再把候选盒收紧至实际变形边界附近复测，避免把临时巨盒当最终值。
3. 固定修正盒与离屏蒙皮设置，选择包含明确离屏阶段及返镜头阶段的相机路线，对比原 Animator 设置和 `AlwaysAnimate`。使用确实会运动的骨骼，记录局部于模型的实际位置与旋转；若项目使用回调或作业写骨，在对应写回之后检查。若两组本来一直被当成可见，此对照并未触发离屏差异。
4. 恢复真实运行配置后验证过渡、IK 和换装组合；在目标设备分别测动画/蒙皮和绘制准备开销。不借用本模型预测毫秒数。
