- [最小竞争试件输出](observed.txt)：在一个 SQLite 连接上刻意交错两个过时的读取和随后的更新。无条件加一得到 5/4，权威状态条件更新只允许一次。不是多线程调度实测。
- [双连接试件输出](lease-observed.txt)：SQLite 3.53.1，在临时数据库中用两条连接确定性制造事务重叠，区分第一个请求持锁时的 `SQLITE_BUSY` 和重新尝试后的业务「已满」。确认将同一条预留转为成员，不删除占位再重建；旧定时任务按 ID、玩家、状态与截止检查。另有重发、截止相等、同玩家替换和转给另一玩家的断言。
- 时钟用合成整数，由调用者明确设定；单房实例自然隔离，不实现跨实例令牌、真实连接验证、主机迁移或忙重试策略。过期行作为历史保留；受理成功的同一 ID 重发不创建新预留，之前因满而没有登记的尝试可以重新检查。未运行 GameLift 或 Nakama。
