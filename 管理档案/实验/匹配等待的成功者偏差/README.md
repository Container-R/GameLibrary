# 匹配等待：成功条件 P95 与入队票的到期结局

在本目录运行 `python3 -B fixture.py`，再与 [实际输出](observed.jsonl) 比对。本次 Python 3.12.14、SQLite 3.53.1。没有联网或接入 AWS。

[SQL](wait_funnel.sql) 来自合成入队账本，假定合格的入队本身已按快照收齐：入队窗左闭右开，每票 60 秒跟进（端点包含）；只连接快照前已收到且发生于观察窗内的唯一终态。另有覆盖证据到达的时钟；例子的覆盖字段代表已确认从入队开始的完整性，而不是简单取最大的消息时间戳。试件不使用窗外终态证明待定，因此没有独立覆盖时仍是未知；生产若能核实窗外结果确为该票首次且不可逆的终态，也可据此判断端点时尚未结束。生产接入要自己落实权威、身份、重送、冲突和覆盖保证，不把这里的单票主键当去重算法。

脚本检查对照 A/B 的 P95（45/20 秒）、固定窗成功票（80/70），并验证 170 秒和 220 秒快照：恰好在 60 秒成功但后到、超过 60 秒才成功、系统失败、已确认待定、未成熟、入队右端点排除。没有成功时返回 NULL。断言覆盖两级分母对账。
